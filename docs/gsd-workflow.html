1 · La boucle de phase

Huit étapes, dans l'ordre. Rien n'est « done » avant l'UAT native — on dit « automated-ready ».

  • /gsd-phase --insert N création
    Créer ou insérer la phase dans le ROADMAP avant tout travail (ex. --insert 43 pour les 43.x). Déjà présente ? passer à discuss.
  • /gsd-discuss-phase décision
    Verrouiller uniquement les zones grises. Sortie : N-CONTEXT.md.
  • /gsd-ui-phase frontend seulement
    Contrat UI-SPEC si la phase touche l'interface.
  • /gsd-plan-phase
    Research → plan → plan-check. Couverture des décisions D-01..D-n vérifiée.
  • /gsd-execute-phase
    Waves, commits atomiques. Checkpoints tracer = internes.
  • /gsd-verify-work oracle utilisateur
    UAT native sur l'app réelle. Seuil résumé + confirmation visuelle = evidence suffisante.
  • /gsd-secure-phase oublié en pratique
    Vérification des threats du register. L1 grep short-circuit si ASVS-1 + register plan-time + 0 open.
  • /gsd-validate-phase oublié en pratique
    Audit Nyquist : chaque exigence a une vérification automatisée ou un manual-only assumé.

2 · Quicks & debugs — à tout moment

/gsd-quick automatisé + UAT

Tâche bornée (fix, petit comportement). Même discipline : commits atomiques, UAT native avant de dire « closed ». Pas de récupération d'un quick isolé échoué en exécutant sur main.

/gsd-debug systématique

Bug dur : méthode scientifique, instrumentation avant fix. Jamais de pivot debug → phase en cours de route, sauf demande explicite.

3 · Clôture du milestone — dans l'ordre strict

La phase release suit le skill release du projet (gates → release signée → UAT → publish).

1

/gsd-audit-milestone

Exigences, seams d'intégration, couverture Nyquist. Tant qu'il reste des gaps → corriger (validate-phase, UAT re-runs) puis re-auditer.

2

Phase release finale checkpoints utilisateur

  1. Docs + bump de version sur toutes les surfaces
  2. Gates automatisés verts
  3. Release signée/notarisée — étape crédentielle utilisateur
  4. UAT sur l'artefact signé — une passe complète
  5. Draft GitHub + notes avant publish
  6. Vérification de l'artefact téléchargé + install + lancement normal
  7. Stop conditions = hard gate → publish Latest
  8. Contrôle du tag post-publish — le tag doit pointer sur le commit de release (main pushé d'abord)
3

Re-audit

Score plein exigé. Sinon retour à l'étape 1.

4

/gsd-milestone-summary oublié

Bilan consolidé du cycle — référence pour le milestone suivant.

5

/gsd-complete-milestone

Archive officielle. Le tag existe déjà et pointe correctement — vérifier que GSD ne le déplace pas.

4 · Règles transverses

Push main régulièrement. GitHub crée les tags de release sur la branche distante — un main non pushé = tag sur un commit périmé.
« Automated-ready », jamais « done » avant l'UAT native. L'utilisateur est l'oracle final.
Bug GSD ≠ bug projet. Défaut de guard/sentinel/état avec reproduction indépendante → issue open-gsd via le pipeline du skill gsd-guide (doublons d'abord, redaction, autorisation séparée).
Skills compagnons : gsd-guide (global, ~/.agents/skills) pour l'assistance au quotidien ; le skill release du projet pour la phase release.

1 · The phase loop

Eight steps, in order. Nothing is "done" before native UAT — say "automated-ready".

  • /gsd-phase --insert N creation
    Create or insert the phase in the ROADMAP before any work (e.g. --insert 43 for the 43.x series). Already there? Move to discuss.
  • /gsd-discuss-phase decision
    Lock only the gray areas. Output: N-CONTEXT.md.
  • /gsd-ui-phase frontend only
    UI-SPEC contract when the phase touches the interface.
  • /gsd-plan-phase
    Research → plan → plan-check. D-01..D-n decision coverage verified.
  • /gsd-execute-phase
    Waves, atomic commits. Tracer checkpoints are internal.
  • /gsd-verify-work user oracle
    Native UAT on the real app. Summarized thresholds + visual confirmation are sufficient evidence.
  • /gsd-secure-phase often forgotten
    Threat register verification. L1 grep short-circuit with ASVS-1 + plan-time register + 0 open.
  • /gsd-validate-phase often forgotten
    Nyquist audit: every requirement has automated verification or an accepted manual-only.

2 · Quicks & debugs — anytime

/gsd-quick automated + UAT

Bounded task (fix, small behavior). Same discipline: atomic commits, native UAT before saying "closed". Never recover a failed isolated quick by executing on main.

/gsd-debug systematic

Hard bug: scientific method, instrumentation before fix. Never pivot a debug into a phase midstream unless explicitly asked.

3 · Milestone closure — strict order

The release phase follows the project's release skill (gates → signed release → UAT → publish).

1

/gsd-audit-milestone

Requirements, integration seams, Nyquist coverage. While gaps remain → fix them (validate-phase, UAT re-runs) then re-audit.

2

Final release phase user checkpoints

  1. Docs + version bump across every surface
  2. Automated gates green
  3. Signed/notarized release — user-run credentialed step
  4. UAT on the signed artifact — one comprehensive pass
  5. GitHub draft + notes before publish
  6. Downloaded-artifact verification + install + normal launch
  7. Stop conditions = hard gate → publish Latest
  8. Post-publish tag check — the tag must point at the release commit (push main first)
3

Re-audit

Full score required. Otherwise back to step 1.

4

/gsd-milestone-summary forgotten

Consolidated record of the cycle — reference for the next milestone.

5

/gsd-complete-milestone

Official archive. The tag already exists and points correctly — make sure GSD doesn't move it.

4 · Standing rules

Push main regularly. GitHub creates release tags on the remote branch — an unpushed main means a tag on a stale commit.
"Automated-ready", never "done" before native UAT. The user is the final oracle.
GSD bug ≠ project bug. A guard/sentinel/state defect with an independent reproduction → open-gsd issue via the gsd-guide skill pipeline (duplicates first, redaction, separate authorization).
Companion skills: gsd-guide (global, ~/.agents/skills) for daily assistance; the project's release skill for the release phase.
