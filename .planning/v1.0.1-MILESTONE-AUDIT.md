## Run 2 integration findings — NEW drop-holes (same class)

Write path is `ipcProjectSave(manifest as MceProject)` (`efxPaintPersistence.ts:1241`) → `project_save`; open path is `project_open` → `serde_json::from_str::<MceProject>`. Both silently drop any key the Rust struct does not name. TS round-trip tests **mock** `ipcProjectSave`, so they never cross this boundary — which is why these survived the judged UAT.

### BLOCKER N1 — `video_asset_id` (MceLayerSource) — affects VID-02

TS emits it (`projectStore.ts:353`); Rust `MceLayerSource` has `video_path` only (`project.rs:251`). Dropped every save/open. Hydrate falls back to `crypto.randomUUID()` (`projectStore.ts:544`), then re-discovery `addVideoAsset` (`projectStore.ts:668`) dedupes by the NEW id (`imageStore.ts:115`) → **duplicate gallery row per reopen**, written back by `toMceVideoAssets`. `video_path` survives so playback still finds the file; asset identity does not.

### BLOCKER N2 — `motion_blur` (MceProject) — no REQ-ID

TS emits it every save (`projectStore.ts:470-475`) and hydrates it (`:724-727`). Rust `MceProject` has no such field. Motion-blur prefs reset to defaults on every reopen. **REQ-map gap:** no REQUIREMENTS.md ID covers this persistence.

### WARNING N3 — `source_overrides` (MceKeyframeValues)

Emitted (`projectStore.ts:423`), hydrate reads (`:579`), absent from Rust `MceKeyframeValues`. FX layer source-property overrides lost across save→reopen.

### WARNING N4 — `Sequence.visible` never persisted (TS-side omission)

`sequenceStore` toggles FX hide; Rust `MceSequence.visible` exists (`project.rs:157-159`) but `buildMceProject` never emits it and hydrate never maps it. FX hide/show resets on reopen. This one is a TS omission, not a serde drop-hole.

### Systemic gap

No dual-language field-diff contract test. Only two targeted pins exist (extrapolation roundtrip, fps default). This class will recur until a test enumerates TS-emitted keys against Rust-declared fields.
