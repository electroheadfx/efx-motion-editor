## Integration findings

### BLOCKER — `Sequence.extrapolation` dropped on open (Rust serde hole)

**Affects:** 53.1 D-07 / I-5 (per-clip HOLD/LOOP persisted) · save→close→reopen composition

- **Save path is fine.** `buildMceProject()` emits `extrapolation` (`app/src/stores/projectStore.ts:272`); `buildPackageManifest` copies project fields verbatim.
- **Open path drops it.** `open_project` does `serde_json::from_str::<MceProject>` (`app/src-tauri/src/services/project_io.rs:96`). Rust `MceSequence` (`app/src-tauri/src/models/project.rs:126-160`) has **no `extrapolation` field and no flatten catch-all**. Serde silently drops the key. Hydrate then forces `'hold'` (`projectStore.ts:614`).
- **LOOP never survives save→close→reopen.**
- This is exactly the cross-language law Quick 2 (261012-d6q) established: a field must be declared in **both** TS and Rust. `video_assets` got the dual declaration; 53.1-03's `extrapolation` did not. Grep of `app/src-tauri/` for `extrapolation`: zero hits.
- 53.1-03's "persisted .mce round-trip" evidence is TS-only (`exportEngine.frameList.test.ts` hydrate mapping). The judged UAT checklist never exercised LOOP across reopen, so `53.1-UAT.md`'s coverage note overclaims.

### WARNING-1 — Diagnostic channels mask on export failure

**Affects:** 53.1 D-06/D-14 + VID-04

Gap warnings are computed before `preloadVideos` (`exportEngine.ts:206` vs `:258`), so both channels can co-exist — but `ExportProgress.tsx:60` renders warnings only when `p.status !== 'error'`. VID-04's named fail-closed error hides already-computed gap warnings (one-way mask). Fail-closed still fires; the gap name is lost from the UI.

### WARNING-2 — `sourceFrameCount` cache cold across reopen/resume

**Affects:** 53.1 D-07/I-5 + VID-04 composition

`MceVideoAssetRef` is only `{id, name, source_path}` — `sourceFrameCount` is runtime-only, written by `previewRenderer.resolveVideoSource` after `loadeddata` (`previewRenderer.ts:853-864`). `exportRenderer.buildOverlaySampleClip` falls back to `MAX_SAFE_INTEGER` when the cache is empty (`exportRenderer.ts:78-87`). First past-source frame after reopen/resume: the export gate disagrees with the seek path (which re-probes). Pixels stay correct (seek uses a fresh probe); overlay `localFrame` for fades/keyframes can be wrong.
