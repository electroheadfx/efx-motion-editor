## Narrative Findings (AI reviewer)

### Critical Issues

#### CR-07: The field-exact ack comparator rejects legitimate Loop Clip acks for lifecycle-less clips (infinity rails), after the parent has committed

**File:** `app/src/components/physic-paint/roto/physicsPaintRotoPlayScriptController.ts:3493-3525` (comparator), `2851-2860` (assertion)
**Issue:** The WR-07 fix added `syncState`/`provenanceState`/`phaseOrigin`/`originalEndExclusive`/`visibleRanges`/`frameOverrides` to `sameLoopClipCollections` with `?? null` semantics. The two compared collections are produced by *different projections*:

- `publication.loopClips` is the store collection built from `currentLoopClips()` (`controller:2343-2351`, `2714-2733`) — raw store clips.
- `result.loopClips` is `accepted.after.loopClips` (hook `useRotoPlayScriptController.ts:167`), produced by the coordinator's `captureSnapshot` (`useRotoPhysicalEditCoordinator.ts:1227`), which runs every clip through `cloneLoopClips` -> `parsePhysicPaintRotoLoopClips` -> `normalizeLoopClipForPayload` (`673-679`). The clone **always** writes `syncState`, `provenanceState`, `phaseOrigin`, `originalEndExclusive`, `visibleRanges`, `frameOverrides` (`722-727`).

Infinity Loop Clips are deliberately lifecycle-less in the store: `buildDefaultPhysicPaintRotoGroupLifecycle` returns null for infinity (`physicsPaintRotoPhysicalModel.ts:905-924`), `parsePhysicPaintRotoLoopClips` therefore leaves them lifecycle-less (`1023-1025`, `1074`), and both creation sites omit the lifecycle: `buildNewLoopLifecycle` returns null for infinity (`controller:3295-3311`, called at `2714-2731`), `planRunScriptStackLifecycle` returns null for infinity (`physicsPaintRotoRunScriptStacking.ts:399-403`). The normalizer, however, synthesizes a one-cycle lifecycle for them via `resolvePhysicPaintRotoLoopClipLifecycle` (`physicalModel.ts:958-980`).

Consequence: for any publication carrying a lifecycle-less infinity clip, the left side has `syncState: 'synchronized'` (plus a phaseOrigin/end/ranges) while the right side has `undefined`, so `sameLoopClipCollections` returns false and `assertPublicationAck` throws `'Parent returned a mismatched Loop Clip acknowledgement.'` **after** `ports.commit` already resolved ok (`controller:2378-2381`). The UI reports failure although the edit landed; `recordRailKeyScripts` is skipped (`2386`) and a retry can double-paint. This is reachable on the main paths, not an edge case:

- creating any infinity rail (`controller:2714-2733`, `newLoopRepeat = 'infinity'`);
- stacking onto a track whose target rail (or any other rail) is an infinity clip (`2343-2351`; the dialog even prints `× ∞` at `2397`).

**Fix:** Compare canonical projections on both sides — the model already exposes the authority for this (`physicalModel.ts:983-999`):
```ts
import { canonicalizePhysicPaintRotoLoopClips } from './physicsPaintRotoPhysicalModel';

function sameLoopClipCollections(left, right) {
  const canonicalLeft = canonicalizePhysicPaintRotoLoopClips(left ?? []);
  const canonicalRight = canonicalizePhysicPaintRotoLoopClips(right);
  return canonicalLeft.length === canonicalRight.length
    && canonicalLeft.every((clip, index) => sameLoopClipFields(clip, canonicalRight[index]));
  // sameLoopClipFields = the existing field loop, extracted unchanged
}
```
(or normalize `publication.loopClips` before dispatch/compare). Add a regression test whose `commit` mock returns the coordinator-normalized collection for a publication containing a lifecycle-less `repeat: 'infinity'` clip, and assert `confirm()` resolves `true`. The current infinity test only asserts the published shape (`controller.test.ts:2879-2888`) against an echo mock, so it is green for the wrong reason.

### Warnings

#### WR-12: The "field-exact" comparator still omits `colorize` / `colorizeMix`

**File:** `app/src/components/physic-paint/roto/physicsPaintRotoPlayScriptController.ts:3493-3525`
**Issue:** The new contract claims field-exact acknowledgement verification, and it compares `railKind`, `overrideColor`, `photoWiggle`, `keyScriptEdits`, `paintSeedVariation`, and the lifecycle members — but not the reveal colorize pair (`physicalModel.ts:1049`). Publications do carry reveal clips: the stack path maps **all** current clips (`controller:2343-2345`) and the new-loop path spreads `currentLoopClips()` (`2733`), so a track with a reveal rail is included. An ack that drops or mutates `colorize`/`colorizeMix` passes the comparator while the child adopts `accepted.after.loopClips`, silently losing a reveal rail's colorize setting.
**Fix:** add
```ts
&& (clip.colorize ?? null) === (candidate.colorize ?? null)
&& (clip.colorizeMix ?? null) === (candidate.colorizeMix ?? null)
```
and cover the pair in the ack-mutation matrix (`controller.test.ts:3233-3299`).

#### WR-13: The availability snapshot now parses the complete physical document on every Studio render

**File:** `app/src/components/physic-paint/hooks/useRotoPlayScriptController.ts:36-45`, `179-193`; `PhysicsPaintStudio.tsx:3983-3987`; `physicPaintStore.ts:4309-4332`
**Issue:** The WR-09 fix added `documentRevision: ports.getPhysicalDocument?.()?.revision ?? ''` to `readAvailabilitySnapshot`, which the hook calls in its render body (`useRotoPlayScriptController.ts:39`). The wired port calls `physicPaintStore.getRotoPhysicalDocument`, which builds and validates a full document through `parsePhysicPaintRotoPhysicalDocument` (records, overrides, loop clips; validate + freeze) on **every Studio render**, even with no Play Script dialog open. Beyond the avoidable per-render work, `parsePhysicPaintRotoPhysicalDocument` throws on an invariant violation, so a document state that other paths surface as an error would now throw inside the Studio render body. Only the revision string is needed here.
**Fix:** add a scalar port (`getPhysicalRevision: () => physicPaintStore.getRotoPhysicalContentRevision(layerId, studioActiveTrackId()) ?? ''`) and use it in `readAvailabilitySnapshot`; or wrap the document read in a try/catch returning `''` with a memoized getter.

#### WR-14: Cancel during a stack bake unpins the session but leaves the dialog open, re-exposing the old silent no-op

**File:** `app/src/components/physic-paint/roto/physicsPaintRotoPlayScriptController.ts:2867-2874`, `613`, `830-848`, `2460`
**Issue:** `cancel()` clears `pinnedStackDestination` whenever `canCancel` is true — which includes `preparing` and `rendering` (`613`) — but does not close the confirmation (`2872-2873`). If the playhead has moved out of the rail while the floating dialog was open, `runDestination` falls back to the live destination (create surface), the dialog re-renders creation controls, and the primary Run calls `confirmGeneration`, whose create branch returns `false` silently when `startingSelection.appFrame !== start` (`2460`). That is the pre-WR-01 dead click, now reachable after a cancelled stack render.
**Fix:** when cancelling a pinned stack session, close the confirmation as well (`confirmationOpen.value = false` when the pin was set), or keep the pin until the dialog closes; and replace the silent guard at `2460` with a surfaced error.
