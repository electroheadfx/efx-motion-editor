# Quick 261104-q82: Editor paint-row rail alignment with Studio v7 — Summary

**Editor paint rows now draw the v7 rail contract: a 4px palette pill at the row top, Roto keys centred on their frame cells, and repeat/PlayScript spans painted from the locked `timelineRailDesign` palette with zero legacy rail literals left in the renderer.**

## Performance

## Accomplishments

- `getPhysicPaintRailLineGeometry` + `drawPhysicPaintRailLine`: 4px rail-line pill at `y` with roundRect radii `[railLineRadiusTop, railLineRadiusTop, railLineRadiusBottom, railLineRadiusBottom]` (the 4x top / 1x bottom nose), spanning `inFrame` to `outFrame` via `projectTimelineRailLineWidth(frameCount, frameWidth, endVisible, 0)`.
- Paint-row bar fill (`'40'`/`'26'`), border (`'80'`/`'40'`), edge handles and `drawCoverageGapTail` now read `resolveTimelineRailPalette('standard', tier).line`; the header eye, selection trait and non-paint branches keep `resolvedColor` byte-for-byte.
- `getPhysicPaintRotoKeyMarkerGeometry` returns the frame-cell centre (`+ frameWidth / 2`); `getPhysicPaintRotoKeyMarkerHalfSize` clamps the diamond to 2..5px; fill/stroke moved from the legacy `#F5A623` to `palette.keyFill` / `palette.keyRim`, and the clip is the full row so the last frame's key is not shaved.
- Repeat spans paint `resolveTimelineRailPalette(resolveTimelineRailType('playscript', marker.mode), tier).line`; PlayScript active stroke / range fill / endpoint fill / label read `palette.line`. `#06B6D4`, the cyan/violet ternary and the `getThemeColors()` read are gone from those paths.
- Full suite green: 368 files / 7209 tests passed; `tsc --noEmit` clean (strict, `noUnusedLocals`, `noUnusedParameters`).

- `endVisible` cannot change the rail-line width when the gap argument is 0 (both branches produce `frameCount × pitch`); it is still computed and returned so the helper mirrors the Studio contract and stays testable.
- PlayScript's active label text now uses `palette.line` per the plan ("the active label decision"); inactive labels stay white-translucent.

## UAT revision (2026-11-04, user feedback)

The first live look rejected two of the three changes and asked for a dedupe:

1. **Removed the rail-line pill entirely.** With many rails/tracks the extra line above every row is noise; the Editor shows the row bar + keys only. `drawPhysicPaintRailLine`, `getPhysicPaintRailLineGeometry` and the `TIMELINE_GEOMETRY` / `projectTimelineRailLineWidth` imports are gone; the bar recolour, repeat/PlayScript palettes and key palette stay.
2. **Key marker back on the frame's left edge.** The Studio centres keys on 16x22 cells, but the Editor ruler anchors frame N on the cell's left edge (tick and playhead share that x), so centring put every key half a frame late — the reported "key between frame 1 and 2". `getPhysicPaintRotoKeyMarkerGeometry` no longer adds `frameWidth / 2`.
3. **Stacked keys draw once.** `drawRotoKeyMarkers` tracks drawn x values (`Set` keyed on `Math.round(x)`) and skips repeats, so coincident keys across rails/tracks — and sub-pixel neighbours at low zoom — paint one diamond.

Tests updated: key-geometry pins assert the left-edge x; the rail-line describe became a "no pill" guard plus the surviving palette-bar pin; a new pin covers the dedupe.

### Second UAT round (same day)

The user still saw a line above the bar and keys missing from the Editor row:

4. **The remaining line was the repeat/loop strip, not the pill.** `drawPhysicPaintRepeatDurationMarkers` drew a 3px strip at `barY + 1`; it was purple before this quick and turned Motion orange via the palette, so it read as a newly added "rail line". The method, its geometry helper and its call are removed from the Editor renderer — the row is bar + keys only. The `repeatDurationMarkers` DATA stays on `FxTrackLayout` (frameMap/Studio contract tests still pin it).
5. **Keys were read from the active track only.** `frameMap` built `rotoKeyFrames` from `getRotoRealKeyRecords(layerId, activeTrackId)`, so keys added on another Roto track never reached the Editor row. New `physicPaintStore.getRotoRealKeyRecordsAcrossTracks(layerId)` unions every track, and `frameMap` dedupes `appFrame` with a `Set` — one diamond per frame across all rails/tracks, as requested.

Tests: the repeat-strip describe is now a "no strip" guard; a new store/layout pin seeds two tracks and asserts `[1, 3, 3, 5]` collapses to `[1, 3, 5]` on the Editor row.

### Third UAT round (same day)

6. **Layer bar reverted to its own accent.** The green bar was rejected: the v7 palette now applies to the KEYS (and their connectors) only. `barColor` is back to `resolvedColor` (`fxColorForLayerType` → `var(--color-accent)` for physic-paint), so the row keeps its pre-quick identity colour.
7. **Key-to-key connectors.** `drawRotoKeyMarkers` now joins consecutive keys with a 1px palette-line connector at the diamond centre line: a straight line across interpolated frames, and a 2px-amplitude / 10px-period sine across a repeat/cycle range (the range is classified by the segment midpoint against `repeatDurationMarkers`). Connectors draw before the diamonds so the glyphs sit on top.

Tests: the palette guard now pins `const barColor = resolvedColor` and the palette-for-keys split; a new source pin covers both connector styles and their draw order.

### Fourth UAT round (same day)

The mapping was right (straight = interpolated, sine = cycle) but the cycle RANGE was wrong: `repeatDurationMarkers` spans the whole loop placement, so every interp segment inside a loop painted as a sine — the user saw the inverse of what they asked.

8. **Cycle spans start after one source cycle.** New derived `rotoCycleRanges` on `FxTrackLayout` (`getTimelineRepeatProjection`): for each loop range, `cycleStart = max(placementStart, phaseOrigin + cycleLength)` — exactly the frames the Studio paints as cycle cells (`repeatInstance > 0`), clamped to the visible fragment. `repeatDurationMarkers` keeps its locked shape (the Studio parity pin still checks `startFrame/frameCount/mode`).
9. **Connectors split per frame.** The key-to-key span is walked pixel by pixel and split at every cycle boundary, so a mixed span renders `-~--~--`: straight over interpolated frames, sine over cycle frames. Keys remain flattened across every Roto track (round 2), so all rails land on the single Editor row.

Tests: the connector pin now covers the per-frame split (`isCycleX`, `strokeRun`) and a new frameMap pin covers the `phaseOrigin + cycleLength` derivation.

### Fifth UAT round (same day)

The Editor row still followed the active Studio track: keys changed with the selected track, and selecting the no-loop track turned every connector straight ("all line, no cycle").

10. **Active-track dependence removed end to end.** Two sources were still track-scoped:
    - loop/cycle ranges were derived from the ACTIVE track's loop clips only (so the wave disappeared when another track was selected);
    - the key list read the live runtime union, but a realm's runtime only holds the tracks mounted in it, so a track carried only by the document was invisible.
    New `getTrackPhysicalStates(layerId)` resolves each document track's physical state as *runtime when mounted, else the document carrier*. Keys union every track from both sources; `getTimelineRepeatProjection` now derives the loop ranges per track and unions them (deduped by span), so the row is identical for every `activeTrackId`.
11. **Regression pins:** two new tests — the key list is unchanged after `setActiveTrackId`, and a document-only track's keys appear even though the runtime never mounted it.

### Sixth UAT round (same day)

12. **Cycle tails beyond the keys.** The connector only ran between keys, so a Studio dots run that outlives the last key (e.g. frames 14–18 after a key at 13) had no line — the reported "nothing between 14 and 18". `drawRotoKeyMarkers` now also strokes each cycle span from the last key to the cycle end, and the symmetric prefix when a cycle precedes the first key. A straight tail is never drawn: only cycle frames extend the line.
13. **The tail splits, so no hole at the key→cycle boundary.** Round 12's tail started at the cycle start, leaving the single frame between the last key and cycle 2 empty. The tail now runs from the last key through the cycle end through the same per-frame splitter: straight to the cycle boundary, sine across it. Same for the prefix.

### Seventh UAT round (same day)

14. **The segment into the first cycle frame is a wave.** The per-frame splitter classified every pixel by the cell it sits in, so the span from the last key (13) to the first cycle frame (14) took frame 13's non-cycle style and painted straight — the reported "a line up to 14". The cycle span now extends one frame left, because the repeat run includes the transition into its first cell: the wave starts on the key at 13 and runs through the cycle end (`•~~~~~`), with no straight sliver. Test: the connector pin now asserts the one-frame extension.

### Eighth UAT round (same day)

15. **Combined interpolated + cycle line.** Two Studio tracks — one interpolated (key / interp / key / interp / key) and one cycling (key / cycle / cycle / cycle / cycle) — flatten onto the same Editor frames, but the row painted only the wave between the keys: the interp track's straight rail vanished. Key-to-key spans now draw the straight interpolation baseline first and the cycle wave on top, so the flattened row shows both rails at once (the wave rides the line).
16. **Brighter connectors.** The connectors (baseline, wave and cycle tails) stroke with the palette's highlight tint (`keyRim`) instead of the dark unselected rail line (`line`), so the green reads against the blue layer bar.

Tests: the connector pin asserts `palette.keyRim` and the `strokeRun(fromX, toX, false)` baseline call.

### Ninth UAT round (same day)

17. **Taller, longer wave.** The 2px / 10px sine read as a dense wiggle beside the straight baseline. Amplitude 2 → 5 (peaks at the diamond tips, still inside the 20px bar) and period 10 → 30 (about four cycles per frame at working zoom), so the combined line + sine is legible.

### Tenth UAT round (same day)

18. **Rail-boundary flags.** Flattening hides which track a line belongs to, so the row now shows where each rail begins and stops. `getTimelineRepeatProjection` derives every track's rail spans — key-rail segments via `deriveKeyRailSegments` (interpolation-break and group aware) plus each loop clip's placement — and exposes the deduped frames as `rotoRailStarts` / `rotoRailEnds`. The Editor draws `[` hugging the start key, `]` hugging the end key (a loop rail ends at its line's right edge), and the blended double sign (feet both ways) when one frame both ends a rail and starts another.

Tests: a frameMap pin seeds an interp track (rail 1..9) and a loop track (rail 1..5) and asserts `rotoRailStarts` `[1]` / `rotoRailEnds` `[5, 9]`; renderer source pins cover the flag drawing and its position before the diamonds.
