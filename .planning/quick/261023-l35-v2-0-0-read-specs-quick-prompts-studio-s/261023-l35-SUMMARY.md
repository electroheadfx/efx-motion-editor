# Quick 261023-l35: Studio script snapshot persistence Summary

The Studio's watercolor timeline and per-frame brush ledger are snapshotted to an app-managed Rust disk cache under a durable project/layer/track key, restored before the launch context is published, coalesced into one debounced write, isolated across tracks, and refused fail-closed on corrupt or foreign files.

## Storage path and format (required record)

- **Storage path convention:** `<app_data_dir>/studio-script-snapshots/<projectId>/<layerId>/<trackId>-v1.snap`
- **Format version:** 1 — SNAP v1 container (`SNP1` magic, u16 version 1, u16 flags 0). The brush block has its own u16 version 1 inside the container. The file name's `-v1` and the Rust `STUDIO_SCRIPT_SNAPSHOT_FORMAT_VERSION = 1` name the same version; a newer container version is refused by the decoder before any allocation.
- **Key law (T-261023-l35-01):** each component is 1..=128 bytes of `[A-Za-z0-9._-]` with no leading dot — this rejects `.`, `..`, separators and absolute paths before any syscall. The root is resolved in Rust from `app.path().app_data_dir()`; the renderer never supplies a path.
- **Size cap (T-261023-l35-04):** 64 MiB, checked from metadata BEFORE the read and before the write.
- This is a machine-local app cache. It is never written into the `.mce` package and never affects the document schema.

## Measured heavy-fixture file size — FIXTURE-DERIVED

**631,790 bytes (≈ 0.60 MiB / 617 KiB)** for a heavy fixture of **3 frames × 40 primary strokes × 180 pixel points, each primary plus one diffusion continuation** (empty watercolor body; the brush section is the dominant cost). The exact byte length is pinned as a literal in `studioScriptSnapshotController.test.ts` (`HEAVY_SNAPSHOT_BYTE_LENGTH = 631_790`), so any format change fails loudly.

**This number is FIXTURE-DERIVED. A live heavy-project measurement was NOT possible in this environment** — the executor may not run the app or the dev server, so no real project could be opened, painted and measured. The fixture mirrors the scale the 261023-f9c live measurement established (40 strokes × 180 points per heavy frame); it is a codec-size measurement, not an in-app cache observation.

## What was built

1. **Task 1 — Rediscoverable watercolor script.** SNAP v1 container + codec with typed refusal codes; Rust snapshot service and two Tauri commands (write raw body, read base64, atomic rename, digest, 64 MiB cap, missing→silent); renderer IPC ports; controller with bind/restore/saveNow/isDirty/reset; launch restore dispatched BEFORE `applyPhysicsPaintLaunchContext`; engine mutation clock reserved past restored ids at restore and at the engine-ready seam; close-path save bounded by 2000 ms.
2. **Task 2 — Brush frames in the same snapshot.** Versioned brush section (frames, groups, primary + continuations, sticky paint settings, presence-tagged optional fields, pixel f32 points); brush store gains `getBrushScriptFrameEntries`, `restoreBrushScriptFrames` and `pruneBrushScriptFramesTo` (one revision bump each); controller restores/prunes the brush ledger to the same live real-key set; Studio close chain captures the current brush frame before the write; signature includes `brushScriptRevision`.
3. **Task 3 — Save discipline.** 800 ms coalescing timer, one in-flight write, at most one queued follow-up, FIFO prepared-payload commits; written termination laws (cleared by reset/dispose/bind; a failed write never re-arms; only a new revision bump re-arms); one Preact `effect` subscription over the two store revisions with a first-run skip; cross-track save/reset/bind/restore law at the existing `lastEditStateTrackIdRef` seam with the bind generation guard; close path uses `flushNow`; heavy-fixture measurement.

The only subscription inputs are `aquarelleStrokesRevision` and `brushScriptRevision`. `recordAquarelleStroke` and every brush capture/clear/prune bump them, so a stroke that completes without a revision bump is the one silent-loss case this design rules out.

**1. [Rule 3 - Blocking] Exposed the durable `projectId` signal on `projectStore`**
- **Found during:** Task 1
- **Issue:** the plan's launch wire reads `projectStore.projectId.peek()`, but the signal was module-private.

**2. [Rule 2 - Missing critical functionality] Added `getLiveFrames` to the controller contract**
- **Found during:** Task 1
- **Issue:** the plan's controller deps did not include the live real-key frame set, yet restore/save pruning needs it; pruning on an empty set would wipe a script restored before key records load.
- **Fix:** added the dependency plus the fail-safe law (null/empty disables pruning), pinned by controller tests.
- **Files:** `studioScriptSnapshotController.ts` + test.

**3. [Rule 2 - Missing critical functionality] Added `aquarelleRecordState.restore.test.ts`**
- **Found during:** Task 1
- **Issue:** restore/reset/clock/frame-replay behavior had no regression suite; the plan listed the source file but not this test file.
- **Fix:** 5 focused tests.

**4. [Rule 1 - Bug] Rust atomic write uses a Uuid temp sibling, not the `tempfile` crate**
- **Found during:** Task 1
- **Issue:** `tempfile` is not a project dependency and the plan forbids new dependencies.
- **Fix:** Uuid-suffixed sibling temp + `sync_all` + rename, temp removed on failure — the same atomic pattern the repo already uses in `script_library.rs` / `efx_paint_media.rs`.

**5. [Rule 2 - Missing critical functionality] FIFO prepared-payload write queue**
- **Found during:** Task 3
- **Issue:** a debounced write already in flight could land after the track-switch outgoing save and un-write newer content (a stale snapshot would win).
- **Fix:** every enqueue site prepares its bytes synchronously (so the outgoing key is captured before any reset) and commits strictly in FIFO order; one commit in flight at any time.

**6. [Rule 2 - Missing critical functionality] Close path flushes the debounce**
- **Found during:** Task 3
- **Issue:** a bare `saveNow()` would ignore an armed debounce timer and could write while a queued follow-up was pending.
- **Fix:** the close step now calls `flushNow()` (clear timer → drain in-flight → write once if dirty), still inside the 2000 ms race. The Task 1/Task 2 pin was updated accordingly.

**7. [Rule 2 - Correctness of an existing guard] Scoped the 261023-g4p revision pin**
- **Found during:** Task 3
- **Issue:** the g4p pin forbid ANY `brushScriptRevision.value` occurrence in the Studio, but Task 3 mandates exactly one subscription.
- **Fix:** the pin now asserts exactly one occurrence, located inside the Task 3 coalescing `useEffect` after its marker — the render body still never subscribes.
