<objective>
Make a Studio painting session's script survive the window: snapshot both Studio script stores (watercolor timeline + per-frame brush groups) to an app-managed disk cache, and restore them at launch before the user can interact.

Purpose: the Studio's script stores are session-scoped module state. Closing the Studio destroys the webview realm, so every watercolor stroke and every brush frame's ledger is lost; the pixels remain but are no longer editable or replayable. The brief (SPECS/quick-prompts/studio-script-snapshot-persistence.md) asks for a machine cache keyed by project + layer + track + format version, written through Rust, restored before first interaction, pruned to live frames, and failing closed on anything unexpected.
Output: a SNAP v1 container codec (watercolor section reuses the proven AQTL v1 codec), a Rust snapshot store with atomic writes and strict key validation, a never-rejecting save/restore controller, launch-restore and close-save wiring, and a track-scope law that makes cross-track mixing impossible.
</objective>

**Scope laws (from the brief — non-negotiable):**
- The snapshot is an app-managed DISK CACHE. It is never part of the `.mce` package; the document schema and the package format are untouched.
- All IO goes through Rust. Atomic write (temp + fsync + rename). The renderer never touches the filesystem for cache paths.
- Persist watercolor ids/order/playFrame/params/toolOverrides/cuisson/Dry events, and every captured brush frame's groups from the per-frame store.
- Restore at Studio launch BEFORE the first user interaction. Prune entries whose frames/keys no longer exist. Fail closed on unknown version/corruption: keep pixels, never crash, report on the existing status capsule.
- Never mix layers or tracks.
- Out of scope: package/schema changes, project-reopen durability beyond the cache, brush navigation-reload / backward-editability changes, gauge/purge UI, new dependencies.
- The SUMMARY must record: the storage path convention, the format version, a heavy-project file size (fixture-derived is acceptable if live measurement is impossible — say so explicitly), and the UAT rows.

**Preconditions verified while planning:**
- AQTL v1 is measured viable (3,737 B binary vs 18,068 B JSON on a 185-point fixture, 4.83x) and lives in `app/src/components/physic-paint/performance/scriptTimelineCodec.ts` with 19 passing tests. Reuse it; do not write a JSON fallback.
- The per-frame brush store (`brushScriptRecordState.ts`) retains immutable `RecordedStrokeGroup[]` per frame with sticky `complete` and sticky `paintSettings`; it is reset on launch replacement and on Studio unmount.
- The Studio is a separate Tauri window: closing it destroys module state, so module-level stores are naturally empty on every launch.
- The Studio has no durable project id today. `project.contextId` rotates on every project open (`rotateProjectContext`) and cannot key a cache. `projectStore.projectId` (adopted from the package manifest, rotated on project close) is the durable package identity and already keys `<app_data_dir>/frame-cache/<projectId>`. It must be added to the launch project context (TS type + the closed validator whitelist + both publishers + the Rust struct, which drops undeclared members).
- The active track id is NOT on the launch context; it is `document.activeTrackId` and can change in-session (`setActiveTrackId`). The Studio already resets the brush store on a cross-track switch at the `lastEditStateTrackIdRef` seam in `PhysicsPaintStudio.tsx`.
- The existing close hook uses `hasPending = () => workflowMode === 'roto'`; a non-roto close destroys the window with no flush at all. The snapshot save must therefore be part of the pending decision or it is lost.
- Brush points are PIXEL coordinates (`PenPoint.x/y`), unlike the watercolor UV clamp in AQTL. The brush section must never reuse the [0,1] quantization.
