**Scope-ownership finding (Open Question 2, resolved from code, not assumed).** A layer switch cannot be an in-place launch replacement in the running child: `open_physics_paint_window` navigates a reused window (`lib.rs:186`), the main window is hidden while the Studio owns the session (`lib.rs:260-265`), and closing the Studio destroys its window (`physicPaintBridge.ts:3003-3017`). The child webview therefore re-boots on every layer switch, so NO in-child state can satisfy the locked decision "the scope holds while the Studio session lives (including layer switches)". The only realm that survives a Studio session inside one open project is the main realm, and it is also the realm that owns the live layer list. TS-only, no Rust, no IPC command, no format change. The reset rule is exact and testable: `rotateProjectContext()` (`projectStore.ts:82-84`) returns the scope to All; a layer identity change does not.
