- **Primary noun:** the project-scoped Action (one store per project, applicable to any layer).
- **Decision: promote.** The origin layer is demoted from an authority to display metadata. There is no origin gate to remove (the research refuted recon claim 3); the work is to make the *destination* explicit and the *origin* cosmetic.

<objective>
Deliver the project-scoped Action library with a layer-scope filter: every Action is visible and applicable from every physic-paint layer, applied to the CURRENT layer at apply time, with a Scripts-panel selector (All, plus one entry per layer that owns Actions) that narrows the list by origin layer without ever changing what an apply touches.

**The research refuted a load-bearing premise of the brief — read this before touching code.** At HEAD there is NO origin-layer gate anywhere on the read path or the apply path: `scan_root` reads every `*.efx-roto-script.json` in `<project>/scripts` with no layer predicate, the panel renders `library.rows` unfiltered, and `source.layerId !== launch.layerId` inside `prepareRotoScriptTargetRef` compares the live source snapshot against its own launch context — a tautology. Provenance already exists in schema v1 (`source.layerId` / `source.layerName`, required, validated, already rendered). Test 5 as literally written ("a pre-provenance script still loads") is VACUOUS: a file without `layerId` cannot be a valid row — it scans as `invalid-managed-script`. The reachable scope-unknown case is an ORPHAN layer id.

What the codebase genuinely lacks, and what this plan therefore builds:
1. a scope filter with live layer names (the child has no layer list at all);
2. live provenance resolution with an orphan fallback (the row prints the snapshotted name today);
3. an explicit, user-visible refusal when target resolution returns null (the clipboard already sets `apply-empty-target-failed`, but the Studio drops it into a write-only `setLastError` and only the terse `Failed` reaches the capsule).

**Task 1 opens with an evidence step, not with code.** Write the reachable behavioural legs, RUN them at HEAD, and record which are already GREEN. The researcher expects the cross-layer legs to pass. Do NOT manufacture a failing gate to satisfy the brief's "RED first" wording: a green-at-HEAD leg becomes a regression guard, and the verdict is recorded in `260922-al1-RED-EVIDENCE.json`. Only the genuinely-red items drive implementation.

**Scope-ownership finding (Open Question 2, resolved from code, not assumed).** A layer switch cannot be an in-place launch replacement in the running child: `open_physics_paint_window` navigates a reused window (`lib.rs:186`), the main window is hidden while the Studio owns the session (`lib.rs:260-265`), and closing the Studio destroys its window (`physicPaintBridge.ts:3003-3017`). The child webview therefore re-boots on every layer switch, so NO in-child state can satisfy the locked decision "the scope holds while the Studio session lives (including layer switches)". The only realm that survives a Studio session inside one open project is the main realm, and it is also the realm that owns the live layer list. So: the scope is main-realm-owned session state, published with the layer list on the EXISTING `physic-paint:project-context` channel, pulled by the child at mount (the publisher only fires at project bind, before the Studio exists), and written back over one new child→main request event. TS-only, no Rust, no IPC command, no format change. The reset rule is exact and testable: `rotateProjectContext()` (`projectStore.ts:82-84`) returns the scope to All; a layer identity change does not.

Purpose: make the origin layer cosmetic and the destination current, so an artist who saves an Action on one layer can reuse it on any other, and can still find it again.

Output: the scope round trip (main realm ↔ child), the pure scope model and the panel control, the explicit refusal surface, the five brief-mandated behavioural legs with their HEAD verdicts, and the pending native UAT rows.
</objective>
