# Quick 261028-k03c: Lift eraser UAT blockers — Code Review

**Depth:** quick (advisory) · **Files:** 30 · **Status:** issues_found

## Summary

The engine half and the punch are sound. The tip-space projection (`uAspect` squeeze, `q.y /= uTipAspect`, uAxis rotation with y up), the sticky tilt azimuth ordering, the dwell/moving amount law, the punch-versus-shader parity, the preview-versus-punch shape resolution, the engine cursor's rotation sign, the single-punch law, the eager sheet snapshot, the per-(track, frame) capture fence, the one-retry commit and the set-before-await merge-base pin all check out. The `bakeAquarelleEventsToFrame` refactor preserves the recipe (encode, flush, dispose-before-publish) and the restored Brush tab is a single-state second view. No injection, secret, or path issue exists in the changed surface.

The two blockers are both in the new **orchestration** layer, not in the math: the lift transaction has no navigation/track identity guard across its multi-second awaits (CR-01), and the recovery's ≤3/255 gate is mathematically incapable of detecting that P and S came from different scripts or paper, which is the exact risk RESEARCH A1/A2 and threat T-k03c-02 rely on it to catch (CR-02). Two warnings: the new D6 cursor does not re-render on stationary pen tilt/pressure (WR-01), and the non-recover scripted arm writes its durable base without the revision bump that the plan's own done criterion requires (WR-02). The targeted suites pass, but they cannot catch CR-02 (IN-09) and the new acceptance tests pin a numeric threshold against an injected buffer unrelated to the recovered base.

## Narrative Findings (AI reviewer)

### Critical Issues

#### CR-01: The lift transaction has no navigation/track guard across its awaits

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/PhysicsPaintStudio.tsx:6016-6398`
**Issue:** The transaction captures `plan` once and then re-checks the session identity nowhere. Its awaits (6071 `flushLivePixels`, 6149 the script bake, 6158 the recovery decode/recombine, 6184/6204 the punch, 6230 the rebake, 6330/6333 the commit) are long enough for the user to switch tracks from the Studio rail (7759-7760) or move the playhead. A track switch resets the module-global `payloadTimeline` (`view/aquarelleRecordState.ts:1522`) and re-binds the per-track display cache, so reads taken after the await can pair the OLD `plan.keyId` with the NEW track's display bytes (6134) and events (6142) and then persist a wrong recovered base under the old key (6179, 6193). The shared scripted tail then resets the current live sheet (6220) and calls `aquarelleRebakeRef` with `getAquarelleEventsForFrame(plan.frame)` (6229-6230) — `applyAquarelleTimeline` applies that event list to the now-current session, so one frame's events can be baked onto another frame/track. The queued re-entry in `finish()` (6037-6040) replays a stale plan against the new session too. Only the raster arm's two publishes (6338, 6363) check `launchContextRef.current?.startFrame`; the scripted arms check nothing.
**Fix:** capture the session identity and a navigation epoch at entry and bump the epoch in the rail `onSelectTrack` and on every start-frame change:
```ts
const trackAtEntry = plan.trackId;
const frameAtEntry = plan.frame;
const epoch = aquarelleNavigationEpochRef.current; // new ref, bumped on track/frame change
const drifted = () =>
  aquarelleNavigationEpochRef.current !== epoch ||
  launchContextRef.current?.startFrame !== frameAtEntry ||
  (aquarelleSessionTrackIdRef.current ?? studioActiveTrackId()) !== trackAtEntry;
```
Re-check `drifted()` after every await and before 6134, 6142, 6179-6195, 6204-6214, 6220 and 6229-6230; on drift, revert the preview, record a `lift-erase` diagnostic and return without touching the map, sheet or timeline. Drop queued plans whose identity drifted in `finish()`.

#### CR-02: The ≤3/255 recovery gate cannot detect provenance drift, so a wrong base is adopted silently

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/roto/aquarelleBaseRecovery.ts:18-21,181-184` and `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/PhysicsPaintStudio.tsx:5915-5923,6131-6153`
**Issue:** The gate is tautological. B is constructed from (P, S) using the current S, and the production `pigment-alpha` recombine (`roto/physicsPaintRotoAlphaMerge.ts:54-75`; `app/src/lib/rasterAlpha.ts:95-125`) is exactly `S − min(S) + (1−a)·B`. Substituting the inversion returns P for ANY S; the mean error is zero unless a channel clamps. So the gate verifies only clamping, never that P was baked from the same script and paper as S. RESEARCH A1 ("recovery would invert against the wrong P and fail validation — a fail-closed refusal, not corruption") and A2 ("a paper mismatch ... the 3/255 gate may reject") are therefore false, and threat T-k03c-02's mitigation does not hold. Reachable paths: (i) paper id/strength/scale changed since the display bake — `aquarelleLiftPaperRef` mirrors the CURRENT settings (5915-5923) while P is the old bake; (ii) brush strokes recorded (in `getAquarelleEventsForFrame`) but not yet settle-captured when the lift starts, so the flush at 6071 has nothing to drain and P lacks paint that S contains; (iii) the CR-01 race. For dark pigment the error is amplified by `1/(1−a)` before clamping, so the adopted base can be visibly wrong and is then persisted and used by every later Apply — the opposite of the "never silently adopt a bad base" contract.
**Fix:** make provenance explicit. Store alongside each cached display frame the bake fingerprint that produced it (paper id/strength/scale plus the events content signature), and in the recover arm require an exact match with the current (paper, events-minus-lift) before calling `recoverAquarelleDurableBase`; refuse with the existing unknown-base refusal on mismatch. Additionally refuse recovery while the frame has a live sheet with un-captured paint or any recorded event newer than the display bake (require an Apply first). Keep the ≤3/255 check as a clamp sanity check, not as the provenance gate.

### Warnings

#### WR-01: The D6 cursor ignores stationary pen tilt and pressure changes

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/engine/AquarelleCanvasLayer.tsx:81-90,117-126,891-898`
**Issue:** The footprint inputs (tilt, pressure, buttons, pointer type) and the layer height are module variables; only `cursorX`, `cursorY` and `cursorVisible` are signals (78-79). A stationary pen whose pressure or tilt changes delivers the same x/y, whose signal writes are equal and therefore do not notify, so `AquarelleBrushCursor` does not re-render and the ring keeps the previous size/rotation until the pointer moves. This contradicts the "live pen-tilt azimuth" behavior promised in `engine/aquarelleFootprint.ts:99-104`; pressure/buttons also stay stale from the previous hover until the first move.
**Fix:** add a `cursorStateVersion` signal bumped compare-then-write whenever a tracked input changes (tilt, pressure, buttons, type, and the pointerenter/move height updates), and read it in `AquarelleBrushCursor`; or promote those fields to signals.

#### WR-02: The non-recover scripted arm writes the punched durable base without a revision bump or markDirty

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/PhysicsPaintStudio.tsx:6196-6215` (write at 6213)
**Issue:** The other three durable writes bump and mark dirty (6180-6181, 6193-6195, 6353-6359), but this arm sets the punched base with neither. The snapshot content signature is the aquarelle revision alone (`:1151`), and `markDirty` no-ops when that signature equals the last saved one (`snapshot/studioScriptSnapshotController.ts:761-762,873-877`), with an 800 ms coalesced save. If the punch (which runs after `await flushLivePixels` plus a WebP decode/encode) outlives the debounce armed by the recorded lift, the pre-punch base is saved, the later map write schedules no save, and a leave/return or reopen restores the unpunched base — the erased pixels return on the next Apply. This violates the plan's own done criterion ("every durable write is followed by a revision bump and markDirty").
**Fix:** mirror 6194-6195 immediately after the set:
```ts
aquarelleDurableBaseByKeyRef.current.set(plan.keyId, punchedDurable.bytes);
bumpAquarelleStrokesRevision();
studioScriptSnapshot.markDirty();
```
and after any other map mutation in this arm.

### Info

#### IN-01: Every failure is reported as a decode failure

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/roto/aquarelleBaseRecovery.ts:188-190`
**Issue:** The blanket `catch` maps encode/recombine exceptions to `reason: 'decode'`, so a codec or encode fault is diagnosed as a missing decode capability.
**Fix:** wrap each leg in its own try/catch, or add an `'exception'` reason carrying the message.

#### IN-02: `meanAbsoluteChannelError` can pass the gate vacuously

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/roto/aquarelleBaseRecovery.ts:118-132,181-184`
**Issue:** It compares only the common prefix (`Math.min(a.length, b.length)`) and returns 0 when either buffer has no full pixel, so an empty or truncated recomposition passes the `<= 3` gate. Length mismatches between the decoded display and script (read defensively with `?? 255` in the inversion) are also silent.
**Fix:** return `Infinity` when `count === 0`, require `a.length === b.length`, and validate that display/script/recombined share one size in `recoverAquarelleDurableBase`.

#### IN-03: The cursor re-derives the rounded threshold and omits the engine floors

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/engine/AquarelleCanvasLayer.tsx:164-168`
**Issue:** Line 168 re-computes `footprint.aspect < 0.6` instead of using `footprint.rounded` (the law already carries it), duplicating `ROUNDED_ASPECT`; `footprintCssSize` (`engine/aquarelleFootprint.ts:165-172`) also does not mirror `Engine.updateCursor`'s `Math.max(4, …)` / `Math.max(3, …)` floors (`Engine.ts:1514-1515`), so a very flat tip can render below the engine's minimum height.
**Fix:** use `footprint.rounded` and clamp the CSS size to the same floors.

#### IN-04: A durable punch failure publishes the unknown-base message

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/PhysicsPaintStudio.tsx:6291-6299`
**Issue:** When `punchTransmittanceBytes` fails on a KNOWN durable base (6295), the code publishes `AQUARELLE_LIFT_UNKNOWN_BASE_REFUSAL` ("The frame's painted pixels are unavailable — nothing changed"), which misdiagnoses a codec/punch failure as an unknown base and contradicts the arm above it (6208-6210), which uses the failure message.
**Fix:** publish `AQUARELLE_LIFT_FAILURE_MESSAGE` here and keep the unknown-base copy for the truly unknown case at 6287.

#### IN-05: The Lift shape select has no placeholder for a null id

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/view/LiftShapePicker.tsx:41-52`
**Issue:** `value={liftTipId ?? ''}` has no option with an empty value, so a null id renders a blank select while the thumb falls back to Filbert (line 37). The setter can normalize an unknown id to null (`view/aquarelleRecordState.ts:233-241`).
**Fix:** add a disabled placeholder option (`<option value="" disabled>—</option>`) or keep the selection non-null.

#### IN-06: A contract test's title contradicts its assertion

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/roto/aquarelleLiftEraseContract.test.ts:401-406`
**Issue:** The title says "adds the four lift durable-base set sites" while the assertion requires 7 occurrences of `aquarelleDurableBaseByKeyRef.current.set(`.
**Fix:** retitle to "seven" (and keep the enumeration in the comment aligned).

#### IN-07: The liftFS comment promises a fallback that does not exist

**File:** `/Users/lmarques/Dev/efx-motion-editor/packages/efx-watercolor/src/playground/shaders.ts:266-285` (comment 268-269, discard 280, mix 282)
**Issue:** The comment says `uRound = 1` "restores the radial-only erase", but the discard at 280 is unconditional and the engine always binds `uRound = 0` (`Engine.ts:1910`). With `uRound = 1` the result would still be clipped to the tip square, so the claimed fallback is dead code with a false description.
**Fix:** either gate the discard on `uRound` (`if (uRound < 0.5 && (abs(q.x) > 1.0 || abs(q.y) > 1.0)) discard;`) or remove the uniform/mix and correct the comment.

#### IN-08: The lift shader ignores the dry-media roughness and jitter the stamp applies

**File:** `/Users/lmarques/Dev/efx-motion-editor/packages/efx-watercolor/src/playground/shaders.ts:48-58` versus `:270-285`
**Issue:** `stampFS` re-thresholds the tip with `uRough` and offsets each dab's tip slice with `uJitter`, but `liftFS` samples the raw tip. A Chalk lift (`brushes.ts:187`: `roughness: 0.7`, `stampJitter: 0.1`) therefore erases with the smooth tip rather than the crumbly net the same brush paints, so the "shaves the silhouette to its contour" claim is only true for tips with a clean alpha edge. The punch and preview share the raw-tip law, so the mismatch is with the painted stroke, not between the three erase paths.
**Fix:** port `uRough`/`uJitter` to `liftFS` (using the same `uPoint`-seeded slice offset), or declare the dry-media approximation explicitly in the comment and the plan's limitations.

#### IN-09: The recovery tests cannot catch CR-02

**File:** `/Users/lmarques/Dev/efx-motion-editor/app/src/components/physic-paint/roto/aquarelleBaseRecovery.test.ts:206-252`
**Issue:** Both gate tests inject a `recombined` buffer that is independent of the recovered base (`filled(103)` / `filled(104)`), so they pin the numeric threshold only. No test asserts that a display which disagrees with the script bake is refused, and the production recombine is never exercised against the inversion — precisely the combination that makes the tautology invisible.
**Fix:** add a test with a deliberately mismatched P/S pair (e.g. invert with S, validate against P baked from a different S) asserting the result is rejected once the provenance check from CR-02 exists; at minimum, derive the `recombined` fixture from the adopted base using the same analytic law as the production merge.
