# Quick Task 261124-0l5: Make Living Script Apply a Paste — Summary

**Clipboard Apply now RECORDS the copied Living Script onto the destination key (fresh mutation ids, destination keyId anchor, soft-delete replacement, one `aquarelle-script` undo) and bakes THAT recorded timeline — the key owns a script, so Shift+R, re-edits and Alt+click all work on a pasted key.**

## Accomplishments

- `beginAquarelleScriptPasteEdit` / `rollbackAquarelleScriptPasteEdit` in the selection module: the caller's replace + record runs inside ONE before/after snapshot pair (one undoable `aquarelle-script` edit); a throw or a zero recorded count restores only what moved (revision compare), and a failed bake installs the before snapshot unconditionally.
- The clipboard controller gained an opt-in paste seam: `applyScript('wet', { paste: true })` calls `pasteAquarelleScript` once with the clipboard's non-Dry events and the resolved target; the bake is fed `session.events` mapped through the SAME projection as `applyAquarelleTimeline` (`isAquarelleDryEvent ? {...event} : withAquarelleReplayGrid(event)`); the session settles exactly once — commit after a successful bake, rollback on `false` and on throw — before the UI-staleness guards. Without a port the opt-in is refused (`Failed`, one `apply-partial-failure` message), so a raster-only Apply is impossible; every other apply entry point (plain applyScript, applyAquarelleTimeline, applyCurrentScript, prepared load + apply) stays non-pasting.
- The hook forwards `pasteAquarelleScript` through the live `portsRef`, so the once-created controller reaches the Studio's implementation (the port the earlier bug left unreachable).
- Studio wiring: ONE record seam `recordAquarelleEventsOnFrame(events, destinationFrame, destinationKeyId?)` holds the only `copyAquarelleScriptToFrame(` allocation; `recordAquarelleScriptCopyForFrames` (Duplicate/+Key) is now a delegating wrapper with unchanged behavior. The late-bound `recordAquarelleScriptPasteRef` collects the destination frame's live non-Dry ids, soft-deletes them, records the clipboard under fresh ids anchored to `input.target.keyId`, and returns `{ events: getAquarelleEventsForFrame(destinationFrame), commit, rollback }`; commit mints the one ledger edit via `aquarelleScriptEditRecorderRef` and republishes the owner via `applyFrameModuleState(destinationFrame)`.
- `handleApplyScript` now calls `rotoScript.applyScript('wet', { paste: true })` — HOLD-WET still rides Apply, and the file keeps exactly two `'wet'` literals.
- Source pins: the apply literal updated, the 61-24 seams re-anchored to the new record seam plus a delegation assertion, and a new `261124-0l5 Apply pastes the copied script` describe pinning the opt-in, the single copy call, the late-bound ref, replace-before-record ordering inside the one edit, the recorded-timeline bake source, the one-entry commit and the unconditional rollback.

## Decisions Made

- Record-first, bake-second: the bake reads the RECORDED destination timeline, so first paint equals every later replay (fresh `traceSeed`s from fresh ids; same replay grid).
- The destination's live strokes are soft-deleted inside the one edit BEFORE the fresh record, so one Cmd+Z restores timeline + pixels together; Dry markers (global sheet actions) are never swept.
- A refused/empty/portless paste fails the Apply through the existing `apply-partial-failure` surface rather than degrading to a raster-only render.
- The paste stays opt-in per call site: no other `applyScript` / timeline / prepared-load path can paste, and the `'wet'` literal count stays 2.
- The paste port is late-bound in a ref (prepareRotoScriptTargetRef precedent) because the ports object is built before the record seam; the controller reaches it through the hook's live ref — no signal writes in the render body.
