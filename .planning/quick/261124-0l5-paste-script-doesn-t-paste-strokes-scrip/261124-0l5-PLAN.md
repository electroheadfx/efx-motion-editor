<objective>
Make Living Script Apply a PASTE. Today `handleApplyScript` → `rotoScript.applyScript('wet')` → the aquarelle branch of `dispatchApply` replays the clipboard's events into pixels and publishes the frame, but never records the timeline on the destination: `hasAquarelleScriptForFrame()` stays false, so the key owns a render and no script — it cannot be replayed, edited or deleted, and it is not a Living Script.

After this quick, Apply on a real key records the copied script onto the destination under fresh mutation ids bound to the destination keyId, then bakes THAT recorded timeline through the existing aquarelle pipeline. The paste is the source of truth; the render is its consequence. An existing destination script is replaced. The step is one `aquarelle-script` undo.

Purpose: the clipboard Apply path silently broke the Living Script contract (Copy works, Apply produced a raster-only result). Every other script-copy path (Duplicate, +Key) already records through one seam; Apply must reuse it rather than fork a second one.

Output: a paste-as-one-edit primitive in `aquarelleStrokeSelection.ts`, an opt-in paste port in the clipboard controller, and the Studio wiring that keeps ONE record seam (`recordAquarelleEventsOnFrame`), ONE bake path (`ports.applyAquarelleEvents`) and ONE undo entry per Apply.
</objective>

|----------|-------------|
| clipboard script -> destination timeline | Artist-authored stroke data crosses from the clipboard into a key's recorded script; ids, key anchors and Dry markers must stay coherent. |
| destination timeline -> bake | The bake is fed the just-recorded timeline; a wrong source here makes the first paint differ from every later replay. |
| script mutation -> undo ledger | A paste changes the script AND the pixels; it must be exactly one ledger step and must roll back to the pre-paste script on failure. |
