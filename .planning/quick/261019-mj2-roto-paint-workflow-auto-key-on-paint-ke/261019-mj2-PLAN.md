<objective>
Implement the approved Roto paint workflow law for the Physic Paint Studio timeline:

1. **Auto-key on paint** — painting an empty or interpolated/generated frame creates a real key at pointer-down (blank in both cases, stroke is its only content), buffers the first gesture, and replays it only after the key's physical ack and settled surfaces. Painting an existing real key is unchanged. Undo groups the created key and the first stroke as one action. Both engine-1 and Water color use the same promotion seam.
2. **+ Key** — on a non-real cell, clone the NEAREST PREVIOUS REAL KEY's paint to the destination (blank only when no previous key exists); never shift later keys; keep the existing Key Rail/segment derivation.
3. **Insert = pure gap / ripple right** — shift every real key at/after the cursor by +1, create NO key, keep the cursor on the inserted position. Occupied-real, empty, generated, and tail cells are insertable. Tail inserts extend document capacity AND the parent sequence span; keys are never clamped or dropped. `insert-empty-segment` is retired from the Insert button.
4. **Delete/Backspace** — keep D-06 left ripple and its pin test untouched.

Purpose: remove the "create a key first" tax from the paint loop without reintroducing the 52.1 WKWebView stall family, and make Insert/Delete exact inverses (Insert opens a gap, Delete closes one) with physical span/cache integrity on both sides of the bridge.

Output: one cohesive change set across the pure resolver/timeline actions, the Studio orchestration, the store/bridge authority chain, and both paint engines; tests for every pure/harnessable seam; a live UAT report covering the five required rows.

**Locked decisions (do not revisit):** auto-created keys start BLANK in both empty and generated cases; + Key uses the nearest previous REAL key, never the displayed interpolated frame.

**52.1 stall rollback/safety (named, do not regress):** the 52.1 regression happened because auto-promotion ran INSIDE the first stroke's completion path, so the fast-chained second stroke hit cold fresh surfaces and stalled. This plan never promotes inside a stroke path. Promotion starts at pointer-down; the first gesture is captured at the stack (capture phase, pointer capture, propagation stopped) into a bounded sample buffer; replay happens only after (a) the physical `paste-key` ack, (b) `warmCanvasSurfaces()` plus `lockInputForWarm(FRESH_FRAME_WARM_MS)` for engine-1, or the sheet reset plus two rAFs for aquarelle, and (c) the gesture has ended. Rollback: if promotion or replay fails, no pixels are committed, the buffer is discarded, the key remains (a declared, visible outcome), and the error surfaces; the previous "painting disabled" behavior is NOT restored.

**Scope fences:** no new dependencies; no dev-server runs; no pushes; atomic local commits; Preact + @preact/signals only (no useState); tests are `.test.ts` and run via `pnpm vitest run` only (never watch); `physicPaintStore.ts` must keep zero `getImageData`/`putImageData`; do not tick `SPECS/v1.1.0-water-color/phase-55-issues/index.md`; do not alter the approved watercolor look.
