<objective>
Implement the approved Roto paint workflow law for the Physic Paint Studio timeline:

1. **Auto-key on paint (direct paint, no buffering)** — painting an empty or interpolated/generated frame starts the stroke immediately on the already-warm canvas while a blank real key is promoted in parallel at pointer-down. The generated display is cleared synchronously so the stroke lands on the blank key. Capture (engine-1 and Water color) awaits the promotion and attaches to the created key. One undo removes the stroke and the key. A centered "Create key" button is the explicit fallback on non-real cells: it creates a BLANK key at the current frame with the existing preparation/warm progress and moves no later keys.
2. **+ Key** — on a non-real cell, clone the NEAREST PREVIOUS REAL KEY's paint to the destination (blank only when no previous key exists); never shift later keys; keep the existing Key Rail/segment derivation.
3. **Insert = pure gap / ripple right** — shift every real key at/after the cursor by +1, create NO key, keep the cursor on the inserted position. Occupied-real, empty, generated, and tail cells are insertable. Tail inserts extend document capacity AND the parent sequence span; keys are never clamped or dropped. `insert-empty-segment` is retired from the Insert button.
4. **Delete/Backspace** — keep D-06 left ripple and its pin test untouched.

Purpose: remove the "create a key first" tax from the paint loop without reintroducing the 52.1 WKWebView stall family. The feasibility audit pinned the ~1s preparation to `restoreFrame`'s `FRESH_FRAME_WARM_MS` gate (PhysicsPaintStudio.tsx ~2912-2936) and to the physical +Key acceptance reload decoding the blank WebP (`loadCachedRotoReferenceFrame` -> `useRotoReferenceController`); it is NOT key creation. The self-promotion therefore skips the accepted-key reload and the warm lock entirely and paints on the already-warm surface, with the explicit Create key button retained as the fallback if direct-paint latency fails live UAT. Insert/Delete remain exact inverses (Insert opens a gap, Delete closes one) with physical span/cache integrity on both sides of the bridge.

Output: one cohesive change set across the pure resolver/timeline actions, the Studio orchestration (direct paint + fallback button), the store/bridge authority chain, and both paint engines; tests for every pure/harnessable seam; a live UAT report covering the seven required rows.

**Locked decisions (do not revisit):** auto-created keys start BLANK in both empty and generated cases; + Key uses the nearest previous REAL key, never the displayed interpolated frame; the Create key button is the distinct init affordance and must ship in this quick.

**52.1 stall rollback/safety (named, do not regress):** the 52.1 regression came from running promotion inside the first stroke's completion path, which forced a reload/cold-surface settle. This plan never reloads and never locks input for the self-promotion: promotion starts at pointer-down, the engine starts the stroke immediately, and the generated display is cleared synchronously. Rollback: if promotion fails, the stroke is discarded (engine undo/clear; aquarelle sheet reset), a key accepted but not validated is removed by replaying its `before` snapshot, and the error surfaces. No silent blank key, no orphan paint. The previous "painting disabled" behavior is NOT restored.

**Scope fences:** no new dependencies; no dev-server runs; no pushes; atomic local commits; Preact + @preact/signals only (no useState); tests are `.test.ts` and run via `pnpm vitest run` only (never watch); `physicPaintStore.ts` must keep zero `getImageData`/`putImageData`; do not tick `SPECS/v1.1.0-water-color/phase-55-issues/index.md`; do not alter the approved watercolor look.
</objective>
