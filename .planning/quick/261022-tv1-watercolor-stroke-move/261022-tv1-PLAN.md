<objective>
Add Cmd+drag stroke move to the Water color sheet in the Physic Paint Studio, reusing the select/delete machinery shipped by quick 261022-pim.

1. **Drag** a recorded stroke while the select surface is active (rail Select toggle or held Cmd): a ghost outline follows the pointer and nothing else happens — the sheet is untouched and no replay runs during the gesture.
2. **Release** translates every point of that stroke and its payload-timeline entry, resets the sheet, and re-applies the frame script through the shared Apply pipeline (bake + 0/N -> N/N pill + publish + display reconcile).
3. **One undo step** covers move + re-bake, through the existing `aquarelle-script` ledger entry and its revision-authoritative snapshot replay.

Purpose: the user can reposition a finished watercolor stroke without repainting the sheet, with the same settled wash Apply Script produces.
Output: a draggable ghost, a script-level translation, and a single ledger command for move + replay.

The live UAT gate (ghost moves / progress then new spot / Undo back to origin) is the acceptance. The executor finishes at "automated-ready" and hands the three rows to the user.

Tracer note: Task 1 is the tracer and intentionally touches one file per layer (bridge, record state, select/edit ledger, overlay, layer, canvas mount, Studio) plus its tests — the path cannot be sliced into runnable halves without leaving a layer unwired.

Design decisions (locked by this plan):
- **A move replaces objects, never mutates them in place.** Snapshots keep the timeline's event references (that is what lets a measured cuisson patch survive a swap). Translating in place would therefore also translate the `before` side and undo could never restore the origin. Build new point arrays + a new stroke + a new timeline entry, and splice the new entry at the SAME index.
- **The snapshot must cover the stroke registry.** `applySnapshotContent` currently restores the timeline only; after a move the registry (`recordedStrokes` / `recordedStrokeEntries`) would still point at the moved objects, so the select outline, the hit-test, `buildAquarelleEventsFromCapture`, and a later delete's `indexOf` splice would disagree with the restored timeline. Capture and restore the registry in the SAME snapshot, before membership and timeline.
- **One ledger family, no new command kind.** `beginAquarelleMoveEdit` mirrors `beginAquarelleDeleteEdit` and reuses the 10-entry ledger + `recordAquarelleScriptEdit`; the existing undo/redo branch and replay port then work unchanged. Nothing new enters the coordinator.
- **One in-flight guard.** Move and delete share the script-edit in-flight flag (delete-named exports stay as aliases) so a drag release and an Alt+click can never interleave.
- **No new async machine.** The move re-bake rides the delete path's gates and the clipboard controller's own busy/launch invalidation; per `efx-async-orchestration` §1 there is no named architectural problem that would justify XState/Effect here.
- **Ghost is a narrow leaf.** The drag signal is written in the overlay's pointer handlers and read only by that overlay; no Studio or layer body reads it.
