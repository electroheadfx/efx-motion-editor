## Decision: release, do not transfer, on a drifted publication (no CONTEXT.md exists)

The drift branch runs AFTER `publishCompleteDocument` succeeded: the child holds a complete, canonically parsed document for the track, and the parent has already accepted and committed the edit. A transfer exists for AMBIGUOUS child state; a completed publication has none. Holding a recovery lease after a completed publication is exactly what disabled every Studio mutation surface (the availability gate reads the store lease, and the coordinator's own release path is unreachable behind that gate). Releasing reproduces, automatically, the only recovery the user has today — closing and reopening the Studio — and the next edit re-stages from the published document, so nothing stale can be re-applied. The failure surface (error status, diagnostic, failure output) is unchanged.
