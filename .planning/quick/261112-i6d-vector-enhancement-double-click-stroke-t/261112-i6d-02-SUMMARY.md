## Accomplishments

- `ANCHOR_WIDTH_MAX` raised from `2` to `20` in `packages/efx-watercolor/src/vector/spine.ts`. Its docblock now states this is the ONE storage/evaluation ceiling every consumer reads (clamp, per-anchor factor, sampling, engine scripted width channel, payload reopen guard) and that the UI's x10 slider track is an app constant layered on top, not a second ceiling. No consumer code changed: `clampAnchorWidth`, `anchorWidthFactor`, `sampleVectorWidths`, `Engine.scriptWidthFactor` and the payload guard all inherit the constant.
- Both remaining prose sites that named the old band were corrected: the spine header comment (`0.2..2.0` -> `0.2..20`) and the `clampAnchorWidth` docblock; `Engine.ts`'s `scriptBegin` docblock was likewise reworded (comment only, no statement change).
- The spine clamp suite pins the new boundary: `clampAnchorWidth(ANCHOR_WIDTH_MAX + 1)` lands on `ANCHOR_WIDTH_MAX`, and the inside-the-range loop gained `10` (the app track maximum) and `20` (the new ceiling) while keeping every existing value.
- The scripted-width channel (`engineScriptWidth.test.ts`) — the pin the first checker pass missed — now proves `ANCHOR_WIDTH_MAX + 1 -> ANCHOR_WIDTH_MAX`, `ANCHOR_WIDTH_MAX -> ANCHOR_WIDTH_MAX`, `10 -> 10`, and keeps `0.05 -> 0.2`, `NaN -> 1`, `Infinity -> 1`. The `ENGINE_SOURCE` character pins are untouched.
- The reopen data-loss path kept its shape: the payload guard still refuses the WHOLE anchor list out of band; `vectorPath.test.ts` and both `codec.test.ts` probes now read `width: ANCHOR_WIDTH_MAX + 1` (was the bare literal `3`, which is now inside the band). The adapter fixture moved from `maxAuthored = 9` to `ANCHOR_WIDTH_MAX + 7`, keeping the "clamped from above" assertion meaningful.
