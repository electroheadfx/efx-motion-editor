<objective>
Make texture a setting of the brush response instead of a competing brush.

Today `buildBrushForStroke` lets any registered mask win the whole brush: a textured
tip builds from `CUSTOM_BASE` and silently discards the response the user picked, so
every textured tip paints as generic watercolor with a texture. This plan enforces the
law "the response owns the physics; the texture only replaces the footprint", threads
an optional `textureId` through the engine, the payload, the record/replay chain and
the Roto script carriers, and rebuilds the two UI surfaces around the two axes.

Accepted loss (state it in the SUMMARY): a phase-63 project stroke whose `brushId` is a
texture id replays through `presetFor` → `round`. No migration, no recovery, no legacy
mapping entries.

Hard exclusions (verbatim from the source spec — an executor must not widen scope into
any of these): no new brush responses and no Medium Engine work (phase 64); no texture
blending or modulation modes (a texture replaces the footprint, nothing else); no
`wc/texture-*` id prefix (textures stay `wc/builtin-*` / `wc/custom-*`); no migration for
existing projects or strokes; no texture on the eraser; no rename of existing `brushId`
readers (the change is additive).

Purpose: the user's reported behaviour is unfixable without this split, and phase 64
(Medium Engine) adds brush responses — it must not inherit a layout where a texture
displaces a response.

Output: one law in `brushBridge.ts`, one `textureId` carrier inside the opaque `engine`
slot, a texture row in the library and a texture strip in the top-bar popover.

Note: this quick has no ROADMAP requirement ids (`requirements: []`); acceptance is the
nine items of `SPECS/v2.2.0-brush-tips/GSD-QUICK-PROMPT-03-texture-axis.md`.

Why Task 1 is one large task: the signature change makes every call site a compile
error, so the sweep must land as one pass — splitting it would leave the tree
uncompilable between tasks. The resulting estimate overage is accepted and recorded
in `<budget_note>`, together with the slicing recommendation for a non-quick re-plan.
</objective>
