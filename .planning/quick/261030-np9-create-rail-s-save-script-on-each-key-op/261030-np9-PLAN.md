<objective>
Make Create Rail's "Save script on each key" preserve the script ON EACH DRAWN KEY, so every rail key is editable exactly like a normal painted key.

Today the option (shipped by quick 261030-ig0) stores per-key SETTINGS overrides on the rail while the keys own no script at all: the memory panel says "No watercolor script on this key" and Move/Select stay grey. This plan replaces that wrong model with the correct one — each key owns its slice of the source script — and retires every part of ig0's override model (types, propagation, comparators, the key-edit dialog mode, the single-key re-bake, the Regenerate discard plumbing) with no shims and no dead code.

Purpose: on a 5-stroke script over 5 frames, F0 owns the top line, F1 the first bar, F2 the "0", F3 the second bar, F4 the bottom line — selecting F1 edits only its bar. Static rails give every key the complete drawing; Reveal rails get the same slicing applied to the wash script. Option OFF stays byte-identical to today.

Output: one new pure slicing module (plus tests), one additive bake option, one Studio recording port wired into every rail commit point, and the moved Key Script Editing card.
</objective>

<decisions>
D-01 — The bake is the ONE slicing authority. The slice module never calls `buildProgressiveStrokeSchedule` and never re-derives `recordedOrder`/`ticks` timing. The bake exposes its own `startFrameOf` map through a new optional `onStrokeFrameAnchors` callback fired once, after both anchor branches have populated the map, so the recorded slices can never disagree with the pixels (spec BUILD 1).

D-02 — Static = the complete drawing on EVERY key. Progressive = each stroke lands on the key whose slot equals the bake's start-frame index for that stroke; a slot with no starting stroke inherits the last stroke that started at or before it (and, when no stroke has started yet, the first stroke of the slot that follows). Every key therefore owns at least one stroke, which is what makes Move/Select available on every key while keeping the 5-strokes/5-frames case at exactly one stroke per key.

D-03 — Per-key scripts live in the EXISTING aquarelle record timeline: `recordAquarelleStroke(mutationId, stroke, keyId)` with `stroke.playFrame` = that key's app frame. No document schema change, no new payload field, no per-key copy inside the rail record (the 16 MB envelope cap stands).

D-04 — Mutation ids come from the Studio's ONE `paintMutationLedger`, reached through a new `recordRailKeyScripts` port. No second clock, no negative or deterministic ids (the snapshot codec encodes u32).

D-05 — Re-bake replaces the cycle's scripts. Every path that re-bakes an opted-in rail's cycle (new Apply over the same cycle, Source Edit, Regenerate, Repair) purges each cycle frame with `purgeAquarelleFrameScript(frame)` and records the fresh slices, gated on the rail's PERSISTED flag — never on the dialog signal, which resets on open and is not rendered in source-edit mode.

D-06 — OFF is byte-identical. The port is not called, nothing is purged, nothing is recorded, and the document write stays exactly `...(keyScriptEdits.peek() ? { keyScriptEdits: true as const } : {})` at the two existing sites.

D-07 — Persistence needs no new serializer. The Studio Script Snapshot already carries the event timeline plus `watercolorKeyAnchors` (mutationId→keyId), its prune law seeds a stroke only when its anchor equals the live key at its playFrame, and `bumpAquarelleStrokesRevision` already drives `markDirty()`.

D-08 — The Key Script Editing card moves AFTER the tab conditional (immediately before the summary bar) on BOTH tabs and drops `physics-paint-play-script-card-wide`, so grid auto-placement puts it in column 1 of the next row, directly under Timing. Its ids, its `dialogMode === 'apply'` gating, and the no-scroll CSS pin stay.

D-09 — `replayRevealRail` has no live caller (the D-24 Replay control ships with a disabled-reason and no handler), so the recorder is deliberately NOT threaded there. When Replay is wired it must record slices exactly like creation; leaving dead recording code in place now would be untestable code.

D-10 — The ig0 symbols are deleted outright: no deprecated aliases, no `still supported` shims, no "keep just in case". Tests that pinned the retired behaviour are deleted or rewritten; the list is enumerated in Task 1.

D-11 (assumption delta, primary noun = the rail key) — The key's identity model does NOT change: `sourceKeyIds[slot]` / keyId remains the identity, and the override-style "settings-only key" is simply deleted. What changes is that the key now OWNS a script slice. Decision: `no-change` to the key identity model; the ownership is additive and addressable through the existing frame-script seam.

Residual, accepted: undoing a rail creation restores the physical document but not the frame-script timeline (scripts are not part of the document projection). This cannot strand an editable dead script — `watercolorMoveAvailable` requires a real key at the frame, and the snapshot prune law drops anchors whose key is gone.
</decisions>
