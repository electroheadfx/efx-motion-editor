<objective>
Make typing apply immediately in the rail-creation Frames and Cycle fields. Today the blended value box commits only on blur or Enter, so a typed frame count leaves the slider and the controller signal stale and Create can use the old value. Add a default-off `commitOnInput` opt-in to the shared SliderStepper and NumericStepper that emits the parsed/clamped value on every input event while keeping the raw text in the box, and enable it on exactly the four rail-creation fields.

Purpose: quick 261105-sk3. The report calls the TAB requirement anti-UX: the user types a value, the knob does not move, and Create sometimes uses the previous count. The commit law already lives in `commitStepperInput`; the fix is a second, live entry point into that same law plus draft preservation so the controlled `value` prop never rewrites a half-typed number.

Output: `commitOnInput` on SliderStepper and NumericStepper (default false, opt-in only), the four opt-ins in `PhysicsPaintPlayScriptCards.tsx`, and a pin matrix covering the live emit, the raw draft, empty/unparseable input, the clamp/grid/comma law, the end-to-end controller write, and the untouched surfaces.
