<objective>
Align the hide/solo semantics so that hide is a hard off-switch on both authorities, per the v1.0.0 milestone audit's hide/solo truth-table divergence warning (TML-04, CMP-02; `.planning/v1.0.0-MILESTONE-AUDIT.md` lines 49-52, 154, 186).

The law (locked, from the quick task description):
1. A hidden track NEVER renders, even when soloed — Studio, canvas composite, export.
2. Solo arms only when at least one VISIBLE track is soloed; a solo flag on a hidden track does not arm solo filtering.
3. Both authorities implement the identical truth table.

Verified at planning time (2026-09-11) — two corrections to the audit/task text, confirmed against current code:

- The task's PROBLEM section swaps the two authorities' labels relative to the code and relative to the audit file. The audit has it right: `previewRenderer.ts:97`'s `resolvePhysicPaintTrackVisibility` is the predicate consumed by the Studio live surface (`PhysicsPaintStudio.tsx:2373`, `:3546`), and it arms solo over ALL tracks (`previewRenderer.ts:100`). `efxPaintHideSolo.ts`'s `participatingPaintTracks` is the flattened-composite/export authority and it already arms solo only over VISIBLE tracks (line 37).
- Rule 1 already holds on both paths: no current code path renders a hidden+soloed track (`previewRenderer.ts:99` and `efxPaintHideSolo.ts:39` both return not-visible for `visible === false` before any solo check). The observable defect is rule 2: a hidden-only solo arms solo filtering, so the Studio live surface blanks visible tracks (PhysicsPaintStudio.tsx:2373 display state flips to `hidden`, :3546 hides the engine surface) while the flattened composite still renders them — Studio is not WYSIWYG.

Net: ONE production change — the arming predicate at `previewRenderer.ts:100` — plus contract tests on both paths. `participatingPaintTracks` needs no production change (the audit's own recommendation: "cheap fix: reuse `participatingPaintTracks` semantics in `resolvePhysicPaintTrackVisibility`"). This satisfies the guardrail "Align the compositor to the law; touch Studio only if its arming diverges from rule 2" — only the diverging authority is touched.

Out of scope, do not touch: the fond paper preload-gate warning (a separate audit item — `collectRotoPaperTextures` / paper textures / fond logic), reveal, track transforms, any other compositor logic, REQUIREMENTS.md, and the audit/verification records.

Purpose: restore Studio/composite WYSIWYG on the hide/solo truth table and pin it with tests so the two authorities cannot drift again.
