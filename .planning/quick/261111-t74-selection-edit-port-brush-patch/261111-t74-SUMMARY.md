**A brush id and a complete eight-multiplier bag now ride the existing appearance patch, and a peek-only selection edit port forwards the selected strokes to the Studio's shipped one-undo appearance handler — automated-ready data plumbing, no UI consumer yet.**

## Accomplishments

- `ScriptStrokeAppearancePatch` and `AquarelleStrokeAppearancePatch` both carry `brushId?: string` and `toolOverrides?: Partial<AquarelleToolOverrides>`.
- `updateAquarelleStrokesInScript` validates the whole patch first: a brush id must resolve through `findTip` OR a `BRUSH_PRESETS` id (a preset is not a tip), and every multiplier entry must be one of the eight known fields with a finite value. Any failure refuses the batch with zero and no write.
- The multiplier merge always materialises the complete eight-field bag from `NEUTRAL_TOOL_OVERRIDES` plus the stroke's stored bag; a neutral patch stays a no-op and never creates a bag on a stroke that had none.
- `brushId` is written onto the replacement stroke record, so `toStudioStroke` re-projects it into both the entry's top-level and `engine` slots — points, params, colour, cuisson, ticks and stack position untouched, one revision bump, one same-index replacement.
- `aquarelleStrokeSelection.ts` exposes `setAquarelleSelectionEditPort`, `aquarelleSelectionEditActive` (peek-only: Select mode on AND a non-empty selection) and `commitAquarelleSelectionAppearance` (no-attempt `null`, otherwise a snapshotted id array to the registered port).
- The Studio registers exactly one port, immediately after the appearance ref write, forwarding to `handleAquarelleAppearanceStrokes` — so a brush change inherits ONE undo entry, the shared re-bake and the shipped paint-seed re-roll with no second edit path.

## Decisions Made

- The merged bag is built on a complete base (`stroke.toolOverrides ?? NEUTRAL_TOOL_OVERRIDES` via spreads), not a bare partial spread: the engine needs all eight multipliers and a bare spread would infer `Partial<AquarelleToolOverrides>` and fail typecheck.
- The port's `null` means NO ATTEMPT (caller keeps its own path); a resolved `false` means the Studio refused. This keeps the future brush-pick surface from mistaking a refusal for an inactive surface.
- No UI consumer is in scope: the visible brush-pick surface is a follow-up task. This quick is automated-ready, not a shipped user-facing feature.
