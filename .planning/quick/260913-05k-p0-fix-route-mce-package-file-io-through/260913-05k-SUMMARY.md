## Provenance

The live P0: package saves died silently. The renderer drove `@tauri-apps/plugin-fs` at the package staging root — `forbidden path: …/.efx-paint-package-staging-<uuid>` — because the capability grants only `fs:scope-appdata-recursive`. The only feedback was a `console.error`. App-defined Tauri commands carry no capability scope, so the package IO legs (layer sub-file write/read, staging discard) now run as Rust commands; the machine-local frame-cache legs genuinely live under appdata and were left alone.

Second half of the P0: even after the reroute, *any* future save/open failure must be impossible to miss. All 13 failure sites (3 in `shortcuts.ts`, 3 in `Toolbar.tsx`, 2 in `WelcomeScreen.tsx`, 3 in `main.tsx`, 2 in `autoSave.ts`) now end in a blocking native modal carrying the underlying error text.

### What changed (round 2)

- **Four cache staging commands** (`services/physic_paint_cache.rs` +
  `commands/physic_paint_cache.rs` + `lib.rs` + `ipc.ts`):
  `prepare_physic_paint_cache_generation` (root + staging generation via
  `create_dir_all`), `stage_physic_paint_cache_frame` (raw-byte body +
  request headers, mirroring `efx_paint_write_frame_media`),
  `discard_physic_paint_cache_staging` (symlink-refusing, idempotent
  cleanup) and `remove_physic_paint_cache_entry` (commit-arm track
  deletions + the empty-documents canonical removal; the first segment must
  be `efx-paint/`, symlinks are refused). Prepare/stage answer the typed
  soft failure (`accepted: false` + diagnostic); discard/remove are
  best-effort.
- **`efxPaintPersistence.ts` drives NO plugin-fs call at all**: `ensureDir`,
  `removeStagingGeneration`, `stageFrame`'s mkdir+writeFile and the settle
  arm's exists/remove are gone. The cache leg's whole body (fingerprint to
  publish) sits behind the restored never-throw boundary: any cache-side
  failure is recorded (`console.warn` — "cache leg degraded" / "cache
  settlement degraded" / publication refused / cleanup skipped) and the
  authoritative save commits; a cache rollback failure can no longer mask
  the save's own failure. A degraded prepare records no fingerprint/token,
  so the next save retries the leg.
- **The boundary scan grew to the cache class**
  (`efxPaintPackageIoBoundary.test.ts`): the module scan is allowlist-free
  (any plugin-fs call in the persistence module fails) and a second scan
  fails any module that references the fs plugin specifier AND a
  machine-cache token. Static scope reading has missed twice; the class is
  pinned in the suite now.
- Seven suites retargeted to the command surface (persistence, round-trip,
  cutover, multi-track, track-delete laws, scratch sync, ipc media); the
  deletion laws now witness the removal command's arguments.
