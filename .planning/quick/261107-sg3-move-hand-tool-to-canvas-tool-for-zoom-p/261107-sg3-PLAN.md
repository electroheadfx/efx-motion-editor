<objective>
Move the Hand out of the Studio tool rail and into the floating canvas zoom pill as a LATCHED canvas pan mode.

Purpose: the Hand is no longer a momentary hold-to-pan rail button. It is an internal canvas tool: one click on the Hand icon in the zoom pill arms pan mode, a primary-button drag anywhere on the canvas pans through the same store path as middle-drag, and a second click on the same icon disarms. The rail keeps its paint tools and host tools; it must no longer render a Hand.

Output: a latched `aquarelle-hand-toggle` in `PhysicsPaintCanvasZoomBar.tsx`, primary-button routing plus a grab/grabbing cursor in `PhysicsPaintCanvasZoomViewport.tsx`, a Hand-free `PhysicsPaintToolRail.tsx`, an updated contract comment in `physicsPaintHandTool.ts`, and rewritten source pins that describe the latched design.

Locked decisions (do not revisit):
- D-01: LATCHED. One click arms; a primary-button drag on the canvas pans; a second click disarms. Not momentary.
- D-02: An internal CANVAS tool, independent of the paint tool. Only the Hand icon toggles it. No coupling to `aquarelleActiveTool`, Select mode, picker state, motion mode, keys, or Escape.
- D-03: The Hand is never disabled at Fit or when `hasOverflow` is false. At Fit the pan clamps to zero.
- D-04: The Hand button and its hold-to-pan session code leave `PhysicsPaintToolRail.tsx` entirely.

Scope notes: no CSS rule is added — the pill already styles `.physics-paint-canvas-zoom-button[aria-pressed="true"]` (physicsPaintStudio.css:1075). The pill keeps its existing `!pickerOpen` step-aside in `PhysicsPaintStudioView.tsx:549`, so while the picker overlay is open the Hand control is hidden while the armed flag is untouched; that is the locked behavior (only the Hand icon toggles), not a defect to patch with coupling. `workflow.tdd_mode` is on: each task writes its pins first.
</objective>
