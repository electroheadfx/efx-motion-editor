<objective>
Fix the watercolor instance of key-spacing-script-loss and remove the duplicated key-identity frame mapping.

d47be996 remapped the brush script ledger by key identity when force-spacing rewrites key appFrames. Watercolor has the same defect: the recorded strokes, payload-timeline entries and their playFrame anchors stay on the old frames, so respaced keys can no longer find their scripts. At the same time the mapping logic now exists twice (rotoPhysicalOwnership.ts builds two identity maps; brushScriptRecordState.ts builds its own frame remap).

This plan extracts ONE shared pure helper, adopts it in both existing consumers without changing pixel ownership, adds the watercolor identity remap, and wires both remaps into the accepted-replace paths.

Purpose: one mapping law, two session stores, no duplicated identity logic and no session script loss when keys move.
Output: shared helper + test, refactored roto/brush consumers, aquarelle remap + tests, Studio accepted-replace wiring + source pins. No resolver/UI/key-delete-UX change, no snapshot retained-union change, no schema/package change.

Quick-mode note: ONE plan, three sequential tasks. Task 1 is the tracer for the shared data path (helper extracted and proven end-to-end through the already-wired brush path). Task 2 extends the vertical slice to watercolor. Task 3 wires both remaps into every accepted-replace path.
</objective>
