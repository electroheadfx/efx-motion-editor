# Quick Task 260731-9l0: Add a Cut tool to the Efx Paint bottom timeline toolbar - Context

**Gathered:** 2026-07-31
**Status:** Ready for planning

<domain>
## Task Boundary

Add a Cut tool to the Efx Paint (Physics Paint Studio) bottom timeline toolbar (`PhysicsPaintWorkflowStrip.tsx`) using the Lucide `Scissors` icon. Cut must copy the selected Roto key frame or selected key group to the existing reusable clipboard (`session.copiedKey` via `useRotoKeyUtilities.copyKey`), then delete the same frames (`rotoPhysicalActions.deleteRotoFrame` in `useRotoTimelineActions.ts`, which already routes single selections to `delete-key` and groups of 2+ to the atomic `delete-key-group` transaction). Support single and grouped selections, expose Cmd+X, preserve existing Copy/Delete ordering and selection semantics, and make the deletion one atomic Undo/Redo operation. Add focused regression coverage.

</domain>

<decisions>
## Implementation Decisions

### Cut failure semantics
- **Fail-closed atomic Cut.** Cut is all-or-nothing: if copy or delete is unavailable/fails, nothing happens and a status message explains why. The clipboard stays untouched when the delete half fails. Cut's enabled state requires BOTH copy availability AND delete availability for the current selection.

### Toolbar placement
- **Between Copy and Paste.** Final ordering: Copy → Cut → Paste → Delete. Cut sits with the clipboard actions it feeds; Delete keeps its trailing destructive position.

### Cmd+X shortcut scope
- **Studio keyboard route.** Handle Cmd+X in `physicsPaintStudioKeyboard.ts` only — active while the Studio has focus, consistent with existing Roto keyboard routes. Do NOT register in global `app/src/lib/shortcuts.ts`.

### Claude's Discretion
- Exact status-message wording for Cut failure/success.
- Test file placement and naming (follow existing roto test conventions).
- How Cut composes copyKey + deleteRotoFrame internally (single handler in Studio wiring vs. dedicated hook), as long as fail-closed semantics and atomic group delete are preserved.

</decisions>

<specifics>
## Specific Ideas

- Reuse `useRotoKeyUtilities.copyKey` (handles both single `session.copyKey()` and grouped `session.copyKeyGroup(entries)` paths) — clipboard must remain reusable for repeated Paste after Cut.
- Reuse `rotoPhysicalActions.deleteRotoFrame` unchanged — it already implements atomic `delete-key-group` for 2+ selected keys (D-13 shared transaction, one Undo/Redo step).
- Icon: `Scissors` from `lucide-preact`, matching the existing icon import pattern in `PhysicsPaintWorkflowStrip.tsx` line 1.
- Guarded tooltip pattern: use `buildGuardedActionTooltipCopy` with a disabled reason, matching Copy/Paste/Delete buttons.

</specifics>
