# Quick 260827-s52: NLE Ruler Seek + Playhead Bar (Physics Paint) Summary

**One-liner:** Selection-free NLE ruler seek/scrub (seek-on-press, 4px threshold, rAF-coalesced) plus a full-height accent playhead bar overlaying ruler, all track rows, and the Bg row — both driven by the existing cursorAppFrame single position source.

## What Was Built

### Task 1: Ruler seek end-to-end (tracer, TDD)

- `usePhysicsPaintRulerScrub` hook (`app/src/components/physic-paint/hooks/usePhysicsPaintRulerScrub.ts`): pointer-down seeks synchronously with the floored, clamped frame derived from the ruler element's own bounding rect; horizontal travel past `RULER_SCRUB_THRESHOLD_PX = 4` arms scrub mode where moves store the latest frame and schedule ONE rAF — the seek fires at most once per animation frame and only when the frame changed. Pointer capture on the ruler element; pointerup/cancel/unmount cleanup is idempotent (capture released, pending rAF cancelled, window listeners removed).
- 9 unit tests (`usePhysicsPaintRulerScrub.test.ts`) following the `usePhysicsPaintKeyRailDrag.test.ts` conventions (hook-runtime mocks, window/ruler doubles, stubbed rAF queue): down-seek exactness, clamping to `[0, frameCount-1]`, own-rect derivation, rAF coalescing with latest-frame-wins, same-frame dedupe, sub-threshold wiggle emitting nothing beyond the down-seek, idempotent cleanup, and guarded pointer-down inputs.
- Strip wiring: hook instantiated next to the other drag hooks with `frameCount: () => frameCells.length` and `onSeek` routing to `props.onNavigateToSyncedFrame`; the `.physics-paint-ruler` div carries the pointerdown binding plus `title="Seek playhead"` (aria-hidden dropped, no slider role per the plan's ARIA rationale).

### Task 2: Playhead bar overlay (TDD)

- `PhysicsPaintPlayheadBar` leaf component (module scope, next to `RotoPlaybackCurrentFrameOutput`): resolves `frame = playbackActive ? (playbackTick?.value?.appFrame ?? currentFrame.value) : currentFrame.value`, clamps to the physical extent, and renders one `aria-hidden` div at `left = 4 + frame * ROTO_CELL_WIDTH_PX + 8` px (4px scroll padding + cell-center − half the 2px line). Rendered as the LAST child of `.physics-paint-timeline-scroll` so it overlays the ruler + every row + the Bg row and rides horizontal scroll.
- CSS: `.physics-paint-timeline-scroll` gains `position: relative` (padding-left 4px and column flex unchanged); `.physics-paint-ruler` gains `cursor: pointer`; new `.physics-paint-playhead-bar` block (`position: absolute; top: 0; bottom: 0; width: 2px; background: #A6D334; pointer-events: none; z-index: 30`).
- 6 source-inspection contract tests (`PhysicsPaintWorkflowStrip.rulerSeek.test.ts`): overlay placement after the rows-region, the padding-inclusive offset, the guarded tick read (idle = zero per-tick subscriptions), no new position state, CSS pointer-transparency/geometry/palette, and the scroll-container positioning context.

### Task 3: Hard-contract regression gates + full suite

- Region-scoped negative gates: the ruler div block contains the scrub binding and NONE of the strip's 12 selection/track-activation prop identifiers; the hook imports no store module and references no selection callback; the non-active row click keeps its select-then-navigate pair (positive-shape gate on `PhysicsPaintTrackRow.tsx`); the strip's ruler path uses `onNavigateToSyncedFrame` as its ONLY navigation port (no go-to quartet, no selection prop in the instantiation block).
