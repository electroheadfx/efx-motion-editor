<objective>
URGENT user-blocking regression: the app freezes ~15 s on editor open and ~15 s again on Studio open. Get procedural paper-sheet generation off the main thread and cut the pixel mass.

Diagnosis (from source — verify the call sites, do not re-derive the architecture):

The procedural paper sheet is generated ON THE MAIN THREAD at full fond size.
`app/src/lib/projectPaperRaster.ts` `buildProceduralPaperFond` (around line 50) tries `renderPaperSheetGl` (`app/src/lib/paperFieldGl.ts`), then falls back to `renderPaperSheet` (`packages/efx-watercolor/src/papers/playgroundPaperField.ts`). The CPU entry is a per-pixel loop over width*height (field / light / colour, with nested specks and fibres passes) — at 1920x1080 that is the freeze.

Three aggravating factors:
1. `app/src/lib/paperSheetWarmup.ts` / `app/src/components/physic-paint/hooks/usePaperSheetWarmup.ts` (c93077c3) run this eagerly at Studio open via setTimeout/requestIdleCallback — those only defer, they do not leave the main thread.
2. `app/src/stores/physicPaintStore.ts` `_resolveFlattenedFrame` (around line 2794) calls `getProjectPaperCanvas` in the main editor too — the other freeze.
3. The main-thread GPU host is likely returning null here (`document.createElement('canvas')` WebGL2; AquarelleCanvasLayer precedent). Confirm which path runs via the /tmp capture; the contract is worker-first regardless.

User cost insight (honour it): generate a field at capped resolution and scale it up — cut the pixel mass. The playground caps document size (`clampDocSize` in Engine.ts) and samples a precomputed paper texture; that clamp is the upper-bound law, not the target. Paper grain is stochastic — a modest upscale is acceptable, a 15 s freeze is not. Do not reintroduce visible tiling: scale ONE continuous field up, never repeat a small tile (screenshot 49 rejection).

Required outcomes, in priority order:
1. NEVER block the main thread. Generate in a Web Worker (OffscreenCanvas + WebGL2 first, CPU-in-worker fallback). Fond shows the existing flat tint until delivery. Warm-up becomes a worker prefetch. Callers take the existing resolve-subscription path when the sheet is not ready.
2. Cut the pixel mass. One named long-side cap constant, aspect preserved, uScale from the capped height so feature size is preserved on upscale.
3. Log which path ran. App writes JSON to /tmp (established convention — never console-copy): path, requested WxH vs field size, duration ms.
4. Keep the content-keyed cache. Same (paperId, seed, W, H, grainScale) is a pure hit.
5. Look must not regress. Cold Press still matches SPECS/v1.1.0-water-color/paper/cold press.png at normal zoom. Slight upscale soften is OK; tiling, seams, or wrong-scale blobs are not.

Purpose: the user cannot work while the UI is frozen. The look and the field math are already right (261017-ki6 / 261017-lny / 261017-iwm) — this quick only moves generation off the main thread and reduces its pixel mass.

Output: a worker + client + capped field module, a non-blocking fond seam with resolve-subscription delivery, a reworked warm-up, a /tmp capture writer, and pin tests.
