<objective>
**Defect.** The photo-reference surface has a transform tool (resize, move, rotate). The background image has none — it draws contain-fit + per-clip scale only, with no way to reposition, resize or rotate it on the canvas.

**Expected.** The background image is transformable (move, resize, rotate) with the SAME tool/affordance as the photo reference. The transform persists across Studio close/reopen AND save/reopen, and export/render reflects it.

**Guardrails (non-negotiable).** Reuse the photo-reference transform path — do not fork a second transform code path (one gesture component, one bounds core, one transform type, one setter idiom, one canonical encoder). Existing photo-reference behaviour unchanged. Do not touch the package format beyond what the stored transform needs (`BACKGROUND_KEYS` + parser validation for the two new members — nothing else).

**Mechanism (live observation at planning time).** `BackgroundTrack` has no transform field; the compositor ignores any; the handles component reads `document.photoReference` exclusively; sync/save/cache fingerprints have no background-display term. The fix adds `transform`/`transformLocked` to `BackgroundTrack` (mirroring `PhotoReferenceTrack`), a display-pref setter mirroring `_setPhotoReferenceDisplayProperty`, one canonical encoder feeding sync + save + cache fingerprints, compositor application after the existing contain-fit × clip-scale base rect, and a target-parameterized reuse of `PhysicsPaintReferenceTransformHandles`.

**Design decisions (Claude's discretion, executed as stated):**
- Transform is TRACK-level on `BackgroundTrack` (applies to whichever clip shows) — mirrors photoReference and "the background image" singular phrasing; the existing per-clip `scale` stays a separate concern.
- The transform is a DISPLAY PREFERENCE (D-11/D-12/D-13 class): setter bumps NO revision, records NO undo (a drag writing undo per pointermove would flood the ledger) — identity no-op guard, single `_notifyChange()`.
- Persistence rides three terms built from ONE encoder: sync fingerprint (Studio close/reopen), save fingerprint (save/reopen), flattened cache key (stale-raster prevention).
- Parser: `transform`/`transformLocked` allowed and validated with the photo-transform idiom; ABSENT members normalize to identity/locked-true (the `FrameLoopClip.scale` optional-normalize precedent — not migration code).
- Composition order: contain-fit → clip `scale` (existing) → track transform (translate/rotate/scale around the base-rect center).
- Unlock affordance: Lock/LockOpen button in `PhysicsPaintBackgroundClipSection` mirroring the photo dialog's (`aria-pressed`, lucide icons); Escape relock joins the existing chain after the reference relock. Unlocking one target LOCKS the other (mutual exclusion — only one handle set active).
- Bounds: extract ONE rotation/offset core from `getReferenceBounds`; photo keeps base = natural size, background base = contain-fit × clip-scale — shared math, only the base rect differs (that is reuse, not a fork).

**RED first.** Task 1 builds the inert surface (type fields, parser acceptance, inert no-op setter, handles prop signature) and the behavioural legs: compositor applies move+resize+rotation, sync/save fingerprints rotate on transform-only change, setter writes the field with no revision/undo.
