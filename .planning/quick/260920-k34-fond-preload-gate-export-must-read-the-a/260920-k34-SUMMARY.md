## Resolution precedence as implemented

`_resolveFondSource(layerId, efxDocument)` in `app/src/stores/physicPaintStore.ts` — total and deterministic:

1. An entry **EXISTS** for the document's **active track** in `_rotoBackgroundMetadata` → it governs. `background: 'transparent'` means the user chose no paper for that track → **no fond** (null, never a throw, never an invented texture).
2. No entry → the document fallback, exactly as it resolved before: `transparent` → none, `solid` → the color, `paper` → the paper texture with the existing `paperGrain ? texture : ''` mapping.

Visibility and solo are deliberately **not** consulted. Both `_resolveDocumentFondInstruction` (the flattened composite at :2519 — preview, export, monitor — and `getDocumentFondInstruction` for the Studio fond layer) and the new `getFondPaperTexture` accessor consume that one function, so the gate and the draw cannot disagree by construction. Instruction construction stays in `resolveMissingRotoFrameDraw` (no second switch, no format change).

**Memo-rotation guard.** `activeTrackId` is absent from the flattened key (its config term covers track id/order/visible/solo/opacity/blendMode + background id/visible/fallback). `_rotateFlattenedMemoOnFondChange` therefore runs BEFORE the memo lookup in `_resolveFlattenedFrame`: it compares a compact signature (`kind:texture:paperGrain:grainStrength:color`) per layer and clears that layer's `_flattenedMemo` + `_trackRasterMemo` only when it actually changed. An unchanged resolution never clears (no recomposite churn); `setRotoBackgroundMetadata`'s existing memo clear still covers the paper-edit case. **It is a memo CLEAR, not a key change.** Proven load-bearing: with the guard temporarily disabled, k34-C fails (the switch served the previous track's paper); restored, it passes.

## Supersession record

**`53-CONTEXT.md` D-09 supersedes the RESOLUTION half of Phase 49 D-11.** D-11 declared the document fallback the *single* fond authority; the new law is *active-track mirror first, document fallback only when the track has no paper of its own*. **D-11's STRUCTURAL half STANDS:** the paper remains ONE composite-level fond beneath the tracks — never per-track raster content — so the v1.0 rendering law is untouched (only *which* paper that single fond resolves changed).

The two superseded contract tests were **rewritten, not deleted, and not left asserting the old law**:

- `app/src/stores/physicPaintStore.test.ts` — `49-03 T1` → **"the active track's own paper governs the fond over the document fallback"** (same seeding; now expects `fill(#f4efe3,…)` instead of `fill(#ffffff,…)`).
- `app/src/stores/physicPaintStore.test.ts` — `49-03 T4` → **"deleting the track's paper metadata falls back to the document fallback"** (same seeding; now expects `fill(#f4efe3,…)` while the entry exists and `fill(#ffffff,…)` after `background: null` deletes it — the test that used to prove the deletion was *invisible* now proves it is *precisely* what re-enables the fallback).

Both carry the supersession in their comments; the module doc comment on `_resolveDocumentFondInstruction` records it too.
