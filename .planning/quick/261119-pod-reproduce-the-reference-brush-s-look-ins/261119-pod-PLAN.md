## Locked mappings (do not re-litigate)

1. **Pickup IS the smear knob — and it drives TWO laws with two ceilings (D-A).** Studio exposes no `smear`; `uSmear` = `this.params.pickup` (0..1) at a 1:1 rate, so Pickup 0 is exactly zero by construction and Pickup 100 the full rate. The SAME value feeds the carrier's §3.1 pickup (`uPickupRate`), whose fragment clamps at 0.75, while the deposit's smear weight caps at 0.8. The reference keeps these independent (pickup 0.6, smear 0.25). Visual cost, to be named in the report: at Studio's default 100 a crossing drags about four times harder at the deposit than the reference does at its defaults, and past Pickup ~75 the carrier saturates (no more paint lifted) while the smear keeps rising (more dragged). No new control is added.
2. **Coefficient space, never RGB (D-28).** The smear mixes `g.cA` (4 absorbance coefficients), `g.cB` (3) and the carried alpha toward the snapshot's. Mixing absorbance toward 0 is Studio's analogue of the reference mixing premultiplied RGB toward white over bare paper — same visual direction, different metric. The scattering S is NOT smeared: Studio's own deposit already lerps S toward `uScatter` on every dab, so S carries no canvas information, and the reference has no S at all.
3. **The pre-dab snapshot replaces the reference's compute read-modify-write.** The deposit draws into `ink.read` and `fixed`, so sampling the destination inside that pass is a WebGL2 feedback loop. `bristleInk` therefore copies `ink.read` + `fixed` into a new `smearCanvas` target — ONE `g.target(dw, dh, [HALF_FLOAT_RGBA, HALF_FLOAT_RGBA], NEAREST)`, attachment 0 = `inkA + fixedA` (coefficients 0..3), attachment 1 = `(inkB + fixedB).rgb` (coefficients 4..6) with `(inkB.a + fixedB.a)` in .a (the paint alpha the wetness law gates on) — 16 B/px, ≈ 7.7 MB at 800×600, ≈ 67 MB at the 4.2 MP sheet cap. One rect-limited draw, gated on `params.pickup > 0`; the target is cleared once at allocation (and reached by the sheet wipe through `docTargets`), so an uninitialised NaN can never enter the mix. Both consumers sample THAT. This is the one architectural accommodation; its cost is a number in the report, named against 64-24's documented delivery-law set (a second document-sized pair and a fourth per-dab pass).
4. **Feather maps onto §6 softness plus a Studio-only four-side ramp.** `gatherSoftness(feather)` already equals the reference's `paint.softness` law (0.09 + 0.25·Feather); the ramp is added because the reference has no feather control and its side edges are held only by `touch` + `dryEdge`. `featherFall(across, along)` multiplies the pre-threshold coverage by `mix(1, sideFall·endFall, uFeather)` with `sideFall = 1 − smoothstep(1 − R, 1, |across|)`, `endFall = 1 − smoothstep(1 − R, 1, |along|)`, `along = q.y`, and R = `BRISTLE_FEATHER_REACH` (0.45). Enclosed in `if (uFeather > 0.0)`, so Feather 0 is exactly today's law (never a `mix` that could re-associate the arithmetic). Named in the report as the one law with no reference counterpart.
5. **One wetness expression, two fragments.** `bristleCarrierFS`'s `paintAlphaAt` / `wetAt` are pinned line-for-line by scattering.test.ts (:982-983), so the gather may not import them without breaking a pin this plan is not allowed to touch. The gather therefore declares `paintAlphaAt` (reading the snapshot's .a) and `wetAt` with the SAME two pinned lines verbatim, and a new unit pin asserts that exact text appears in both fragments — drift is caught by the suite, not by review.
6. **The along coordinate is per pixel, exactly like the reference.** `hash21(vec2(float(nearest), floor(alongPx / uSmearPeriodPx)))` with `alongPx` computed at each call site from the already-present `q` (`uAlongPx` is the dab's cumulative distance; `q.y · uHalfWidthPx` is the pixel's offset from the dab centre). No dab-constant hash, no `uAlongPx` divergence to excuse.
