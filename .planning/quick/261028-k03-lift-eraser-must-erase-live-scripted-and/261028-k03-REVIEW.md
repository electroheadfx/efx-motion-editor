# Quick 261028-k03: Lift three-state erase — Code Review

**Depth:** quick (advisory) · **Files:** 12 · **Status:** issues_found

## Summary

Engine half is sound: `liftFS` samples no texture, so writing `this.fixed` while bound as the draw
target cannot feed back; `vec4(f)` on both attachments is correct (`fixedA.a` is a real absorbance
coefficient in `displayFS`, `fixedB.a` is 0); `history.protect(1, rect+margin, this.fixed.views)`
runs before the fixed draw with the same margin as `touch()`; blend ends `disable(BLEND)` as before.
Pool exhaustion cannot crash (it evicts — WR-05). Typecheck clean; 40 new tests pass.

The punch module is well built (linear-light `t^K`, alpha untouched, caller bytes copied, both codec
legs awaited). All real defects sit in the Studio orchestration: two fail-open paths that resurrect
pixels, three timing/identity gaps around the commit, and tests that never run the production codec.

## Critical Issues

### CR-01: Committed key with no display cache silently skips the punch
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:5877`
**Issue:** `if (!rasterBacked) return { kind: 'normal' }` runs after the frame is known to be an
`ordinary-key`. The Lift event is then recorded and (Script ON) the pre-erase raster pinned, but
nothing punches it — the next Apply merges the script sheet over the unpunched base and the erased
pixels return (rows 7/8). Reachable whenever `findCachedRotoDisplayFrame` is null (cache eviction /
revision mismatch).
**Fix:** `normal` only for `target.kind === 'empty'`; otherwise refuse with `AQUARELLE_LIFT_NO_CACHE_REFUSAL`.

### CR-02: Pen-eraser gesture bypasses both the D3 gate and the D2 punch, and replays as paint
**File:** `app/src/components/physic-paint/engine/AquarelleCanvasLayer.tsx:419,594` + `Engine.ts:1417,1890`
**Issue:** the recorded `tool` is `toolForSelection()`, but the engine forces `lift` for
`pointerType === 'pen' && buttons & 32`. With Brush selected and the stylus flipped: the D3 gate never
fires, the preflight never runs (`stroke.tool !== 'lift'`), and a **brush** event is recorded. Since D1
the live sheet now loses dried pigment permanently while replay *deposits* pigment — the inverse.
**Fix:** consume `Engine.onStrokeTool` (it already delivers the real tool), record that tool, and gate
on the live pointer type as well as the selection.

## Warnings

### WR-01: Flush and commit resolve the frame identity differently
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:5935`
**Issue:** `flushLivePixels(plan.frame)` resolves identity from the document's **active** track
(`useRotoFramePersistenceCoordinator.ts:833-835`), the commit uses `plan.trackId` (**session** track)
and its own `keyId`. On the documented session/document divergence the wrong key is drained, so a
settle capture that already read the pre-erase base can land after the erase.
**Fix:** drive both from `{ trackId: plan.trackId, keyId: plan.keyId }`.

### WR-02: Merge base updated only after `await captureLivePixels`, so a superseding capture reverts the erase
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:5996-6032`
**Issue:** a capture enqueued during the punch bumps the per-key revision
(`rotoLivePixelCacheTransactions.ts:157`) and rejects the erase at `stale-before-commit`; that newer
capture read `aquarelleMergeBaseRef` *before* the erase wrote it and merges the erased sheet over the
pre-erase base — pixels restored. The erase also exits on `!ok` without writing the base at all.
**Fix:** set `aquarelleMergeBaseRef` to the punched base before awaiting the commit (keep the durable
`set` after `ok`).

### WR-03: `willPinBase` writes a durable base the pin may have refused
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:5968-5992`
**Issue:** `willPinBase = !has(keyId)` is computed at preflight, but the pin (`:6605-6650`) also
refuses on `script-already-present` (any dry event counts), `payload-unavailable`,
`record-unavailable` — cases where the base is deliberately left UNKNOWN. The erase then synthesizes
an entry from `punched.bytes`, which is only byte-identical to the pin if the display cache equals the
key payload.
**Fix:** re-read the map after the pin; if `willPinBase && !has(keyId)` refuse, else punch the pinned bytes.

### WR-04: A third Lift during an in-flight erase is dropped silently
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:5895-5909`
**Issue:** the single pending slot is overwritten by a newer plan with no message; the overwritten
stroke's event is already recorded, its punch never runs, and its base pixels survive replay.
**Fix:** publish the failure message (or keep a small FIFO) when the slot is occupied.

### WR-05: Each lift dab allocates from a one-document fixed pool, silently evicting undo steps
**File:** `packages/efx-watercolor/src/playground/Engine.ts:1876` + `history.ts:139-144,214-220`
**Issue:** the fixed pool is `documents: 1` (`Engine.ts:381`). A full-canvas lift needs a whole
document of tiles; `allocSlot` then evicts the **oldest** step. Only `fix()` used this pool before —
now every eraser stroke does, so a second lift (or a lift after a Dry) drops earlier undo steps.
**Fix:** surface `history.evictions` on the eraser path, or raise the fixed group to `documents: 2`.

### WR-06: Tests never exercise the production codec
**File:** `app/src/components/physic-paint/roto/aquarelleLiftErase.test.ts:399-489`
**Issue:** every `punchTransmittanceBytes` test injects `codec`; `DEFAULT_LIFT_ERASE_CODEC`
(`createImageBitmap` decode + `encodeRotoFrameFromCanvas` encode, `aquarelleLiftErase.ts:323-360`) has
zero coverage. The assertion guarding the shipped `.bytes`-on-a-promise bug runs only against the
double, so the same class can pass every test while the production erase no-ops.
**Fix:** add one DOM-backed test calling `punchTransmittanceBytes` with no `codec`.

### WR-07: Refusals fire after the engine already erased the live sheet
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:6082-6091`
**Issue:** the preflight runs at stroke **end**. For group / unknown-base refusals the sheet is already
erased and stays dirty, so the ordinary capture or save flush can commit that erased composite —
"nothing changed" is false. D3 moved the Script-OFF case to pointerdown, but not these.
**Fix:** hoist the group / unknown-base decision into the D3 `getLiftBlocked` seam.

## Info

### IN-01: Dead guards in the punch loop
**File:** `app/src/components/physic-paint/roto/aquarelleLiftErase.ts:273` — `typeof k === 'number'` is
always true and `k < 0` is unreachable. **Fix:** `if (!(k < 1)) continue;` (NaN already covered).

### IN-02: No-dab branch re-encodes (lossy) instead of returning the input
**File:** `app/src/components/physic-paint/roto/aquarelleLiftErase.ts:380-382` — unreachable today
(both call sites guard), but it would degrade a raster. **Fix:** return `{ bytes: input, canvas: source }`.

### IN-03: Contract pins cannot see a dead runtime path
**File:** `aquarelleLiftEngineContract.test.ts`, `aquarelleLiftEraseContract.test.ts` — pure source
greps: the engine pin passes with the wrong pool index, empty `fixed.views`, or a driver-level no-op;
the Studio pin passes for any reachable-but-wrong wiring. **Fix:** keep as pins, add one behavioral
assertion (fake history recording the pool, or a `captureLivePixels` spy).

### IN-04: Stroke-end deps omit the two new callbacks
**File:** `app/src/components/physic-paint/PhysicsPaintStudio.tsx:6141` — both are `useCallback([])`, so
nothing is stale today, but adding a dep later would freeze this path. **Fix:** list them.
