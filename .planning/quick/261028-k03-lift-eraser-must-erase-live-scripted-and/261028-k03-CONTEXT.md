# Quick Task 261028-k03: Lift (eraser) three-state erase — Context

**Gathered:** 2026-10-28
**Status:** Ready for planning

<domain>
## Task Boundary

Lift (tool id `lift`, label "Lift", user says "drift" by voice transcription) must erase paint in the
three frame states the user works in, with the script/cache layers staying consistent:

1. **Live paint** on the current sheet — works today (mobile ink/wet only). Verify Script ON/OFF
   semantics and replay parity.
2. **Cooked frame + script** — displayed paint comes from the cached raster under a cleared live
   sheet; lift currently does nothing. Make it erase the displayed pixels without a manual Apply.
3. **Raster-only frame** (no script) — lift must erase the key's pixels directly and persist.

### Verified current behavior (do not re-derive)

- `Engine.lift()` (packages/efx-watercolor/src/playground/Engine.ts:1869) multiplies only
  `ink.read` and `wet.read`; it never touches `fixed`. Display density is inkA.x + fixedA.x
  (playground/shaders.ts:612). `fix()` (Engine.ts:1218) moves pigment into `fixed`; the auto
  settle-cap is reopened on the next pointerdown (`cancelAutoFix`, Engine.ts:1237;
  AquarelleCanvasLayer.tsx:576-580). A recorded Dry moves the replay's pigment to fixed too
  (aquarelleBake.ts:527-540, 645-680).
- Lift IS already recorded and replayed: tool id 3 (performance/scriptTimelineCodec.ts:122-128),
  `getAquarelleEventsForFrame` has no tool filter (aquarelleRecordState.ts:1484), the bake adapter
  accepts lift (adapter/engineAdapter.ts:109). Do NOT add a second recording path.
- Cooked frames show the cached raster in the DOM (`AquarelleCachedBaseLayer`,
  engine/PhysicsPaintCanvasMount.tsx:164) UNDER the cleared live sheet. The capture merge is
  additive: pigment-alpha t' = a*C + (1-a)*t_base (roto/physicsPaintRotoAlphaMerge.ts:24-76), so a
  lift stroke on the live sheet cannot subtract from the cached paint.
- The erase seam already exists with no producer since engine-1 was removed: `captureLivePixels`
  accepts `baseCanvas` ("engine's erased copy of the cached paint") and the merge draws it instead
  of the cached bytes (hooks/useRotoFramePersistenceCoordinator.ts:605-615, 693-695). The Studio
  passes no baseCanvas today (PhysicsPaintStudio.tsx:6509-6522). Precedent: commit 6eee6fda
  (261003-hpi, cache pixel erase).
- A lift on an empty live sheet sets `hasPaint` (Engine.touch sets everPainted) but the
  `AQUARELLE_MIN_CAPTURE_INK` gate rejects the white sheet (PhysicsPaintStudio.tsx:6400-6410), and
  the layer's settle/flush capture is gated on hasPaint (AquarelleCanvasLayer.tsx:543-552, 592-601).
  A cooked-frame erase needs its own commit trigger; the normal settle capture cannot carry it.
- The status capsule is the workflow strip's `statusMessage`/`statusIsError`
  (PhysicsPaintStudio.tsx:8069 → PhysicsPaintWorkflowStrip.tsx:266, 3958), fed by
  setApplyMessage/setApplyStatus.

### Consistency traps (must be solved)

- `aquarelleMergeBaseRef` pins the cached base per (track, sheet session)
  (PhysicsPaintStudio.tsx:6467-6482). A direct erase must update that pinned base or the next
  capture resurrects the paint.
- The durable pre-script base is pinned at the key's first recorded stroke
  (PhysicsPaintStudio.tsx:6327-6374, `aquarelleDurableBaseByKeyRef`) and composited UNDER every
  script bake (PhysicsPaintStudio.tsx:1751-1890). Re-baking cannot erase paint that lives in the
  durable base; a direct erase must touch the base bytes (and the script, when Script is ON) or a
  later Apply resurrects.
- The stored cache/key payload is an OPAQUE transmittance sheet (white = no pigment). Erase must
  lighten toward white in transmittance space, never punch alpha holes.
- Raster-only key: `rasterKeyImplRef` (PhysicsPaintStudio.tsx:6608-6657) rasterizes and purges the
  script; the key payload is the authoritative raster. A destructive pixel edit must commit through
  the acknowledged physical-edit transaction (`captureLivePixels`/`upsertCachedFrame`), not just the
  LRU cache.
- Recording a lift on a committed frame can pin the PRE-erase raster as the durable base if the lift
  is the first recorded stroke of the key (6327-6374). The punch must include that pinned base.

<decisions>
## Implementation Decisions

### D1. Explicit Dry + Lift (REOPENED by user: "Yes — Lift erases fixed too")
- `Engine.lift()` must also multiply the `fixed` layer (absorbance), not just ink/wet. Pigment baked
  into `fixed` by an explicit Dry becomes liftable.
- Add a fixed-layer undo snapshot at lift stroke start (the `history.protect(1, …, fixed.views)`
  pattern `fix()` uses at Engine.ts:1223), so global paint Undo restores fixed pigment erased by a
  lift.
- Declared consequences (user-approved):
  - "Dry is permanent" no longer applies to Lift (it stays true for the other tools).
  - Recorded Lift events that were no-ops after a recorded Dry become effective on the next Apply.
  - This is an engine BEHAVIOR change (lift pass + fixed undo protection), not a new vendor API and
    not a new undo kind.
  - If the planner judges the vendor lift + fixed-undo change unsafe, STOP and escalate to a phase.
- This dissolves the Dry-in-script resurrection hazard: a recorded Dry followed by a recorded Lift
  now replays the lift against fixed pigment, so no refusal is needed for Dry-containing scripts.
- The live-dry feedback/no-op policy is moot (there is no no-op case for dried paint anymore).

### D2. Committed frame + Script ON (user: option 1, "Punch pixels + record")
- Punch the displayed cached pixels and the durable pre-script base in transmittance space
  (lighten toward white, never alpha holes), refresh the display immediately, and record the Lift
  event so a re-bake replays it.
- The punch must update all three copies: the session merge base, the durable pre-script base bytes,
  and the key payload/cache through the physical-edit transaction.
- No resurrection on a later Apply. Base punch is permanent; script-layer erase follows the event
  (delete/move + Apply restores script-layer paint only).
- Applies to cooked+script and to raster-only frames while Script is ON (recording converts the
  raster-only key into a scripted key; the pinned durable base must be punched too).

### D3. Script OFF while a script exists (user: option 1, "Forbid with a clear message")
- Lift is forbidden with a clear, non-modal message telling the user to turn Script ON to lift
  recorded paint.
- Raster Key is the only escape hatch for a pixel-only erase on a scripted frame — not Script OFF.
- No silent resurrection; nothing destructive happens.

### D4. Undo policy (user: option 1, "No undo — declare it")
- A destructive raster erase is not undoable. It commits through the existing physical-edit
  transaction; no new undo kind or undo machinery.
- Script-layer paint remains restorable by deleting the Lift event and re-Applying.
- Raster-only erases are permanent and must be declared in the UI (status capsule).
- Escalation stays: if D1 cannot hold replay parity without engine changes, or D4 safety is judged
  insufficient, STOP and propose promoting this to a phase.

<specifics>
## Specific Ideas

- Lift footprint law (must match replay): `f = amount * exp(-(d²/r²)²)` with blend
  dst *= (1 - f) (shaders.ts:266-277); `amount = min(0.9, 0.22 * dwell)` (Engine.ts:1715-1718);
  `r = (0.012 + 0.03*pressure) * sizeMult`, `sizeMult = 3^((size-0.5)*2) * scriptScale`
  (Engine.ts:1526, 1513). The punch must use the same recorded sample points/radii/amounts.
- Punch is in the stored opaque transmittance space. The displayed layer converts transmittance to
  pigment alpha (`transmittanceSourceToPigmentAlpha`, lib/rasterAlpha). Lighten toward white; do not
  write alpha.
- Display refresh pattern after a committed pixel edit: the Apply path at
  PhysicsPaintStudio.tsx:1911-1928 (`loadCachedRotoReferenceFrame(..., generation)` +
  `physicPaintVersion.value++`) is the precedent.
- The erase commit should go through `captureLivePixels` with `baseCanvas` (and the current live
  sheet snapshot) so the live sheet's uncommitted paint and the punched base land in one physical
  edit; bypass the Studio ink gate for this dedicated erase path.
- Engine change (D1): `Engine.lift()` draws `this.fixed` with the same lift program and blend after
  ink and wet, and `lift()` protects the fixed views for undo
  (`history.protect(1, rect + margin, this.fixed.views)`) before drawing — mirroring `fix()` at
  Engine.ts:1223. The bake replays the same engine, so existing recorded Lifts after a Dry become
  effective on Apply (declared consequence).
- Visible messages (status capsule):
  - Raster-only erase: one-time declaration that the erase is permanent (no undo).
  - Refusals: Script OFF with a script (D3), group frames (fail closed), unknown durable base (fail
    closed). Non-modal, no dialogs.
