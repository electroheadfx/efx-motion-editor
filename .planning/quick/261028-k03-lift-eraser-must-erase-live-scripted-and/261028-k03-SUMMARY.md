# Quick 261028-k03: Lift (eraser) three-state erase — Summary

**Lift now erases in all three frame states: the live sheet (including pigment baked into `fixed` by an explicit Dry, with one-Undo restore), the cached composite of a committed frame, and the durable pre-script base a later Apply would otherwise resurrect**

## Accomplishments

- **D1 — the engine AND the law oracle erase fixed pigment.** `Engine.lift()` draws `this.fixed` after ink and wet with the full `amount` (the 0.8 tissue factor stays on the wet pass), and snapshots the fixed pool (`history.protect(1, …, this.fixed.views)`) over the same per-dab margin as the mobile tiles, so one Step restores both pools. `deposit.ts liftAt` subtracts `fixed`/`fixedR/G/B` at the same coverage share instead of returning on mobile-only emptiness.
- **The pure punch module.** `aquarelleLiftErase.ts` turns the recorded tick-grid dabs into a `K = PROD(1 - f_i)` coverage map over the union bbox and applies `t' = t^K` per channel in linear light, never writing alpha and never touching a pixel outside the rect. Both codec legs are awaited (`encodeRotoFrameFromCanvas` returns a promise); the caller's bytes are copied.
- **The Studio pipeline.** A Lift stroke on a committed frame runs a preflight first (empty frame → live path; group/occurrence/override → refusal; scripted key with an unknown pre-script base → refusal), takes the sheet snapshot eagerly, drains the frame's in-flight settle capture with `flushLivePixels`, punches the composite and the durable base, and commits through `captureLivePixels({ baseCanvas: D^K, cachedBase: null, mergeBlend: 'pigment-alpha' })`. Only after the acknowledgement are the merge base, the durable map (exactly one `set(`) and the display updated.
- **The pointerdown gate (D3).** With Script OFF on a frame that owns a script, a Lift pointerdown is prevented and stopped in the capture phase before `engine.cancelAutoFix()` and before the engine's own listener — no live erase, no record, and the capsule carries the exact refusal copy.

## Decisions Made

- **The two durable booleans are never conflated.** `scripted` = a script existed BEFORE this stroke (gates the durable rewrite); `willPinBase` = this stroke is about to pin the pre-erase raster (gates the pin overwrite). A third term, `has(keyId)`, covers a surviving entry whose strokes were all deleted.
- **A known-empty base stays known-empty.** `durableSource === null` writes `null`, not `undefined`, so the publish path keeps its raw-bake meaning.
- **A raster erase is permanent** and says so (`'Lifted — erased pixels are permanent (no undo).'`), for every `!scripted` case including `willPinBase`.
- **The display refresh copies the Apply precedent** (`content-token max` → `loadCachedRotoReferenceFrame(..., true, generation)` → `physicPaintVersion.value++`) instead of inventing a second reconcile.

## Code Review Follow-ups (2026-10-28)

The `gsd-code-reviewer` pass found 2 blockers + 7 warnings. Both blockers and five
warnings were fixed in `d0094edf`; the full review is at `261028-k03-REVIEW.md`.

- **BLOCKER — stylus eraser parity.** The engine resolves `buttons & 32` to `lift`, but the layer
  recorded `toolForSelection()`, so a hardware eraser erased live pigment while recording a brush.
  The layer now records `Engine.onStrokeEnd(tool)` — the resolved tool for THAT stroke — and the
  pointerdown gate also recognizes the stylus eraser end. (First attempt cached `onStrokeTool` in a
  ref; the verifier caught it leaking across strokes because the engine emits only on a change.
  Fixed in `234655ad`, with a lifecycle pin in the contract suite.)
- **BLOCKER — refusals ran after the gesture.** Group/unknown-base refusals happened at stroke end,
  after the live sheet was erased and with "nothing changed" copy. The pointerdown gate now reuses
  the full preflight and blocks every refusal before the engine; the stroke-end check stays as
  defense.
- **No-cache edge.** An empty sheet with a committed key but no displayable source now refuses
  instead of recording an unpunchable lift.
- **Pin refusal.** A `willPinBase` that the recorder refused (payload/record unavailable) now
  refuses before the record instead of synthesizing a base.
- **Re-entrancy.** The single pending slot became a FIFO queue, so a rapid third lift can never
  lose its punch while keeping its recorded event.
- **Concurrent settle capture.** The session merge base is pinned before the commit await and
  restored on a failed commit, so a settle capture enqueued mid-punch cannot merge over the
  pre-erase base.
- **Track-scoped flush.** `flushLivePixels(appFrame, trackId?)` drains the session track, matching
  the commit's `plan.trackId`.

### Declared limitations (not fixed in this quick)

- The fixed undo pool holds ONE document; a second lift step can evict the oldest fixed-layer
  snapshot (Undo then restores mobile paint, but not the earlier fixed erase). This is the
  pre-existing history-pool budget, not a new undo kind; a second fixed document would double a
  full fixed-layer snapshot in memory.
- The default codec legs (`createImageBitmap` / `encodeRotoFrameFromCanvas`) are exercised only
  through injected doubles; the awaited-encode contract is pinned, but no DOM test covers the real
  decode/encode pair.
- The punch mirrors the recorded 60 Hz tick grid; on another refresh rate a hold-and-lift dwell
  diverges by up to 2× (declared in `HOST_DT_SECONDS`).
- The pigment-alpha composite is not an exact multiply on saturated pixels; punching composite and
  base by the same K deviates by a few percent there. This is not resurrection.
