<objective>
Extend the user-approved v2.0.1 rail dissolve law (quick 261104-l0i) to every canonical lifecycle rail kind: a + Key or paint promotion on an empty frame strictly after a Motion, Static or Reveal rail must remove that rail's Loop Clip and land the new key joined to its last source key in one atomic edit, so the derived Key Rail is one continuous segment instead of a detached one-key rail behind a rail line that stops at its old end.

Purpose: quick 261104-l0i implemented the whole dissolve machinery but gated the qualification on the rail kind in exactly one place (`isCompleteStandardRailClip` ends with `isStandardMergedLoopClip`). Motion/Static (`scriptId`) and Reveal (`railKind: 'reveal'`) rails still fall through to the detached-key path, which is the regression the user reported for v2.0.1. Every other qualification (canonical lifecycle, unique ending ownership, ascending contiguous sources, exact stored end, empty frameOverrides, destination strictly at/after the stored end, no shared sources, no other clip's extent covering the destination) is already rail-kind agnostic, and `addEmptyKey` already dispatches the dissolve rail-kind agnostically. So the fix is a qualification change, not new machinery.

Output: the renamed, widened `isCompleteCanonicalLifecycleRailClip`, updated docs/comments that no longer claim Standard-only, and a pin matrix proving scripted Motion, scripted Static and Reveal rails dissolve while overridden scripted/Reveal rails, the append path, the 58 insert and ordinary Copy/Paste stay byte-identical.

Scope note: no persisted schema or serializer change; no PlayScript regeneration/stacking change; no append-path widening; no change to the 58 insert path or the rail-set boundary law.
