<objective>
Fix the main-editor regression "a timeline layer span cannot re-extend after being shrunk" (user repro, main-editor timeline, EFX Paint layer; sibling rows likely affected).

Root cause chain (verified 2026-09-18, read in full):

1. `TimelineInteraction.onPointerMove` FX branch (app/src/components/timeline/TimelineInteraction.ts:842-866) clamps the dragged end against `const totalFr = timelineStore.totalFrames.peek()` (line 845): resize-right at line 862, move at lines 855-858.
2. `TimelineRenderer.frameFromX` (app/src/components/timeline/TimelineRenderer.ts:1326-1331) clamps every pointer frame to `totalFrames - 1`, so once the timeline collapses the pointer literally cannot address a frame beyond it.
3. `lib/frameMap.ts:50-52` derives `totalFrames` from `getTimelineRequiredFrameCount` (lines 244-259) = max over visible sequences of `globalEndExclusive` (flat fx / content-overlay spans included) and Physic Paint roto display ends. The bound is therefore circular: shrinking the span collapses the total onto the span's own new end, which becomes the clamp — no extension is possible, in the same gesture or a later one.
4. `sequenceStore.updateFxSequenceRange` (app/src/stores/sequenceStore.ts:342-358) has NO clamp — the store accepts any in/out and `frameMap` re-pads the timeline from it. The refusal lives entirely in the interaction/renderer pair, so removing it cannot lose data.

Row coverage: `isInFxArea` / `fxTrackIndexFromY` index `fxTrackLayouts`, which is built for every non-content sequence (`lib/frameMap.ts:288-325`) — generators, Paint, Physic Paint, imported static-image / image-sequence / video. All share the one broken branch, so one fix covers all.

Related refusal (2026-09-14, user-reported sequence extension): the same family. Spans are seeded from `totalFrames.peek()` at creation (`components/timeline/AddFxMenu.tsx:76,119,152`; `components/views/ImportedView.tsx:103-105,172-174`), so a source longer than the project lands truncated and then could not be dragged back out. Task 3 audits and records this; with the drag fixed, extension past the project length works again.

Out of scope (do not touch): audio row drags (`audioStore.setInOut` path — same pointer clamp exists but audio is not a layer span; record only), creation-time span defaults in `AddFxMenu` / `ImportedView` / `AddLayerMenu` (defaults, not clamps), `.mce` load-time span validation, `getTimelineRequiredFrameCount` / `frameMap`, `sequenceStore`, the FX hit zones / cursors / coalescing / pointer-capture machinery.

Purpose: restore the ability to lengthen a layer span up to what the layer's own content and the user's intent require, with the timeline growing to follow.
Output: pure, tested span-drag resolver + fixed interaction/renderer pair + regression pins + the audit verdict.
</objective>
