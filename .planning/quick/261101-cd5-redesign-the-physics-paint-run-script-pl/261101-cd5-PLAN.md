<objective>
Redesign the Physics Paint Run Script (Play Script) dialog to the approved fixed 700 × 660 design across all four creation variants (Paint/Reveal × Motion/Static) and every preserved dialog mode.

Purpose: the current dialog is a 700px two-column card grid whose hierarchy is inverted — tabs, Rail Type, Timing, Motion wiggle, the summary bar and the global options all compete as equal cards, the header has no close affordance, the Reveal reference guard is a full-width notice, and Requested/Effective takes a bordered row that no longer fits the redesigned panel. The approved design promotes the tabs to the panel frame, demotes Rail Type to a subheader, makes Timing the hero, collapses Motion wiggle into a 2 × 2 grid, compacts the global options into one equal-height row and moves the readout into a borderless footer tooltip.

Output: a rewritten scoped CSS block, a recomposed dialog shell (header, folder tabs, tab-owned panel, footer), restyled extracted cards, and structural tests updated to the new composition with every behavioral assertion preserved. Behavior is untouched: no controller, port, timing, stacking, source-cycle, loop-clip or async change.

Scope note: UI and composition only. `physicsPaintRotoPlayScriptController.ts`, the hooks/ports, timing laws, stacking/collision logic, source-cycle and loop-clip logic, async flows, dialog opening/focus/drag/keyboard-containment behavior and the picker step-aside are read-only here. The only behavioral addition is the header Close button wired to the existing `playScript.cancel()`. English copy and `system-ui` only; no web font, no new runtime dependency (`lucide-preact` is already a dependency), no global CSS.

Two resolutions this plan fixes so the executor does not improvise:
1. **Source cycle (Paint creation only, when an identical cycle exists).** The fixed 660 surface has ~11px of vertical slack, so a separate Source-cycle card cannot fit. It renders as a fourth equal-width compact card in the Global options row (title, mini Link/Create segmented, active helper as a one-line subline with the full copy in `title` + `aria-describedby`, plus the source range when Link is chosen). The row already tolerates a variable card count ("The row can contain fewer than three cards; keep equal widths").
2. **Preserved modes use a static tall-surface rule.** Only the four creation views (apply Paint/Reveal × Motion/Static) keep the exact 700 × 660 surface. Every non-creation mode — loop edit, source edit, all three stack kinds (including a collision) and regeneration — sets one `physics-paint-play-script-surface-tall` modifier (`height: auto`, width/radius/chrome unchanged) from the dialog's mode flags (`loopEdit || sourceEdit || stacking`; `regenerateImpact` is only reachable under `sourceEdit`). The rule is statically evaluable at render time — never a runtime measurement, observer or content probe — so no preserved mode can overflow the `overflow: hidden` surface. No `overflow: auto|scroll` is introduced anywhere in the dialog block; the pre-existing bounded `overflow-y: auto` on the regenerate shared-group list stays (an in-card list, not a dialog scroll).
</objective>
