<objective>
Unify the two stroke-size previews behind the one shipped "Preview stroke size" switch, and stop the per-vertex envelope from painting its interior self-intersection lines on EVERY surface that draws it — the Edit-path chrome, the 61-13 wireframe, and the Select/Move preview band.

Purpose: the switch and the Edit-path auto-preview were two parallel implementations of the same idea — the switch drew a paint-footprint band (a constant approximation for vector strokes that ignored their per-anchor widths) while opening a path edit drew the per-vertex envelope for free. One control (OFF by default) must own the vector preview, and the envelope it now reveals — including the same envelope drawn as the Select/Move band — must stop painting the crossing straight lines that its closed, self-intersecting ring produces inside the band. ONE mechanism covers both surfaces: the band descriptor returned by `bandFor` carries an edge policy (`{ polygonPx, maskedEdge: true }` for the vector branch; paint and lift descriptors stay plain), and the drawing surface honours it with the same mask + doubled-width law.

Output: `VectorPathOverlay` gated on the shared signal with a split fill/edge envelope (masked edge); a `ScriptStrokeBand` descriptor on the edition port; `resolveAquarelleStrokeBandPx` resolving vector strokes to the same per-vertex envelope flagged `maskedEdge`; `ScriptStrokeOverlay` drawing a flagged band as an unmasked fill node plus one masked edge node, and keeping the shipped single path for paint and lift; the three test suites repointed and extended. The port type change, its resolver and its ONLY consumer land in the SAME task, so no task boundary ever runs typecheck against a mismatched contract.

Scope boundary: UI/geometry-display only. NO UI removal — the one switch already exists in the Draft strip (`stroke-settings-preview-stroke-size`), there is no second button to delete; the duplicate is behavioural. No CSS edit, no new dependency, no polygon union, no SVG filter (the file's own law), no change to `projectVectorPath` / `buildEnvelope` / `buildStrokeBandCached`, no document write, no new signal, no new effect, no Studio render-body signal read. `ScriptStrokeOverlay.tsx` changes ONLY how it paints the band it already receives: a conditional `<defs><mask>` and, for a flagged band, an unmasked fill node plus a masked edge node at the doubled width; paint and lift keep the shipped single path with unchanged rendered props. Its pointer, selection, drag and transform lifecycle is untouched. `scriptStrokeEdition.ts` changes are type-only (the descriptor interface + the `bandFor` return type). `vitest run` only, never watch; no dev server.
</objective>
