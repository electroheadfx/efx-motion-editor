<objective>
Make the AQTL v4 reader accept the two relief-modifier marker bits that a reverted build wrote into real snapshots.

Quick 261123-jak (2cdd99cbd) added vectorFlags bit 5 (relief-only); quick 261123-kpy (efe819015) replaced it with bit 5 (erode) + bit 6 (deposit); the revert ca6ad738d removed both bits from `VECTOR_FLAGS_MASK`. Any Studio snapshot saved between 2026-11-23 15:36 and 17:08 carries bit 5 and/or bit 6 in at least one stroke's vectorFlags byte, and today those files fail closed: decode throws 'invalid-value: vector block has reserved flags set' -> the snapshot controller's `restore()` returns 'refused' -> CR-02 latches -> every routine save is withheld and the artist sees "This track's unread script snapshot is being preserved...".

After this quick, both bits are accepted-and-discarded LEGACY markers: a snapshot from that window restores, the stroke keeps its `vectorDrawn` provenance, the engine gains no relief key, and because the encoder never writes the bits the next save cleans the file. Bit 7 and above still fail closed. No wire byte is added or consumed, so the stream cannot desync.

Purpose: recover the artist's unreadable snapshots without resurrecting the reverted relief feature — the bits are inert provenance markers, not payload.

Output: two named constants + a widened `VECTOR_FLAGS_MASK` + a documented legacy exception in the module header, and three pins (accept, fail-closed, encoder-never-writes) plus one retargeted stale reserved-bit test.
</objective>
