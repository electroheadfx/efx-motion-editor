## Color

Theme-aware via CSS custom properties. Reference values below are the **dark theme** (`:root` / `[data-theme="dark"]`) — implement with `var(--…)` so medium/light themes follow.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F0F0F` (`--color-bg-root`) | App shell, panel backgrounds' base |
| Secondary (30%) | `#111111` (`--color-bg-sidebar`), `#1A1A1A` (`--color-bg-card` / `--color-bg-right`), `#1E1E1E` (`--color-bg-menu` / `--color-bg-input`) | Right sidebar, cards, menus, popover surfaces, input fields |
| Accent (10%) | `#2D5BE3` (`--color-accent`; Studio alias `--ps-accent: oklch(0.60 0.19 262)`) | See reserved-for list — nothing else |
| Destructive | `#FF6666` (`--color-error-text`) on `#2A1A1A` (`--color-error-bg`) | Destructive / error surfaces only |

**Accent reserved for** (explicit list — never "all interactive elements"):

1. The active (checked) segment fill in the ModuleSwitcher.
2. The active tool in the aquarelle tool row (`brush | water | pen | lift`).
3. The active paper cell in the paper-picker grid.
4. The selected tip row's left accent bar in the Brushes docker.
5. The Dry action button's pressed/active state.
6. Focus rings on the new controls: `outline: 2px solid var(--color-accent)`.
7. The existing Physic Paint layer dot in AddFxMenu (already `--color-accent`; unchanged).

**NOT accent:** hover feedback (use `--color-hover-overlay` / the existing `#f59e0b` orange on `.paint-action-btn` only), disabled states (opacity + `--color-text-dim`), the inert Krita slot (muted grey, never accent, never hover-activated), unselected picker cells, slider tracks (SliderStepper native).

**New identity token** (FIXED across all themes — joins the `:root` identity block beside `--color-dot-blue/purple/green/orange/yellow`):

| Token | Value | Usage |
|-------|-------|-------|
| `--color-dot-watercolor` | `#4FC3C7` | The Water color layer-kind dot in AddFxMenu, and any timeline layer marker for a Water color layer. Chosen to read as water-teal while staying distinct from `--color-dot-blue #5588FF`, `--color-audio-waveform #22B8A0`, and `--color-accent #2D5BE3`. |

Second semantic color: **destructive only** (row above). Orange `#f59e0b` stays hover-only feedback on `.paint-action-btn` (existing) and is **not** a second accent.

Mirror/repeat highlight stays `#4b6382` (locked) — untouched by this phase.

## Copywriting Contract

### Naming law and the known collision

`ENGINE_DISPLAY_NAMES` in `app/src/components/physic-paint/roto/physicsPaintRotoScriptApplyRefusal.ts` **already maps** `efx-watercolor` → `Water color` (two words), `efx-physic-paint` → `Brush`, `efx-krita` → `Krita`. The live tree is the oracle; every new user-visible string matches it.

| Surface | Exact label | Rule |
|---------|-------------|------|
| ModuleSwitcher slot (both mounts) | `Water color` | Two words. D-01. |
| Layer-kind menu entry (AddFxMenu, PAINT section) | `Water color` | Two words. Sibling of `Paint / Rotopaint` and `Physic Paint`. |
| Cross-engine refusal display name | `Water color` | Already live in `ENGINE_DISPLAY_NAMES`. **Do not change.** |
| Right-sidebar module section header | `Water color` | Two words. |
| FX brush style chip (PaintModeSelector `FX_STYLES`) | `Watercolor` | **One word. STAYS AS-IS.** This is the p5.brush FX brush style — a different concept from the Water color engine/layer kind. Do not rename it to match. |
| Code identifiers | `efx-watercolor`, `watercolor`, `aquarelle` | Never user-visible. |

**Known copy constraint (locked):** the string `Watercolor` (one word) remains in `PaintModeSelector.tsx` `FX_STYLES`. This is intentional. The two labels name different things and **never appear on the same surface** — PaintModeSelector lives inside the Brush module's Basic/FX panel, and the Water color module panel never shows PaintModeSelector (D-14). If a future surface would show both, disambiguate with a qualifier (`FX Watercolor` / `Water color`) — never by renaming the FX style.

### Core copy

| Element | Copy |
|---------|------|
| Primary CTA | `Dry` — exact visible label of the flash-dry action button in the Water color module panel (D-15). Verb-only is intentional inside a panel whose section header already supplies context. Tooltip: `Flash-dry the sheet. Recorded in the script.` |
| Empty state heading | `No brushes match` (Brushes docker, search or category filter yields zero) |
| Empty state body | `Try another search term or choose All categories.` |
| Error state | `Apply rejected — this script is for {scriptName}, not {targetName}. Nothing changed.` (cross-engine Apply, MOD-05 — extends `buildEngineMismatchLine`; falls back to `Apply rejected — this script is for a different paint module. Nothing changed.`) |
| Destructive confirmation | None in this phase's locked surface set (AQUA-03 locks tip **import**, not removal). If custom-tip removal is added during execution: **no confirmation dialog** — the row disappears and one Undo restores it, matching the project's no-confirm delete convention. |

### Supporting copy

| Element | Copy |

| ModuleSwitcher labels | `Brush` / `Water color` / `Krita` |
| Krita inert tooltip | `Coming in v2.1.0` |
