<objective>
Make a committed-frame relight refused during playback, Draft or wireframe survive until the state clears, and run exactly once then.

This is the third of four gap-closure plans from the 2026-11-22 re-review and `64-VERIFICATION.md`, ordered criticals-first by the artist's G-01 ruling. WR-04: the relight runner returns false while playing, in Draft mode or in wireframe; `createSingleFlightRelight` grants a `false` result exactly one immediate follow-up, which also returns false while the state persists, so the budget is exhausted and nothing re-requests when the state ends — `settle()` exists but has no caller. A light committed during playback therefore leaves the committed frame on the old light until an unrelated trigger.

Purpose: CR-01 and CR-02 were fixed in the previous delta, but the fix's own gate can swallow the very re-bake it exists to schedule. The clean separation is to tell the scheduler WHY it cannot run instead of letting it discover a busy `false`: a blocked scheduler parks the request without starting, and an idle edge drains it. That keeps the bounded-budget law intact (one in flight, one queued, one busy follow-up), introduces no timer and no polling, and makes a refusal structurally distinguishable from a run that changed nothing.

Output: `SingleFlightRelight.setBlocked` with a parked request and an idle-edge drain, its fake-runner gates (park, coalesce, drain once, bypass-free, settle-through), and the Studio's one narrow signal effect wiring the gate from `isPlaying`, `draftMode.value` and `wireframeMode.value`, with the 64-19 wiring block extended and every co-located pin kept green.
</objective>
