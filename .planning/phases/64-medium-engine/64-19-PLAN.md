<objective>
Close the light-reaches-frames gap: the light enters the frame cache fingerprint, and a light change deterministically re-bakes the visible committed frame through the shipped Apply seam.

Closes 64-07 truth 5 — "a light change changes the Studio content signature, so a cached artifact keyed on it is a miss and the next render uses the new light; a same-value write leaves the signature unchanged" (CR-01).

Purpose: 64-05's backstop claimed "the document revision includes the light, so a light change rotates the revision and every cache keyed on it misses". CR-01 shows that claim does not hold at the roto frame cache, whose revision is built from the roto physical `contentRevision` plus a paper-only term; the committed base layer takes a URL and draws the baked raster unchanged, and the engine applies light only to the live sheet. The two candidate fixes are not equal: the cached raster already contains the emboss, computed from a thickness field that is not persisted, so draw-time re-lighting cannot reproduce it (the shipped caching law in CONTEXT is explicit — the frame cache stores composited pixels, so a light change re-bakes). This plan takes the cache-term plus deterministic-re-bake route the ROADMAP delivery law already states ("the light ... enters the cache content fingerprint, so a light change is a cache miss and a deterministic re-bake").
Output: `lightCacheTerm` beside `paperCacheTerm` at every real-frame revision site, the `getDocumentLight` input and the threaded projection parameter, the single-flight relight controller, the commit and undo/redo triggers, and the both-direction rows (change → miss + re-bake; same value → identical revision + no bake).
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| light gesture release → re-bake scheduler | A user-paced stream becomes render work; an unbounded scheduler would bake per pointermove |
| document light → frame cache revision | A missing term serves pixels baked under a different light (the CR-01 defect) |
| relight run → aquarelle apply lane | The wrong lane would re-roll a paint seed or mint an undo entry behind the user's back |
