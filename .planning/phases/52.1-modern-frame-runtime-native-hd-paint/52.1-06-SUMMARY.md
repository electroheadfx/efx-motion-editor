- `PHYSICS_PAINT_WORKING_LONG_EDGE` raised 1000 → 1920 in `physicsPaintCanvasSizing.ts:3` — the single cap constant. `getPhysicsPaintWorkingSize` already scales by it, so a 1920×1080 project now paints at native HD (no downscale) and 2K/4K still downscales to the 1920 long edge (D-15).

## D-18 Watch (HD pixels through the new runtime)

The capture/commit path (`rotoCanvasFrames.ts` `encodeCanvasAsWebp`) reads `getImageData` (transient RGBA) → invokes the Rust `encode_webp_frame` command → returns compact WebP bytes. The raw RGBA is a transient local (`imageData`) released after the encode; the at-rest form is compact WebP bytes only. No per-frame raw RGBA is held in the JS heap — the 8.3 MB/frame transient at 1920×1080 is the same pattern as at 1000px, just larger. No change needed.

## D-15 Legacy (one-way)

`drawCanvasAtSize` (`rotoCanvasFrames.ts:187`) already scales legacy keys (recorded at 1000px) at draw time — no re-paint affordance. The cap raise only affects newly-created working canvases. No change needed.
