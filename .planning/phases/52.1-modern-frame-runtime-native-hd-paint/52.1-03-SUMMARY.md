# Phase 52.1 Plan 03: Frame Identity Retarget Summary

**Retarget the runtime frame identity from base64 string to compact WebP bytes (D-05/D-18): `PhysicPaintRenderedFrame.bytes: Uint8Array`, capture off the synchronous string export, three registries re-keyed to stable IDs (D-06), and the child→main apply path transporting raw bytes with no base64 in JS (D-07).**

## Recovery Context

This plan was executed by a **recovery executor** after two gsd-executor agents died at the 32k output-token cap mid-plan. The full dataUrl→bytes retarget (production + tests) was **inherited uncommitted** from those executors; the recovery executor verified it, fixed the remaining failures, and committed it as one atomic commit.

**Inherited uncommitted (from the dead executors):** the frame type retarget, WebP byte probe, capture retarget, registry re-keying, and raw-byte apply path — plus ~60 test-file fixture updates.

**Written fresh (by the recovery executor):**
- Broke two module-body cycles introduced by the retarget by extracting leaf modules (`webpBytes.ts`, `rotoAlphaCanvasRegistry.ts`, `webpFrameCodec.ts`). The cycles were masking ~164 test failures (the handoff's "69 failures" was an undercount; the true count was 233).
- Fixed `isStructuredClonePlainData` to accept `Uint8Array` (structured-cloneable, not a plain record).
- Fixed `cloneAndDeepFreezePlainData` to skip `Uint8Array`/`ArrayBuffer` (array-buffer views cannot be frozen).
- Fixed `canonicalPhysicalEditPayload` to pass through already-base64 bytes (JSON round-trip idempotence).
- Updated the Rust hash parity pin (`project-416-550fa14e` → `project-598-5cf0b794`).
- Updated the legacy-revision test to expect rejection (clean break).

## Decisions Made

- Blend/interpolation path uses sync `canvasToWebpBytes` (toDataURL+atob) — the store's regeneration API is synchronous; the async Rust encoder would ripple through the whole store mutation API.
- Document-sync backgroundSources carry base64 at the JSON persistence boundary only; the frame apply path uses raw invoke.
- Legacy pre-G-52-6 revision acceptance deleted (clean break, no compat).
- Canonical intent serialization carries bytes as base64; the validator accepts both Uint8Array and canonical base64 forms.
- Rust `canonical_physical_hash` retargeted to the bytes token matching JS `buildFrameBytesToken`.

## Deviations from Plan

- **Module-body cycles:** the retarget's new imports (`physicsPaintRotoPhysicalModel → types/physicPaint`, and `rotoCanvasFrames → physicPaintStore`) created two cycles that broke module load order. Resolved by extracting leaf modules — a structural change not in the plan, but required for the tests to load.
- **`isStructuredClonePlainData` / deep-freeze:** the plan did not anticipate that the structured-clone guard and deep-freeze would reject `Uint8Array`. Both were retargeted to accept/skip bytes.

## Issues Encountered

- Two gsd-executor agents died at the 32k output-token cap; the second left 12 modified files uncommitted and no SUMMARY.
- The module-body cycles masked ~164 test failures, so the handoff's "69 failures" was an undercount.
