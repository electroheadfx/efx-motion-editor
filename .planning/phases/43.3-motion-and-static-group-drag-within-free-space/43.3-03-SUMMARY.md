- roto-fill-empty gap preview (D-02, UI-SPEC G3): `collectRotoGroupDragGapPreviewAppFrames` extends the strip's vacated-cell diffing so the Group-drag session's vacated interval AND any newly opened destination interval between the moved Group's first source key and its new predecessor apply the existing `roto-fill-empty` class (border #3D454D, background #4D535A) — byte-identical to 43.2 deleted-gap cells, class application only, no new DOM nodes. Raw resolver diagnostics stay in the `detail` channel only (T-43.3-03-03)
- Busy gate (T-43.3-03-04): the existing `pendingOperationId` gate covers the new prepare, so a second drag session cannot start while a Group mutation is in flight — locked by an explicit regression test
- Post-commit stability (D-17): the moved Group stays selected, the publication's selectedKeyId/selectedAppFrame are forwarded unchanged (cursor unmoved), no navigation is triggered, and the canvas reconciles through the existing current-frame reconciliation path only when the current frame's content changed

## Decisions Made
- The ghost destination derives from the plan-02 exported pure clamp function — never reimplemented in the view layer — so preview-is-the-commit holds by construction (D-05)
- Blocked-edge direction: a rightward intent pulled back (clamped < proposed) leaves the ghost's right edge flush against the blocking content; a leftward intent pushed forward (clamped > proposed) leaves the left edge flush; equal means unclamped — no bar (UI-SPEC G4)
- The vacated gap is the Group's original half-open interval [phaseOrigin, resolvedEffectiveEnd), reported only when source-attached; a duplicated placement never moves its shared source keys so vacatedInterval is null (D-07, D-11)
- The duplicated placement arm reports changed when the placement translates (identity key mapping is not a no-change) so duplicated placement drags commit instead of rejecting as 'This move would not change the timeline.' (D-11, Rule 1 fix)
- Commit acceptance publishes through the same `.then((accepted) => ...)` continuation the strip drag uses, NOT runPhysicalAction whose kind union is a bounded Extract (D-07)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Duplicated placement drags rejected as no-change**
- **Found during:** Task 2 (GREEN test runs)
- **Issue:** The plan-02 duplicated placement arm set `changed: computeChanged(identities, mapping)` with an identity key mapping (shared source keys never move), so `proposal.status.changed` was always false and the hook's no-change guard rejected every duplicated placement drag with 'This move would not change the timeline.' — but D-11 defines a duplicated placement move as a valid placement-only move, and plan-03 Task 2 Test 2 requires an accepted no-gap move (exactly the duplicated case)
- **Fix:** Changed the duplicated arm to `changed: destination !== clip.placementStart` so the placement delta is the change signal, not the key mapping; updated the plan-02 resolver test assertion from `ok-no-change` to `ok`
- **Files modified:** app/src/components/physic-paint/roto/physicsPaintRotoPhysicalResolver.ts, app/src/components/physic-paint/roto/physicsPaintRotoPhysicalResolver.test.ts
- **Verification:** all 83 resolver tests + all 39 hook tests pass
- **Committed in:** 89710eaf (Task 2 GREEN)

**2. [Rule 1 - Bug] No-space test scenario used a valid destination**
- **Found during:** Task 2 (GREEN test runs)
- **Issue:** The no-space test dragged the source-attached group leftward to destination 0, but the clamp found destination 0 valid (B@3 is inside the Group's own interval so it is pass-through per D-08, and D@10 is outside [0,8)) — the test's premise was wrong, not the implementation
- **Fix:** Replaced the scenario with an end-of-content fixture (group at [10,16), unowned boundary B@16 immediately after, capacity 20, rightward drag to 15) where every destination [d, d+6) either exceeds capacity or contains B@16, so the clamp genuinely returns ok:false
- **Files modified:** app/src/components/physic-paint/hooks/useRotoTimelineActions.test.ts
- **Verification:** no-space and mapper tests pass; the locked literal copy is asserted
- **Committed in:** 89710eaf (Task 2 GREEN)

**3. [Rule 3 - Blocking] TypeScript narrowing on the preparation result union**
- **Found during:** Task 2 (typecheck)
- **Issue:** `prepareRotoGroupDrag('group-1', 4).reason` failed typecheck because `RotoGroupDragPreparationResult` is a union and the `ok:true` variant has no `reason` property
- **Fix:** Narrowed with `if (disabled.ok) throw new Error(...)` before reading `.reason`, matching the pattern used elsewhere in the file
- **Files modified:** app/src/components/physic-paint/hooks/useRotoTimelineActions.test.ts
