## Decisions Made

- **Straddle guard scope:** fires for ANY selected Loop member (attached OR duplicated) whose sourceCycleId is shared with an unselected Group — differs from move-rails (attached-only) because spacing resolves source cycle keys for BOTH attachment kinds; 'Duplicated placements never straddle' means a fully-selected family never straddles.
- **Crossing hard wall:** an explicit branch (from < U && to > U) || (from > U && to < U) per moved key vs unselected keys -> 'duplicate-destination-frame' + conflictingAppFrames, because finalizeProposal has no order check.
- **Break collection:** identity travel only; vacated-successor/landing-gap rules deliberately NOT applied — landing-gap would split respaced rails (a1@2 with predecessor a0@0: 2-0=2>1 -> spurious break); spacing never vacates the set's boundary as a block.
- **nextLoopClips = null always:** attached Groups keep placementStart (first source key anchors; placementStart === first source key frame); duplicated placements keep placement; no clip translation ever.
- **Break authority threaded to the resolver:** the spacing-on-set dispatch passes incomingInterpolationBreakKeyIds to resolvePhysicPaintRotoPhysicalEdit (the force-spacing path does NOT — 43.5 scope boundary); without it a break-split segment fails exact-match membership.
- **Scope-line port on the static chrome:** the prop lives on PhysicsPaintWorkflowStaticChromeProps, not the outer PhysicsPaintWorkflowStripProps — the strip derives railSetCopy internally from its own membership props; the RED test's interface assertion was corrected to the static chrome interface.
