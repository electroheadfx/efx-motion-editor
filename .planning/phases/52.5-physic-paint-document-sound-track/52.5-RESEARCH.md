## User Constraints (from CONTEXT.md)

### Locked Decisions
- **D-01:** **One clip per document.** The document carries a single sound clip (dialogue or foley). No multi-clip sound track, no gaps/overlaps model. — **Reversibility:** costly — the document model, modal, stain renderer, mix paths, and sync payload are all shaped around a singleton clip; lifting to N clips means new identity/range/overlap semantics everywhere.
- **D-02:** **Import entry point = an audio icon on the Studio timeline strip** (the frame-number band). Clicking it opens the audio modal. Explicitly rejected: Add-Audio button, Tools-popover entry, drag-and-drop-only path, or any new panel beyond that modal. — **Reversibility:** reversible — the icon is a launcher; other entry points could be added later without moving the model.
- **D-03:** **Import/replace/remove goes through the SAME shared media gallery** used for reference-image and Background import (`BackgroundAssetPickerView`), opened for audio. **No separate file picker, no second gallery, no new import path.** The modal is the only new surface; the gallery underneath is reused. — **Reversibility:** costly — the gallery is the asset-authority seam for the document; a second picker would fork import/persistence/copy semantics (52.2 reference packaging).
- **D-04:** **Formats = same as the main app** (WAV, MP3, AAC, FLAC). Reuse the existing decoder + peaks pipeline unchanged. — **Reversibility:** reversible.
- **D-05:** **The audio modal is the single control surface for the clip.** It carries: import / replace / remove (via D-03 gallery), volume, fade-in/out, **"sound in output"** (export/master gate, D-12), and **preview-mix** (include main-app audio in the Studio preview, D-11). No second properties panel. — **Reversibility:** costly — modal field set becomes the clip's edit contract consumed by sync + persistence.
- **D-06:** **Not an audio rail.** The waveform is a **dark-blue filled stain** (same blue as the main app) drawn **behind the frame numbers** across the **full height of the timeline strip**. The stain shape carries the sound variations (loudness). — **Reversibility:** costly — the strip renderer, layout metrics, and hit-testing key on this presentation; converting to a rail later re-lays out the Studio timeline.
- **D-07:** **Frame numbers stay on top (filled, no outline).** Tick marks and cuts stay at the bottom, unchanged. The strip becomes **slightly taller** so the numbers sit lower and the wave has room to express. — **Reversibility:** reversible — height is a layout constant.
- **D-08:** **Drag the stain to reposition** the clip on the time axis. Drag law from Phase 51 stands: drag updates playhead + a short audio peek only; full settle on release. — **Reversibility:** reversible.
- **D-09:** **In/out edited from a short bar at the top of the timeline, 2 px tall.** Left end sets start, right end sets end. No handles on the stain edges. — **Reversibility:** reversible.
- **D-10:** **Volume + fades are in scope** and live **inside the audio modal** (not on the timeline). Timeline stays lean: stain + 2 px bar only, no extra handles. This is justified by the roadmap's "the way the main app shows audio" (Phase 15 ships volume + fades); it is still one clip, not FUT-07 NLE editing. — **Reversibility:** costly — volume/fades enter the clip model, the mix math, and the sync payload.
- **D-11:** **Studio playback hears both** the document clip **and** the main app's global audio by default. The modal's **preview-mix toggle** can exclude the main app audio from the Studio preview so the user can **isolate the studio sound** while working. **Preview-only** — this toggle never affects export or main-editor playback. — **Reversibility:** reversible.
- **D-12:** **"Sound in output" is the master gate.** ON: the clip is exported mixed with the main audio **and** audible on main-editor playback. OFF: removed from export **and** not audible from main-app play. Studio preview still lets you hear the clip while editing regardless. Two distinct modal toggles: *sound in output* (export + main playback) vs *preview main app too* (monitoring isolation). — **Reversibility:** costly — export mixer and main playback both branch on this flag; it is part of the persisted clip state.
- **D-13:** **The clip follows layer hide/solo in the main editor.** Audible whenever the Physic Paint layer is in the composite (not hidden, or soloed when solo is on) — sound follows the layer like its pixels. Combined with D-12: D-12 is the clip's master on/off; hide/solo is the layer's compositing state. — **Reversibility:** reversible.
- **D-14:** **Clip volume + fades ARE the level everywhere** (Studio preview, main-editor playback, export). No second main-side fader. — **Reversibility:** reversible.

## Summary

Phase 52.5 gives the Physic Paint document exactly one owned sound clip, surfaced in the Studio as a full-height dark-blue waveform stain behind the frame numbers (not an audio rail), edited through a single audio modal that reuses the existing shared gallery for import/replace/remove, mixed into Studio playback alongside main-app audio, and — gated by "Sound in output" and layer hide/solo — into main-editor playback and export. The clip lives **inside the EFX Paint document** (parsed by the closed-key `parseEfxPaintDocument`, persisted in `layers/<layerId>.json` per 52.2, synced to main via the existing revisioned docSync bridge), so no new document type, IPC channel, or bridge is needed.

The three highest-leverage findings: (1) the document parser **throws on unknown members**, so the new clip field must be added to `DOCUMENT_KEYS` — but following the photoReference display-preference precedent (exclude from `encodeValidatedEfxPaintDocumentContent`, append a term to `buildEfxPaintDocumentSyncFingerprint`) makes clip edits ship through both sync guards without bumping the pixel revision; (2) the Studio mix should dispatch the clip **inside** `efxPaintAudioMonitor.playAtCursor` so stopAll/seek-restart/drift/loop-wrap/scrub funnels cover it for free — but `useRotoCachedPlayback` only prepares audio when a non-empty main `audioPreview` section exists, a gate that must widen or a project with no main audio will never play the clip; (3) main-side playback/export reuse `playbackEngine.startAudioPlayback` / `audioExportMixer.renderMixedAudio` by feeding the clip as an `AudioTrack`-shaped record, but the clip's buffer must be decoded in the **main** `audioEngine` (extend the projectStore re-decode loop).

**Primary recommendation:** ride every existing seam — document parser + sync fingerprint, monitor play funnel, playbackEngine/exportEngine gates, shared gallery — and make exactly one structural extension per seam (one `DOCUMENT_KEYS` member, one fingerprint term, one dispatch site, one gate condition). Flagged open questions below need user confirmation before task locking.

### Pattern 4: Studio mix — dispatch inside the monitor funnel

**What:** Add the document clip as a second source inside `efxPaintAudioMonitor.playAtCursor` (after the main-track loop), so `stopAll`, seek-restart, drift (`checkDrift` full restart > 40 ms), loop-wrap (`notifyLoopWrap`), and scrub (`scrubAt` throttled snippet) all cover it for free.
**When to use:** D-11 Studio playback.

Gate order in `playAtCursor` (opened this session): `audioPreviewEnabled` toggle (:125-135) → `efxPaintAudioOwnership.canStartAudio()` + `noteSuppressed()` → `ensureContext` → `if (state === 'playing') audioEngine.stopAll()` → per-track `resolveTrackPlayback` → `audioEngine.play/playDelayed` with `const trackLike = track as unknown as AudioTrack` (:146) → `claimAudio()` [VERIFIED: app/src/components/physic-paint/audio/efxPaintAudioMonitor.ts:44-52,88-104,125-187,207-228,248-260,333-360].

Constants: `0.04` (drift threshold s), `10`, `120` (scrub throttle ms), `4` (snippet frames) at :44-52 [VERIFIED: same file].

- **Clip plays through ownership:** the ownership guard (`canStartAudio(): claimHeld || !otherWindowPlaying.peek()`, efxPaintAudioOwnership.ts:68-70 [VERIFIED: read this session]) suppresses **doubled MAIN audio** (first-player-wins, `EFX_PAINT_AUDIO_SUPPRESSED_NOTE = 'Audio playing in main editor'` :25). Per CONTEXT: the clip must **mix, not contend** — dispatch the clip regardless of claim state, or place it before the ownership gate. Mitigation for a doubled-clip edge (main also plays the clip concurrently): "Studio open = main window hidden" (memory) makes real overlap unlikely; document exposure anyway.
- **Preview-mix toggle (D-11):** gates only the main-audioPreview leg (skip main-track dispatch when OFF), never the clip leg, never export/main playback.
- **Clip as AudioTrack-shaped record:** `audioEngine.play(trackId, offsetSeconds, track, fps, maxDurationSec?)` takes fade fields + `offsetFrame/inFrame/outFrame/slipOffset/totalFramesInFile`; the monitor already casts (`track as unknown as AudioTrack`), so a compatible record reuses gain/fade math unchanged.

## Common Pitfalls

### Pitfall 1: `useRotoCachedPlayback` audio-prepare gate starves the clip
**What goes wrong:** a project with NO main audio but a document clip never decodes/plays the clip in the Studio.
**Why it happens:** prepare only runs when a non-empty main `audioPreview` section exists — `if (audioPreview && audioPreview.tracks.length > 0)` [VERIFIED: app/src/components/physic-paint/hooks/useRotoCachedPlayback.ts:225-344].
**How to avoid:** widen the gate to "main tracks OR document clip" (the monitor's `prepare` already per-track-skips 404s).
**Warning signs:** clip stains fine (peaks come from a different path) but playback is silent in Studio.

### Pitfall 2: Two toggles both govern the main-audio leg
**What goes wrong:** existing Volume2/VolumeX session toggle (`audioPreviewEnabled`, checked first in `playAtCursor`) and the new "Preview main app too" both mute main audio in Studio → confusing double gate, AUD-03 risk.
**How to avoid:** define the composition explicitly — recommendation: effective main-audio-in-preview = session toggle AND preview-mix toggle; the clip leg is never affected by either. Confirm in plan (open question).
**Warning signs:** toggling one control appears dead because the other is OFF.

### Pitfall 3: Ruler scrub session fights stain/trim gestures
**What goes wrong:** stain drag or 2px trim jumps the playhead / starts a seek scrub instead of trimming.
**Why it happens:** `.physics-paint-ruler` has `onPointerDown={(event) => rulerScrub.onPointerDown(...)}` with a `RULER_SCRUB_THRESHOLD_PX = 4` arm and rAF-coalesced seek/frame [VERIFIED: app/src/components/physic-paint/view/PhysicsPaintWorkflowStrip.tsx:4356-4385] [VERIFIED: app/src/components/physic-paint/hooks/usePhysicsPaintRulerScrub.ts:5,105-107]; stain/trim children will live inside that element.
**How to avoid:** sub-threshold stain click = one seek (bubbling, desired); armed trim/stain gestures must `stopPropagation` once armed (per UI-SPEC gesture truth table) or explicitly cooperate with the ruler session. Verify both behaviors live.
**Warning signs:** click-to-seek breaks, or trim also moves the playhead.

### Pitfall 4: Layout — band height lives in TWO places
**What goes wrong:** 28→36px change half-applies; ruler and column misalign; chrome math drifts.
**Why it happens:** `.physics-paint-ruler { flex: 0 0 28px; height: 28px; ... }` [VERIFIED: app/src/components/physic-paint/physicsPaintStudio.css:3138-3177] AND `.physics-paint-track-column-strip { flex: 0 0 28px }` (ruler-spacer "so it aligns with the frame ruler") [VERIFIED: physicsPaintStudio.css:3826-3847], plus the chrome-height comment `46 (header) + 1 + 1 + 28 (ruler) + 34` in the strip component [VERIFIED: PhysicsPaintWorkflowStrip.tsx:489-498 region].
**How to avoid:** change both CSS rules and the comment/chrome constant together; tick `line-height: 22px` and `::after` tick metrics need re-check at 36px.

### Pitfall 5: Closed-key parsers reject the new member (or a payload)
**What goes wrong:** `parseEfxPaintDocument` throws `'EfxPaintDocument: unknown members; ...'` on documents carrying `sound` before `DOCUMENT_KEYS` is extended — or launch parsing rejects an added key.
**How to avoid:** extend `DOCUMENT_KEYS` and (if used) `LAUNCH_KEYS` in the same change; tests assert round-trip + unknown-member rejection.

### Pitfall 6: Clip edit never leaves the child / never registers in main
**What goes wrong:** modal changes appear in Studio but revert on reopen or are absent in main playback.
**Why it happens:** clip edits excluded from the doc revision (correct) but forgotten in the sync fingerprint (bug), or push made mid-drag violating the settle-on-release law, or the failure-path guard swap (quick 260921-ffh: decision must consult the ref at decision time — pinned by `stores/efxPaintStudioOriginSync.scratch.test.ts`) [VERIFIED: documentSyncPushGuard.ts:55-77].
**How to avoid:** add `sound` term to `buildEfxPaintDocumentSyncFingerprint`; push only on settle; keep the guard-swap behavior intact.

### Pitfall 7: Missing media fails silently instead of fail-closed
**What goes wrong:** `.mce` moved / `audio/` file deleted → blank stain or dead controls with no explanation.
**How to avoid:** CMP-05 style — no stain + modal error copy (UI-SPEC ships this copy: empty/loading/error strings); decode failure logs and skips (monitor per-track skip precedent :88-104). Path safety via `isSafePackageRelativePath` + `layers/` prefix guard (efxPaintPersistence.ts:1305) for any new path joins.

### Pitfall 8: Export includes clip when it shouldn't (or vice versa)
**What goes wrong:** D-12 violated — clip exported with Sound in output OFF, or omitted when ON.
**How to avoid:** single gate expression `settings.includeAudio && clip.soundInOutput` at the exportEngine call site; pre-check decoded buffer (warn pattern :339-344); preview-mix toggle must never appear in export logic.

### Pitfall 9: React patterns / effect sprawl
**What goes wrong:** `useState`, effect-driven selection, un-idempotent setters, unstable effect deps → the historical 2-click and render-loop bugs.
**How to avoid:** `efx-preact-reactivity` skill mandatory before components; signals-only; selection applied in click handler.
