## Objective

Make the document sound clip audible where the audience hears it: the main editor plays the clip mixed with main-timeline audio under the D-12 clip switch and the D-13 layer hide/solo composite gate, the export mixer joins the clip under `includeAudio && enabled`, the clip decodes once in the main realm serving both paths, and Plan 1's Studio edits prove out over the existing two-window sync and save/reopen.

## Model drift from 52.5-02-PLAN.md (read this first)

The plan was written before UAT rounds 2–4 reshaped the clip model. The implementation targets the **shipped** contract, not the plan's stale field names:

| Plan says | Shipped reality | Where it matters |
|---|---|---|
| `soundInOutput` (D-12 master gate) | the clip's single `enabled` switch — ON = audible in Studio + main playback + export; OFF = silent everywhere (UAT round 2) | `mainPlaybackClipEnabled`, `exportClipEnabled` |
| `previewMainApp` (D-11 flag) | never shipped as a field; the D-11 preview-mix toggle is the **session** monitoring toggle and is preview-only | structurally absent from every export input (m6 pins it) |
| `volume` (0–100 percent) | `gain` (signed −100..+100, 0 = unity at the waveform center) | adapter maps `(gain + 100) / 100` → linear 0..2 |
| `clipStart = sound.startFrame` compared to `currentFrame` | `sound.startFrame` is **document-local**; global = `sequence.inFrame + sound.startFrame` | dispatch window + export `offsetFrame` |

The plan's frame-space line is the one substantive correction, not just a rename: a clip whose document-local start is 48 on an fx sequence at `inFrame: 50` must play at global 98, and `renderMixedAudio` schedules `startTimeSec = offsetFrame / fps` on the global export timeline. Treating `sound.startFrame` as global would misplace every clip on a sequence that does not start at frame 0.

Also note D-12's "Studio preview still plays it when the output gate is OFF" is superseded: UAT round 2 made `enabled` silence the clip everywhere, Studio included. The separate Studio-vs-output split the plan describes is not in the shipped model.

## What shipped

### Task 1 — main-editor mixed playback + decode-once (MAIN-MIX-01/02)

`documentSoundGates.ts` gained three pure functions (the existing Studio gates are untouched):

- `collectDocumentSoundClips(sequences, getDocument)` → `{ layerId, sound, sequence, timelineStartFrame }[]`. Mirrors frameMap's overlay membership (a physic-paint layer on a non-fx sequence is not an overlay and is never collected), deduped by layer id, one entry per layer whose document carries a sound. Pure — callers inject `efxPaintStore.getDocument`, so playback and export share the one read.
- `layerInComposite(sequenceVisible, soloActive)` = `sequenceVisible && !soloActive`. The **A1 pin** is a passing test row: `(true, true) -> false`, durably recording that `renderGlobalFrame` skips overlay sequences under solo (exportRenderer.ts:334-335) and physic-paint layers ride fx sequences (frameMap.ts:60). `physicsPaintSoloArm.ts` is the separate Studio session arm and plays no part here.
- `mainPlaybackClipEnabled(sound, sequenceVisible, soloActive)` = present && `enabled` && in-composite.

`playbackEngine.startAudioPlayback` dispatches the clip **after** the main-track loop, inside the same function body — so the 41-04 claim guard (line 271), every `stopAll` funnel, and every seek / loop-wrap restart cover the clip leg for free (T-52.5-11's doubled-audio risk is contained by the same guard that already suppresses main tracks). Schedule math mirrors the main-track loop exactly (`play` when the cursor is inside the window, `playDelayed` when it is before the start), with `sourceOffset = (sound.inFrame + framesIntoClip) / fps`. The audible end is `min(clipEnd, sequenceOverlayOut, maxFrames)` — sound stops where the layer's pixels stop. The existing scrub snippet path is untouched (MON-01).

`projectStore`'s existing re-decode IIFE gained a second loop: for each active physic-paint layer's `sound`, guard with `isSafeAudioRelativePath`, `readFile` → `audioEngine.decode(sound.id, …)`, warn-and-skip on any failure. No peaks here — the Studio band renders from its own `sourceId`-keyed cache (52.5-01b), and main has no peaks consumer.

### Task 2 — export joins the clip (EXPORT-01)

`exportClipEnabled(sound)` = present && `enabled`, and `buildExportMixEntries(includeAudio, tracks, clipEntries, fps)` returns `[]` when `includeAudio` is off, else the tracks plus one `toDocumentSoundAudioTrack` entry per export-enabled clip (collection order, one per layer) with `offsetFrame` rebased to the global start and `filePath` carrying the path-safe join.

D-11 is proven **by construction**, not by prose: `exportClipEnabled` takes only the clip and `buildExportMixEntries` has no preview parameter, so the preview-mix toggle can never gate export. A source assertion additionally pins that `exportEngine.ts` never reads `audioPreviewEnabled`.

In `exportEngine` the audio block now gates on `mixEntries.length > 0` instead of `hasAudioTracks`, so a **clip-only** project (no main-timeline audio) takes the audio branch and renders `audio_mix.wav`. Clip references are resolved `projectRoot + '/' + sound.relativePath` only after `isSafeAudioRelativePath` passes; a bad reference is refuse-and-skipped (T-52.5-05). Cancel/abort wiring is byte-for-byte unchanged, and `renderMixedAudio` is untouched (guardrail: reuse the mixer).

### Task 3 — sync proof + plan gates (SYNC-01, PERSIST-01, MON-01)

PIN 4 in `efxPaintStudioOriginSync.scratch.test.ts` follows PIN 1–3's fidelity contracts exactly (FG-1 guard in the loop, FG-2 `serializeRuntimeIntoDocument` as the document source, FG-3 two real module instances) but measures the **settle** shape SYNC-01 asks for: a clip-only edit through the modal's member setter produces **exactly one** push, the parent realm and the reopen carrier both hold the identical (field-wise) sound member, and an immediate no-op re-settle of the same state is a content duplicate that yields **zero** further pushes. PIN 1–3 and both CONTROL rows are unchanged and green.
