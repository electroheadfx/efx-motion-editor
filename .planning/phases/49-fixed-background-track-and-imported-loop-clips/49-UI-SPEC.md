# Phase 49 — UI Design Contract

> Visual and interaction contract for the fixed Background track authoring surface inside EFX Physic Paint Studio: imported still/sequence Loop Clips, collision and interruption law, repeat config, fallback config, and persistence. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Primary authority:** `49-CONTEXT.md` D-01..D-12 (gathered 2026-08-30), the locked `SPECS/milestone-v1.0.0-plan.md` §Phase 5 + §"Background track and Loop Clips" + §"Canonical document concept", `.planning/REQUIREMENTS.md` §BKG (BKG-01..BKG-09), and the carried-forward `47-UI-SPEC.md` design contract (which already locks the Bg row rendering surface).

**Copy language (locked, carried from Phase 47):** all user-facing copy is **English**. Never implement French labels.

**Naming contract (locked, carried from Phases 45/46/47/48):** "EFX Paint" = the inline main-editor Basic/FX layer (out of scope, unchanged). "EFX Physic Paint" = the independent module + Studio window — the sole target of this phase.

**Phase boundary:** the compositor side is done (Phase 48 D-03: modulo source mapping, finite/infinite repeat, gaps, next-clip interruption resolved through the Loop Clip resolver; missing source = transparent + capsule). The document model already carries `background.clips` + `background.fallback`. This phase adds ONLY the authoring surface: the scoped asset picker, clip CRUD UI, rail drag, repeat/fallback config, undo/redo recording, and save/reopen. Photo/reference track and the `'photo'` fond mode are **Phase 50** scope. Re-import/re-link of a missing clip is **deferred** (fail-closed only in Phase 49, D-10).

## Geometry and Layering Contract

### Asset-picker surface (S2)

- Full-area swap of the canvas region: one bordered panel filling the region with the grid inside, a top bar with the surface title and `Confirm` / `Cancel` actions. The engine stays mounted underneath (paused) — the swap is a paint/visibility change, never a canvas recreation (D-01).
- Grid cells reuse `ImportGrid` tile geometry. Multi-select uses the existing `onToggleSelect` selection marks (`Use image` / `Selected` treatment from the main editor).
- The picker refreshes the library on open; no live cross-window sync (D-01).
- No backdrop overlay, no Tab trap — this is a region swap, not a modal (consistent with the Play Script floating-dialog precedent).

### Bg clip rails (S3)

- Same row geometry as Phase 47: 48px row height inside the 141px vertically scrollable rows region; frame pitch 18px (`ROTO_CELL_WIDTH_PX`); rail 3px with 12px hit target (functional geometry exceptions, locked).
- Gaps render the fallback display: transparent checkerboard or solid fallback swatch (47-CONTEXT D-06).
- Infinite repeats bound by the visible frame window (T-47-04-03 DoS guard, carried); fully-outside clips render nothing.
- Layer order unchanged from `47-UI-SPEC.md`: row cells 0, overlays 1–5, rail hit targets 6, visible rail paint 7 (`pointer-events: none`), focus ring 8, tooltip 60, dialogs 70.

### Right-panel clip section (S5)

- Reuses the right-panel Track-section card geometry (`md` 16px section spacing, `Label`/`Body` typography rows).
- Repeat control: numeric input with the `Enter a positive integer.` hint plus an explicit ∞ toggle; the rail badge shows `× {N}` or `× ∞` (D-06).
- Delete uses the existing icon-button geometry (24px hit target) with the destructive color treatment.

### Monitor checkerboard (S7)

- A repeating-conic-gradient checkerboard pattern (two grays, 8px cells — same family as the existing `Transparent` swatch `repeating-conic-gradient(#777 0% 25%, #d8d8d8 0% 50%) 0 0 / 8px 8px`) drawn beneath the monitor content, clipped to the canvas bounds. Appears ONLY in the no-fond case; with paper/canvas texture or solid fallback active, the monitor shows the fond as today (D-12).

**Accent reserved for:** the active-track marking, selected-rail marking, selected tiles and the `Confirm` action in the asset picker. It is not used for every sidebar fact, ordinary text, the fallback swatches, or destructive/warning states.

**Background row (47-CONTEXT D-06, locked):** muted tone — darker/desaturated vs Paint rows (`#2A2C2E` row background family with `#9CA3AF` label text) — plus the lock indicator. Gaps show the transparent checkerboard or the solid fallback swatch.

**Missing source:** the clip's missing frames render transparent in the flattened output and surface through the status-capsule red warning (Phase 48 D-09); no placeholder fill, no stripe (Phase 48 D-09 placeholder excision).

### State precedence (locked, carried)

Highest visible state wins: (1) unresolved/error red, (2) keyboard focus ring, (3) selected accent, (4) truncated amber end treatment, (5) hover, (6) normal. Focus never hides error. Selection never replaces the amber end treatment. State changes alter paint only, never geometry.

### Placement rule (D-03/D-04)

- Confirm drops the clip at the current playhead frame. Rejection applies ONLY when the landing frame sits **strictly inside** an existing clip.
- A clip longer than the gap is NOT rejected: the existing interruption law applies — visual cut at the next clip's start, data preserved (Phase 43/48 semantics). Same rule for import and drag; no asymmetric snap behavior.

### Empty states

- **No Background clips:** the Bg row shows the fallback display — transparent checkerboard or solid fallback swatch (47-CONTEXT D-06).
- **Empty project library:** the picker shows `Drag & drop images here or use Import button`.
- **One still imported:** a one-frame-cycle clip (`Cycle 1f × {R}`, `× ∞` when indefinite).

### Error states

- **Start collision (import or drag):** status capsule with red warning triangle; copy per table. Prior geometry, selection, and focus are preserved.
- **Repeat input invalid (empty, zero, negative when not indefinite):** input stays visible with the `Enter a positive integer.` hint in the error treatment; the edit is not committed (existing PlayScript-dialog validation pattern, D-06).
- **Missing library asset at resolve time:** transparent pixels + `Source missing` capsule (Phase 48 D-09). No re-import/re-link affordance in Phase 49 (D-10, deferred).

### Destructive actions

| Action | Confirmation approach |
|--------|----------------------|
| Delete Background clip | **No confirmation dialog** — plain undoable delete; one Undo restores the clip by reference (D-08, BKG-08). The destructive treatment signals consequence without a blocking modal. |

## Interaction Contract

### Import (BKG-02, D-01, D-03)

| Input | Result |
|-------|--------|
| Click `Import images` on the Bg row header | Canvas region swaps to the scoped asset picker; engine stays mounted (paused); library refreshes |
| Multi-select images + click `Confirm` | Clip created at the current playhead frame; `sourceFrameRefs` ordered by natural filename sort of original filenames (`shot_1 < shot_2 < shot_10`), never by asset UUID (D-02); repeat defaults to finite 1 |
| Click `Cancel` | Returns to the Studio untouched — no clip, no document mutation |
| Library `Import` inside the picker | Imports new images into the project library; they appear selectable without leaving the picker |

- Selecting already-imported images reuses existing assets — no durable asset duplication (D-09, BKG-07).

### Clip placement & collision (BKG-03/BKG-05, D-04)

- Import and drag landing strictly inside an existing clip reject through the status capsule; nothing is written.
- Downstream extent follows the interruption law (next clip interrupts without overlap; stop at next clip or parent end); the shortened state is a visual cut + distinct status, never hidden data loss.
- Moving/removing a next clip recalculates the previous loop deterministically (Phase 48 resolver semantics).

### Rail drag (D-05)

- Reuses the Phase 43 drag machinery: live preview, release-time commit, collision rejection on start collision only.
- The Bg row participates in NO cross-track drag (Phase 47 D-15 covers Paint rows); Background clips move only along their own fixed row.

### Repeat & properties (BKG-04, D-06, D-07, D-08)

- Clicking a Bg clip rail selects it and opens `Background Clip` in the right panel (existing selection/inspector routing).
- Changing repeat (finite integer or ∞ via the toggle) commits on blur/Enter and re-resolves the loop immediately; the badge, shortened status, and gap display update from accepted state only — no optimistic facts.
- `Delete clip` removes the clip immediately; Undo restores it by reference.
- Undo/redo covers clip creation, move, repeat changes, import references, deletion, and fallback changes (BKG-08), riding the unified document-wide 10-level undo ledger (Phase 46 D-01..D-03).

### Fallback config (BKG-06, D-11)

- Clicking a swatch in the `Background` segmented row mutates the document fallback (revision bump + dirty, single dirty-callback law); gaps, the monitor fond, and the flattened output update identically.
- `'photo'` never appears in the selector; the reserved `photoReference` slot is Phase 50.

### Monitor (D-12)

- The checkerboard appears only when effective fond is transparent; it is paint-only beneath the composite, never a document state, never exported.

### Busy and rejected-operation behavior (carried from `47-UI-SPEC.md`)

- During controller preparation/commit, rails and the right panel remain visible; mutation controls use `aria-disabled="true"`; rail targets expose `aria-busy="true"`.
- No optimistic rail width, badge, repeat, or fallback changes. Update only from accepted canonical state.
- On rejection, preserve prior geometry, selection, focus, inputs, and references; announce through the status capsule.

## Accessibility Contract

### Roles and names

- Import control: `aria-label="Import images"` on the Bg row header.
- Asset picker: `role="region"`, `aria-label="Import background images"`; grid retains the existing `ImportGrid` accessibility (`Use image` / `Selected` button labels); `Confirm` / `Cancel` are named buttons.
- Bg clip rail: `role="group"`, `aria-label="Background clip from frame {start}"`; tooltip carries the full facts.
- Repeat input: `aria-label="Repeat"` with `aria-describedby` pointing at the hint; ∞ toggle: `aria-label="Loop indefinitely"`, `aria-pressed` reflecting state.
- Fallback selector: existing `role="group"`, `aria-label="Background"` with per-swatch labels (`Transparent`, `White`, `Paper 1..3`).
- Delete clip button: `aria-label="Delete clip"`.
- Status capsule: existing `aria-live="polite"`; rejections additionally use `role="alert"`.

### Focus visibility and target size

- All new controls keep the existing 2px `#F2F5F7` focus ring with 1px offset.
- Icon-only controls (Import, Delete clip) use the 24px icon-button hit target; the 12px rail target remains the explicit compact-editor exception.
- Opening the picker moves focus to its first actionable control; `Cancel` and `Confirm` restore focus to the Import control.

### Reduced motion

- Picker swap, clip resolution changes, fallback changes, and monitor checkerboard are immediate paint changes; no slide, scale, shimmer, pulse, or tween.
- Under `prefers-reduced-motion: reduce`, disable the existing 120ms color/background transitions for any newly touched controls.

### Contrast and non-color cues

- Selected picker tiles use the accent mark plus the existing `Selected` button state — never color alone.
- Shortened loops use the distinct shortened visual plus the `Loop shortened by next clip` label; missing sources show `Source missing` text plus the red triangle.
- The ∞ state uses the `∞` glyph plus the `Loop indefinitely` toggle state — never the absence of a number alone.

## Implementation Boundaries

- Build the scoped asset-picker variant from `imageStore` + `ImportGrid` only. **Never port `ImportedView`** into the Studio window (D-01 — it is coupled to sequence/layer/audio intents).
- Clip ordering in `sourceFrameRefs` is natural filename sort of ORIGINAL filenames, hard lock — never asset UUID sort (`image_pool.rs` UUID v4 ordering is effectively arbitrary and must not be copied, D-02).
- Collision law is symmetric for import and drag: reject on landing frame strictly inside an existing clip only; downstream extent follows the interruption law — no asymmetric snap (D-04).
- The Bg row does NOT participate in cross-track drag; Background clip drag stays inside its own fixed row.
- Missing source is fail-closed only: transparent + capsule. No re-import/re-link affordance (D-10, deferred).
- The monitor checkerboard is paint-only and monitor-only; the compositor, flattened raster, and export paths are untouched by it (D-12).
- The document fallback union extension (fond modes) is a persisted schema change under the clean-break contract; the `'photo'` fond mode is dropped from the selector and reserved for Phase 50 (D-11).
- All clip CRUD records undo by reference on the unified document-wide ledger (BKG-08, Phase 46 D-01..D-03); no raster-byte snapshots.
- Mutations bump the appropriate revisions and the global clocks per the single dirty-callback law; the `efx-preact-reactivity` skill's rules govern every store setter and signal read.
