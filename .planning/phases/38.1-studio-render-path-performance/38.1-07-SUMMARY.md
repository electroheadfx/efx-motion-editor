## Decisions Made

- **Identity-triple validity, nothing else:** the memo compares `recordMap === recordMap && interpolation === interpolation && capacity === capacity` — selection/cursor writes (`setRotoPhysicalSelection`) touch none of the three and provably never invalidate. An absent layer deletes the cache entry and returns the miss as the current null behavior, byte-for-byte.
- **Single cache entry computes both outputs:** one resolver read produces `{ projection, contentRevision }` together, so a post-mutation projection read recomputes the revision exactly once too (asserted as 1+1 spy calls, then zero).
- **Cache-hits apply synchronously:** the approved timing win — the decoded image needs no round-trip; the guards stay single-sourced in `applyPreviewBaseImage`, used by both the onload and cache-hit paths, so guard semantics are identical by construction.
- **Stale loads never populate the cache:** the requestId/destroyed/animationMode/drawing guard runs before cache insertion in onload, matching the plan's "after the guard passes" ordering and keeping supersession behavior verbatim.
- **resetBackground skip is conservative:** requires bgData non-null + identity match + full input-tuple match; first-ever call always executes; any reassignment of `this.bgData` (all 7 writer sites verified as reassignments, none in-place) re-arms execution.
- **Destroy tolerance:** `this.previewBaseImageCache?.clear()` — pre-existing partial `Object.create` engine stubs lack the class field (initializers don't run without the constructor); optional chaining keeps those suites green UNMODIFIED while production engines always have the map.
