# Phase 38.1: Studio render-path performance - Context

**Gathered:** 2026-07-27
**Status:** Ready for planning

<domain>
## Phase Boundary

Restore canvas-first responsiveness in the Physics Paint Studio at realistic key counts by restructuring the per-frame render path: the timeline-model rebuild on every `currentFrame` change (`useRotoTimelineModel.ts:77`), the full strip cell re-render per frame, the per-render Studio view-model reconstruction, and tube/log sidebar updates during scrub and playback. This is a **timing-only** phase — zero user-facing behavior change; any behavior delta is a bug. It unblocks the re-run of the Phase 38-06 native UAT, which was rejected solely on this slowdown.

Diagnosed root cause (accepted): pre-existing 36.x/37 scaling ceiling — per-frame O(N)-over-keys work that was invisible at small N and became a 5-10x degradation after group paste multiplied key counts. All Phase 38 production diffs were statically cleared; nothing in Phase 38 introduced per-frame work.

</domain>

<decisions>
## Implementation Decisions

### Playback UI Suspension

- **D-01:** During cached playback, the ONLY live UI updates are the **canvas**, a **minimal current-frame indicator**, and **play/stop control state**. Cells, capsule, and tube/log are **frozen** for the duration. On playback stop, exactly **one catch-up render** restores full UI currency. — **Reversibility:** reversible — a subscription-gating change in the Studio/strip render wiring, not a data-model contract.
- **D-02:** Missing-frame events that would have appeared in the capsule during playback (Phase 38 D-10) are **queued and shown once on stop**, then the idle context line resumes. The 38 D-10 event-driven behavior is preserved, deferred — not dropped.

### Scrub / Navigation Policy

- **D-03:** **Canvas-first ordering:** on key-click or any navigation, the canvas paint is issued in the same tick, BEFORE any Preact UI work. Clicking through keys must give instant canvas feedback — this is the primary interaction contract. — **Reversibility:** costly — becomes the render-ordering invariant the whole Studio hot path is organized around; undoing means re-architecting the navigation pipeline.
- **D-04:** **UI updates are rAF-batched:** at most ONE UI render per animation frame regardless of click/nav rate. Fast clicking never queues more than one UI render behind the canvas.
- **D-05:** **Latest-wins canvas under saturation:** when navigation outruns the canvas (fast drag-scrub), stale queued paints are skipped — the canvas always shows where the playhead IS, never where it was. Discrete key-clicks still each paint.

### Acceptance and Regression Protection

- **D-06:** The UAT fixture is the **user's current real project** (the one that measured 5-10x slow). Success = the same project feels instant: canvas feedback on every key click, playback at full project fps, no perceptible lag. This is the same bar applied when rejecting 38-06.
- **D-07:** Regression protection = **native UAT (blocking) + one deterministic render-count instrumentation test** (vitest run, never watch) asserting a frame change does NOT rebuild the timeline model and triggers bounded renders. No timing-budget assertions (flaky on loaded machines). — **Reversibility:** reversible — test-only artifact.

### Surgery Scope and Behavioral Boundary

- **D-08:** **Full per-frame path in one pass:** timeline model (decouple structural rebuilds from `currentFrame`), strip cell render path, Studio view-model reconstruction, and tube/log sidebar updates during scrub+playback. One phase, one UAT — no second perf round.
- **D-09:** **Timing-only, zero behavior change.** Selection gestures, capsule wording, tooltips, drag, undo/redo, clipboard, scripts panel, save/reopen — all identical. Only WHEN things paint changes, never WHAT. Any behavior change is a bug and fails UAT. — **Reversibility:** one-way — it is the UAT contract for the phase; relaxing it retroactively would invalidate the verification.
- **D-10:** Phase 38 locked mechanisms are **preserved verbatim**: the 38-05 tooltip fixed-in-place positioning (no portal) with viewport-fixed notch, and the 36.15/38 capsule single-owner arbitration with the ambient idle-context feed.

### Claude's Discretion

- The decoupling mechanism for the timeline model (e.g. splitting structural signals from current-frame selection computeds) — D-03/D-04/D-05 ordering invariants are NOT flexible.
- The rAF batching mechanism (scheduler, signal gating, or batch utility) as long as it is Preact-signals-native per project CLAUDE.md (signals over hooks, no effect-dependency sprawl).
- The playback freeze mechanism (subscription gating vs render short-circuit) as long as D-01/D-02 hold.
- Plan boundaries and test placement.

</decisions>

## Existing Code Insights

### Reusable Assets
- `@preact/signals` (`signal`, `computed`, `effect`) — the project's sanctioned reactive primitive; use for gating and batching, not new hook layers
- `useRotoCachedPlayback` — existing playback loop with status lines; the freeze gate attaches here without changing its event semantics
- `resolvePostAcceptanceRotoSelection` / multi-selection reducers — pure, tested (18/18); must stay pure and untouched

### Established Patterns
- Studio re-renders on `currentFrame` signal; `rotoKeyRecords` memo subscribes to `physicPaintVersion` (project memory: always bump AND subscribe to paintVersion — do not break this contract)
- Pure selector + thin view pattern (physicsPaintWorkflowPresentation.ts) — keep derivations pure and render-time, no new controller state
- Effects only for external sync (project CLAUDE.md); rAF scheduling qualifies as external sync

### Integration Points
- `useRotoTimelineModel(input)` — split structural inputs (records, interpolation, capacity) from `currentFrame`; expose current-cell as a cheap computed
- `PhysicsPaintWorkflowStrip` — gate per-frame work behind the rAF batch; playback freeze short-circuits cell/capsule updates
- `usePhysicsPaintStudioViewModel` — the per-render reconstruction point; memoize against structural inputs
