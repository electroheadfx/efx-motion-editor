## Blocking Gaps

### Gap 1: Cached playback violates the canonical Roto background contract

**Classification:** BLOCKER  
**Affects:** `38.1-D-09`, `R-D-08`  
**Owner:** `app/src/components/physic-paint/view/PhysicsPaintStudioView.tsx:47-60`

The cached-playback background path:

- Always fills the canvas with `background.color ?? "#ffffff"`, making transparent projects opaque white.
- Uses `background.background` as the paper subscription source even though background mode and `paperGrain` are separate metadata fields.
- Does not apply `paperGrain` or `grainStrength` to pixels.

This conflicts with the canonical renderer in `app/src/lib/rotoFrameDraw.ts`, which preserves transparency and resolves paper texture, paper grain, and grain strength independently.

**Required remediation:**

- Route cached playback through the shared Roto background/compositing seam.
- Add behavior coverage for transparent playback.
- Add coverage where background texture, paper grain, and grain strength differ.

### Gap 2: `stopPhysics()` finalizes the restored mode instead of the completed session mode

**Classification:** BLOCKER  
**Affects:** `38.1-D-09`, `R-D-08`  
**Owner:** `packages/efx-physic-paint/src/engine/EfxPaintEngine.ts:708-750`

`stopPhysics()` restores `savedPhysicsMode` before checking whether the completed session used `last`, choosing selective versus complete wet-layer synchronization, and recording replay metadata.

A `startPhysics("last")` session can therefore skip selective last-stroke finalization and record the restored mode instead of the mode that actually ran.

**Required remediation:**

- Capture the completed session mode before restoring the previous mode.
- Finalize wet pixels and record replay metadata using the completed mode.
- Restore the previous mode only after finalization.
- Add a behavior test proving unrelated wet pixels remain unchanged and replay metadata records `last`.

### Gap 3: Capacity-only physical replacements are discarded as no-ops

**Classification:** BLOCKER  
**Affects:** `38.1-D-09`, `R-D-08`  
**Owner:** `app/src/stores/physicPaintStore.ts:1202-1225`

The no-op comparison considers only records and interpolation. When capacity changes alone, the function returns success before updating capacity, clamping the cursor, incrementing the physical revision, or notifying visible subscribers.

This contradicts the structural-cache identity contract, which treats capacity as one member of the identity triple.

**Required remediation:**

- Include previous capacity in the no-op comparison.
- Add a regression test using identical records/interpolation and a changed capacity.
- Assert capacity installation, cursor clamping, projection replacement, revision publication, and visible notification.

## Warnings

### Profiling storage access is not fail-closed

`physicsPaintPerformanceTrace.ts` accesses `window.localStorage` without exception handling. A restricted or throwing storage implementation can abort Studio rendering even though profiling is optional.

Add a `try/catch` and tests for a throwing property getter and throwing `getItem()`.

### Persistent-canvas automated tests are predominantly source assertions

The CanvasMount and Studio persistent-boundary suites read implementation source and assert strings or regular expressions. They do not mount Preact components and verify instance preservation, stable-forwarder callback freshness, keyed remounting, dimension reconfiguration, or exactly-once cleanup.

Native acceptance provides current evidence, but runtime component tests are required for durable regression protection.
