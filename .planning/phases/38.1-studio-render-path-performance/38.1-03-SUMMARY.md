## Decisions Made
- Playback availability uses the exact-equivalence derivation path (not array memoization): in the physical roto workflow `findCachedRotoDisplayFrame` resolves a frame exactly when `physicPaintStore.getRotoPhysicalRenderSource` returns non-null (it is the same store truth `loadCachedRotoReferenceFrame` consults), so `selectRotoPlaybackAvailable`'s boolean is identical in all four cases: no launch -> false; empty list -> false; all-missing -> false; mixed -> true iff any frame resolves.
- The scheduler disposal is a single mount-scoped `useEffect(() => () => scheduler.dispose(), [scheduler])` — external-sync rAF revocation sanctioned by the project conventions; the scheduler/generation helpers themselves are `useMemo`-created, never effect dependencies.
- `restoreFrame`'s startFrame update moved after the paint within its own flow (canvas-first reorder, D-03) and through the shared scheduler (D-04); no generation gate added there because its flow has no await between intent and paint — there is no interleaving point at which staleness could arise.
- `pendingFrameSyncRef` and `sendPhysicPaintFrameSyncMessage` keep per-navigation behavior and ordering after the canvas paint — the parent frame-sync contract is behavior, not UI estimation, and is deliberately NOT coalesced (38.1-D-09).
