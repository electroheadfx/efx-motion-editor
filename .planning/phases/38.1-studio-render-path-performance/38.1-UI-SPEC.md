# Phase 38.1 — UI Design Contract

> Retroactive visual and interaction contract for the Physics Paint Studio render-path performance phase. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

## Contract Intent

Phase 38.1 is a timing-only performance and behavior-preservation phase, not a visual redesign. The governing rule is: **only when approved surfaces update may change; what users see and what each interaction means must not change.**

No intentional change is permitted to visual design, copy, spacing, typography, color, control placement, control order, labels, icons, tooltips, the status capsule, timeline cells, canvas composition, sidebar, tool rail, transport, focus behavior, keyboard behavior, or pointer behavior.

The current user-approved production implementation is the visual source of truth. When historical specifications conflict with current approved production, preserve current production. In particular, do not restore superseded Phase 36.14 values or presentations: the approved workflow strip is 161px high, the action row is 34px high, and action controls retain their current short visible labels.

### Source Precedence

1. Current approved production UI in `PhysicsPaintStudioView.tsx`, `PhysicsPaintWorkflowStrip.tsx`, `PhysicsPaintCanvasMount.tsx`, and `physicsPaintStudio.css`.
2. Phase 38 interaction and tooltip decisions.
3. Phase 37 multi-selection behavior.
4. Phase 36.15 complement and accepted UAT refinements.
5. Phase 36.14 base UI contract only where not superseded.

## Frozen Visual Contract

1. Top bar.
2. Left tool rail.
3. Central canvas region.
4. Right panel, including its current collapsed state.
5. Workflow strip at the bottom.

Do not add, remove, resize, reorder, or visually regroup these regions. The canvas, sidebar, tool rail, transport, and timeline retain their current borders, backgrounds, radii, shadows, icons, labels, and density.

### Workflow and Timeline

- Workflow strip height remains 161px.
- Internal vertical allocation remains 46px header, 1px divider, 28px ruler, 38px lane, 34px action row, and 14px scrollbar.
- The virtual timeline remains 120 frames with 18px fixed cell pitch, 2160px lane width, and 54px ruler ticks.
- Timeline cells retain their current dimensions, state classes, data attributes, key markers, labels, focus ring, selection outlines, drag previews, and per-cell tooltips.
- The current-frame output stays in the transport header and changes no surrounding geometry.
- The status capsule stays a single elastic 32px-high capsule with `#2d3741` background, `#51606d` border, `#dde7f0` text, the existing `#f8c96b` Info icon, and one-line ellipsis.
- The action row retains its current icons, short visible labels, order, grouping, enablement rules, and tooltips.
- Plain vertical wheel input over the timeline continues to scroll horizontally; Shift-wheel and dominant horizontal deltas retain current behavior. The custom scrollbar remains synchronized.

### Tooltips

Preserve the approved tooltip contract:

- Fixed viewport positioning without a portal.
- Opposite-side placement based on source region.
- Viewport clamping.
- Existing directional notch.
- Maximum width 280px and maximum height 96px.
- Dark `#20262d` surface with existing border/shadow and 10px semibold text.
- Bounded multiline content without viewport overflow.
- 1000ms hover delay.
- Immediate display for keyboard focus.
- Escape dismissal.
- Preact text children only.

### Canvas and Cached Playback Layers

- Canvas-region geometry and measured canvas bounds remain unchanged across idle, navigation, cached playback, playback stop, and mount-error states.
- Cached playback uses the current overlay stack: canonical background canvas below the cached frame image, with the live engine canvases hidden only when cached playback is ready.
- The background canvas remains below the playback image; production z-order and pointer-event behavior remain unchanged.
- Transparent playback frames reveal the canonical configured background or remain transparent as dictated by the existing composition. They must never acquire an accidental opaque fill.
- Background texture, color, paper grain, and grain strength remain independently observable and must match preview/export composition.
- Reference images and onion overlays retain current visibility rules outside cached playback.
- No loading spinner, skeleton, flash, layout shift, replacement canvas, or new playback chrome may be introduced.

## Interaction and Update-Timing Contract

### Idle and Direct Navigation

- A non-superseded frame navigation paints the requested canvas frame and publishes the matching current-frame, timeline, capsule, and related UI state.
- Canvas painting remains first; deferred UI publication must not delay the visible canvas result.
- Rapid navigation may coalesce deferred UI updates, but the latest requested frame must win.
- Coalescing must not alter click, keyboard, drag, selection, or focus semantics.
- The Studio shell, TopBar, ToolRail, right-panel static region, static workflow chrome, CanvasMount, and Efx child must not rerender or remount solely because the current frame changed.
- Timeline cell updates remain localized and bounded; unrelated cells retain identity and visual state.

### Cached Playback Active

During cached playback, exactly these user-visible surfaces remain live:

1. The cached canvas playback composite.
2. The existing current-frame output.
3. The existing Play/Stop control state.

The timeline cells, status capsule, sidebar/tool regions, static workflow chrome, CanvasMount, and Efx child remain visually frozen. Frozen means they preserve the exact pre-playback presentation; it does not authorize disabled styling, dimming, placeholders, or alternate copy.

Playback frame delivery must use the narrow Signal subscribers already assigned to the canvas image and current-frame output. Do not route each tick through Studio-wide props/state or add synchronization effects.

### Playback Stop and Missing Frames

- Stopping playback performs one catch-up publication so all previously frozen surfaces become current together.
- The catch-up must not flash an intermediate stale frame, duplicate a status message, or shift focus.
- A missing-frame event encountered during playback is queued rather than forcing capsule rerenders on each tick.
- After stop, the queued missing-frame message is surfaced once through the existing capsule arbitration and then yields according to current priority/timeout rules.
- Missing cached frames retain the approved transparent/background playback behavior; no static explanatory filler is added.

### Timeline Editing and Capacity Changes

- Selection, multi-selection, Shift range extension, Meta/Ctrl toggling, plain-click collapse, navigation, Copy/Paste, drag, group drag, keyboard handling, focus restoration, and transaction rollback retain current semantics.
- Real-key drag keeps the 6px threshold, pointer capture, Escape cancellation, lost-capture cleanup, edge scrolling, complete proposal preview, settlement, and rollback behavior.
- Capacity-only physical timeline replacements are visible structural updates: timeline extent, cursor/current frame, selection validity, and derived cells publish immediately according to current rules.
- An exact structural match remains a no-op and must not create a visual pulse, notification, selection change, or rerender cascade.
- Capacity publication uses existing UI surfaces; no new badge, toast, or status copy is introduced.

### Physics Completion and Replay

- Stopping a completed physics session preserves the final wet-buffer paint and records the completed mode before restoring the prior editing mode.
- The visible final paint, metadata, restored mode, and subsequent replay must match existing accepted behavior.
- No mode label, transition animation, toast, or new completion state is introduced.

### Optional Profiling

- Profiling is diagnostics-only and has no visible UI.
- Unavailable or throwing storage access fails closed and must not change canvas behavior, controls, copy, layout, timing semantics, or console-facing user workflow.
- Do not add a profiler toggle, badge, warning, error state, or permission prompt.

## CanvasMount and Efx Lifecycle Contract

The persistent CanvasMount/Efx boundary is part of the interaction contract even when no visible pixels change.

| State | Required contract |
|-------|-------------------|
| Same `canvasKey`, parent rerender | Preserve the same CanvasMount/Efx ownership. Stable forwarded callback identities invoke the latest parent callbacks. No canvas flash, repaint-from-zero, lost stroke, focus loss, or mount-state copy change. |
| Same key, same dimensions | Do not restart the dimension-owned effect, observer, or initial sizing rAF. Presentation is byte-for-byte unchanged. |
| Same key, width or height changes | Run the existing dimension cleanup/reconfiguration path exactly once for the change while preserving the Efx engine instance. Fit/size updates use existing canvas geometry and styling without replacement chrome. |
| Changed `canvasKey` | Replace the prior CanvasMount/Efx child once, clean the prior owner once, and mount the replacement once. Preserve existing loading/error presentation and surrounding geometry. |
| Unmount | Cancel the active rAF and disconnect active observers exactly once. Repeated cleanup is idempotent and produces no visible artifact or late update. |
| Engine ready | Preserve current tool initialization, mount notification, canvas assets, default paper, `.paint-canvas` class, and callbacks. |
| Mount failure | Preserve the current error paragraph and placement; do not add a dialog, toast, retry control, or rewritten error. |

Automated Node evidence may prove stable-forwarder freshness, dimension-effect dependencies, observer/rAF cleanup, and idempotent unmount. It must not claim real Preact keyed reconciliation or Efx instance ownership. Same-key persistence, changed-key replacement, and exactly-once native ownership remain blocking native acceptance contracts.

## Accessibility and Focus Contract

- Preserve all existing semantic regions and accessible labels, including the Studio, canvas, workflow, status, tooltips, and shortcuts help.
- The status capsule remains `role="status"` with `aria-live="polite"`; playback suspension must not create per-frame announcements.
- Decorative cached playback images retain empty alt text; the compositing background canvas remains hidden from assistive technology.
- Existing button names, titles, disabled states, tab order, focus rings, keyboard shortcuts, and Escape behavior remain unchanged.
- Playback start/stop, catch-up publication, timeline scrolling, and CanvasMount lifecycle changes must not steal, reset, or strand focus.
- Pointer-event suppression during input-disabled states retains the current message and behavior.

## Verification Contract

Approval requires all of the following without redesign exceptions:

- Pixel parity for transparent and configured background/texture/grain cached playback.
- No visible or semantic change to Studio regions, transport, status capsule, tooltips, timeline cells, action row, sidebar, tool rail, or canvas.
- Canvas-first latest-wins navigation with preserved discrete input behavior.
- Playback live-surface restriction and one-shot stop catch-up.
- Event-driven missing-frame status with no static filler copy.
- Immediate capacity-only structural publication with exact-match no-op behavior.
- Preserved completed-physics final paint, metadata, mode restoration, and replay.
- Invisible fail-closed optional profiling.
- Native proof of same-key CanvasMount/Efx persistence, dimension-only reconfiguration, changed-key replacement, and exactly-once cleanup.
- Accepted render/lifecycle threshold matrix for both forward and backward navigation.

The agent must not launch the server, browser, or native runtime. Native visual and lifecycle acceptance is user-owned.
