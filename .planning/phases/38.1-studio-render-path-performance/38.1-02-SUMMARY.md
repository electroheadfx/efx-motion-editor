## Decisions Made
- Guard-check-then-post ordering in `schedule()` is the D-04 contract: the pending rAF id is never revoked to be re-posted, so UI is never deferred until input settles; the test's cancel stub records zero revocations across all coalescing tests.
- `dispose()` clears the flag after revoking so post-dispose `schedule()` calls work — needed for Studio unmount safety without a permanent latch.
- Generation staleness is supersession-only: no time-based or distance-based heuristics, because any heuristic could silently drop discrete clicks (threat T-38.1-02-01 mitigation).
