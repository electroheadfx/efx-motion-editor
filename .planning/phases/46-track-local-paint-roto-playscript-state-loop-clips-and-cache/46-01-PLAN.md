<objective>
Re-key the EFX Physic Paint runtime store from `layerId → frame` to `layerId → trackId → frame` addressing: every runtime map becomes two-dimensional, the two global counters split into a per-track signal map (with the global clock kept for existing subscribers), operation leases gain a track dimension, and the structural cache memo keys by track. This is the tracer slice: the vertical path from track-scoped store read/write through per-track reactivity and track-scoped invalidation, proven by isolation tests, with every later plan (projection, edit ops, authority, deletion, Hold) building on these primitives.

Purpose: TRK-01 (track ownership) and TRK-03 (per-track revision/dirty/invalidation) are impossible while the runtime is one-dimensionally keyed. The document model from Phase 45 is already track-shaped — this plan makes the runtime match it, keeping every existing subscriber compiling via the global `physicPaintVersion`/`rotoPhysicalRevision` clocks.

Output: `physicPaintStore.ts` fully track-addressed with per-track signals; the whole existing `physicPaintStore.test.ts` suite green on the new signatures; new `trackIsolation.test.ts` proving one-track edits never touch another track.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| bridge payload → store mutation | apply payloads carry a trackId that must match the captured authority, not the current active track |
| per-track maps ↔ document identity | runtime maps keyed by UUID trackId mirror the document; a mismatched key is a store bug, not a security boundary |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-46-01 | Tampering | per-track map addressing | high | mitigate | trackId is always the UUID from the document (`getDocument(layerId).tracks[].id`); every accessor takes it explicitly; no `tracks[i]` indexing anywhere (Task 1 tests 2, 3; ASVS V5) |
| T-46-02 | Spoofing | duplicate track identity | high | mitigate | the store never allocates IDs; a trackId that does not exist in the document is rejected at the accessor boundary (fail closed, no auto-create except mountTrackRuntime, Task 3 test 3) |
| T-46-03 | Tampering | cross-track lease confusion | high | mitigate | lease identity includes trackId; _validateRotoPhysicalLayerPublication checks token.trackId against the claimed track before any write (Task 3 test 1) |
</threat_model>
