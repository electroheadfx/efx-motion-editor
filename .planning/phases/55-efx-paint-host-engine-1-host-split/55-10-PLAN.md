## Measured call-chain gap (do not plan from the hypothesis)

The brief's hypothesis was: "the app-timeline scrub path drives `playbackEngine` (document audio tracks) but NEVER dispatches `efxPaintAudioMonitor.scrubAt` / `scrubEnd`". Measured end to end, that observation is true but it is **not the cause**. `efxPaintAudioMonitor` is the Studio child's paint-audio monitor (hydrated from the Studio launch `audioPreview` context in `usePhysicsPaintLaunchIntegration.ts`). The main editor already has its own paint-audio path — it is the one that makes play-from-cursor audible.

**Working PLAY path (A2's "Play starts at the cursor" = PASS):**
`playbackEngine.start()` → `startAudioPlayback()` (playbackEngine.ts:272-357):
1. main audio tracks (`audioStore.tracks`) via `audioEngine.play` / `playDelayed`
2. **paint document-sound clips** via `collectDocumentSoundClips(sequenceStore.sequences.peek(), getDocument)` → `mainPlaybackClipEnabled(sound, sequenceVisible, soloActive)` (D-12 enabled switch + D-13 composite gate) → `toDocumentSoundAudioTrack` → `audioEngine.play` / `playDelayed` (52.5-02 MAIN-MIX-01/02)

**Broken SCRUB path (A2 = FAIL, silent):**
`TimelineInteraction.ts` TIME-03 playhead drag (line 1023) → `playbackEngine.scrubToFrame(frame)` (138-148) → `startAudioSnippet(frame)` (160-176) → **iterates only `audioStore.tracks`**. The `collectDocumentSoundClips` leg is absent from `startAudioSnippet`. On a project whose only audio is a paint document-sound clip, the snippet path dispatches nothing → scrub is totally silent, while play-from-cursor is audible. That is exactly A2's observed split.

**Release path (already correct):**
`TimelineInteraction.ts` line 1306 → `playbackEngine.scrubAudioEnd()` (152-157) → `audioEngine.stopAll()`. Once paint clips ride `audioEngine.play` inside the snippet, release stops them with no further change.

**Therefore the fix is:** give `startAudioSnippet` the same document-sound-clip leg `startAudioPlayback`'s immediate arm has — same membership, same gate, same frame-space law (`timelineStartFrame = sequence.inFrame + sound.startFrame`, `sourceOffset = (sound.inFrame + sound.slipOffset + framesIntoClip) / fps`) — capped to `TIMELINE_SCRUB_AUDIO_SNIPPET_FRAMES` (4) exactly like the main-track snippet. No `playDelayed` in the snippet arm. Single-source the membership/gate/frame math with the play path so the two arms cannot drift. Do **not** wire `efxPaintAudioMonitor` into `playbackEngine` — wrong surface, and it would double-dispatch when the Studio is open.
