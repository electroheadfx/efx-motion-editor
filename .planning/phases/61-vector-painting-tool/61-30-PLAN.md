<objective>
Let a vector stroke be edited as a smooth spline instead of Bézier, behind an explicit switch (G-20).

Purpose: the user asked for "spline editing instead of / in addition to Bézier, selectable with a
switch" (61-UAT test 11). D-04 explicitly REJECTED a user-selectable Catmull-Rom curve family and D-01
fixed exactly two anchor kinds, so this plan changes the model under an explicit, user-authorised
scope change and nothing implicit.

**2026-11-11 — D-01 / D-04 REVISED (user-authorised, G-20 test 11).** The switch is an EVALUATION
MODE over the SAME anchor list, never a third kind and never a rewrite of authored data: an anchor
stays `auto` or `bezier`, its stored handles stay in the document, and `spline` merely evaluates every
anchor through the spine's existing derived-smooth family. Switching back to `bezier` restores the
authored geometry exactly, byte for byte. Existing documents never gain a key and never gain a flag
byte (REL-02: absent = today).

Output: the persisted `curveMode` field through payload, codec, AQTL, and both `.mce` declarations;
one evaluator that dispatches sampling; one batch door that switches a stroke and re-samples its
points; and the switch UI's entire model half.

Project law for this plan:
- `spine.ts` is the ONE evaluator authority and stays a PURE module (no imports). `handlesFor` already
  derives the smooth family for any anchor whose kind is not `bezier`, so spline evaluation is a VIEW
  (`kind: 'auto'`) passed through the same `sampleVectorPath` — no second walk, no second station list.
- 61-29 re-samples `points` on a path write; this plan routes that sampling through the mode, so a
  spline stroke's edited path is drawn as a spline (the G-17 law applied here).
- `renderMode` is the precedent in EVERY layer: a per-stroke optional field, a closed union with a
  guard and a resolver, a `recorded…Field` helper that writes only non-default values, a payload
  projection conditional on presence, a codec validation clause, an AQTL flag bit + code byte, and a
  two-language `.mce` declaration pinned by `mceFieldContract.test.ts`. `curveMode` mirrors it exactly.
- `efx-preact-reactivity` (project skill, mandatory): not applicable — every file here is a pure
  module or a plain record mutation; no signal, effect or render body is touched.
  `efx-async-orchestration` (project skill, mandatory): not applicable — synchronous data only.

Out of this gap-closure scope — deferred, never planned here: the switch's UI, its placement, the
rail/settings surface and the overlay chrome for spline targets (61-31), the path-edit drag lifecycle
(61-28), the G-17 diagnosis (61-29), and every paint re-bake concern.
</objective>

  <name>Decide the switch's scope and accept the one-way persistence consequence</name>
  <decision>Should the new spline switch be a PER-STROKE persisted property (recommended) or a DOCUMENT-LEVEL setting?</decision>
  <context>
G-20 test 11 asks for spline editing "instead of / in addition to Bézier, selectable with a switch".
D-01 defines exactly two anchor kinds and D-04 explicitly rejected a user-selectable curve family;
both are reopened here under the user's authorisation, and the revision line in this plan's objective
records that. The two candidate scopes are not cosmetic — they decide where the mode is stored and
what the `.mce` gains.

Per-stroke mirrors `renderMode`, the shipped per-stroke precedent: a closed union, a guard and a
resolver, a `recorded…Field` helper that writes only non-default values, and a stroke that stores
nothing until the user actually switches it. Document-level would change the meaning of every existing
vector stroke at once, including already-authored Bézier handles, and cannot express a project where
one curve is spline and another is Bézier.

One-way consequence, identical under both options but triggered only by per-stroke use: the AQTL v2
vector block gains flag bit 2 and a code byte. A saved project whose script body carries a spline
stroke is REFUSED by the shipped build's decoder ("vector block has reserved flags set"), and no
downgrade path is planned (project law: no backward compatibility for old payloads). The `.mce`
declaration gains `curveMode` on both sides; Rust's serde does not deny unknown fields, so an older
build tolerates the key in the opaque engine slot but cannot interpret it. A document that never uses
the switch keeps today's exact bytes — no key, no flag byte, no code byte.
  </context>
  <options>
    <option id="per-stroke">
      <name>Per-stroke `curveMode` (recommended)</name>
      <pros>Matches the shipped `renderMode` precedent in every layer; the switch acts on the selected stroke and stamps new drafts; absent means Bézier so untouched documents stay byte-identical; mixed projects are expressible.</pros>
      <cons>Adds one optional `.mce` key and one AQTL flag bit; a project saved with a spline stroke cannot be decoded by the shipped build.</cons>
    </option>
    <option id="document">
      <name>Document-level curve setting</name>
      <pros>One value, no per-stroke key, nothing to reconcile when strokes are copied between frames.</pros>
      <cons>Reinterprets EVERY existing vector stroke at once, including authored Bézier handles; no mixed project; still needs the AQTL flag byte, so it does not avoid the one-way consequence.</cons>
    </option>
  </options>
  <resume-signal>Select: per-stroke or document. This task writes nothing; the answer only selects which branch Tasks 2 and 3 implement (both are specified below for per-stroke, which is the recommended path; a `document` answer returns the plan to the orchestrator for re-scoping).</resume-signal>

    - The one-way persistence consequence is acknowledged before any file is written.
  </acceptance_criteria>
