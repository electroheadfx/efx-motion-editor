<objective>
Give the draw state its missing live preview (IN-01) and stop the capture-phase vector listener from swallowing keystrokes aimed at focused controls (WR-05).

Purpose: two independent defects reported against the shipped phase. `VectorDrawDraft.cursor` is written
and never read, so a user drawing a path sees committed segments only and cannot see the curve the next
click will produce — the UI review's Top Fix 1 and Interaction Contract §2's "ancestors placed so far + a
live rubber-band spine to the cursor". And the window key dispatcher (61-16) yields only to text fields,
so Enter on a focused button and the arrow/Tab keys on a focused control are consumed by the vector
handlers.

Output: one cursor writer in the session, one provisional spine in the overlay, one widened yield
predicate with its two call sites updated, and the pins for both.

D-06 is untouched: the pen and path edit stay two distinct states, and a pointer move is not a gesture.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pointer stream -> draft session | Every pointer move crosses into session state. A move that could commit would turn an accidental drag into a recorded stroke; a move that writes on every event would notify the overlay without value change. |
| window capture keydown -> vector handlers | The capture-phase listener sees keystrokes before the focused control does. A wrong yield either swallows a control's Enter/Escape or hands canvas keys to a control. |
