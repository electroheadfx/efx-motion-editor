### Gaps Summary

Eight of eighteen truths fail, and the failures are structural rather than cosmetic. The green suite is real (53 + 75 + 424 + 56 tests, plus the probe), but it pins data shapes and static wiring while the user-facing pipeline is severed in five places:

1. **Bake pipeline (gaps 1-2).** Every vector script mutation lacks the reset + `applyAquarelleTimeline` step that every sibling handler has. A drawn path and every path edit are recorded but never rasterized, so the feature is not reachable as a visible result; with Script Off a draw is a silent no-op. This is review CR-04 and the single largest blocker.
2. **Pointer and keyboard capture (gaps 3-4).** The overlay never captures the pointer, and its window-level key handler has no focus guard. Long path-edit drags can be lost, and typing in a dialog deletes anchors. Review CR-01/CR-02.
3. **Tool-state law (gaps 6-7).** Select does not release the pen (CR-06), and Select/Shift+A can force Draft OFF while wireframe is ON, re-enabling capture and re-bake under the mode that must suspend them (CR-03). The wireframe performance guarantee (VEC-05) is therefore not enforced.
4. **Undo ledger (gap 8).** Path edits are stored in the edit map and never recorded in `useRotoPhysicalEditHistory`; VEC-07 covers zero path operations. This defect is not in the review; it was found by tracing `beginAquarellePathEdit` to its callers.
5. **Edit target identity (gap 5).** The Anchor width commit reads the live selection while the gate is snapshot-derived, so a commit can write to a different stroke than the one being edited (CR-05).
