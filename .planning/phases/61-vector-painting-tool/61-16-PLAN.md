<objective>
Close the two gesture-surface gaps in `VectorPathOverlay`: a path-edit drag must own the pointer for its
whole lifetime, and the window-level vector keys must yield to a focused text field.

Purpose: G-3 and G-4. `61-VERIFICATION.md` found that `startEditDrag` never calls `setPointerCapture`, so a
drag that leaves the overlay stops receiving pointermove/pointerup and the edit is stranded mid-gesture;
and that the window `keydown` listener has no `event.target` guard, so Enter/Escape/Delete/Backspace are
swallowed while the user is typing in the Stroke Settings dialog or any other input. This plan also
corrects the two shipped assertions that describe the edit-map snapshot as a history entry (G-8's test
truth), because a false title is how the missing ledger entry stayed invisible.

Output: pointer capture on the drag, a guarded window-key dispatcher backed by a dependency-free target
predicate, the tests that fail without both, and truthful assertion titles.
</objective>

|----------|-------------|

| window keydown → vector edit | A capture-phase window listener sees every keystroke in the Studio, including keystrokes meant for a focused input. |

|-----------|----------|-----------|----------|-------------|-----------------|
| T-61-57 | Tampering | `startEditDrag` / `finishEditDrag` | high | mitigate | Capture at press and release at both ends; the release runs after the commit decision so a capture release can never swallow an edit. |
| T-61-58 | Denial of service | window `keydown` listener | medium | mitigate | The dispatcher yields to any text-entry target before either key handler runs, so a dialog's Enter/Delete are never swallowed and never `preventDefault`ed. |
