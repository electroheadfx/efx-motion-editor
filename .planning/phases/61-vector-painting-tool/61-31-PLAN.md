<objective>
Put the spline switch in the user's hands and make the canvas honour it (G-20).

Purpose: 61-30 ships the model — a per-stroke `curveMode` that evaluates the same anchor list through
the derived-smooth family. This plan adds the one visible control, the one commit seam, and the canvas
threading that makes the switch mean something: a path selected in the stroke settings can be flipped
between Bézier and Spline, the flip is one undoable edit, and every preview, hit test and insert
follows it.

**2026-11-11 — D-01 / D-04 REVISED (user-authorised, G-20 test 11; scope confirmed in 61-30).** The
switch is an evaluation mode over the same anchor list: anchors keep their `auto` / `bezier` kind and
their stored handles, and Spline only changes how the spine is walked. The switch is explicit,
per-selection and discoverable in the Paint tab; it never silently reinterprets authored handles, and
switching back restores them exactly.

Output: the Curve row, its batch edit seam, and the overlay mode threading with derived-only chrome.

Project law for this plan:
- The shipped Render row is the template in every layer: a model reading over the hydrated
  appearances, a bundle commit prop, a segmented control with an `active` guard, and ONE batch edit
  wrapper with a snapshot pair.
- 61-UI-SPEC §340-341: amber `#f59e0b` marks a control the user OWNS. Under Spline the tangents are
  derived from anchor positions, so no anchor is an owned control — every anchor wears the auto-smooth
  treatment and no handle dots are drawn. The promosition shape/colour change of D-03 stays the Bézier
  behaviour, untouched.
- `efx-preact-reactivity` (project skill, mandatory): the overlay keeps its narrow reads and adds NO
  signal — the mode is read from the stroke it already resolves; the dialog is a render-body read of
  hydrated props, and every write lives in a click handler; no new effect anywhere.
  `efx-async-orchestration` (project skill, mandatory): the handler mirrors the shipped render-mode
  handler's single-flight shape — one settle, one terminal state, guards peek-only.

Out of this gap-closure scope — deferred, never planned here: a document-level curve setting, a
session draw mode that stamps new drafts (a new path is still recorded Bézier and flipped with this
switch in one click), per-anchor curve families, the path-edit drag lifecycle (61-28), the G-17 replay
diagnosis (61-29) and every paint re-bake concern.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| selection state -> switch display | The row states a mode the stroke may not hold; a wrong reading makes the next press a no-op the user cannot explain. |
| click -> recorded stroke | The switch is the only door that can change an evaluation mode; a second writer or a duplicate entry breaks undo. |
| spline edit gesture -> authored handles | Any drag on a spline path must not rewrite the stored kinds or handles that Bézier mode will restore. |
| stroke mode -> canvas chrome | Chrome that shows owned handles the evaluation ignores tells the user their drag will do something it will not. |
