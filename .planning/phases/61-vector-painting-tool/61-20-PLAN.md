Give every committed vector path edit exactly one undo entry by recording it at the one writer 61-15 built,
and prove that the failure route and every other vector route add none.

Purpose: G-8's ledger half. `61-VERIFICATION.md` found that a path edit writes the script with no
`recordAquarelleScriptEdit` call at all, so Cmd+Z after an anchor drag, a handle drag, an insert, a delete
or a width change was a no-op. 61-15 builds the ONE commit (`commitAquarelleVectorPathEdit`) and 61-19
routes the Anchor width member through it; this plan attaches the ledger entry to that commit's success
branches — twice, once per route — and nowhere else. The shipped ledger kind (`aquarelle-script`), its
push/trim/clear-redo sequence and its replay route already exist and are already pinned.

Output: the two record sites inside the shared commit, the stable recorder in its dependency array, and the
region-scoped pins that prove one entry per gesture, none on failure, and none from any delegating route.
</objective>

Project law for this plan: VEC-07 — undo/redo covers each vector operation. The ledger contract is shipped:
`recordAquarelleScriptEdit(editId)` pushes ONE `{ kind: 'aquarelle-script', editId }`, trims, clears redo
and publishes availability (`useRotoPhysicalEditHistory.ts:986-991`), and its undo/redo replay pins are
already green (`useRotoPhysicalEditHistory.test.ts:3606-3650`). The reference ordering is the delete
handler: record on the Draft branch, record on the Live success branch, no record on the failure branch
(`PhysicsPaintStudio.tsx:8803-8813`, `:8824-8838`). This plan is the ONLY place that records for a path
edit — 61-15 built the commit, 61-19 routes the width member through it, and both stay record-free.

`efx-preact-reactivity`: the hook returns a FRESH wrapper each render; its `recordAquarelleScriptEdit` is
the stable `useCallback` (:8859-8861 states the law). Depend on the callback, never the wrapper. The record
call lives inside async handlers/callbacks, never in the Studio render body.
`efx-async-orchestration`: recording is a success callback of a bounded sequence — never before the apply
resolves, nothing on a false or rejected apply, no retry, no unhandled rejection.

Out of this gap-closure scope — deferred, never planned here: WR-01 (dead `VectorDrawDraft.cursor`),
WR-02 (missing draw rubber band), WR-03, WR-04, WR-05, IN-01, IN-02, IN-03. The `behavior_unverified` row
(vertex-editing responsiveness) stays a manual UAT row.

A drawn vector stroke is NOT recorded here: a draw is a paint mutation on the stroke seam, and adding an
`aquarelle-script` entry for it would double-count the same gesture.

Why wave 4: this plan edits `PhysicsPaintStudio.tsx` and `PhysicsPaintStudio.test.ts` — the same two files
61-15 (wave 1), 61-18 (wave 2) and 61-19 (wave 3) edit — so it cannot share any of their waves. All three
are declared dependencies, not just a wave number: a scheduler keyed on `depends_on` must not start this
plan before 61-19 has written those files.
