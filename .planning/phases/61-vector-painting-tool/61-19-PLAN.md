<objective>
Make the Anchor width commit write to the path the Edit-path gate says it is editing, and make the control
say so when it cannot.

Purpose: G-5 and the width half of G-8. `61-VERIFICATION.md` and CR-05 found that `applyAnchorWidths`
resolves its stroke from `ids[0]` — the dialog's selection — while the anchor indices come from
`vectorPathSession.vectorAnchorSelection`, which belongs to the open path edit. Re-selecting a different
single vector stroke keeps the gate open on the old edit, so the commit writes the NEW stroke's anchors at
indices selected in the OLD path. With 61-15's shared commit the same defect would now also produce a
ledger entry for an edit the user never made.

Output: one pure target resolver with red-first tests, the bundle member rewritten to use it and to
delegate to the shared commit, the dialog's inert state with its reason, the two 61-11 bundle pins
REPLACED (they encode the `ids[0]` truth this plan removes — stated in the commit message), and the
four 61-11 dialog pins PRESERVED intact and unchanged.
</objective>
