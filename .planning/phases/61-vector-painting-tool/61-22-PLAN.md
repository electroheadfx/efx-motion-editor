<objective>
Make per-vertex width discoverable where the user already is (G-11): the sheet's default list view, plus a visible treatment for a selected anchor so "selected" no longer looks identical to "unselected".

Purpose: UAT test 3 failed as a discoverability failure, not a broken gate. The control is correct and
functional, but it lives only in the sheet's SETTINGS view, which a user reaches only through the header
sliders icon, and the overlay never reads `vectorAnchorSelection`, so a selected anchor renders exactly
like an unselected one. The user's report was "I don't know how change size stroke size per vertex".

Output: one extracted `AnchorWidthControl` mounted twice (list view + Paint tab), and one accent ring per
selected anchor in the overlay.

The width law is untouched (D-09): the value is a MULTIPLIER of the stroke's Size, the band stays
0.2..2.0, and the commit stays `bundle.applyAnchorWidths`. This plan moves and reveals the control; it
never changes what the control writes.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| selection signal -> dialog mount | The list-view mount is gated by a selection-derived flag. A wrong gate would expose a width control whose anchors belong to a different stroke, and its commit would write through `applyAnchorWidths`. |
| anchor selection -> overlay chrome | The ring renders whatever indices the session holds. A stale or out-of-range index must fail closed rather than draw chrome for a non-existent anchor. |
