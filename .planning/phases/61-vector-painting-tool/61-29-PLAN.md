<objective>
Make a committed path edit actually paint (G-17 — blocks VEC-02 and VEC-07).

Purpose: the user reported that after finishing an Edit path gesture the paint never follows the new
curve; forcing Shift+R reproduces the PRE-edit geometry. Investigation order for this plan is fixed:
(1) `updateAquarellePathInScript`, (2) commit -> `runAquarelleScriptRebake` ->
`applyAquarelleTimeline(getAquarelleEventsForFrame(playFrame))`, (3) the defer route, (4) the three
silent early returns in `commitAquarelleVectorPathEdit`. The working hypothesis — to be CONFIRMED by
Task 1's evidence before any edit — is that (1) is the only broken layer: the write replaces `anchors`
and `renderMode` and the payload entry, but carries the OLD `points` through the spread, and
`toStudioStroke` maps `s.points` into `pts`. Every replay, including a forced Shift+R, therefore
deposits the original geometry while `engine.anchors` carries the new path.

Output: the path write re-derives the sampled spine from the anchors it just stored, one retargeted
shipped assertion, and a native row that proves the paint follows the curve.

Project law for this plan:
- 61-09: the draw commit ALREADY samples — `finishVectorPath` calls `buildDraftPath`, which calls
  `sampleVectorPath`, and `buildVectorStroke` stamps every point with p 1, tx 0, ty 0, tw 0. The path
  write must reproduce that exact shape, or a replayed edit would differ from a freshly drawn stroke.
- 61-10 / T-61-34: the payload entry is regenerated through the ONE projection after every path write,
  at the SAME timeline index. That law is unchanged; only the input to the projection gains fresh points.
- REL-02 / D-10: an unchanged anchor list still returns 0 and stores nothing; a hand-painted stroke still
  has no `anchors` key and is refused whole by `normaliseAquarelleAnchors`.
- The one shipped assertion that encodes the bug — `expect(strokeAfter.points).toEqual(editedStroke().points);`
  in `VectorPathOverlay.test.ts` ("Every other field survives the path write") — is RETARGETED, not deleted:
  it keeps the params/registry/index/anchors assertions and replaces the points assertion with the sampled
  law. This is the only existing assertion this plan edits.

Out of this gap-closure scope — deferred, never planned here: painted-stroke curve editing (Phase 62),
closed/filled paths, and the multi-curve menu.
</objective>
