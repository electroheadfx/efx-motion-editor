<objective>
Close the bake seam for vector paths: a finished draw and a completed path edit both reach the live sheet
on commit, a Script-Off draw is refused instead of silently dropped, and every user path edit leaves one
shared commit for the ledger to attach to.

Purpose: G-1, G-2 and the single-writer half of G-8. `61-VERIFICATION.md` found that a drawn path exists
only in the recorded script until something else re-bakes the frame, and that
`handleAquarelleVectorPathEdit` validates and writes the script with no re-bake at all. The behaviour the
phase promised — draw it, see it, edit it, see it — is absent end to end.

Scope boundary: this plan builds the ONE commit route; the undo entry itself (G-8's second half) is
`61-20-PLAN.md` (wave 4), which records on the success branches of `commitAquarelleVectorPathEdit`. Do
not add a `recordAquarelleScriptEdit` call here — two plans writing the same seam is how a gesture would
end up with two entries.

Output: one decision/sequence module with red-first tests, the Studio's vector draw bake tail plus the
Script-Off refusal, one shared path-edit commit that re-bakes the sheet, the mount prop that carries the
async result, and the pins that replace the now-false 61-10 / 61-11 assertions.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| gesture → recorded script | The overlay hands a full anchor list to the Studio; the Studio is the only writer of the recorded path. |
| recorded script → engine bake | The re-bake reads the recorded events for the current frame; a stale or partial write would bake the wrong path. |
| ledger → history stack | A record taken before the bake resolves would make undo revert something the sheet never showed. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-61-54 | Tampering | `handleAquarelleVectorPathEdit` / `commitAquarelleVectorPathEdit` | high | mitigate | The read-and-refuse guard runs before any write: a missing stroke or an unreadable path publishes the fixed rejection and returns without touching the script (the shipped 61-10 guard, preserved verbatim). |
| T-61-55 | Repudiation | `runAquarelleScriptRebake` | medium | mitigate | The ledger entry is recorded only after the apply resolves true; a failed apply restores the pre-edit snapshot and records nothing, so the undo stack never claims an edit the sheet rejected. |
| T-61-56 | Denial of service | the re-bake in-flight bracket | medium | mitigate | One latch per seam: an already-in-flight sequence returns false without resetting or applying, so a repeated pointer-up cannot stack two bakes over one sheet. |
| T-61-SC | Tampering | npm/pnpm package installs | high | mitigate | No dependency is added by this plan; if any install is proposed it needs a package-legitimacy check and a blocking human checkpoint. |
