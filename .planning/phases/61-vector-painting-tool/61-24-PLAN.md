<objective>
Make a new key inherit the previous key's vector path (G-15), so a duplicated/added key is a re-editable
vector stroke rather than an orphaned raster clone.

Purpose: UAT test 7 failed. `+Key` clones the previous real key's raster bytes only
(`useRotoKeyUtilities.ts:411-445`); no script is copied. The Duplicate path's projection
(`aquarelleStrokeFromScriptEvent`, `physicsPaintRotoDuplicateScript.ts:172`) also drops `anchors` and
`renderMode`, so it cannot be reused verbatim either.

Output: the projection carries the vector fields, the previous-key resolver names its source frame, `+Key`
records a fresh-id copy of that frame's script after the key is created, and the Studio owns ONE script-copy
seam used by both Duplicate and +Key.

The copy is RECORD-ONLY. The cloned bytes already equal base∘script, and `ensureAquarelleDurableBase`
inverts them on the next durable edit — applying the script again would double-paint the new key.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| previous-key script -> new key record | The copy projects stored payload events into the live registry. A malformed or foreign-frame event would attribute paint to the wrong key. |
| async key creation -> script copy | Two awaits share one in-flight latch. A second click or an interleaved navigation must not copy onto the wrong frame. |
