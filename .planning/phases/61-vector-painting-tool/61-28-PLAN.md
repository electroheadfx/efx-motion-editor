<objective>
Make an interrupted path-edit drag impossible to resurrect (CR-01).

Purpose: `dragRef` and `vectorPathEditDrag` are cleared only by the gesture's own
`finishEditDrag` / `cancelEditDrag`. When the edit closes mid-drag — Escape, a selection change, a
rail toggle — those handlers stop being attached (`editInteractive` goes false and the surface returns
null), so the drag state survives inside the mounted leaf. The captured pointer and the stale preview
then wait for the next edit: a pointerup can commit the OLD stroke's anchors into the NEW edit, and the
stale preview can paint the old path under the new one.

Output: three defects closed — an edit-lifetime cleanup effect, two target guards, and a start-of-gesture
reset — with the gesture sequence pinned as a human UAT row.

Project law for this plan:
- T-61-30 (61-10): the preview signal clears BEFORE the commit runs, so a same-tick repeat finds nothing.
  The cleanup effect keeps that law and adds a second clearing site for the ABANDONED gesture.
- 61-16 (T-61-57): pointer capture is released AFTER the commit decision, so the release can never swallow
  the edit. The cleanup effect releases only when there is no commit to protect.
- `efx-preact-reactivity` (project skill, mandatory): the leaf is the only subscriber to the session latches;
  the cleanup is an effect keyed on the primitive `editMutationId`, writes only compare-then-write, and never
  runs in a render body.
- The harness materializes the vnode tree and calls the component directly, so a mounted re-render with a
  surviving `dragRef` is not expressible — the effect and the two guards are pinned by source text, while the
  start-of-gesture reset is pinned behaviourally through the real pointer handlers.

Out of this gap-closure scope — deferred, never planned here: the G-17 replay law (61-29), the path-edit
bake copy (61-26) and every paint re-bake concern.
</objective>
