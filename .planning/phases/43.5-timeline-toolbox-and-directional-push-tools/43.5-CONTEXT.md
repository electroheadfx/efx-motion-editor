<domain>
## Phase Boundary

Two workstreams in the Physics Paint Studio bottom workflow strip:

1. **Toolbox consolidation** — Replace the top-level Interpolation pill (Blend toggle + duplicate/blend mode select) and Key Spacing pill (Set Key Space input + Apply) with one compact `ToolCase` button (export verified in the installed lucide-preact) opening a Studio-local anchored popover containing both control groups. Every accepted behavior, value, shortcut, guard, selection scope, accessibility label, Undo/Redo contract, and error message is preserved; no second state authority; no persistence change. The freed toolbar space hosts the Push tools without increasing the 161px workflow-strip height or covering cells or rails.

2. **Directional Push tool** — ONE selection-first Push tool. The moved set is THE SAME for both drag directions: the selected Rail (the explicit anchor) plus every Rail starting at/after its start. The drag direction only sets the movement direction — right opens a gap immediately before the anchor and clamps at capacity; left consumes the empty space immediately left of the anchor and clamps at the nearest fixed boundary on the left (previous rail/key end, or frame 0). One rigid atomic set preserving relative timing, internal spacing, Action provenance, synchronization status, source sharing, and Group membership. Opened intervals are recorded as persistent Phase 43.1 stable-key-owned interpolation-break gaps (Interpolation On never generates across them; Off/On restores them exactly). Preview/drag feedback shows direction, boundary, affected set, delta, resulting range, gap, and capacity status before commit. Frame-0/capacity/collision/stale-authority rejection leaves project and history untouched. The complete movement is one atomic parent-acknowledged transaction with one Undo/Redo, surviving save/reopen, playback, preview, and export.

The accepted canonical physical document, exact parent acknowledgement, stable-key-owned break authority, Motion/Static Group lifecycle (`visibleRanges`, `phaseOrigin`, `frameOverrides`, synchronization), Key Rail derivation, existing drag contracts (43.3/43.4 stay local — never push neighbors), Key Spacing/Interpolation state authority, preview/export parity, and Paint brush history remain authoritative and unchanged. Phase 43.5 exclusively owns every multi-object movement. The Motion Editor timeline is unchanged.

Requirements are not yet assigned IDs in `.planning/REQUIREMENTS.md`; downstream research/planning must derive Phase 43.5 IDs and traceability from the activated product prompt without reopening completed Phase 43/43.1/43.2/43.3/43.4 requirements.

**43.2 carryover caution (restated):** frozen `69d07703` still has open native red loops for project-local save staging, Paint into a deleted Group gap, and original-extent Regenerate. Push work must build on the accepted Group lifecycle authority without reopening those repair paths, and its own native UAT runs from a fully restarted frozen-code session (43.2 D-39).

<decisions>
## Implementation Decisions

### Toolbox surface mechanics

- **D-01:** The ToolCase button opens a **non-modal anchored popover**, anchored to the button and opening **upward** (the toolbar is at the bottom). It must never cover the rails/cells lane — the user must see and click Key Spacing proxies on the strip while the popover is open. — **Reversibility:** reversible — presentation-only; state authority is untouched.
- **D-02:** Dismiss on outside click and Escape; no focus trap. Cmd+Z, Delete/Backspace, and timeline shortcuts keep their normal routing while the popover is open.
- **D-03:** Both complete control groups move into the popover: Interpolation (Blend toggle + mode select) and Key Spacing (Set Key Space input + Apply). The Interpolation/Key Spacing state lives in the timeline as the single source of truth; the popover only edits it — no duplicated state (spec invariant).
- **D-04 (user guard):** The ToolCase button always reflects the live Interpolation on/off state at a glance (distinct icon or badge treatment) — a read-only projection of timeline state, never a second authority.
- **D-05:** ToolCase button sits at the Interpolation pill's current spot (after the key-utilities group, before Close). ONE Push button sits in the freed space beside it. The 161px strip height is unchanged; nothing covers cells or rails.

### Push activation and delta input

- **D-06 (design revision — supersedes the two-button armed-tools contract):** ONE Push tool, **selection-first**, direction from the drag. The button is enabled only when **exactly one Rail (Key/Motion/Static) is selected** and the strip is not mutation-locked; otherwise disabled with a guarded tooltip (`Select a Rail to push.` / the lock reason). Key/cell selection alone does NOT enable it — rail selection is the explicit anchor. Click arms (orange active state, same language as rail selection); re-click, Escape, Select All, any other toolbar action, or a lock transition disarms. **The anchor is bound to the selected Rail's identity at arm time** (43.5-05 Defect 1); if the selection is cleared or changes type while armed, the tool disarms — a stale anchor is never pushed. A horizontal drag past the ~4px threshold performs the push; the **drag direction** sets the movement direction only — the moved set is the SAME for both (selected Rail + every Rail starting at/after its start). The fixed side stays byte-position fixed.
- **D-07:** The anchor is the **selected Rail** (explicit at arm time) — never a hovered frame and never re-resolved at drag position. The moved set derives from that anchor alone (suffix set); the drag direction only sets the movement direction. Empty/gap frames and the ruler are inert while armed (unavailable cursor).
- **D-08:** **Drag-only** delta this phase — the prompt's "drags or specifies" is satisfied by drag with full live preview. Numeric delta entry is deferred.
- **D-09:** While armed, a plain click under the ~4px threshold does normal frame cursor navigation and keeps the tool armed. Delete/Backspace and other shortcuts keep normal behavior and disarm nothing.
- **D-10:** No keyboard shortcut for the Push tools this phase — toolbar buttons plus guarded tooltips only (43.4 D-05 Scissor precedent).

### Push preview and feedback

- **D-11:** During the drag, **every object in the moved set** (including the anchor Rail) shows a translucent mode-colored ghost at the proposed destination (per-object, full set — 43.3/43.4 ghost language); originals stay visible until exact parent acceptance; the fixed side shows no ghost, making the boundary obvious. The ghost paints exactly at the clamped destination for both directions — preview-is-the-commit (D-14) — so the painted ghost range equals the live readout range (smoke 1, Push Left geometry).
- **D-12:** **Live status-line readout during the drag**: direction, frame delta, moved set's resulting range, and the opened-gap interval (e.g. `Push Right +12 — frames 40–87 → 52–99, gap 40–51`). No floating badge; nothing floats over cells.
- **D-13 (design revision — armed anchor pre-highlight):** Because the anchor is explicit at arm time, the pre-highlight paints **as soon as armed**: the selected Rail shows the prospective-set treatment (established hover brightening of its base color, never a ghost). **Smoke 2 — the anchor keeps its full orange selection visual (capsule + selected key box) above the pre-highlight and the ghosts for the whole armed→drag→commit cycle**: a dedicated anchor-capsule layer renders above the hover (7) and ghost (8) layers at the anchor's original interval, so ghosts/pre-highlight complement but never replace the anchor's selection. On drag start the direction locks and the per-rail ghosts + gap preview + live readout take over; on commit the anchor re-binds to its new position and stays selected (43.3/43.4 stay-selected precedent). No status-line change on arm — the live readout starts with the drag.
- **D-14:** Clamp contract carried verbatim from 43.3/43.4: the ghost clamps at the nearest fixed boundary on the left (previous rail/key end, or frame 0) for Push Left or capacity/parent end for Push Right; the moved set's blocked edge shows the red treatment; dropping while clamped commits at the clamp (preview-is-the-commit). Rejection only when zero valid movement exists, via the same mapped sentence: `No empty space in that direction.`
- **D-15 (user-locked copy family, Rail terminology):** Accepted Push Right: `Pushed {N} Rails right by {D} frames — moved set now frames {A}–{B}. Gap opened at frames {G1}–{G2}.` Push Left mirrors (`left`). Singular: `Pushed 1 Rail right by {D} frames — ...`. The gap sentence appears only when a gap actually opened (43.3 D-12: no successor/predecessor → no break). **Zero-delta commit** (drag under threshold or clamp at current position) publishes nothing, creates no history entry, and keeps the tool armed (smoke 3 — no-op drops keep armed). The internal `push-drop-noop` sentinel is never surfaced — a no-op drop shows no tooltip and no status (internal reason codes never reach any user surface; the strip filters it in both `onRejected` and `onBlocked`). One deterministic mapper owns all variants: live drag readout, accepted status, rejection, singular/plural.

### Push boundary edge cases

- **D-16:** When a **source-attached Group in the moved set shares its source cycle with a Group on the fixed side**, the push **fails closed** with a mapped product reason (e.g. `Can't push: a Group in the moved set shares its source with a fixed Group.`). No mutation, no history entry. The family is never silently pulled into the set; a straddling source-attached Group never moves placement-only. — **Reversibility:** one-way — rejection semantics join the product-reason mapper, resolver guard vocabulary, and UAT; relaxing to silent set-expansion later would contradict the prompt's byte-position-fixed guarantee that users will have learned.
- **D-17 (design revision — blocked-direction at drag):** The straddle rejection (and the frame-0/capacity flush) is a **blocked-direction verdict at drag time**, not a hover preflight — the direction is chosen by the drag, so it cannot be pre-judged at arm time. While a drag is live in a blocked direction, the not-allowed cursor + tooltip carry the mapped reason for that direction only; the other direction stays available (the tool stays armed). **The blocked-direction tooltip anchors to the user position** (43.5-05 Defect 2) — the hook passes the user's viewport coords to `onBlocked` and the strip positions a zero-size anchor span there — never to an unrelated panel element. A zero-delta no-op drop's `push-drop-noop` sentinel is filtered out in `onBlocked` too (never surfaces). Preflight and rejection copy can never disagree (43.1/43.4 guarded-preflight pattern).
- **D-18 (user-locked):** The Push tool respects the existing mutation-lock authority — while playback/busy locks mutations, the Push button is disabled with a mapped reason (same family as the key-tool lock copy). **Entering a locked state disarms** an armed Push tool; no armed state outlives a lock transition. **Smoke 3 exemption:** the Push tool's OWN accepted commit is exempt from this disarm — a successful push keeps the tool armed and re-binds the anchor to the moved Rail's new position (chained pushes); a `push-commit-in-flight` guard exempts the mutation-lock disarm during the commit, and the disarm-on-selection effect re-binds instead of disarming. All other disarm vectors (Escape, re-click, Select All, other toolbar action, external selection change) are unchanged.
- **D-19 (user-locked):** Armed state is **session-only, never persisted** — save/reopen always starts disarmed; nothing about the armed tool enters the document, history, or session restore.
- **D-20 (user-locked):** Select All disarms (covered by "any other toolbar action disarms"). The moved set derives from the **selected Rail (the explicit anchor) plus the drag direction** — never from a multi-rail selection set (multi-rail selection is Phase 43.6 scope).

### Carried forward from prior phases (pre-answered, restated for downstream agents)

- Duplicated (shared-source) placements inside the moved set move **placement-only** per 43.3 algebra — they own no source keys, so no straddle arises; only source-attached straddles reject (D-16).
- Gap recording reuses 43.1 stable-key-owned break semantics with complete-collection replacement (43.3 D-09/D-10/D-12): the opened gap's break is owned by the first real key after it (Push Right: the moved set's first key); Push Left keeps the anchor's incoming break traveling with its identity (43.4 D-19 — never a silent merge with the previous segment) and manufactures no successor break because the moved set is the suffix; an existing break is reused, never duplicated; a later reverse push that closes the gap normalizes the break collection. Breaks owned by moved keys travel with stable identity (43.1 D-14).
- Group-local deleted phases/`visibleRanges` move rigidly with their Group at original relative source phases and never convert into key-owned breaks (43.3 D-13).
- After an accepted push, the anchor rail stays selected, the physical cursor stays where it is, and the Studio canvas reconciles from the accepted document only when the current frame's content changed (43.3 D-17). No automatic navigation.
- One new dedicated fail-closed resolver intent per direction (or one intent carrying direction) joins the closed union with strict parsing, canonical revision participation, coordinator payloads, and history replay (43.3 D-14 precedent). The complete movement — records, Loop Clips, breaks, selection, cursor — is one atomic parent-acknowledged history command with one Undo/Redo (43.4 D-24).
- Push never alters Repeat, Infinity, Motion/Static type, Action provenance, synchronization state, source sharing, Paint pixels, interpolation mode, or Key Spacing values (prompt-locked). Neither tool toggles Interpolation automatically.
- This phase produces a UI-SPEC via `/gsd-ui-phase 43.5` after context (43.4 D-22 precedent; the prompt explicitly requests UI discussion + UI-SPEC for toolbox placement and push feedback).
- Native visual UAT is the final oracle from a fully restarted frozen-code parent/child session (43.2 D-39), covering the prompt's 13-step acceptance list.

### Claude's Discretion

- Exact popover internal layout, section labeling, and positioning geometry, provided it opens upward, never covers the rails/cells lane, and preserves every existing control's behavior/labels/shortcuts (D-01..D-03).
- Exact live-state treatment on the ToolCase button (badge vs icon swap vs active tint), provided Blend-on vs Blend-off is distinguishable at a glance and stays a read-only projection (D-04).
- Exact ghost translucency, hover-brightening amounts, pivot boundary marker geometry, and red blocked-edge rendering within existing rail/cell tokens — zero added strip height; no confusion with selection orange, unresolved red, gap gray, or white endpoint cuts (D-11, D-13, D-14).
- Exact push intent name(s) and payload shape (one intent with direction field vs two intents), provided the closed-union/strict-parse/revision-participation contract holds.
- Exact rejection copy wording for the shared-source straddle beyond naming the cause, provided one mapper owns it (D-16/D-17).
- Exact test decomposition. Native visual UAT remains required for the toolbox relocation, armed/disarm lifecycle, anchor resolution, hover pre-highlight, ghost/clamp preview, gap persistence across Interpolation Off/On, Undo/Redo, and save/reopen.
