## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Push buttons gated behind selection (A1)**
- **Found during:** Task 1 native smoke
- **Issue:** The Push buttons were disabled whenever no key was selected (`!physicalDragAvailable` in `pushToolDisabled`), so the tools could not be armed on an empty selection even though push anchors resolve from any non-empty cell/rail.
- **Fix:** Dropped `!physicalDragAvailable` from `pushToolDisabled` — the buttons gate on busy/lock state only.
- **Files modified:** app/src/components/physic-paint/view/PhysicsPaintWorkflowStrip.tsx
- **Verification:** A1 source-contract test green; full suite green
- **Committed in:** bf33e08b (RED), 4a304872 (GREEN)

**2. [Rule 1 - Bug] Push mostly did not work — ruler drag, wrong coordinate space, Push Left never committed (A2/A3/A4)**
- **Found during:** Task 1 native smoke
- **Issue:** (a) A drag starting on the ruler (not a valid anchor) still started a push session; (b) the pointer delta was projected in raw pixels instead of FRAMES (not divided by ROTO_CELL_WIDTH_PX=18 and rounded), so a 4px drag produced a huge delta; (c) Push Left never committed because the sign of the frame delta was not preserved.
- **Fix:** Added a `laneElement.contains(event.target)` anchor check so only pointer-downs on a valid push anchor start a session; projected pointer travel in FRAMES (pixels / ROTO_CELL_WIDTH_PX, rounded); preserved the sign so Push Left projects negative frame deltas.
- **Files modified:** app/src/components/physic-paint/view/PhysicsPaintWorkflowStrip.tsx
- **Verification:** A2/A3/A4 source-contract tests green; full suite green
- **Committed in:** bf33e08b (RED), 4a304872 (GREEN)

**3. [Rule 1 - Bug] Armed lane did not suspend other interactivity (A5)**
- **Found during:** Task 1 native smoke
- **Issue:** While armed, cell/rail drags and selection still fired — the armed tool did not own the lane.
- **Fix:** Contract revision — while armed, the lane pointer-down capture stops propagation so cell/rail drags and selection never fire; a plain click moves the playback cursor ONLY.
- **Files modified:** app/src/components/physic-paint/view/PhysicsPaintWorkflowStrip.tsx
- **Verification:** Two A5 source-contract tests green; full suite green
- **Committed in:** bf33e08b (RED), 4a304872 (GREEN)

**4. [Rule 1 - Bug] Lane class template-literal broke 3 source-contract tests**
- **Found during:** Task 2 implementation
- **Issue:** Switching the lane's `class` to a template literal (`physics-paint-lane physics-paint-push-armed-right ...`) broke 3 existing source-contract tests in `PhysicsPaintWorkflowStrip.test.ts` that search for the exact string `class="physics-paint-lane"` (returned -1).
- **Fix:** Switched the lane's armed/invalid state from classes to data attributes (`data-push-armed` / `data-push-hover-invalid`) so `class="physics-paint-lane"` remains a literal string; updated the CSS selectors to attribute selectors. This avoids modifying existing tests (which would be a deviation).
- **Files modified:** app/src/components/physic-paint/view/PhysicsPaintWorkflowStrip.tsx, app/src/components/physic-paint/physicsPaintStudio.css
- **Verification:** All 102 strip tests green; full suite green
- **Committed in:** a10fad62 (Task 2 commit)
