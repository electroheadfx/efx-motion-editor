### Auto-fixed Issues

**1. [Rule 1 - Bug] BLOCKER — outside-click dismiss fired on portaled/interior surfaces**
- **Found during:** Task 1 native smoke check (issue 1)
- **Issue:** The popover is portaled to `document.body`; the dismiss handler checked only `anchor.contains(event.target)`, so ANY interior pointerdown (including the native select's OS-drawn listbox, which renders outside the popover's DOM subtree) dismissed without applying.
- **Fix:** Extracted `shouldDismissToolboxPopover(target, surfaces, isDetached?)` — a pure classifier that dismisses only when the target is provably outside every registered surface (anchor wrapper, portaled panel) and treats a detached target (`defaultIsDetachedTarget`: a `Node` no longer in the document — native WKWebView select popup artifact) as unprovable, never dismissing. The owning chrome now keeps `toolboxPanelRef` and passes it through the popover's new `panelRef` prop.
- **Files modified:** `PhysicsPaintWorkflowStrip.tsx`, `physicsPaintToolboxPopover.test.ts`
- **Commit:** `2e669b68`

**2. [Rule 1 - Bug] Popover overflowed the Actions sidebar**
- **Found during:** Task 1 native smoke check (issue 2)
- **Issue:** Left-anchoring under the Tools button (right end of toolbar) pushed the panel over the Actions sidebar (Studio grid column 3, `minmax(316px,340px)`).
- **Fix:** `computeToolboxPopoverPlacement` right-aligns the panel's right edge to the button's right edge and clamps 8px inside the strip's horizontal bounds (`maxRight = strip.right - 8`), with the bottom edge 4px above the strip top. Pure function — node-testable; the popover's layout effect now consumes it.
- **Files modified:** `PhysicsPaintWorkflowStrip.tsx`, `physicsPaintToolboxPopover.test.ts`
- **Commit:** `2e669b68`

**3. [Rule 1 - Bug] Stray tooltip floated bottom-left on popover open**
- **Found during:** Task 1 native smoke check (issue 4)
- **Issue:** A tooltip left visible across the open transition measured the freshly-mounted panel at its unpositioned end-of-`document.body` location (bottom-left of the window) because child layout effects run before the parent panel positions; programmatic/mouse-click focus could also pop a pill anchored at a stale position.
- **Fix:** (a) `useStyledTooltip.onFocus` now takes the focus event and shows only when `relatedTarget` is non-null (keyboard Tab/arrow focus) — programmatic and mouse focus never pop a pill (43.5 smoke fix 4); (b) `interpolationTooltip.hide()` added to `closeToolboxPopover` and the Tools button `onClick` so the relocated tooltip is suppressed across the open/close transition.
- **Files modified:** `PhysicsPaintStyledTooltip.tsx`, `PhysicsPaintStyledTooltip.test.ts`, `PhysicsPaintWorkflowStrip.tsx`
- **Commit:** `ca583fec` (tooltip gate), `2e669b68` (transition suppression wiring)

**4. [Rule 1 - Bug] Flat dark card surface replaced by liquid-glass**
- **Found during:** Task 1 native smoke check (issue 3)
- **Issue:** The popover used the flat `#20262D` card idiom; the user requested the app's Apple liquid-glass language.
- **Fix:** Panel becomes `background: rgba(28,30,34,0.66)`, `border: 1px solid rgba(255,255,255,0.09)`, `border-radius: 12px`, soft shadow with inset top highlight. The backdrop blur/saturate (`blur(20px) saturate(1.8)`) lives ONLY on an empty `.physics-paint-toolbox-popover::before` so the panel itself stays transform/filter-free and the relocated `position:fixed` interpolation tooltip keeps the viewport as its containing block.
- **Files modified:** `physicsPaintStudio.css`
- **Commit:** `048e573a`
- **Note:** This is a user-driven override of the locked UI-SPEC T2 "dark card idiom" line (43.5-UI-SPEC.md:71/191). Geometry locked by the spec (z-index 60, min/max width 232-280px, 240px bound, 16px padding, overflow) is unchanged.

## Key Technical Notes

- **CSS containing-block rule:** `backdrop-filter`/`filter`/`transform` create a containing block for `position:fixed` descendants — the panel MUST stay filter-free; the glass blur sits on an empty `::before` whose own descendants are none.
- **Layout-effect ordering:** child `useLayoutEffect` runs before the parent's, so a tooltip visible during the open commit measures the panel at its unpositioned location — the suppression on open/close eliminates that window.
- **`FocusEvent.relatedTarget`:** non-null for keyboard navigation focus, null for programmatic and mouse-click focus — the discriminator that keeps tooltips reachable by keyboard without stale pills from opening surfaces.
