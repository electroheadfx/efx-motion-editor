# Phase 43.5 — UI Design Contract

> Visual and interaction contract for the ToolCase toolbox popover (Interpolation + Key Spacing consolidation) and the armed Push Right / Push Left directional tools in the EFX Paint/Roto bottom workflow strip. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Primary authority:** `43.5-CONTEXT.md` D-01..D-20, gathered 2026-08-17, and the activated product prompt `SPECS/milestone-v0.9.0-new-phases/phase-43.5-timeline-toolbox-directional-push-prompt.md`. Supporting authority: `.planning/phases/43.4-derived-key-groups-and-scissor-breaks/43.4-UI-SPEC.md` (accepted Rail family presentation, toolbar icon-button idiom, terminology), `.planning/phases/43.3-motion-and-static-group-drag-within-free-space/43.3-UI-SPEC.md` (accepted ghost/clamp/gap-preview/status contract carried verbatim), `.planning/phases/43-hold-loop-clips-filmstrip-capsule/43-UI-SPEC.md` (accepted integrated rail contract), `.planning/phases/43.1-intentional-gap-insert-use-specs-milestone-v0-9-0-new-phases/43.1-CONTEXT.md` (stable-key-owned break marker, product-reason mapper, guarded-tooltip idiom), `.planning/phases/43.2-motion-and-static-group-stabilization-and-action-lifecycle-u/43.2-CONTEXT.md` (mutation-lock gating, neutral deleted-gap cell treatment, frozen-session UAT D-39).

**Extension rule:** this contract adds one toolbar button with an anchored popover, one two-button Push pill group, one hover pre-highlight, and one directional multi-rail drag application on top of the accepted Phase 43/43.3/43.4 rail contract. It changes no strip geometry (161px height, 38px physical row, 3px rail, 12px rail target, 18px pitch), no rail mode colors, no selection orange, no physical-cell semantics, no relocated control's behavior/labels/shortcuts, and no Motion Editor timeline paint. The moved set for a Push contains only Rails; Interpolation/Key Spacing state authority stays in the timeline with the popover as an editing surface only — no second state authority, no persistence change (D-03, D-19).

**Terminology (43.4 D-01 carried, binding):** user-facing copy uses the Rail family — **Motion Rail**, **Static Rail**, **Key Rail**. The locked Push status family (D-15) and all Push tooltip/status copy use Rail vocabulary. The shared-source straddle sentence (D-16) is a Group-domain sentence about source-cycle sharing, not a rail type label — it keeps Group vocabulary verbatim, following the 43.4-07 Scissor Group-domain precedent.

## Geometry and Layering Contract

### Existing geometry is immutable

The workflow strip remains exactly **161px**; the physical-frame row remains **38px**; the visible rail remains exactly **3px** high at `y: 0`; each rail target remains **12px** high at `top: 0`; frame pitch remains **18px/frame**. The ToolCase button, popover, Push pill, hover pre-highlight, ghosts, gap preview, and blocked edge add zero row, track, lane, or height. Nothing covers the rails/cells lane except the established 12px transparent rail targets (D-01, D-05).

### T1 ToolCase button geometry

- Reuses the existing key-toolbar icon-button idiom exactly (`physics-paint-roto-key-icon-button`): 26px high, 18px `ToolCase` icon, 10px compact label `Tools` under/beside the icon per the existing icon-label layout, border `#58616b`, background `#3a424c`, radius 4px. No new button geometry.
- Sits at the Interpolation pill's current position: after the key-utilities group, before Close (D-05). The locked toolbar order is otherwise untouched.
- The Blend-state badge is a **6px filled dot** pinned at the icon's top-right corner (2px insets), paint-only, `aria-hidden`; it changes no button geometry (see Color for paint).
- Guarded tooltip and screen-reader reason span follow the exact Cut/Copy/Delete/Scissor idiom (`buildGuardedActionTooltipCopy`, `aria-describedby`, `PhysicsPaintStyledTooltip`).

### T2 popover geometry (Claude's discretion within D-01..D-03 — locked here)

- **Placement:** the popover body renders **entirely above the workflow strip**: its bottom edge sits exactly **4px above the strip's top edge** (over the canvas's lower region). It never overlaps any part of the 161px strip — the rails, physical cells, action rows, and toolbar (including the spacing-proxy cells) remain fully visible and clickable while it is open (D-01).
- **Horizontal anchoring:** the popover's left edge aligns with the ToolCase button's left edge, clamped to stay 8px inside the timeline viewport on both sides. No caret crosses the strip; anchoring is conveyed by horizontal alignment and the button's `aria-expanded="true"` state.
- **Size:** width content-driven between **232px minimum and 280px maximum** (existing styled-tooltip max-width precedent); height content-driven with `max-height: 240px` and internal vertical scroll only if content ever exceeds it (it does not with the two locked control groups).
- **Surface:** existing dark card idiom — background `#20262D`, 1px border `#58616b`, border-radius 8px, padding 16px, z-index 60 (shared with the styled-tooltip layer; only one of tooltip/popover is visible at a time).
- **Internal layout:** two stacked sections separated by an 8px gap and a 1px `#3F4851` divider:
  1. Section heading `Interpolation` (Micro role, see Typography), then the relocated Blend toggle + mode select rendered with their **existing classes and props verbatim** (`physics-paint-roto-interpolation-controls`, toggle, select).
  2. Section heading `Key Spacing`, then the relocated Set Key Space input + Apply rendered with their **existing classes and props verbatim** (`physics-paint-roto-force-spacing-controls`, input, pill Apply button).
- Relocated controls keep their exact accepted geometry, guards, pending states, disabled states, and focus treatment; the popover adds only the two section headings and the panel chrome. CSS additions are strictly additive.

### T3 Push pill group geometry

- `Push Right` and `Push Left` are two adjacent `physics-paint-roto-key-icon-button` instances (26px high, 18px icons `ArrowRightFromLine` / `ArrowLeftFromLine`, 10px labels) grouped in one small pill in the freed toolbar space beside the ToolCase button (D-05). Group spacing follows the existing toolbar flow gap; no new row, no strip-height change, nothing covers cells or rails.
- The armed (active) state is paint-only on the same button geometry (see Color); armed state never changes size, never moves neighboring controls.

### T4 hover pre-highlight geometry (Claude's discretion within D-13 — locked here)

- Prospective-set brightening is paint-only on each rail's existing 3px geometry — the established per-kind hover brightening (Motion/Static per 43-UI-SPEC; Key Rail `#A7B0B9` per 43.4-UI-SPEC). No translation, no height growth, no ghost, never selection orange.
- **Pivot boundary marker:** a **2px wide × 8px high** vertical tick in `#F2F5F7` at **70% opacity**, positioned in the lower half of the 12px rail band (`y: 4px` to `y: 12px`):
  - Push Right: at the left edge of the anchor rail's first cell (the moved set's frame-0-side edge).
  - Push Left: at the right edge of the anchor rail's last cell (the moved set's capacity-side edge).
- The marker is deliberately distinct from both existing idioms: white endpoint cuts are pure `#F8FAFC`, full rail height, and paired with white boundary-cell borders; the clamp bar is `#FF6B6B` and spans the full 12px band on the ghost. The pivot tick never appears on the fixed side.
- Marker and brightening are `aria-hidden="true"`, `pointer-events: none`, removed on mouse leave, disarm, or when the drag threshold passes (per-rail ghosts replace them).

### T5 push drag preview geometry (43.3/43.4 contract extended to the directional set)

- **Per-rail ghosts:** every rail in the moved set renders a paint-only 3px ghost at the proposed destination with that rail's exact geometry, in the rail's kind base color at **55% opacity** (Motion `#8B5CF6`, Static `#06B6D4`, Key Rail `#8A939C`). Ghosts never show selection orange, white endpoint cuts, lifecycle dots, or hover brightening. Originals stay fully visible at 100% opacity until commit (D-11).
- **Gap preview:** the interval the push would open (between the fixed side and the moved set's near edge) previews as ordinary empty cells — existing class `roto-fill-empty` (border `#3D454D`, background `#4D535A`), byte-identical to the 43.2/43.3/43.4 gap treatment. No distinct push-gap visual (D-12 preview obligation carried).
- **Blocked edge on clamp:** when the moved set is clamped — Push Left at frame 0, Push Right at capacity/parent end (D-14) — a **2px wide × 12px high** `#FF6B6B` vertical bar paints on the moved set's blocked outermost ghost edge (left edge of the leftmost ghost for Push Left; right edge of the rightmost ghost for Push Right). The bar is the sole blocked signal; ghosts remain kind-colored at 55% opacity.
- All preview paint is `aria-hidden="true"`, `pointer-events: none`, and removed on commit, cancel, or rejection.

### Layer order

Unchanged from 43/43.3/43.4-UI-SPEC: physical cells 0; existing cell overlays 1–5; transparent rail targets 6; visible 3px rail paint 7 (`pointer-events: none`); hover brightening and pivot marker paint on layer 7; ghosts and blocked edge between 7 and 8; rail focus ring 8; styled tooltip and toolbox popover 60. Popover never shares the strip's containing block.

### State precedence

Highest visible state wins (accepted rail layer), then preview layers:

1. Keyboard focus ring `#F2F5F7` (accepted rail only)
2. Selected `#F59E0B` (accepted rail only)
3. Hover pre-highlight brightened base (prospective set only, while armed and hovering a valid anchor)
4. Normal base color (Motion purple / Static cyan / Key Rail gray)
5. Ghost kind paint at 55% opacity + blocked-edge bar on the ghost layer (drag only)
6. Gap preview empty-cell fill (cell layer, beneath all rail paint)

The accepted rail never inherits hover, ghost, clamp, pivot, or gap state. Push hover pre-highlight and ordinary rail hover share the exact brightening treatment; they differ only in set scope (prospective set vs single rail). State changes alter paint only, never geometry.

### Responsive contract at 1280×720 minimum

Unchanged from 43-UI-SPEC: existing three-column Studio layout, 161px strip, shared horizontal scroller. The toolbar row keeps every control readable and unclipped at 1280×720 (prompt acceptance step 13): the ToolCase button plus Push pill occupy only the space freed by the removed Interpolation/Key Spacing pills. The popover clamps horizontally inside the viewport and extends upward over the canvas; it never forces strip overflow. Ghosts, blocked edge, pivot marker, and gap preview clip at the shared timeline viewport exactly like accepted rails.

## Interaction Contract

### T1/T2 popover behavior (D-01, D-02)

- Clicking the ToolCase button toggles the popover. The popover is non-modal: the Studio timeline, spacing proxies, rails, and canvas stay fully interactive while it is open.
- Dismiss on outside pointerdown and Escape; no focus trap, no backdrop. Focus is never moved into the popover automatically; popover controls follow the ToolCase button in natural Tab order.
- Cmd+Z, Delete/Backspace, and all timeline shortcuts keep their normal routing while the popover is open (D-02).
- The popover only edits timeline-owned Interpolation/Key Spacing state through the existing callbacks — no duplicated state, no local mirror, no persistence change (D-03). Closing the popover changes nothing by itself.
- While a physical mutation is in flight, relocated controls render their existing pending/disabled idioms unchanged.

### T3 armed-tool lifecycle (D-06, D-09, D-18, D-19, D-20)

- Clicking `Push Right` or `Push Left` arms the tool: button shows the armed tint with `aria-pressed="true"`; the cursor over the strip becomes directional — `e-resize` for Push Right, `w-resize` for Push Left; over an invalid anchor (empty/gap frame, or straddled anchor) the cursor is `not-allowed` and the guarded tooltip carries the mapped reason.
- The tool stays armed for further pushes until: **Escape**, re-click of the armed button, arming the other Push tool, activating any other toolbar action (including Select All — D-20), or **entering a mutation-locked state** (D-18: no armed state outlives a lock transition). Arming the other Push tool switches direction in one click.
- While armed, a plain click under the 4px threshold performs normal frame cursor navigation and keeps the tool armed (D-09). Delete/Backspace and other shortcuts keep normal behavior and disarm nothing.
- Armed state is session-only, never persisted: save/reopen always starts disarmed; nothing about the armed tool enters the document, history, or session restore (D-19).
- While playback/busy locks mutations, both Push buttons are disabled with the mapped lock reason (D-18).

### Anchor resolution and hover preflight (D-07, D-13, D-17)

- Valid anchor = any non-empty physical cell (real key, generated frame inside a Group, linked occurrence) or rail band, resolving to the containing Motion Rail / Static Rail / Key Rail. A frame inside a Group targets the complete Group; the tool never creates an implicit cut.
- While armed, hovering a valid anchor pre-highlights the prospective moved set (per-kind hover brightening on every set rail + pivot tick at the set's boundary edge); the fixed side shows nothing. Hovering an empty/gap frame shows `not-allowed` and no highlight.
- The shared-source straddle guard is preflight at hover: a straddled anchor shows `not-allowed` and the guarded tooltip carries the locked straddle sentence; the drag never starts (D-17).
- The pre-highlight clears on mouse leave and on disarm, and is replaced by per-rail ghosts once the drag passes the threshold. No status-line change on hover.

### Push drag session (D-08, D-11, D-12, D-14; 43.3/43.4 carried verbatim)

| Input | Result |
|-------|--------|
| Pointer down on a valid anchor while armed | begin tracking; no paint change, no navigation, no drag session yet |
| Pointer moves ≤ 4px and releases | plain click: normal cursor navigation; tool stays armed |
| Pointer moves > 4px horizontally in the armed direction | drag session starts; pointer capture; cursor `grabbing`; every moved-set rail ghosts at the clamped proposed destination; would-open gap previews as `roto-fill-empty` cells; status line begins the live readout |
| Pointer moves during session | ghosts and gap preview recompute the clamped destination; blocked-edge bar appears/disappears with clamp state; live readout updates (`Push Right +{D} — frames {A}–{B} → {A′}–{B′}, gap …`) |
| Escape during session | cancel the drag and disarm the tool: zero state change, zero history, all preview paint removed; selection and focus unchanged |
| Release (drop) | commit request at the currently shown (possibly clamped) position — the preview is the commit (D-14) |
| Release with zero delta (under threshold or clamp at current position) | nothing publishes; no status, no history entry (D-15) |
| Release with zero valid movement in the armed direction | rejection: preview removed, nothing mutates, status publishes `No empty space in that direction.` |

- Clamp contract (D-14): Push Left clamps at frame 0; Push Right clamps at capacity/parent end. Dropping while clamped commits at the clamp. Rejection only when zero valid movement exists.
- Push never pushes, pulls, reorders, stretches, splits, or retimes anything outside the moved set; the fixed side remains byte-position fixed. Relative timing, internal spacing, Action provenance, synchronization status, source sharing, and Group membership inside the moved set remain unchanged. Neither tool toggles Interpolation automatically (prompt-locked).
- Opened intervals record persistent Phase 43.1 stable-key-owned interpolation breaks (complete-collection replacement; existing breaks reused, never duplicated; a later reverse push that closes the gap normalizes the collection). Interpolation On never generates across the gap; Off/On restores it exactly.
- After an accepted push: the anchor rail stays selected, the physical cursor stays where it is, no automatic navigation occurs, and the canvas reconciles from the accepted document only when the current frame's content changed (43.3 D-17 carried).
- Ghosts, gap preview, blocked edge, and the live readout are presentation-only; nothing presents as moved before exact correlated parent acknowledgement. The complete movement — records, Loop Clips, breaks, selection, cursor — is one atomic parent-acknowledged history command with one Undo/Redo.
- Direct Group/Key Rail drag (43.3/43.4) remains local and never pushes neighbors; the two gestures keep separate anchors and contracts. The Push drag originates only from the armed-tool state; ordinary rail drag remains disarmed-only.

### Keyboard and focus

- ToolCase and Push buttons are ordinary toolbar tab stops with the existing 2px `#F2F5F7` focus ring.
- **Escape** closes the popover when open; disarms the armed Push tool when no drag is active; cancels the active push drag and disarms when a drag is in progress. One Escape handles at most one layer.
- No keyboard shortcut arms the Push tools this phase (D-10; 43.4 Scissor precedent). Arrow-key physical-frame navigation and every existing shortcut remain unchanged.
- Popover controls keep their existing keyboard behavior verbatim (toggle activation, select interaction, input editing, Apply).

### Busy and rejected-operation behavior

- During controller preparation/commit, accepted rails remain visible in place with the existing `aria-busy`/busy-opacity idioms; Push buttons expose `aria-disabled="true"` with the current controller reason; a second push session cannot start while a physical mutation is in flight.
- No optimistic movement, gap, break, or status change. Update only from accepted canonical authority state.
- On rejection, preserve prior geometry, selection, focus, cursor, and armed state; announce the reason through the existing status channel.

### Accessibility

- ToolCase button: accessible name carries live Interpolation state (D-04); `aria-expanded`/`aria-controls` wire the popover; badge is `aria-hidden`.
- Popover: `role="dialog"`, `aria-modal="false"`, `aria-label="Timeline tools"`; section headings are plain text (no heading-role requirement); relocated controls keep their existing accessible names and `aria-describedby` reason spans verbatim.
- Push buttons: `aria-pressed` reflects armed state; guarded tooltips plus screen-reader reason spans follow the Cut/Copy/Delete/Scissor idiom.
- Status updates publish through the existing `aria-live="polite"` status line; rejections additionally use `role="alert"`. The live drag readout updates at pointer-move cadence on the same polite channel — it never creates live-region churn on rails or cells.
- All preview paint (pre-highlight, pivot tick, ghosts, blocked edge, gap preview, badge) is `aria-hidden="true"` with `pointer-events: none`.
- The 12px rail target and 26px toolbar buttons are the established compact-editor exceptions; tooltips, keyboard access, and the toolbar provide equivalent larger action access.
- Reduced motion: popover open/close, badge, arming, pre-highlight, ghosts, clamp, and gap-preview changes are immediate paint changes with no slide, tween, spring, shimmer, or pulse. Under `prefers-reduced-motion: reduce`, no transition is added to any touched element.
- No state relies on color alone (see Non-color cues).
