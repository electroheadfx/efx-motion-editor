# Phase 52.3: Paint content export — per-frame compositor enumeration - Context

**Gathered:** 2026-09-19
**Status:** Ready for planning

<domain>
## Phase Boundary

Any project containing paint exports its painted frames — PNG sequence, paint-only and mixed projects alike, both canvas orientations. Exporting a paint-only project renders every frame of the export range through the compositor; the "No frames to export (timeline is empty)" refusal becomes unreachable for paint content.

Diagnosis is complete (quick 260919-azh, verdict NEVER-WIRED): the fx overlay RENDER leg already works — `exportRenderer.ts:300-362` draws physic-paint layers via the CMP-01 `getFlattenedFrame` seam for any global frame inside the sequence span. The break is ENUMERATION: `frameMap.ts:16-47` materializes `FrameEntry` only from `kind === 'content'` keyPhotos, and the tail pad (`:41-45`) can only replicate an existing content entry, so a paint-only project yields zero entries and `exportEngine.ts:152-156` hard-errors. This phase designs and wires the missing paint enumeration branch — it is not a read repair (all runtime reads were probed green in-test).

**In scope (from ROADMAP.md):** designed answers to the four design questions (decided below); per-frame compositor enumeration for paint content in the export path; the canvas-clear fix; the 2 parked `it.todo` contracts and the RED discrimination matrix turned green; native UAT (§7-pair 31 keys full range; fresh paint-only project in EACH orientation; mixed project; exported frames visually match the on-canvas composite).

**Out of scope (from ROADMAP.md):** resolution-policy changes — the format-free architecture from 260918-ovi stands as shipped (1920 long-edge clamp included; raising it is a v1.2.0 measured decision); fx-sequence work beyond Q4; new export pipelines (ProRes/H.264); platform safe-zone overlays. Preview rendering is unchanged (the canvas-clear fix is export-path only).

</domain>

<decisions>
## Implementation Decisions

### Paint FrameEntry ownership (Q1)
- **D-01:** Paint-carrying frames are materialized as an **explicit discriminated FrameEntry variant** (e.g. `kind: 'paint'`) carrying the owning fx `sequenceId` and the paint layer identity — **no `keyPhotoId`/`imageId`**. Fail-closed by type: TypeScript forces every FrameEntry consumer to confront the variant rather than tolerating sentinel ids. This keeps the parked Case C contract (`frameMap` length 5 for a 5-key paint-only project) reinstatable as written. — **Reversibility:** costly — the variant enters the shared `FrameEntry` type consumed by frameMap, exportRenderer, preview, and test harnesses; removing it later means touching every discriminated consumer the compiler surfaces.
- **D-02:** Per frame, **content wins**: a paint-kind entry exists only where no content entry covers that frame. Mixed frames stay ordinary content entries; paint draws via the fx overlay leg exactly as it does today (Control B stays green). The content branch (`exportRenderer.ts:148-298`) renders nothing for a paint-kind entry — `hasContentEntry` semantics are preserved, not broadened.
- **D-03:** When paint extends beyond the content clip's span in a mixed project, the frames beneath the paint keep the **clip's last content frame** — today's tail-pad hold behavior (pinned green by Control B) is preserved as the designed behavior, not an accident.

### N derivation + clamp owner (Q2)
- **D-04:** Export length N follows the **existing `getTimelineRequiredFrameCount` law** (`frameMap.ts:244-259`): `N = max(content end, every visible sequence's authored end, seqStart + loop-aware paint extent)`. Paint keys are **never clipped** by a shorter authored fx span; a longer authored span yields trailing fond-blank frames. No new clamp semantics — the user owns the span (260918-o0n), paint owns its extent, export takes the union.
- **D-05:** WYSIWYG invariant: export length always equals what the timeline shows (`totalFrames` already reads the same law). Enumeration spans `[0, N)` with fond-blank frames where neither content nor paint exists, and **frameMap stays dense** over that range so positional indexing (`renderGlobalFrame` reads `fm[frameIndex]`, `exportRenderer.ts:138`) remains valid.

### Canvas clear lifecycle (Q3)
- **D-06:** A **single top-level canvas clear** is added at the start of `renderGlobalFrame`, gated on `!hasContentEntry` (identity-transform `clearRect`, same style as the GL transition path at `exportRenderer.ts:206`). Content frames keep byte-identical behavior (the content branch's own `clearCanvas=true` renders are untouched, including both cross-dissolve sub-paths). Paint-kind and gap frames start from clean pixels — no uncleared-canvas ghosts (Q3 regression pin).
- **D-07:** Fond/paper arrives via the flattened raster wherever an fx span covers the frame (the internal compositor owns the fond — v1.0 rendering law). True gap frames (inside N but outside every content/fx span) export **transparent**. Scope is the export path only; preview rendering is unchanged.

### selectedSequenceOnly for fx actives (Q4)
- **D-08:** With an fx sequence active, 'Selected sequence only' **filters by the fx sequence id** — the existing `fm.filter(e => e.sequenceId === activeId)` predicate (`exportEngine.ts:145-150`) now matches that sequence's paint-kind entries. The export contains that sequence's paint over clean frames (D-06 clear), no content; other fx overlays in range still ride — the same "overlays always ride" behavior content-selected exports have today. — **Reversibility:** costly — this redefines a user-visible export semantic and re-pins the Case E characterization test; reverting means restoring the hard error and re-amending the test.
- **D-09:** The `FormatSelector.tsx:88-91` info line stops computing the frame count from `activeSeq.keyPhotos.reduce(...)` (always 0 for fx) and instead reflects the filtered entry count, so the UI no longer lies for fx actives.
- **D-10:** The 'No frames to export (timeline is empty)' refusal stays reachable only for genuinely empty timelines (no content AND no paint). It is unreachable for fx-with-paint. Case E is re-pinned from the error characterization to the new filter behavior.

<code_context>
## Existing Code Insights

### Reusable Assets
- `getTimelineRequiredFrameCount` (`frameMap.ts:244-259`): already computes the correct N including paint extents — the enumeration branch should reuse it unchanged (D-04/D-05).
- `getPhysicPaintRotoDisplayEndFrame` (`frameMap.ts:227-242`): loop-aware paint extent read, proven correct by in-test probes (5 records / end 5 with a registered reference-only document).
- `renderGlobalFrame`'s null-entry tolerance (`exportRenderer.ts:138-140`): the `hasContentEntry = !!seq && seq.kind !== 'fx'` shape is the model for how paint-kind entries flow through without content rendering.
- The GL transition's identity-transform `clearRect` (`exportRenderer.ts:206`): the style precedent for the D-06 top-level clear.
- `exportEngine.paintEnumeration.test.ts`: the ready-made harness (mocks verbatim except `./frameMap` and `../stores/sequenceStore`) — reinstate parked contracts there first.

### Established Patterns
- Discriminated unions + fail-closed parsing are this repo's house style (e.g. `EfxPaintBackgroundFrameResolution` content/missing union, Phase 48) — D-01 follows it deliberately.
- `frameMap` entries are dense and positionally indexed; `totalFrames` (frameMap.ts:50-52) already separates "how many frames exist" from "how many entries carry content".
- Cross-dissolve zones only ever span consecutive CONTENT sequences (`crossDissolveOverlaps`, frameMap.ts:376-417) — paint-kind entries never participate, so their internal clear semantics stay untouched.
- The fx overlay leg self-computes `fxLocalFrame = globalFrame - inFrame` — paint entries do not need to carry paint-local frame info for rendering.

### Integration Points
- `frameMap` computed: the single enumeration seam — new paint branch lands here (feeding both export and `activeSequenceFrames`/preview, whose consumers must tolerate the variant).
- `exportEngine.startExport`: total/frame iteration and the selectedSequenceOnly predicate read `fm` — no structural change needed beyond the entries now matching fx ids (D-08).
- `renderGlobalFrame` top: the D-06 clear insertion point, before the content branch.
- `FormatSelector.tsx:88-91`: info-line count source changes per D-09.

</code_context>
