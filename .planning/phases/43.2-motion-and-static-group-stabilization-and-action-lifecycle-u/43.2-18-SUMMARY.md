## Decisions Made

- The store registry remains deliberately narrow: callers acquire, validate, transfer, or release tokens, while the existing physical document remains the sole accepted-state authority.
- Recovery transfer preserves the lease generation and atomically changes only the owner. The old exclusive token then fails exact validation while the recovery token remains valid.
- Runtime payload parsing requires a lease token even though the TypeScript field remains optional for construction-only legacy fixtures. This preserves strict production behavior without broad unrelated fixture churn.
- Accepted coordinator output is published before acknowledgement, but ownership is retained until Studio completes selection and canvas aftermath in the same result route.
- Durable journal discovery remains the responsibility of the planned Action recovery integration; this plan provides the store reconstruction and gating interface it will invoke before exposing mutations.
