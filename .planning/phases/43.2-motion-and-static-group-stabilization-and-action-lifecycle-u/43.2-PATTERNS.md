## Scope Notes

- Preserve internal `loopClip`, `scriptId`, `progressive`, and `static` identifiers where they are transport or persistence details. Replace only user-facing terminology.
- The existing `PhysicPaintRotoLoopClip` record remains the canonical logical Group authority. Do not create a second Group, fragment, gap, selection, or cache store.
- The exact additive field names remain a planning decision. Research names such as `syncState`, `provenanceState`, `phaseOrigin`, `originalEndExclusive`, `visibleRanges`, and `frameOverrides` are recommendations, not locked schema.
- The proposed `physicsPaintRotoGroupLifecycle.ts` is the only recommended new source module. It must be pure and authority-free.
- The Motion Editor implementation is out of scope. Only its regression tests may be touched to prove no visual or interaction change.

- project context ID;
- layer ID;
- launch operation ID;
- expected physical revision;
- expected Action revision;
- accepted command ledger provenance for replay;
- Rust active project authority token;
- main-window guard where the existing command requires it.

**Sources:** `physicPaintBridge.ts:876-943`, `script_library.rs:85-120`, `commands/script_library.rs:7-10`.

### Error handling

- Pure model/resolver functions throw or return typed failures before mutation.
- Coordinators map internal failures to one canonical product reason and retain detailed diagnostics for logging.
- Tauri IPC uses `Result<T>` through `safeInvoke` (`ipc.ts:7-20`).
- Rust maps filesystem errors with operation-specific context and cleans temporary paths.
- Stale rejection preserves accepted state and keeps destructive/restorative dialogs open.
