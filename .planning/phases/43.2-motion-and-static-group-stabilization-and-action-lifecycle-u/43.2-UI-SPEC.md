# Phase 43.2 — UI Design Contract

> Canonical visual, interaction, accessibility, copy, and state contract for Motion Groups, Static Groups, and their Action lifecycle inside EFX Paint/Roto.

**Primary authority:** `43.2-CONTEXT.md` D-01..D-39 and the activated Phase 43.2 product prompt. Supporting authority: the approved Phase 43 integrated-rail contract, accepted Phase 43.1 persistent-gap behavior, and the existing Studio Actions/Scripts, rail, tooltip, and floating-dialog implementations.

**Product boundary:** this phase changes EFX Paint/Roto terminology and Group/Action lifecycle surfaces only. The Motion Editor timeline remains byte-for-byte unchanged in visual and interaction scope. Existing saved documents receive no nomenclature-only migration.

**Supersession rule:** every EFX Paint/Roto product string introduced before this phase that says `Loop Clip`, `Loop Rail`, `Progressive`, `Static/Hold`, `Script`, `Scripts`, `Save Script`, `Play Script`, or `Edit Loop Clip` is replaced on the affected user-facing surface by the locked Group/Action vocabulary below. Internal identifiers and persisted wire values may remain unchanged.

## Geometry and Layering Contract

### Immutable workflow geometry

The existing workflow strip remains exactly **161px** high. The physical-frame row remains **38px**, the action row **34px**, and the Group Rail remains overlaid inside the top edge with zero added height.

| Existing band | Height | Phase 43.2 rule |
|---------------|--------|-----------------|
| Workflow header | 46px | unchanged |
| Timeline top border | 1px | unchanged |
| Ruler | 28px | unchanged |
| Physical-frame row | 38px | Group Rail, fragments, dots, and linked halos paint within this height |
| Physical-cell action row | 34px | unchanged; visible Delete remains in its existing position |
| Horizontal scrollbar | 14px | unchanged |

No new row, lane, fragment band, status band, badge row, or vertical scrollbar is permitted.

### G1 Group Rail and fragment geometry

- Retain the existing **3px visible rail** and **12px transparent pointer/focus target**.
- Retain the existing frame pitch and canonical half-open range projection.
- A contiguous Group renders one visible rail range.
- A middle Delete Frame renders exactly two visible ranges—left and right—separated by one exact physical-frame gap. Both ranges reference the same stable logical Group identity.
- Additional accepted Delete Frame operations may produce more ranges. Each range is explicit canonical fragment geometry; there is no invisible per-frame exclusion mask.
- Deleting the first or final occurrence shortens the outer boundary rather than leaving a zero-width fragment.
- Every actual fragment start/end receives the existing 2px white endpoint cut. A viewport-clipped edge receives no false cut.
- Every visible fragment contains one passive synchronization dot centered horizontally and vertically on the visible 3px line. The dot is paint-only and `pointer-events: none`.
- Synchronization dot visible diameter is **6px**, with a 1px `#20262D` outline so it remains legible over Motion, Static, selected, and linked-highlight treatments.
- When a fragment is narrower than 12px, center the dot on the fragment's 12px minimum target without changing canonical range width.
- A deleted-frame gap contains no rail paint, dot, hidden target, tooltip target, or Group-owned frame target. The adjacent fragments remain independently reachable.
- Selecting any fragment applies selected treatment to every visible fragment of that logical Group. The Group appears once in Actions navigation and operation scope.
- Each visible fragment remains one keyboard target so independently scrolled fragments stay discoverable. Every target activates the same logical Group; fragment count is context, not identity.

### Dot and unresolved precedence

- Synchronized: 6px `#34D399` green dot.
- Modified: 6px `#FB923C` orange dot.
- Action detached: 6px `#9CA3AF` neutral gray dot.
- Source Action unavailable: 6px `#6B7280` dark neutral dot with a 1px `#D1D5DB` ring.
- Unresolved/error remains the higher-priority red rail state from Phase 43. In that state, omit the synchronization dot from paint and expose the unresolved reason first in tooltip/accessibility copy. Do not misrepresent unresolved output as synchronized, modified, or merely detached.
- The dot remains visible while Interpolation is Off whenever the Group is otherwise resolvable.
- Dot changes are immediate accepted-state paint changes; no pulse, scale, bounce, or transition.

### Action-linked halo geometry

Selecting an Action highlights all linked logical Groups without selecting them or moving the cursor.

- Motion fragment: retain Motion purple `#8B5CF6`; add a 1px outer halo `#C4B5FD` and a restrained `0 0 5px rgba(196,181,253,.55)` glow around the 12px target.
- Static fragment: retain Static cyan `#06B6D4`; add a 1px outer halo `#67E8F9` and `0 0 5px rgba(103,232,249,.50)` glow.
- Every fragment of every linked Group receives the halo.
- The halo adds no geometry and never changes rail height or target width.
- The actually selected Group remains orange `#F59E0B`; selected orange has precedence over linked halo paint. Other linked Groups keep mode color plus halo.
- Action-linked highlighting is passive. It adds no pointer target, selection state, keyboard route, `aria-selected`, or operation scope.

### Dialog geometry

#### G4 Selection-scoped deletion and sole-occurrence warning

- Routine Delete Frame and Delete Group activation mounts no scope-choice overlay, card, scrim, or action list. Selection is the visible scope authority.
- Individual Group-owned physical-frame selection invokes Delete Frame directly; Group Rail selection invokes Delete Group directly.
- Only Delete Frame on the sole remaining occurrence mounts a focused Studio-local destructive warning above the workflow strip and canvas at `z-index: 72`.
- The sole-occurrence warning uses the existing dark dialog family, one centered card no wider than **440px**, `max-width: calc(100vw - 32px)`, 16px padding, 1px border, 10px radius, and the restrained `rgba(0,0,0,.24)` scrim.
- The warning presents one destructive `Delete Frame` action plus `Cancel`, while explicitly stating that the sole occurrence causes whole-Group removal; do not reintroduce Delete Group / Delete Frame scope choices or add a second confirmation.

#### G3a Regenerate confirmation

- Reuse the existing **700px** draggable Edit Group surface and its header/footer. Do not mount a second overlay above it.
- Replace the editable body with one structured confirmation view while confirmation is active.
- Facts use a two-column definition layout: 104px labels and `minmax(0, 1fr)` values.
- Shared affected Group list is placement ordered, max-height 160px, vertically scrollable, never horizontally scrollable.
- Footer actions: `Keep local changes` then the exact Regenerate CTA.

#### G5 Action deletion dialog

- Reuse the existing Actions-panel confirmation layer, expanded to **min(420px, available panel width)** and max-height `calc(100% - 52px)`.
- Referenced Action dialog uses three vertically stacked action cards plus Cancel; it may scroll vertically for many ranges.
- Unreferenced Action deletion retains the existing compact two-action confirmation, with Action terminology.

### Responsive contract at 1280×720 minimum

- Preserve the three-column Studio layout and 161px strip.
- Right sidebar retains its existing width range. Facts use a fixed 88px label column and `minmax(0, 1fr)` values.
- Long Group/Action names ellipsize in the inspector and wrap in dialogs/tooltips; full values remain available to assistive technology.
- Action-dialog and sole-occurrence warning consequence copy wraps; controls never shrink below 30px height.
- Dialog cards clamp to 16px viewport margins and keep their header and footer visible.
- Fragment rails remain in the shared horizontal scroller and never wrap or stack.

## Interaction Contract

### Group and Action selection

- Plain click on any Group fragment selects the complete stable logical Group, paints every fragment orange, clears incompatible physical selection, and updates the Actions inspector.
- Fragment selection does not create fragment-level operation identity.
- Selecting a Group reveals and selects its Source Action when available. It does not change Action content or Group output.
- Detached or unavailable Groups never select an unrelated Action. The Actions panel remains on the Group inspector and states the provenance condition.
- Selecting an Action highlights every linked Group fragment with the mode-colored halo and initializes `Linked Groups — {current} of {total}` without moving the physical cursor.
- If a linked Group is already selected, preserve it as current. Otherwise select as navigation-current the first linked Group starting at or after the physical cursor; if none exists, use the last Group before the cursor. This initialization does not apply orange Group selection and does not move the cursor.
- Orange remains exclusive to the actually selected Group and operation scope. Action-linked halo is not selection.
- A fragmented Group appears once in the linked count and list.

### Linked navigation

- Logical Groups are ordered by current left-to-right placement; tie-breaking uses stable Group identity only internally.
- `Previous` selects the prior logical Group and moves the physical cursor to that Group's first visible/start frame.
- `Next` selects the next logical Group and moves the cursor to its first visible/start frame.
- Navigation stops at the first and last Group. Controls disable at their respective ends and never wrap.
- With exactly one linked Group, show one `Go to Group` control instead of disabled Previous/Next.
- Navigation selects the target Group, paints every fragment orange, preserves the active Action selection, and reconciles the canvas through the existing accepted current-frame route.
- Navigation never mutates Group placement, fragments, Action provenance, or history.

### Exact-frame local Paint

- Painting or erasing on a Group-owned physical frame targets exactly that physical occurrence within the selected logical Group.
- If source or cache authority is shared, copy-on-write completes before the paint mutation becomes accepted.
- Other repeats in the same Group and every other Group remain byte-equivalent and visually unchanged.
- The Group Rail stays continuous for paint-only changes; no fragment, split, notch, frame marker, or per-frame modified badge is added.
- After exact accepted settlement, every Group fragment dot changes to Modified orange and the inspector/status copy updates.
- Painting into a Delete Frame gap removes that exact locally owned gap, fills the frame, and joins adjacent fragments visually when they become contiguous. The Group remains Modified.
- The persisted Action is never changed by local Paint.
- Group identity, type, placement, repeat, timing, Motion settings, color override, provenance, and Regenerate capability remain unchanged.
- Paint, copy-on-write, gap removal/reunion, canvas reconciliation, synchronization state, and history are one accepted transaction. Rejection/cancellation changes nothing.

### Delete activation and target classification

- Delete, Backspace, and the visible Delete action route through one activation-time target classifier.
- If the complete logical Group is selected through its Group Rail, invoke Delete Group directly for that stable Group identity, regardless of cursor position or `placementStart`.
- Otherwise, if one individual physical frame owned by a Motion Group or Static Group is selected, invoke Delete Frame directly for that exact occurrence.
- If the selection is an ordinary real key, preserve the existing ordinary-key deletion flow exactly.
- If it is a deleted Group gap, linked unresolved position, generated-only frame, ambiguous selection, or otherwise non-deletable target, use the canonical mapped reason and do not open a misleading scope-choice dialog.
- Activation-time classification does not optimistically mutate selection, cursor, canvas, Group, Action, gap, cache, or history.

### G4 direct deletion and sole-occurrence warning behavior

- Delete Group commits the complete logical Group removal atomically and never deletes its Action.
- Delete Frame removes one exact occurrence. Middle deletion creates explicit left/right fragments with one persistent gap; edge deletion shortens the range.
- Delete Frame on the sole remaining occurrence opens only the focused warning. Initial focus is `Cancel`; Tab and Shift+Tab remain inside; Escape cancels; Enter activates only the focused action.
- After accepted Delete Frame, keep the physical cursor at the deleted frame, show an empty canvas result immediately, keep the Group selected through its remaining fragments, and return focus to the visible Delete action or current physical-cell control.
- After accepted Delete Group, keep the physical cursor at its frame, clear the deleted Group selection, retain any still-valid Action selection without linked Group highlight for the removed Group, and restore focus to the visible Delete action.
- Warning cancellation returns focus to the invoking Delete control and changes nothing.
- Stale rejection keeps accepted state immediately retryable, restores focus to the invoking control, and announces the mapped reason through the existing `role="alert"` channel; it does not mount or preserve a routine Delete scope modal.

### Regenerate lifecycle

- `Regenerate` exists only in Edit Group.
- It is enabled only when the selected Group is Modified and its attached Action is available.
- Activation enters G3a within the same floating dialog. No mutation occurs during summary preparation.
- Summary preparation uses a frozen accepted snapshot and revalidates before commit.
- Regenerate restores locally painted frames, deleted frames, original complete range, source-cycle phase, fragment reunion, locally owned Delete Frame gaps, source/cache authority, and Synchronized status.
- Stable Group identity and placement remain unchanged.
- If accepted sharing requires several synchronized Groups to update, every affected logical Group is disclosed before commit and the CTA states the exact count.
- On success, the initiating Group remains selected, its Action remains selected, and the physical cursor remains on its current frame. The canvas reconciles immediately, including when the current frame was a restored gap.
- Shared affected Groups do not replace the initiating selection.
- One Undo restores the complete pre-Regenerate Modified snapshot; one Redo reapplies the regenerated Synchronized snapshot.
- `Keep local changes` returns to Edit Group without mutation.
- Detached, unavailable, Synchronized, unresolved, stale, or ambiguous-sharing states never perform a no-op Regenerate.

### Action deletion lifecycle

- Unreferenced Action deletion retains the existing simple Action-library flow.
- Referenced Action deletion opens G5 before any library or physical-document mutation.
- `Keep Groups` deletes only the Action and detaches all referencing Groups atomically. All Group fragments, keys, timing, placement, repeat, cache, rendered output, occupied ranges, selection, cursor, playback, preview, and export result remain unchanged. Every affected fragment dot becomes detached neutral gray and Regenerate disables.
- `Delete Action and Groups` removes the Action and all referencing logical Groups, fragments, uniquely owned source/cache/gap authority, and linked highlights atomically. Shared data referenced outside the deleted set survives.
- Deleting a Group never deletes an Action.
- Cancellation or stale rejection changes no Actions, Groups, keys, gaps, caches, selection, cursor, or history.

## Accessibility Contract

### Roles and names

- Group Rail collection: `role="group"`, `aria-label="Groups"`; absent when there are no Groups.
- Fragment target: native button preferred.
- Fragment accessible name exact form:
  - contiguous: `{displayName}. {Group Type}. {Cycle math}. Effective {E} frames. {synchronization status}`
  - fragmented: `{displayName}. Fragment {i} of {n}, frames {start} through {end}. {Group Type}. {synchronization status}`
- Every fragment target for the selected logical Group uses `aria-pressed="true"`; every other fragment uses `false`.
- Passive synchronization dot is `aria-hidden="true"`; its meaning is included in the target name and tooltip.
- Action-linked highlight does not set `aria-selected`. Each linked fragment may append `Linked to selected Action {actionName}.` to its accessible description.
- Actions inspector: `role="region"`, `aria-label="Selected Group — {displayName}"`.
- Linked navigation: `role="group"`, `aria-label="Linked Groups for {actionName}"`.
- Routine selection-scoped Delete mounts no dialog. The sole-occurrence warning uses `role="dialog"`, `aria-modal="true"`, is labelled by `Delete the only frame in “{groupName}”?`, and is described by the exact whole-Group consequence warning.
- Regenerate confirmation remains within the existing `role="dialog"` Edit Group surface and updates its labelled heading.
- Referenced Action deletion: `role="dialog"`, `aria-modal="true"`, labelled by Action name and described by affected count.
- Accepted status uses the existing `aria-live="polite"`; rejection uses `role="alert"`.

### Keyboard

- Tab order follows visible fragment placement, then existing strip controls. Fragments of one Group remain separate tab stops but expose one logical identity.
- Enter on a focused fragment opens Edit Group through the existing exact-once route.
- Space selects the complete logical Group without moving the cursor.
- Escape hides the tooltip; it does not clear selection.
- Delete/Backspace from a Group-owned frame opens G4 exactly once.
- Previous/Next are ordinary buttons; Left/Right arrows are not globally captured by the navigation group.
- Actions list retains existing Enter/Space row activation and inline rename keyboard behavior, with Action terminology.

### Focus and target size

- Retain the 12px precision timeline target exception and 2px visible focus ring.
- Synchronization dot is never a target.
- Dialog choice cards and footer controls are at least 34px high.
- Actions toolbar controls remain 30px high with visible focus treatment and discoverable disabled reasons.

### Reduced motion

- Dot, fragment, synchronization, selected, and linked-highlight changes are immediate paint changes.
- No pulse, blink, spring, slide, width tween, fragment reunion animation, or deletion collapse animation.
- Existing tooltip delay remains unchanged.
- Under `prefers-reduced-motion: reduce`, disable newly touched 120ms color/background transitions without changing controller timing.

### Contrast and comprehension

- Status never relies on dot color alone.
- Modified copy explicitly names Regenerate.
- Detached and unavailable are distinct states with distinct copy.
- Fragment gaps are real empty geometry and explicit tooltip/inspector facts.
- Destructive choices disclose scope and retained/deleted Action behavior before commit.
- Linked navigation states current/total and disables boundaries without wrap.
