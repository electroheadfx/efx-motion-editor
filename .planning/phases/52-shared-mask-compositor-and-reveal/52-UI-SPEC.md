## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#0F0F0F` | Studio root background (`--color-bg-root`) |
| Secondary (30%) | `#1A1A1A` | Cards, panels, sidebar, canvas area (`--color-bg-card` / `--color-bg-right`) |
| Accent (10%) | `#2D5BE3` | Primary interactive elements only (see reserved list) |
| Destructive | `#FF4444` / `#FF6666` | Destructive actions and fail-closed error text only |

Accent reserved for: active/selected control states, primary CTA buttons, focus/active fills, and the `paint-style-btn-active` state. **Never** for rail identity colors, status dots, or passive chrome.

**Rail identity colors (this phase — D-22, green family):**

| Rail | Base | Hover | Selection |
|------|------|-------|-----------|
| Reveal / Motion | `#10b981` (emerald-500) | `#6ee7b7` (emerald-300) | `#f59e0b` (orange, shared) |
| Reveal / Static | `#14b8a6` (teal-500) | `#5eead4` (teal-300) | `#f59e0b` (orange, shared) |

The reveal rail **inherits the Loop Clip `overrideColor` mechanism (43-06)** — the variant color is the default, overridable per rail. The base/hover shades mirror the existing Loop Clip convention (violet-500/cyan-500 base → violet-300/cyan-300 hover). Selection orange `#f59e0b` and unresolved red `#ff6b6b` are shared across all rail families.

**Lifecycle status dot (shared, 47 close-out palette — D-23):**

| State | Value |
|-------|-------|
| synchronized | `#a6d334` |
| modified | `#fbbf24` |
| detached | `#bbc0c8` |
| unavailable | `#ff2e56` |

**Source:** All values read from `app/src/index.css` (theme tokens) and `app/src/components/physic-paint/physicsPaintStudio.css` (rail segment, status dot, playhead). The reveal rail green family is the only new color introduced; emerald/teal shades are chosen to match the existing violet/cyan 500→300 pattern.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | **"Reveal with script…"** (photo-reference modal entry — verb "Reveal" + noun "script") |
| Empty state heading | "No source imported" (existing `PHOTO_REFERENCE_EMPTY_SOURCE` — gates reveal-rail creation) |
| Empty state body | "Import a photo reference, then Reveal with script… to bake the reveal." |
| Error state (missing reference) | "Reveal unavailable — no reference placed. Place a reference to replay." |
| Error state (deleted script) | "Reveal unavailable — script deleted. Re-link a script to replay." |
| Destructive confirmation | Replay overwrite / rail delete: **no confirmation dialog** — both are single undo-ledger entries (RVL-06) |

**Freshness tooltip lines (D-23 — the one line the Loop Clip tooltip does not have):**

| State | Copy |
|-------|------|
| Fresh | "baked from current script & reference" |
| Stale | "stale — script or reference changed since bake, Replay to refresh" |

**Replay disabled reason (D-24 — `regenerateDisabledReason`-style):**

| Condition | Copy |
|-----------|------|
| No placed reference | "Replay unavailable — no reference placed." |
| Script deleted | "Replay unavailable — script deleted." |

**Source:** CTA and freshness/disabled copy are locked by CONTEXT.md D-16/D-19/D-23/D-24. Error-state copy follows the existing fail-closed pattern (`"Regenerate unavailable — …"` from `physicsPaintLoopClipPresentation.ts` and `"Missing reference source — use Replace source to re-link."` from Phase 50). All copy is **English** (Phase 47 correction).

## UI Considerations

> State coverage for the reveal rail surface. Empty/error COPY lives in `## Copywriting Contract` above — this section covers state coverage and references those rows.

Applicable state considerations resolved: 6 covered, 1 backstop, 0 unresolved.

| Category | Element(s) | Status | Resolution / Reason |
|----------|------------|--------|---------------------|
| empty | reveal rail (no rail yet) | ✅ covered | No empty-list surface: reveal rails are created via the modal "Reveal with script…" or the track rail-creation flow; creation IS the bake (D-11). The photo-reference "No source imported" empty state gates creation. |
| loading | bake in progress | ✅ covered | Creation/Replay runs the existing per-frame render with the existing onProgress bar (completed/total); no persistent "created but not baked" state (D-11/D-24). |
| error | missing reference / deleted script | ✅ covered | Fail-closed rejections surface in the status capsule (`role="alert"`, red `TriangleAlert` icon) with the documented error copy; existing baked keys untouched (D-12/D-13). |
| populated | reveal rail with baked keys | ✅ covered | Green rail line (emerald/teal) + 20x4px lifecycle status dot + tooltip with script name, variant, span, repeat, and freshness line (D-22/D-23). |
| partial | stale reveal (script/reference changed since bake) | ✅ covered | `modified` status dot (`#fbbf24`) + "stale — script or reference changed since bake, Replay to refresh" tooltip line (D-23). |
| zero-one-many | multiple reveal rails | ✅ covered | Multiple reveal rails per track (successive spans) and across tracks; each is an independent rail+keys unit; tracks composite via the existing v1.0 compositor law (D-03/D-04). |
| long-text | script name in tooltip / accessible name | 🧪 backstop | Long library script names render in the tooltip and accessible name; held out as a visual UI-state test (lifts as `{ statement, verification: backstop }`). |
