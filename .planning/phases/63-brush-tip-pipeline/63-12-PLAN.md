<objective>
Close WR-04 and pin TIP-01's mask boundary: an import that already changed project state can no longer be reported as a timeout because its notification failed, and every structurally valid request answers with success or a named failure.

Purpose: `installPhysicPaintBrushImportListener` injects the RAW `publishPhysicPaintBrushCatalog` as the import's publish port, and `applyBrushImportRequest` awaits it AFTER the mutation batch (D-15 — an import is not undoable) has written the registry, the catalog, the asset cache and the dirty flag. A publish rejection then propagates out of `applyRequest`; none of the three listener registrations has a catch, so no result event is emitted and the Studio's 15 s timer turns an import that already landed into a reported `timed-out` failure (WR-04). The same await path turns a rejecting native encode call into the same false timeout. Both defects sit on one seam: the bridge's answer path.

IN-04 is deliberately not folded here: the wire guard must decode the mask to validate its exact length, and returning the bytes instead would change its boolean contract — not a one-line cleanup.

Output: a catch-and-log publish port injected by the bridge, a total `applyRequest` that answers a handler throw with `encode-failed`, a total `emitResult`, a handler whose publish step is non-fatal, and boundary pins at the wire guard and the handler.
</objective>
