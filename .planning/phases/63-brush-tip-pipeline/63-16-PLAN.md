<objective>
Close CR-02: a refused snapshot restore must never be overwritten by a routine save. Today the refusal branch clears `retainedContent` but the `finally` still settles the generation, so the next session mutation unions `null` with the session and writes a session-only payload over the only copy of a script the app could not read — an unrecoverable loss through the authoritative package leaf. This plan latches the refusal in the controller and withholds every routine save of that binding until the existing explicit purge door runs; it also names the pre-v3 AQTL retirement so the refusal is not reported as corruption (WR-12).

**Mechanism choice (gap option (a), latch — NOT option (b), backup).** The destructive act is a routine save the controller itself prepares, so the latch stops it upstream of the IPC seam: no new file, no new Rust path, no package artifact, and no cross-launch "have I backed up yet?" marker to persist. It is compatible with the no-migration law because it adds no reader and changes no format. Option (b) would require a new Tauri header key, a copy-before-rename path in `write_snapshot_at`, a `<trackId>-v1.snap.pre-v3` artifact inside the authoritative scripts directory, and a new one-time law inside the Rust service — changing the atomic-write contract and its exactly-one-entry pin for protection the latch already provides. Option (a) is smaller, fully reversible, and testable without Rust.

**End-to-end statement.** TS controller: `refusedRestore` is set on BOTH refusal arms (read refused/io and decode failure) and read by `prepareSave`, which returns null before `deps.write` is called. Tauri command: never invoked, because `deps.write` is the only call site (mapped to `ipcStudioScriptSnapshotWrite` at `PhysicsPaintStudio.tsx:1441-1447`). Rust service: never reached, so `write_snapshot_at` never renames over the refused leaf. One-time semantics: the latch is set once per binding, stands across every routine save (not just the next one), is never set on a healthy or missing binding, and is cleared only by `bind`/`reset`, a later successful restore, or a SUCCESSFUL `sessionOnly` purge commit — a failed purge write leaves it set. Because nothing is ever backed up (mechanism (a)), a second routine save cannot create a second backup and a normal healthy save cannot create one — the protected state is the file left exactly as found.

**Named retirement (WR-12).** `studioScriptSnapshotCodec.ts` keeps the inner codec's `unsupported-version` diagnosis instead of flattening it to `watercolor`; `aqtl-retired` maps to a named notice — "This track's script was saved in an older format and is not loaded. The frame pixels are unchanged." — while a genuinely corrupt body stays generic and container versions 1-4 keep their existing notice.

Purpose: the 63-15 AQTL v3 clean break intentionally refuses pre-v3 snapshots whole; the acceptance of that consequence requires the refused file to survive first open intact, and the user to be told the truth about why.

Output: a per-binding refusal latch with the regression pins CR-02 lacked; a dedicated AQTL-retirement code and user-facing notice with controller and codec pins; no Rust, IPC, manifest or dependency change.
</objective>
