# Phase 50 — UI Design Contract

> Visual and interaction contract for the photo/reference track surface inside EFX Physic Paint Studio: the fixed Photo row, the replaceable reference source import, the three source modes, the reference ghost overlay with canvas transform, missing-source recovery, and persistence. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Primary authority:** `50-CONTEXT.md` D-01..D-15 (gathered 2026-09-01), the locked `SPECS/milestone-v1.0.0-plan.md` §Phase 6 + §"Photo/reference track" + §"Canonical document concept" (`PhotoReferenceTrack`: id, source, mode, visibleInStudio, revision), `.planning/REQUIREMENTS.md` §REF (REF-01..REF-05), and the carried-forward `47-UI-SPEC.md` / `49-UI-SPEC.md` design contracts (which lock the strip geometry, right-panel patterns, picker surface, and status-capsule UX).

**Copy language (locked, carried from Phase 47):** all user-facing copy is **English**. Never implement French labels.

**Naming contract (locked, carried from Phases 45/46/47/48/49):** "EFX Paint" = the inline main-editor Basic/FX layer (out of scope, unchanged). "EFX Physic Paint" = the independent module + Studio window — the sole target of this phase.

**Phase boundary:** Reveal compositing is **Phase 52** (RVL); this phase delivers the source and the persisted mode flag it consumes. All three modes behave identically in Phase 50 — the mode is a persisted flag only (D-06 HARD LOCK). The masked-transform workflow that consumes `masked-transform-source` is future scope. The reserved `'photo'` fond mode stays absent from the fallback selector (D-08). The reference pixels NEVER reach the flattened raster, main preview, or export in ANY mode — that exclusion is the release stop condition "Reference-only photo pixels leak into output".

## Geometry and Layering Contract

### Photo row (S1)

- Same fixed-row geometry as the Bg row: 48px row height in the pinned fixed-row block beneath the scrollable Paint rows; frame pitch 18px (`ROTO_CELL_WIDTH_PX`); no reorder grab, no hover CRUD tools.
- Header composition mirrors the Bg header (49-UI-SPEC S1): glyph, label, lock indicator, then the eye toggle and the Import/Replace control — both 24px icon-button hit targets.
- The row header is NOT selectable as a track (no `role="button"`, no tab-select) — the photo/reference track is never the active Paint track (D-06; not a content track). Selection routing happens through the band click (below).
- Lane: the passive reference band spans frame 0 through the parent end at rail-band height inside the row; muted treatment distinct from Paint rail colors (no purple/cyan, no orange); no hit-target drag affordance. Clicking the band selects the photo reference and scrolls/opens the right-panel section (S5).
- Empty lane (no source): no band; the Import/Replace control is the single call to action.

### Asset picker (S2)

- Full-area swap of the canvas region: one bordered panel, top bar with title and `Confirm` / `Cancel`, `ImportGrid` tile geometry, existing multi-select marks (`Use image` / `Selected`), library refresh on open, no backdrop, no Tab trap (49-UI-SPEC S2 carried verbatim — same surface, new title).

### Ghost overlay + transform (S3/S4)

- The ghost draws in the program-monitor ghost layer family, above the composite and beneath selection/tool paint — the same layer seat onion ghosts use (Phase 48 D-06). It is monitor paint only.
- Transform handles render at fixed screen-pixel size (counter-scaled for zoom), matching the main editor `TransformOverlay` appearance: corner scale handles + rotation handle + drag-to-move body hit. Handle layer sits above the ghost and above paint tools' visuals while transform mode is active.
- The reference display transform (position X/Y, scale X/Y, rotation) defaults to centered at natural size, no rotation (D-13). It is applied identically to the ghost in all three modes.

### Right-panel section (S5)

- Reuses the right-panel Track-section card geometry (`md` 16px section spacing, `Label`/`Body` typography rows).
- `Mode`: 3-segment control, full row width, one active segment.
- `Overlay opacity`: slider row with live percentage readout; drag previews live, release commits (Phase 48 release-commit pattern).
- `Lock reference transform`: pressed/unpressed toggle button.
- Source facts: `{N} image(s)` with original filenames in natural filename sort order in the styled tooltip (D-02 carried).

### Layering (carried from `47-UI-SPEC.md`)

Row cells 0, overlays 1–5, rail hit targets 6, visible rail paint 7 (`pointer-events: none`), focus ring 8, tooltip 60, dialogs 70. The picker region swap rides the canvas region (engine mounted beneath). The ghost overlay and transform handles live on the monitor surface, outside the strip layer stack.

## Color

### 60/30/10 contract (carried from `47-UI-SPEC.md` / `49-UI-SPEC.md`)

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `#37393A` with surrounding `#3E3F41` | existing timeline, strip, and sidebar surfaces; picker panel chrome |
| Secondary (30%) | `#20262D`, `#343638`, `#62666D` | header column, right-panel card, picker grid tiles, tooltip |
| Accent (10%) | Active blue `#365ED6` bg / `#6F90FF` border; selected `#F59E0B` | active segment in the Mode control, selected picker tiles, `Confirm` button; NEVER on the passive band or the ghost overlay |
| Focus | `#F2F5F7` | 2px focus-visible ring only |
| Warning | `#FFB020` | truncated/shortened treatments only (no Phase 50 use) |
| Error | `#FF6B6B` | missing-source status, status-capsule rejection triangle |
| Destructive | existing EFX red treatment (`#FF9999` text / red border family) | none in Phase 50 (no delete affordance) |

**Accent reserved for:** the active Mode segment, selected picker tiles, and the `Confirm` action in the picker. It is not used for the passive reference band, the ghost overlay, ordinary facts, or the row's fixed-row chrome.

**Photo row (locked):** muted fixed-row tone — the same `#2A2C2E` row-background family with `#9CA3AF` label text as the Bg row — plus the lock indicator. The identity glyph is a camera/image icon; **the transparent checkerboard swatch is the Bg row's signature and NEVER appears on the Photo row** (spec stop condition: Background confused with the photo/reference track).

**Passive reference band:** muted desaturated tone distinct from every Paint rail color (no purple/cyan Loop Clip colors, no `#A6D334`/`#FBBF24`/`#BBC0C8`/`#FF2E56` status rectangle, no orange selection). It carries no state color — its presence/absence is the only signal.

**Ghost overlay:** the reference pixels at the overlay opacity — no tint, no blend-mode change, no outline. Onion-ghost family (D-09). The overlay toggle-off state removes the ghost entirely; there is no 0-opacity residual rendering.

**Missing source:** the ghost renders absent (no placeholder fill, no stripe — Phase 48 D-09 placeholder excision carried) and the status surfaces through the capsule red warning triangle only.

### State precedence (locked, carried)

Highest visible state wins: (1) unresolved/error red, (2) keyboard focus ring, (3) selected/active segment accent, (4) hover, (5) normal. Focus never hides error. State changes alter paint only, never geometry.

### Placement rules

- `Confirm` in the picker REPLACES the reference source in one operation (D-03): the new selection becomes the source (natural filename sort order, never asset UUID order or click order — D-02); the source revision bumps (REF-04). One still image is a cycle of length 1.
- `Cancel` returns to the Studio untouched — no source change, no document mutation.
- Replacing while a source exists is a single undoable operation: one Undo restores the prior source by reference (Phase 46 ledger). No confirmation dialog (consistent with the Phase 49 no-modal destructive pattern; the replacement is fully reversible and has no dependents until Phase 52).
- The mode switch is one undoable document mutation (D-07): one Undo restores the prior mode.

### Empty states

- **No reference source:** the Photo row renders with NO band; the Import/Replace control reads `Import images`; the right-panel section shows the Mode control (default `Reference only`) and the empty-source fact `No source imported`; the ghost overlay is absent.
- **Empty project library:** the picker shows `Drag & drop images here or use Import button`.
- **One still image:** band spans the full range; fact reads `1 image`; the ghost always resolves source frame 0 (cycle length 1, D-15).

### Error states

- **Missing library asset at resolve time:** ghost absent + `Source missing` band/tooltip status + `Missing reference source — use Replace source to re-link.` capsule with the red warning triangle (D-04). Recovery is the Replace flow — no separate recovery surface. Prior mode, visibility, opacity, transform, and selection are preserved.
- **Overlay toggle off + missing source:** the capsule still reports once; no ghost, no band status change (fail-closed reporting is independent of the visibility preference).
- **Invalid opacity input:** not applicable — the slider is constrained 0–100; no free-text field exists.

### Destructive actions

| Action | Confirmation approach |
|--------|----------------------|
| Replace reference source | **No confirmation dialog** — plain undoable replace; one Undo restores the prior source by reference. The replacement bumps the source revision (REF-04), invalidating dependent Reveal/transformation results — announced informationally via the `Reference source replaced.` capsule note. |
| Delete reference source / photo track | **Not offered in Phase 50** — replace is the only source mutation (D-03: one source at a time); the row and track are durable. |

## Interaction Contract

### Import / Replace (REF-01, REF-04, D-01, D-03)

| Input | Result |
|-------|--------|
| Click `Import images` / `Replace source` on the Photo row header | Canvas region swaps to the reference asset picker; engine stays mounted (paused); library refreshes; picker title reads `Import reference images` |
| Multi-select images + click `Confirm` | Source replaced (or set): `sourceFrameRefs` ordered by natural filename sort of original filenames (`shot_1 < shot_2 < shot_10`), never by asset UUID or click order (D-02); source revision bumps; `Reference source replaced.` capsule note; one undoable record |
| Click `Cancel` | Returns to the Studio untouched — no source change, no document mutation |
| Library `Import` inside the picker | Imports new images into the project library; selectable without leaving the picker |

- Selecting already-imported images reuses existing assets — no durable asset duplication (Phase 49 D-09 carried).
- A single image is a cycle of length 1; a sequence enables frame-aligned resolution over time (D-02, Pitfall M5).

### Missing source (REF-04, D-04)

- The reference renders absent in Studio; the status capsule carries the red warning triangle with the re-link copy; the band/tooltip status reads `Source missing`.
- Recovery = re-open the picker and re-select/re-link through the same Replace flow. No separate recovery surface.

### Mode switching (REF-02, D-05, D-06, D-07)

- The 3-segment `Mode` control in the right-panel section switches between `Reference only` / `Reveal source` / `Masked transform` instantly.
- **Flag-only in Phase 50:** all three modes show the ghost overlay identically; the ONLY visible difference is the active segment. The mode is a persisted document flag consumed by Phase 52 (Reveal) and the future masked-transform workflow.
- HARD LOCK: in ALL THREE modes, reference pixels NEVER reach the flattened raster, main preview, or export — the mode switch never changes what the compositor, `previewRenderer.ts`, or export draws (D-06).
- The switch is ONE undoable document mutation on the unified 10-level ledger and bumps the photo/reference track revision — save/reopen and dependent cache keys see it (D-07).

### Visibility (REF-03, D-10, D-11)

- The Photo row header eye toggle drives `visibleInStudio`: on = ghost visible while painting; off = ghost entirely absent.
- The toggle is persisted in the document and survives save/reopen (D-11).
- The overlay is INDEPENDENT of Paint-track hide/solo — soloing or hiding Paint tracks never affects the reference overlay, and the reference toggle never affects Paint tracks (D-10, the Background rule carried).
- Toggling reference-only visibility NEVER alters the ordinary flattened Paint output (REF-03 acceptance).

### Overlay opacity (D-09, D-12)

- `Overlay opacity` slider, 0–100%, default 50%. Live preview as you drag; commit on release (Phase 48 release-commit pattern).
- Persisted display preference on the photo/reference track (survives save/reopen alongside `visibleInStudio`). It is NOT an undoable document mutation and NEVER touches the flattened raster.

### Reference transform (D-13)

- `Lock reference transform` defaults to **locked** — painting works normally; the overlay has no handles and no canvas grab.
- Unlocking enters **reference-transform mode**: drag moves the reference, corner handles scale, the rotation handle rotates; painting gestures are intercepted by the transform mode.
- `Escape` or re-pressing the toggle re-locks; painting gestures return.
- Default transform: centered at natural size, no rotation. Transform + lock state persist as **display properties** (same class as the opacity slider — not undoable document mutations).
- The transform is IDENTICAL in all three modes — what you align is what Reveal (Phase 52) will reveal.
- The transform NEVER affects the flattened raster or export; the ghost and the handles are monitor paint only.

### Frame alignment (D-15, Pitfall M5)

- Application frame N → source frame N, 1:1 from frame 0, **clamped at the sequence end** (last source frame holds). No start offset, no loop.
- The ghost resolves through the current cursor frame every time it draws — the source is never "resolved once at import". The band tooltip carries `Reference source frame {N}` / `Holding last source frame` accordingly.

### Playback (D-14)

- The ghost overlay is visible ONLY while painting/editing on the active track — it hides during playback and export (onion-skin behavior, Phase 48 D-06). Re-locking the transform is not required for playback; the overlay simply does not draw.

### Busy and rejected-operation behavior (carried from `47-UI-SPEC.md` / `49-UI-SPEC.md`)

- During controller preparation/commit, the row, band, and right panel remain visible; mutation controls use `aria-disabled="true"`; band targets expose `aria-busy="true"`.
- No optimistic band, segment, opacity, or fact changes. Update only from accepted canonical state.
- On rejection, preserve prior source, mode, visibility, transform, selection, and focus; announce through the status capsule.

## Accessibility Contract

### Roles and names

- Photo row header: a plain header cell (NOT `role="button"` — the row is not selectable as a track), `aria-label="Photo row"`.
- Eye toggle: `aria-label="Toggle reference visibility"`, `aria-pressed` reflecting `visibleInStudio`.
- Import/Replace control: `aria-label` reads `Import images` / `Replace source` per state (D-03).
- Reference asset picker: `role="region"`, `aria-label="Import reference images"`; grid retains the existing `ImportGrid` accessibility (`Use image` / `Selected` button labels); `Confirm` / `Cancel` are named buttons.
- Passive band: `role="group"`, `aria-label="Reference source"`; tooltip carries the full facts (source frame, count, filenames, missing status).
- Mode control: `role="radiogroup"`, `aria-label="Mode"`, one `role="radio"` per segment with `aria-checked`; the exclusion hint is `aria-describedby` on the group.
- Opacity slider: `role="slider"`, `aria-label="Overlay opacity"`, `aria-valuemin="0"`, `aria-valuemax="100"`, `aria-valuenow` live during drag.
- Lock toggle: `aria-label="Lock reference transform"`, `aria-pressed` reflecting lock state.
- Status capsule: existing `aria-live="polite"`; missing-source reports additionally use `role="alert"`.

### Focus visibility and target size

- All new controls keep the existing 2px `#F2F5F7` focus ring with 1px offset.
- Icon-only controls (eye, Import/Replace) use the 24px icon-button hit target; the band's 12px target remains the explicit compact-editor exception.
- Mode segments and the lock toggle are reachable and operable by keyboard (`Tab` + `Enter`/`Space`); arrow keys move between radio segments.
- Opening the picker moves focus to its first actionable control; `Cancel` and `Confirm` restore focus to the Import/Replace control.
- While reference-transform mode is unlocked, focus-visible outlines on the transform handles remain visible (the main-editor handle focus treatment).

### Reduced motion

- Picker swap, overlay opacity preview, transform handles, and visibility toggles are immediate paint changes; no slide, scale, shimmer, pulse, or tween.
- Under `prefers-reduced-motion: reduce`, disable the existing 120ms color/background transitions for any newly touched controls.

### Contrast and non-color cues

- Mode selection is shown by the active segment state (accent + `aria-checked`), never color alone.
- Lock state uses the lock icon variant plus `aria-pressed` — never color alone.
- Missing source shows `Source missing` text plus the red warning triangle — never transparency alone.
- The band's presence/absence is reinforced by the right-panel empty fact (`No source imported`) — never an unlabeled blank lane.

## Implementation Boundaries

- **The exclusion lock is the contract's first citizen (D-06):** reference pixels NEVER reach the flattened raster, main preview, or export in ANY mode. `previewRenderer.ts`, the compositor, and the export path receive NO reference input. The mode is a persisted flag only until Phase 52 — any visual mode difference beyond the active segment is a regression.
- The `'photo'` fond mode stays absent from the fallback selector (D-08); wiring it would draw reference pixels as flattened fallback, violating D-06. `BackgroundSelectorMode = Exclude<BgMode, 'photo'>` stays as-is.
- The photo/reference row is NEVER a main-editor content track (spec §"Forbidden sequence-level assumptions"): no row in the main-editor timeline, no `Sequence` mutation, no duration change, no direct main-renderer iteration.
- Build the reference picker from the existing `BackgroundAssetPickerView` variant (D-01). **Never port `ImportedView`** into the Studio window.
- Source ordering is natural filename sort of ORIGINAL filenames, hard lock — never asset UUID sort or selection order (D-02).
- One source at a time; replace is the only source mutation; no delete affordance in Phase 50 (D-03).
- Mode switch and source replacement record undo by reference on the unified document-wide 10-level ledger (D-07, Phase 46 D-01..D-03); no raster-byte snapshots. Overlay opacity, transform, and lock state are persisted display preferences — NOT undoable document mutations (D-12, D-13).
- The `photoReference` null→track model change is a clean-break format change under the v1.0.0 contract: parser extension is fail-closed; no legacy migration.
- Library asset IDs only — never external paths (Phase 49 D-09 carried); missing assets resolve to null and surface fail-closed (D-04), never a throw, never placeholder content.
- Frame alignment is the 1:1 clamped law (D-15): the ghost resolves the source frame per cursor frame — never resolved once at import (Pitfall M5); a missing source is never silent transparency (Pitfall M6 — the capsule always reports).
- Mutations bump the photo/reference track revision and the global clocks per the single dirty-callback law; the `efx-preact-reactivity` skill's rules govern every store setter, effect dependency, and signal read — no `useState`, no render-body signal writes, narrow signal reads in the ghost draw path.
- The transform handle surface follows the main editor `TransformOverlay` counter-scaling so handles keep fixed screen-pixel size at any zoom; the transform never writes to the compositor or cache keys.
- The overlay hides during playback (D-14) by not drawing — no opacity trick, no cache entry, no export residue.
