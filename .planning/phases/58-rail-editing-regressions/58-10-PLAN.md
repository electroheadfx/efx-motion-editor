<objective>
Close CR-03: apply the CR-02 final-mapping source-order proof to the move-key-group branch, so a partial-cycle group move is accepted only when every clip it touches keeps its sourceKeyIds strictly increasing, and is rejected with the existing locked copy otherwise.

Purpose: 58-07 proved that a `move-key` destination must preserve the single referencing cycle's source order, but the sibling `move-key-group` branch builds a candidate and hands it straight to `finalizeProposal` without consulting the loop clips. `buildMoveGroupCandidate` rejects only duplicate destinations and capacity, `finalizeProposal` never validates `sourceKeyIds` order, and the loop follow runs only when the moved set contains the cycle's ENTIRE source list. A partial-cycle group drag past later source keys is therefore accepted and persists a clip that `derivePhysicPaintRotoLoopRanges` marks `unresolved.invalidSourceTiming` — the rail reports "Source missing" and export is blocked, with Undo as the only recovery for merged Standard clips.

Output: one shared order helper used by both move branches, a guard in the move-key-group branch after the candidate is built and before finalization, a rewritten D-04 partial-cycle test at an order-preserving destination plus an order-breaking rejection pin, edge pins for the skip/exemption/dangling/multi-clip boundaries, and UI dispatch pins proving the rejected drag never reaches `executePhysicalEdit`.

Cites: CR-03 (58-REVIEW.md), UAT row 7 (58-UAT.md); Phase 58 D-04 (partial group move stays legal), D-12 (Law A), D-16 (locked copy), D-17 (regression locking); RAIL-06, RAIL-07.
</objective>
