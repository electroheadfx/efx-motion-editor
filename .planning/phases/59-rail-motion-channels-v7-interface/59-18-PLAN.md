<objective>
Make rail-set Copy and Duplicate carry the rails' motion.

Purpose: `buildRailSetCopyDocument` parses the copied document without `railMotions` and hashes a
four-argument revision, so every copied or duplicated rail set loses the motion its rails carry —
`buildRotoRailSetCopyPayload` then finds an empty motion collection and freezes nothing. The paste
side already re-keys motion correctly; only the document the copy is built from is wrong.

Gap closed: G3 — CR-01 (rail-set Copy/Duplicate builds its document without `railMotions` and silently
drops motion), and 59-VERIFICATION truth row 16 ("Rail-set Copy and Duplicate carry the rails' Motion
with the rails (plan 59-14, UAT row 6)"). Because the copied payload is re-keyed per copied rail, this
is also what keeps MOTN-05 true across Copy: motion stays rail-local and travels with the rail.

Wave note: this plan and 59-17 both edit `useRotoTimelineActions.ts` (the action-bundle hub), so they
cannot share a wave; 59-17 lands first. 59-21 is the inspector-honesty slice of the revision-mode 59-17
split; it runs in the same wave as this plan and touches none of this plan's files, so it cannot
change this plan's dependency on the 59-17 hook slice.
</objective>
