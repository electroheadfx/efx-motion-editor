<objective>
Close the one remaining structural blocker and the copy-ownership warning: make every reveal bake reconcile rail
motion against a snapshot that already owns the baked keys, and make both copy paths segment Key Rails with the
document's real group ownership.

Purpose: CR-01 is deterministic silent data loss. `commitRevealBake` builds `nextLoopClips` from the clips that
exist BEFORE creation, reconciles motion, and only then does `createRevealRail` append the reveal clip. During
reconciliation the freshly baked keys are unowned, so a neighbouring Key Rail continuing past the bake span is
classified as a merge: `onMergeRails` re-anchors its record onto a baked key, the appended clip then owns that key,
and the record becomes orphaned (`active []`, `orphaned ['rail-moving']`). WR-06 is the same ownership mistake on the
copy side: `buildRotoRailSetCopyPayload` and `copyTrackSelection` segment with an EMPTY group-owned set while the
display projection excludes every Loop-Clip-owned key, so a Key Rail that follows a clip without a break is folded
into the clip's segment — Copy/Duplicate fails closed as `stale-member`, and the motion freeze binds the wrong rail.

Gap closed: CR-01 (blocker) and WR-06, from `.planning/phases/59-rail-motion-channels-v7-interface/59-REVIEW.md`
and `59-VERIFICATION.md` `gaps[0]`.

Wave note: wave 1. It touches `physicPaintStore.ts`, `efxPaintStore.ts`, the reconciler, the rail-set copy module and
their tests; 59-23 (wave 1) touches only the view/command surfaces and no file listed here, so the two run in
parallel. 59-24 depends on this plan because it also edits `physicPaintStore.ts`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reveal creation -> motion reconciliation | Reconciliation must see the structural edit the creation is about to commit; an incomplete snapshot silently re-binds or orphans rail motion |

| document clips -> rail-set copy | The copied payload's identity and motion are derived from an ownership projection that must match the display exactly |
