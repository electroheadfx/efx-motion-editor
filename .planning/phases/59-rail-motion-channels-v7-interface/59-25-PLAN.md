<objective>
Make the grouped Position lane fully editable and make the lane curve honest about its rail: easing/Wiggle fan out to both
position axes at the command layer, and every rendered curve is sampled with the lane's own `railId`.

Purpose: WR-04 records that `TimelineMotionBlock` forwards `channels[0]` (always `position-x`) for a grouped Position lane
while the model leaves an existing sibling key untouched when `pairedValue` is absent, so `position-y` easing and wiggle
are unreachable from the UI. WR-03 records that the lane curve call omits the fourth argument, so a wiggle-bearing
channel is drawn from the preview seed while the compositor applies the record's real `railId` seed — the drawn curve
and the applied transform disagree. Both live on the same two files and are fixed at their true owners: the command layer
and the lane's curve call.

Gap closed: WR-04 and WR-03, from `.planning/phases/59-rail-motion-channels-v7-interface/59-REVIEW.md` and
`59-REVIEW-DISPOSITION.md`.

Wave note: wave 2, depends on 59-23 because both plans edit `TimelineMotionChannels.tsx` and its test. It has no file
overlap with 59-24 (stores, model, fixture, Rust), so the two wave-2 plans run in parallel.
</objective>
