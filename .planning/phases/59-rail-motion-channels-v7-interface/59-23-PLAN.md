<objective>
Make the `+` row a permanently visible, authority-gated affordance: it renders whenever the Motion block renders, derives
its disabled state and reason from the one availability authority, and cannot open an empty menu; the measured strip
layout adds its 18px from the lane count alone so the layout and the rendered row can never disagree.

Purpose: WR-01 records that the `add-motion-channel` union member, the `hasKeylessChannel` input and the availability
branch are dead, while the module doc claims the row derives its gate from the authority. The shipped row instead
renders only when a keyless lane exists and has no disabled state at all, so a fully-keyed rail silently loses the
affordance instead of showing it disabled with a reason (MUI-06), and the strip independently re-derives the same
condition for layout. Routing the row through `resolveMotionCommandAvailability` makes the branch live, deletes the
second derivation, and keeps T-59-35's one-authority contract.

Gap closed: WR-01, from `.planning/phases/59-rail-motion-channels-v7-interface/59-REVIEW.md` and
`59-REVIEW-DISPOSITION.md`.

Wave note: wave 1. It touches only view surfaces and their tests; 59-22 (wave 1) touches the stores, the reconciler and
the copy module with no file overlap, so the two run in parallel. 59-25 depends on this plan because it edits
`TimelineMotionChannels.tsx` and its test again.
</objective>
