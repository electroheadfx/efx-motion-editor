<objective>
Build the single pure evaluator that turns a motion record plus a rail-local frame into a transform,
with endpoint hold, Hold/ease curves, unbounded rotation, seeded deterministic wiggle, and the lane
curve path derived from the same samples.

Purpose: edit view, Play, export, the gizmo read-out and the lane curve must all agree. Any second
interpolation implementation makes that agreement untestable; this module is the only one.
</objective>

  <behavior>
    - `evaluateRailMotionChannel` on a channel with keys [k0, k1]: frame ≤ k0.frame -> k0.value; frame ≥ k1.frame -> k1.value; between -> k0.easing === 'hold' ? k0.value : smoothstep interpolation.
    - Smoothstep is `t*t*(3-2t)`; it is monotone on 0..1, equals 0 at t=0 and 1 at t=1, and never leaves the [v0, v1] interval.
    - Rotation values are interpolated in degrees and converted to radians once at the transform boundary; no modulo, no shortest-arc normalization.
    - Absent channels contribute their identity: position 0, scale 1, rotation 0, opacity 1.
    - A single-key channel holds that value everywhere.
    - A negative or fractional railLocalFrame is accepted by the evaluator (before-first hold); clamping to 0 happens in `resolveRailLocalFrame`, not here.
  </behavior>
  <action>
    Implement the evaluator in `railMotionEvaluator.ts` as a pure module with no imports from the store, view layer or DOM. Follow the two named PATTERNS analogs: `aquarelleFramePose.ts` for the total, identity-fast-path evaluator shape (readonly inputs, all-zero identity result, purity stated in the header), and `resolvePhysicPaintRotoLoopFrame` at `physicsPaintRotoPhysicalResolver.ts:6945` for the rail-local subtraction and first/last-key clamping — but NOT its cycle arithmetic (D-16 ships hold only). Use a binary search or a linear scan with an early exit; a linear scan is acceptable because the parser caps keys at 4096 and channels at 5, but document the bound in a comment.

    `evaluateRailMotionChannel(record, channelId, frame)` finds the channel by id (returning the identity value when absent) and resolves the segment. `evaluateRailMotion(record, frame)` calls it five times and assembles the frozen transform, converting degrees to radians exactly once: `rotationRadians = rotationDegrees * Math.PI / 180`. Never add a second conversion anywhere else.

    Opacity is clamped to 0..1 after evaluation (wiggle in Task 2 can push it out); scale is floored at 0 (a negative scale would mirror the raster, which is not a shipped behavior). Position and rotation are not clamped. Document both clamps next to the code.

    `resolveRailLocalFrame(appFrame, railStart)` returns `Math.max(0, appFrame - railStart)` and requires both to be finite; a non-finite input throws. This is the ONLY place the subtraction lives.

    Tests first (RED): endpoints, hold vs ease, single key, absent channels, 0→360 midpoint 180, −90 unchanged, 720 distinct from 0 in the stored value but evaluated as the same orientation only at the radians boundary (assert the raw degrees path, then the radians output), fractional frame, negative frame hold.

  <behavior>
    - Wiggle amplitude comes from the OUTGOING key of the segment (the key at or before the evaluated frame); a key with `wiggle: 0` contributes nothing.
    - The noise value at a real-valued frame is a smooth interpolation between integer-frame noise samples, so it does not jitter frame to frame.
    - The seed is a stable 32-bit hash of `${railId}|${channelId}|${keyFrame}`; each integer-frame sample constructs `new Random(seed + sampleFrame)` and takes one draw. No sequential PRNG state is carried between calls.
    - Two calls at the same (record, frame) return bit-identical values; two calls after unrelated evaluations also match.
    - The noise is bounded to [-amplitude, +amplitude]; the result stays deterministic across Play, pause and export.
    - Opacity wiggle is clamped to 0..1 and scale wiggle floored at 0 after addition.
  </behavior>
  <action>
    Implement `railMotionWiggleAt(railId, channelId, keyFrame, frame): number` returning [-1, 1], using an FNV-1a 32-bit string hash over the stable components. Sample at `Math.floor(frame)` and `Math.floor(frame) + 1`, each with `new Random(seed + sampleFrame)` and one draw mapped from [0,1) to [-1,1), then smoothstep-interpolate by the fractional part. This makes wiggle smooth, deterministic and order-independent.

    Apply it inside `evaluateRailMotionChannel` after the eased value: `value + amplitude * railMotionWiggleAt(...)`. Use the segment's outgoing key frame in the seed so a wiggle key's noise is anchored to that key, and hold keys with wiggle > 0 still wiggle (the step value plus noise).

    Keep the hash private; export only `railMotionWiggleAt` for the determinism test.

    Tests first (RED): identical repeated calls; frame 10.0 vs 10.5 differ but continuously; amplitude 0 is exact identity; two different railIds produce different noise; a `hold` key with wiggle still steps plus noise; opacity clamp and scale floor hold.
