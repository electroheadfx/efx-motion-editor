<objective>
Close the removal-result dead surface and the cross-language ordering divergence: cut/clear stop reporting a drop no one
reads, and both canonical encoders order ids by byte value so the same document produces the same revision in TypeScript
and Rust.

Purpose: WR-02 records that `mergedDrop` on `RotoTrackCopyResult`/`RotoTrackClearResult` has no production consumer while
the move path does — a contract that invites a future reader to depend on an unreported drop. WR-05 is a persistence
identity defect: TypeScript sorts with ICU `localeCompare` while Rust sorts with `str::cmp`, so a rail set containing
mixed-case or punctuation-bearing ids can hash to two different revisions for identical content. The fix is one
code-unit comparator in TypeScript at every canonical sort site, pinned by a mixed-case cross-language fixture.

Gap closed: WR-02 and WR-05, from `.planning/phases/59-rail-motion-channels-v7-interface/59-REVIEW.md` and
`59-REVIEW-DISPOSITION.md`.

and lane view surfaces with no file listed here, so the two run in parallel. Task 2 of this plan is independent of 59-22
but stays in this plan to keep the wave-1 store edits single-owner.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| removal transaction -> caller result | A reported drop the caller never reads invites a future consumer to treat cut/clear as announcing merges |
| TypeScript canonical encoder -> persisted revision | The revision is the persistence identity; two orderings for identical content means two identities |
| TypeScript encoder -> Rust encoder | Both languages independently encode the same document; the golden fixture is the only cross-language authority |
| golden fixture -> future regressions | A regenerated fixture can silently bless a wrong encoder |
