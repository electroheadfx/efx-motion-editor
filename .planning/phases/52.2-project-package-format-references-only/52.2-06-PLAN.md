<objective>
Make the persisted document carry media references instead of rasters in both directions (D-06/D-09): serializing runtime state emits `media` and strips the payload; hydrating runtime state reads `media` and never looks for a payload. The bytes themselves move through the native commands from plan 01 — this plan owns only the mapping.

Purpose: the write funnel (plan 07) and the read-back leg (plan 09) both sit on top of this projection. Isolating it here, away from IO, is what makes it TDD-able and keeps the stores thin.

Output: `physicsPaintRotoMediaProjection.ts` with tests, `serializeRuntimeIntoDocument` emitting media references, `installRuntimeStateFromDocument` accepting them, and the multi-track round-trip test proving metadata survives.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime store → persisted document | Runtime-only fields must not leak into the persisted artifact |
| Persisted document → runtime store | A document record is untrusted input at hydrate time |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-18 | Tampering | projection synthesizing media metadata | medium | mitigate | `resolveRef` is the only media source; an unresolved reference is a typed failure naming the keyId, and the produced document is validated by the plan-02 fail-closed parser inside the test — a fabricated or missing digest cannot reach disk. |
| T-52.2-19 | Information Disclosure | runtime bytes leaking into the persisted document | high | mitigate | The persisted record's payload key set is asserted explicitly in tests (no raster field), and the parser rejects any record carrying one — so a leak is a test failure at write time and a refusal at read time. |
| T-52.2-20 | Denial of Service | duplicated key publishing an empty frame | medium | mitigate | The paste path must either resolve pixels from a real source or refuse with a typed reason; a `width: 0` publish is treated as a bug, asserted by test. |
</threat_model>
