# Phase 52.2: Project package format — references only (+ async foundations) - Context

**Gathered:** 2026-09-12
**Status:** Ready for planning (user reviews this CONTEXT before planning — spec Gate 1)

<domain>
## Phase Boundary

Two workstreams in one clean-break window, plus two bounded UI/UX additions:

1. **Package format (references only)** — the project file never contains image bytes: no base64, no binary, images are files referenced by relative path + content digest. The project folder becomes the package: a light top manifest (`project.mce`) + one JSON sub-file per paint layer + real `.webp` media files on disk. The package keeps the `.mce` name: `MyProject.mce` is a folder that behaves like a file (macOS document package). The 52.1 runtime is untouched (WebP-lossless Rust codec, bytes/ImageBitmap path, 512 MB LRU, cap 1920) — only the persistence target changes.
2. **Async foundations (progressive)** — XState v6 + Effect v4 on the sensitive paths only, conventions first, one measured pilot (stroke finalization + flush pipeline), no migration. v1.0.0 ships the bases v1.1.0's AI features need.
3. **UI/UX additions** — solo playback starts at the beginning; numeric − / + steppers everywhere.

**Locked spec (source of truth):** `SPECS/phase-52.2-project-package-format.md` — co-written with the user. Its Laws (§2), save model (§6), bridge (§7), read-back leg (§8), out-of-scope (§12) and gates (§13) are LOCKED. This CONTEXT refines the spec where the 2026-09-12 discussion explicitly amended it: `frames/` tree (was `media/`), pure-index manifest (was the §5 draft split), `cache/` out of the package. Downstream agents MUST read the spec before planning; requirements are not duplicated here.

**Naming contract (carried from Phases 45-52):** "EFX Paint" = the inline main-editor Basic/FX layer (out of scope, unchanged). "EFX Physic Paint" = the independent module + Studio window — the sole target of v1.0.0 and this phase. All user-facing copy is English.

<decisions>
## Implementation Decisions

### Workstream shape (discussed 2026-09-12)
- **D-01:** **One phase, two workstreams — format waves land FIRST, pilot waves after.** 52.2 carries both the package format and the async pilot (matches the spec as written). The XState/Effect pilot targets the POST-format paths (references instead of base64 in the bridge/flush pipeline) — no retargeting the pilot mid-flight. — **Reversibility:** costly — splitting into 52.2/52.3 later re-plans waves, gates, and the pilot boundary mid-flight.

### Package shape & layout (discussed — amends spec §4/§5)
- **D-02:** **Real-key rasters live in a new `frames/<layerId>/<keyId>.webp` tree** at the package root — supersedes the spec's `media/` draft. Rationale (scout, spec §4's mapping ask): no existing folder fits — `paint/<layerId>/frame-NNN.json` holds main-editor INLINE paint frames (still live via `savePaintData`, different subsystem, out of scope), `images/` holds imported source originals + thumbs, `cache/efx-paint/` holds regenerable derived frames, `scripts/` holds the Roto library. One file per real key, WebP-lossless exact alpha (52.1 D-01); key metadata (track/frame/timing) stays in the layer sub-file. — **Reversibility:** costly — the on-disk path contract is recorded in every project file, the rescue converter, and future readers.
- **D-03:** **Full macOS package treatment in this phase.** The project folder becomes `Name.mce/` (document package), the app declares the document type (Info.plist CFBundleDocumentTypes + package flag) so Finder shows ONE icon and double-click opens the project; open/save dialogs target packages; Windows/Linux keep a plain folder. Matches spec §4 and the "icon clicks" native-UAT line (§13.4). — **Reversibility:** costly — a published open/save surface users build habits on.
- **D-04:** **Manifest = pure index; the layer sub-file holds the COMPLETE document.** `project.mce` carries the main-editor project content + a per-physic-paint-layer index (layer file path + document/composite revisions) + `formatVersion`. Each `layers/<layerId>.json` holds the full `EfxPaintDocument` (tracks complete — including visibility/solo/opacity/blend — plus background, photoReference, rails, key metadata, media refs). One authority per fact; the Studio writes exactly one sub-file, so spec §6 ("Studio saves only its layer's sub-file + that layer's changed media") holds structurally. Supersedes the spec §5 draft split (which spread per-track fields across manifest and layer file — hide/solo edits in the Studio would have dirtied the manifest and broken §6). — **Reversibility:** costly — the file partition defines every save/read path.
- **D-05:** **`cache/` moves OUT of the package** — machine-local disposable cache keyed by project identity, the package carries authoritative content only. The plan must: recompute `cachePath` references to the machine-local location on load; and re-derive on cache miss (a moved package opens on a cold machine with an empty cache). Consequence: the package must contain NO machine-local paths — any derived-frame reference inside `layers/*.json` must be recomputable from project identity or re-derivable; the exact scheme is planning's to design. — **Reversibility:** costly — reversing means packages carry regenerable weight again and the ref scheme changes twice.
- **D-06:** **Field split table (user reviews it here — the spec §5 deliverable).** Proposed:

  **`project.mce` (top manifest — light, the main editor's authority):**
  - `formatVersion` (replaces filename versioning — spec §4)
  - main-editor project as shipped: `version`/`name`/`fps`/`width`/`height`/`created_at`/`modified_at`; `sequences` (layers, key photos, timing — everything the main editor owns); `images[]` (imported asset list); `audio_tracks[]` (metadata + relative paths)
  - `efxPaint` index: `{ [parentLayerId]: { layerFile: 'layers/<layerId>.json', documentRevision, compositeRevision } }`
  - the legacy `physic_paint_outputs` carrier is superseded — the pre-52.2 gate discriminates by `formatVersion` (planning designs the new gate shape)

  **`layers/<layerId>.json` (the complete EfxPaintDocument — the Studio's authority):**
  - `version`, `parentLayerId`, `documentRevision`, `activeTrackId`, `compositeRevision`
  - `tracks[]`: `id`, `name`, `order`, `visible`, `solo`, `opacity`, `blendMode`, `revision`, `loopClips` (rails), Roto key metadata (realKeyRecords/groupOverrideRecords WITH the raster payload replaced by media refs)
  - per-key media refs: `{ keyId, relative path 'frames/<layerId>/<keyId>.webp', content digest, width, height }`
  - `background` (id, clips[], fallback, visible, revision); `photoReference` (or null)

  **`frames/<layerId>/<keyId>.webp`:** the real-key rasters (content; digest recorded in the layer file).

### Persistence laws (locked — carried from the spec; do not re-litigate)
- **D-07:** References only — images are files on disk; JSON holds relative paths + content digests, never payloads. No embedded database; the user must open the folder and SEE the `.webp` files (spec §2.1).
- **D-08:** Clean break — pre-52.2 projects are refused by shipped code; no migration shims. The refusal mirrors the Phase 45 no-recourse dialog pattern. A **dev-only rescue converter** (outside app sources, not shipped) converts the user's current 37 MB project; the user's test material survives (spec §2.2, §9). — **Reversibility:** one-way — shipped readers only speak the new format; a migration would need a new reader.
- **D-09:** Granularity: per paint layer, never per key — key metadata lives in the layer's sub-file; key bytes live as `frames/` media files (spec §2.3).
- **D-10:** Extend, don't replace — the shipped transactional save machinery (staging → hardlink unchanged → fsync → atomic rename-swap → digest-bound commit/rollback) is extended to the new file set, not rewritten (spec §2.4).
- **D-11:** Save = write only CHANGED files (per-file change tokens extend the existing `savedFrameTokens` model) + atomic multi-file commit. **No full-document serialize anywhere** — the measured ~4.6 s `persist.serialize` term dies. Studio saves only its layer's sub-file + that layer's changed media (spec §6). The cancelled autosave quick is absorbed: its per-key dirty-tracking becomes per-file change tracking.
- **D-12:** Bridge (Studio↔main) sync passes references + metadata, not base64 payloads; bytes cross only when a frame actually changed (digest-keyed). Kills the ~4.5 s `docSync` term (spec §7).
- **D-13:** Read-back leg — the genuinely new construction (spec §8): open = read manifest + layer sub-files + lazily decode media files through the 52.1 bytes/ImageBitmap + LRU path. Missing media file → locked slate behavior (Phase 49 law); corrupt digest → refuse, no silent fallback. **Note for planning:** the loader comment at `efxPaintPersistence.ts:430-433` claims an existing "fetch the WebP sidecar on demand" — no such fetch exists anywhere in the codebase (verified 2026-09-12); this leg must be BUILT, not wired.
- **D-14:** Derived frames re-derive in memory — nothing reads `cache/*.webp` today (verified; see Verified Facts). Cache files are write-only artifacts (staged/hardlinked/deleted by the save transaction) until the read-back leg ships, and remain re-derivable after.

### Async foundations (locked + discussed)
- **D-15:** Versions locked: **XState v6** (alpha, architecture reworked — schema-first, per-state context, no `assign`, `createAsyncLogic`; risk consciously accepted, mitigation = direct Stately line via GitHub issues) and **Effect v4** (RC; pin `^4` when stable; zero-dep confirmed) (spec §10).
- **D-16:** **Pilot = adoption target #1 only** — stroke finalization + flush pipeline (sensitivity-map rows 1-4: `gestureIdleScheduler.ts`, `physicPaintFlush.ts`, `rotoLivePixelCacheTransactions.ts`, `useRotoFramePersistenceCoordinator.ts`): XState machine for the lifecycle + Effect queue with bounded turns, backpressure, and interruption on navigation. Baseline = committed telemetry (~900 ms atomic steps, ~9 s median queue waits). Success = step slicing schedulable, input-delay percentiles measurably improved, and targeted tests that were not writable against the implicit version. Honest failure allowed (spec §10).
- **D-17:** **Conventions gate:** the async conventions doc is reviewed by the user BEFORE any XState/Effect code (spec Gate 2); all XState/Effect code lives behind the pilot module boundary until native UAT passes; async rules enter the efx-motion skill family only after that.
- **D-18:** **Render-churn inventory + state conventions** (in the conventions scope): render counters on the worst surfaces (tracks strip, right panel, canvas) as before/after evidence; conventions for centralized domain state (domain stores with derived computeds, narrow-selector reads, version-bump discipline). XState also serves here — one machine snapshot replaces boolean clusters read by many components. **Non-imposition law:** the sensitivity map is discuss INPUT, not mandate; every adoption must answer a named architectural problem; "neither library here, and nowhere yet" is a legitimate verdict per area (spec §2.10, §10).
- **D-19:** **Budget gate:** new runtime deps (xstate v6, effect + needed @effect/*) are each justified in the plan; the frozen chunk budget (1320 kB, 52.1-VERIFICATION) is re-measured with them — any raise is an explicit documented decision (6325e2e8 pattern) (spec §10).

### Solo playback start (discussed 2026-09-12)
- **D-20:** **Both solos trigger start-at-beginning on Play** — the rail-set session pill (armed playback filter) AND the persisted row-S document track solo. (Two distinct systems: `physicsPaintSoloArm.ts` session arm vs `setTrackSolo` persisting per-track document flags.)
- **D-21:** **"The beginning" = content start.** Pill → the solo window's first frame (`deriveSoloPlaybackWindow.start` — first soloed rail's first key). Row S → the first painted key across the soloed track(s). No painted keys on the soloed track(s) → fall back to project frame 0. Applies only while a solo is active; otherwise the Phase 51 play-from-cursor law (260902-cfa D-01) stands unchanged.
- **D-22:** **Loop wrap returns to the solo content start** — every loop iteration behaves identically (never back to the pre-solo cursor).

### Numeric steppers (discussed 2026-09-12)
- **D-23:** **Sweep: everywhere numeric inputs exist** — main editor (shared `NumericInput` in Properties/FX/Transition/Audio sidebars, Key Photo Hold Frames, Paint properties, `InlineColorPicker`/`ColorPickerModal`) AND Studio (`PhysicsPaintTopBar`, WorkflowStrip fps + key spacing). One shared stepper treatment; native HTML spinner arrows suppressed everywhere.
- **D-24:** **Layout `− [field] +`** — buttons flanking the field, always-visible first-class click targets; the value stays keyboard-editable; each input keeps its existing `step` (fps 0.5, others 1) and min/max clamping; **hold-to-repeat** after a short delay (single click = one step).

### Regression law (locked — spec §12)
- **D-25:** **The physics render pipeline is NOT a regression target.** Root cause of the glitch/slowdown regression = base64 in the .mce + the decode path, both killed by this phase. A committed re-measurement gate runs right after the 52.2 native UAT (telemetry in place: stroke-train painting on the real project, step sizes + input delays). If a residual remains, the only legitimate future optimization is the physics runtime core itself (possibly ported to Rust) — a later, separate phase; never scheduler slicing of the deferred render.
- **D-26:** Native rewrite — settled NO (2026-09-12; format debt ≠ stack fault). Reopens only as v2.0 with post-52.2 measured WebView bottlenecks.

- The rescue converter's shape/location (dev-only, outside app sources) and its verification method.
- Package icon artwork and the Info.plist / LaunchServices wiring details (research).
- Exact stepper component API and press-and-hold timing.
