<objective>
Extend, do not replace (D-10), the shipped transactional save machinery so one transaction covers the new authoritative file set — manifest + `layers/*.json` + changed `frames/*.webp` — from a package staging root through a per-file atomic publish, with an order-independent aggregate digest and a rollback/commit/recovery path that leaves the pre-save package intact; while the derived-frame cache moves out of the package to a machine-local root keyed by project identity (D-05) and becomes a separate, best-effort leg (D-14).

Purpose: plan 01 created the media primitive and the guards; plan 02 created the TS path contract. This plan makes the native side able to stage, bind, publish and settle the whole authoritative set atomically (nothing authoritative touches its canonical path outside the transaction — spec §6, D-10/D-11). Every save/reopen plan after this one depends on it.

Output: two clearly separated transactions in `physic_paint_cache.rs` (package = authoritative, cache generation = disposable machine-local), a package transaction API (`bind` / `publish` / `settle` / `recover`), `create_project_dir` producing `layers/` and `frames/`, a staged manifest write, a machine-local cache root, and the TS wrappers plus the minimal caller change that keeps the tree green.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Marker file on disk → Rust commit path | A marker written in a previous session is untrusted input at bind time |
| Package root vs machine cache root | Two different filesystem roots that must not be confused |
| Renderer → staging root | The renderer names the staging generation; the root it writes into is derived in Rust |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-14 | Tampering | transaction marker `expected_files` entries | high | mitigate | Every entry's `sha256` is validated as 64 lower-case hex at parse time and every path is resolved through the plan-01 package bound-path guard; a mismatch refuses the commit and names the path — a doctored marker can only refuse, never redirect a write. |
| T-52.2-15 | Tampering | partial multi-file commit | critical | mitigate | No bound file reaches its canonical path outside `publish_package_transaction`, which exchanges each staged file atomically and retains the previous bytes at the staged path; commit verifies every canonical digest before removing the marker, and `recover_package_transaction` rolls forward only when EVERY entry matches, otherwise back to the pre-save package.
