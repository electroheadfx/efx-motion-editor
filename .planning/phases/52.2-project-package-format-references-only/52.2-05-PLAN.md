  <behavior>
    - a transaction bound to three files commits only when all three still hash to their recorded digests
    - changing one byte in one bound file after binding makes the commit refuse with a typed mismatch naming the offending path
    - the aggregate digest is stable across discovery order: binding [a, b, c] and [c, a, b] yields the same digest string
    - the marker persists a sorted entry list of `{path, sha256}` and rejects any entry whose sha256 is not 64 lower-case hex
    - re-binding an already-bound transaction with an identical set is a no-op that keeps the original digest and staging generation
    - re-binding with a different set is refused (no silent rebase)
    - rollback restores the pre-save state of every bound file, including a file that existed before with different bytes
    - a transaction whose set includes a `.webp` under `frames/` and a `layers/*.json` commits both or neither
  </behavior>
  <action>

Compute the aggregate digest as SHA-256 over the UTF-8 concatenation of `"{path}\0{sha256}\n"` for each entry in sorted order — deterministic, order-independent, one string to compare. Keep the existing per-entry 64-hex validation and the existing refusal semantics; a mismatch must name the path that changed (the UI and the rescue converter both need that). Keep `bind_cache_transaction_to_project_write` idempotent: identical set → no-op returning the existing digest; different set on an already-bound transaction → refuse.

    Paths stored in the marker are PACKAGE-RELATIVE (e.g. `project.mce`, `layers/L1.json`, `frames/L1/K1.webp`); resolve them against the package root only through the guard from plan 01 so a bound set can never reference anything outside the package.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Marker file on disk → Rust commit path | A marker written in a previous session is untrusted input at bind time |
| Package root vs machine cache root | Two different filesystem roots that must not be confused |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-14 | Tampering | transaction marker `expected_files` entries | high | mitigate | Every entry's `sha256` is validated as 64 lower-case hex at parse time and every path is resolved through the plan-01 package guard; a mismatch refuses the commit and names the path — a doctored marker can only refuse, never redirect a write. |
| T-52.2-15 | Tampering | partial multi-file commit | high | mitigate | The transaction keeps the shipped staging → hardlink → fsync → single atomic swap → digest-bound commit sequence; all bound files commit or none. Rollback restores pre-save content for every bound file, covered by an explicit test. |
| T-52.2-16 | Denial of Service | cache write failure blocking a save | medium | mitigate | The cache leg returns a typed soft failure (D-14) and the authoritative commit proceeds; asserted by a test that points the cache root at an unwritable location. |
| T-52.2-17 | Information Disclosure | cache written inside the package | medium | mitigate | The machine cache root is resolved once from the app data dir in `lib.rs` and passed explicitly; `create_project_dir` no longer creates a package-local `cache/`, so no machine-local derived data can be committed to the package. |
</threat_model>
