<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| TS/renderer → Rust command | A `relativePath`/`layerId`/`keyId` string supplied by application code crosses into filesystem access |
| Filesystem → Rust read | A file at the target path could be a symlink or a non-regular file placed by anything on the machine |
| Rust → TS | Raw bytes cross back over IPC |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-01 | Tampering | `resolve_package_media_path` / `resolve_package_bound_path` / `safe_frame_media_relative_path` | high | mitigate | Reject ids containing `/`, `\`, NUL, `.`, `..`; require the `frames/` prefix on the media guard (never widened for the transaction's JSON files); the bound-path guard carries its own `project.mce` \| `layers/*.json` \| `frames/*.webp` allowlist and delegates every `frames/` entry back to the media guard; both canonicalize and require `starts_with(package_root)`, enforce on write and read side, and never accept a caller-supplied root (the staging root is derived from the validated basename). Mirrors `resolve_efxasset_path` and `isSafeEfxPaintCachePath`. |
| T-52.2-02 | Elevation of Privilege | read path via symlink swap | high | mitigate | Canonicalize the resolved path (not just the parent), require `Path::is_file()`, re-check the `starts_with` root after canonicalization, and restrict to the `.webp` extension — a symlink pointing outside the package is refused with `PathEscape`. |
| T-52.2-03 | Information Disclosure | error strings returned to the renderer | low | accept | Rejection variants are fixed enum labels with no filesystem detail; the full path is never serialized back. Rationale: no cross-user boundary exists in a single-user desktop app. |
| T-52.2-04 | Denial of Service | unbounded read of an arbitrary `.webp` | low | accept | The command only reads paths under `frames/` inside a package the user opened; no cap is imposed because real keys are already bounded by the 52.1 cap 1920 and lossless WebP limits. |
</threat_model>
