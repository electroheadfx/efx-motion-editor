## Decisions Made

- **The persisted mode lives at the read door, not inside the parser body.** `parseEfxPaintDocument` is not only the on-disk door — it validates the live in-memory document on the save, fingerprint and launch paths. An unconditional persisted rule produced 116 failures across 15 files. The mode is therefore a parameter whose default is the runtime shape, selected once by `loadEfxPaintDocuments`.
- **One record type, two carriers.** `bytes` became optional with `media` as the alternative rather than splitting the payload type — one record type, one parser, one mode parameter, which is what makes the group-override collection covered by construction (D-06).
- **Content identity is total over both shapes.** `buildPhysicPaintRotoPayloadContentToken` returns the byte token for a runtime payload and `media:<digest>` for a persisted one, so revision, project-equality, dedup pruning and the bridge's ref expansion keep working across a reopen without dereferencing the raster carrier.
- **A runtime projection that meets a reference-only record throws.** `requirePhysicPaintRotoInlineBytes` refuses loudly rather than handing the compositor an empty buffer, which would be silent corruption (Law 1).
- **The manifest refuses layer content rather than sanitizing it.** `efx_paint_documents` is dropped (its content is now the layer sub-files); `tracks`/`background`/`photoReference` throw, because their presence means a layer document reached the manifest call.
