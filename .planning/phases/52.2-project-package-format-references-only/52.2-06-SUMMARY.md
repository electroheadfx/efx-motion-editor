## Decisions Made
- **Optional resolver on the serialize seam.** The plan said "add it as a parameter/input"; making it REQUIRED would have broken every live caller outside this plan's file list (`projectStore`, `PhysicsPaintStudio`, `_projectTrackRuntime`) and `efxPaintStore.test.ts`'s no-resolver round trip. Supplied (plan 07's funnel) the projection is mandatory and fail-closed; omitted, records pass through with bytes. The fail-closed truth is intact on the projection path: `resolveRef(keyId) → undefined` is a typed failure, never a payload fallback.
- **Fail-closed guard names the keyId at the hydrate seam** rather than relying on the canonical parser, whose refusal ("malformed real-key record") cannot name the record the plan requires.
- **Typed refusal on the paste path** (`unresolved-key-pixels` added to `RotoTrackSelectionFailureReason`; the three paste callers now propagate `applied.reason`). No UI consumer switches exhaustively on that union, so the addition is contained in the store.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] `buildFreshKeyRecord` dropped the source's raster carrier**
- **Found during:** Task 3 (paste refusal case)
- **Issue:** `physicsPaintRotoRailSetCopy.ts` built every fresh paste/duplicate record with `bytes: sourcePayload.bytes`. With a reference-only source (reopened document) that produced a payload with NEITHER carrier, so `proposeRails` threw `PhysicPaintRotoRealKeyRecordCollection: malformed real-key record` instead of returning a refusal — an unhandled throw on a user path, and no way to distinguish "no pixels yet" from a corrupt document.
- **Fix:** preserve exactly the carrier the source carries (`media` when present, `bytes` otherwise) plus dimensions. A duplicated key renders the same pixels, so its media reference names the same digest; the save projection re-points it at the fresh keyId.
- **Files modified:** `app/src/components/physic-paint/roto/physicsPaintRotoRailSetCopy.ts`
- **Verification:** `physicPaintStore.test.ts` refusal case + the positive duplicate case; full suite shows no new failures.
- **Committed in:** `3e238558` (Task 3 GREEN)

**2. [Rule 2 - Missing Critical] Carrier guard at the hydrate boundary**
- **Found during:** Task 3 (the plan's "group override missing `media` is refused naming the keyId")
- **Issue:** The document→store boundary (a trust boundary named in the plan's own threat model) accepted a record with neither carrier until the canonical parse, whose refusal is generic and names no keyId — the plan's acceptance requires the keyId.
- **Fix:** `_assertRotoPhysicalDocumentCarriers` runs over both collections before the parse and names the offending record.
- **Files modified:** `app/src/stores/physicPaintStore.ts`
- **Verification:** `physicPaintStore.test.ts > refuses a group-override record carrying neither media nor bytes, naming the keyId`.
- **Committed in:** `3e238558` (Task 3 GREEN)

**3. [Rule 3 - Blocking] Paste refusal needed a typed reason the caller can see**
- **Found during:** Task 3 (T-52.2-20 mitigation)
- **Issue:** `_applyRotoTrackPaste` returned `reason: string` and its three callers collapsed every failure to `'apply-failed'`, so a refusal "with a typed reason" was not observable at the API.
- **Fix:** typed the helper's reason as `RotoTrackSelectionFailureReason`, added `'unresolved-key-pixels'`, and propagated `applied.reason` in `pasteTrackSelection` / `duplicateTrackFrames` / the cross-track paste.
- **Files modified:** `app/src/stores/physicPaintStore.ts`
- **Verification:** the refusal case asserts `reason === 'unresolved-key-pixels'`.
- **Committed in:** `3e238558` (Task 3 GREEN)
