# Phase 52.2 Plan 10: Reference-Shaped Document Sync and the Digest-Keyed Byte Channel

**The Studio→main document sync now crosses reference-shaped with a digest-keyed byte channel that ships pixels only for content the receiver does not already hold, and the receiver installs arriving bytes only after re-hashing them against the digest that carried them**

## Performance

- **Duration:** ~30 min (first plan commit 18:06Z → close-out 18:35Z)
- **Started:** 2026-09-12T18:06:05Z
- **Completed:** 2026-09-12T18:35:00Z
- **Tasks:** 3 (all TDD: RED → GREEN each)
- **Files modified:** 10 source files (5 implementation + 5 suites) + 3 RED-evidence artifacts

## Accomplishments

- The sync payload is now reference-shaped: both roto collections project to `{ relativePath, digest, width?, height? }`, and the only pixel carrier is `changedBytes`, keyed by the digest a save would persist.
- The byte channel is selective in both directions — the sender withholds digests it has delivered or been told the receiver holds, and the receiver answers held-ness from `frameLru` + the bridged-bytes map without a decode or a file read.
- The digest is simultaneously the identity and the verification: `installFrameMediaBytes` re-hashes every arrival, records a `digest-mismatch` verdict and stores nothing on a mismatch.
- One request per digest, ever: `_documentSyncRequestedDigests` makes a re-delivered sync exactly as cheap as the first one, which is the T-52.2-35 retry law.
- The apply channel feeds the same claim — the receiver installs the raster it just materialized, so its answer to a later sync is truthful for frames that never crossed the document channel.
- The request event `physic-paint:frame-media-request` exists as a Tauri-guarded main→Studio signal (responder deferred to plan 14, see D6).

## Decisions Made

- **The digest decision runs before the revision guard.** A re-pushed unchanged document may still carry bytes the receiver lost; the guard would have returned before the byte channel was read.
- **Bridged bytes stay undecoded** in `_frameMediaBytes` and enter the LRU only when the compositor needs the frame, then the byte copy is dropped so a bridged frame is never held twice.
- **The apply path installs what it materialized.** The changedBytes optimization is only sound if every path that delivers a raster updates the receiver's claim; the apply channel is one of those paths.
- **The coordinator's mark is an optimization claim, not a delivery gate** — it runs after a successful send and a marking failure is swallowed.
- **The request leg ships as a protocol signal only.** The responder belongs to the sender's queue, which plan 14 restructures; building a Studio-side responder here would have reached outside this plan's file list. Recorded as D6 plus a deferred-items entry.
- **The byte channel stays raw until the emit boundary**, so the transcode tokens remain inside the D-19 allowlist (`webpBytes.ts`) instead of entering the transport module.

**1. [Rule 2 - Missing Critical] Store seam for bridged bytes**

- **Found during:** Task 3 (receiver applies by digest)

**2. [Rule 2 - Missing Critical] One SHA-256 implementation**

- **Found during:** Task 3 (GREEN of the install verification)
- **Issue:** The transport held a private `sha256Hex` while the store needed the identical hash to verify an arrival; two implementations could drift, and T-52.2-33/34 require the bridge digest, the install check and the persisted digest to name the same content.
- **Fix:** Extracted `sha256HexBytes` into the allowlisted `app/src/lib/webpBytes.ts` (copy-then-hash, keeping the hash off a larger backing buffer) and delegated the transport's private helper to it.
- **Files modified:** `app/src/lib/webpBytes.ts`, `app/src/components/physic-paint/bridge/physicsPaintBridgeTransport.ts`, `app/src/stores/physicPaintStore.ts`

## Known Boundaries

- **The request leg has no responder yet.** `requestDocumentSyncFrameMedia` emits `physic-paint:frame-media-request` to the Studio window (Tauri-guarded), but nothing answers it. The retry law still holds — the sender's delivered marks withhold what it shipped — so only a receiver that loses bytes mid-session waits for the next push. The responder rides the sender's queue, which plan 14 (pilot) restructures.
- **The bridged-bytes map survives until `reset()` or a decode.** A digest that is installed but never decoded holds its bytes for the session; it is dropped either when the compositor decodes it or on `reset()`.

The plan's defect entries (the D-19 auto-fix, the deferred request-leg responder) are therefore recorded in this SUMMARY and in `deferred-items.md` instead of the cross-phase register.
