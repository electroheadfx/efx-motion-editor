<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| On-disk project file → refusal gate | A user-supplied file of unknown vintage is parsed before anything else happens |
| Legacy project → rescue converter | A dev tool reads a file whose payloads were never validated by the new format |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-25 | Tampering | refusal gate bypass leading to a half-loaded project | high | mitigate | The gate stays at the existing `openProject` position (after the read, before any sidecar IO or store mutation) with fixed precedence and a non-throwing contract; the refusal test asserts deep state equality before/after, so a partial load is a test failure. |
| T-52.2-26 | Spoofing | a crafted `formatVersion` claiming to be current | medium | accept | Version acceptance only decides which reader runs; the parser (plan 02) then fails closed on any record that does not match the current shape, so a spoofed version cannot smuggle an old shape through. |
| T-52.2-27 | Information Disclosure | the rescue converter's output retaining payloads | medium | mitigate | The converter's verify gate greps the emitted package for payload-shaped strings; a partial conversion exits non-zero instead of silently dropping keys. |
| T-52.2-28 | Tampering | rescue converter shipped in the bundle | low | mitigate | The script lives outside `app/src` with no reference from `package.json`, `tauri.conf.json` or the build, asserted by grep in the acceptance criteria (D-08: not shipped code). |
</threat_model>
