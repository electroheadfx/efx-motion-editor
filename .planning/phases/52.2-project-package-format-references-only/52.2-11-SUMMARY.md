# Phase 52.2 Plan 11: macOS Document-Package Treatment

**`Name.mce` is now declared to macOS as a document package — one hand-authored Info.plist, a `RunEvent::Opened` receiver with a cold-start buffer drained once through a pure dedupe queue, and both the OS-opened and dialog-chosen paths converted from the package directory to the manifest inside it**

## Accomplishments

- `app/src-tauri/Info.plist` is the single source of the `.mce` document type: `CFBundleDocumentTypes` with `LSTypeIsPackage` true (role Editor, rank Owner, extension `mce`) and `UTExportedTypeDeclarations` declaring `com.efxlab.motion-editor.project` conforming to `com.apple.package` — the declaration that makes Finder present `Name.mce/` as one document.
- `packageAssociationContract.test.ts` (8 cases) is the automated judge the plan asked for: it validates the plist with Apple's own reader (`plutil -lint` / `-convert json`, darwin-guarded) and, portably, as text — and it fails the moment a second declaration appears in `tauri.conf.json`, which is the shallow-merge trap.
- The Rust side now builds with `tauri::generate_context!()` `.build()` + `.run(|app, event| …)`: `RunEvent::Opened` (cfg-gated to macOS/iOS/Android) buffers URLs until the frontend declares readiness and emits them after, via a managed `OpenedUrlsState`; `opened_urls` drains the buffer and flips the ready flag in one step.
- The frontend registers `listen('opened')` next to the menu listeners and drains the cold-start buffer once, routing both channels through `createOpenedUrlQueue()` so a double delivery cannot open twice — and both paths hand the result to the same guard + open handler the menu path uses.
- The dialog legs now name the package: `NewProjectDialog` creates `${dir}/${name}.mce` (a directory) and saves the manifest inside it; `Toolbar`'s save-as keeps `defaultPath: ${name}.mce` and converts the chosen path before the store call.

## Decisions Made

- **One declaration site, hand-authored.** Tauri's plist merge is a shallow top-level overwrite and `bundle.fileAssociations` cannot express `LSTypeIsPackage`; splitting the declaration would silently erase the package flag.
- **No document-type icon reference.** The bundle ships app icons only; the contract test refuses a `CFBundleTypeIconFile` that does not resolve to a declared `bundle.icon` asset, so none was invented.
- **Dedupe scope is the pending set.** A URL delivered while a project is open still reaches the caller — the module never discards a request it cannot prove it already served.
- **The module judges namability, not validity.** Suffix and scheme only; a loose `.mce` file is passed to plan 08's refusal gate rather than dropped here.
- **`opened_urls` is drain and ready-signal in one.** The native side switches to live emission as the drain returns, so the cold/warm pair cannot double-deliver by timing.
- **The package→manifest conversion lives at this plan's call sites**, not in `projectStore.ts` (outside `files_modified`; its convention is pinned by plan 09's cutover tests).
- **The opened-package handler runs the unsaved-changes guard**, matching the menu path.

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing Critical] Package-directory → manifest-file conversion (`toPackageManifestPath`)**

- **Found during:** Task 3 (the open handler and the dialog legs)
- **Issue:** The OS, the open dialog and the save-as dialog all name the PACKAGE (`Name.mce`, a directory), while `projectStore.openProject`/`saveProjectAs` read the FILE at the path they are handed and take its dirname as the package root. Handing a directory to `openProject` fails (the Rust leg is `fs::read_to_string` → EISDIR), and `saveProjectAs(packageDir)` would write the package at the package's PARENT. Without a conversion, neither the Finder double-click nor the dialog legs could open or save a project — the plan's own acceptance criteria.
- **Fix:** `toPackageManifestPath` in the new pure module (a path already naming the manifest, or not ending in `.mce`, is returned untouched for the refusal gate), applied at every call site inside this plan's `files_modified`: `main.tsx`'s `openPackageFromPath`, `Toolbar.tsx`'s open and save-as legs, and `NewProjectDialog`'s create leg.
- **Files modified:** `app/src/lib/openedProjectUrls.ts`, `app/src/lib/openedProjectUrls.test.ts`, `app/src/main.tsx`, `app/src/components/layout/Toolbar.tsx`, `app/src/components/project/NewProjectDialog.tsx`
- **Verification:** 3 conversion cases; `tsc --noEmit` clean; full suite no-new-reds.
- **Committed in:** `3a765aef` (module + cases) + `a87c70d8` (call sites)

**2. [Rule 3 - Blocking] TAP summary lines for the RED evidence gate**

- **Found during:** Task 1 RED (the `check tdd-red-evidence` gate)
