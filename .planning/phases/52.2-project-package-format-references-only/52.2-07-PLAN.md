<objective>
Replace the single-document save with the package save: stage only the files whose content changed into the package staging root (per-file change tokens extending `savedFrameTokens`, D-11), publish and commit the whole set through the extended transaction (D-10), and never serialize the project as one string again (spec §6). Layer granularity holds structurally because a layer sub-file contains exactly that layer's document (D-09). The same plan converts the persisted derived-frame cache reference to its machine-relative shape (D-05) — the producer in `efxPaintStore.ts` and the guard in `efxPaintPersistence.ts` are one invariant and cannot land in separate plans without a red intermediate state.

Purpose: this is the plan that kills the measured ~4.6 s `persist.serialize` term. Everything after it — refusal gate, read-back, bridge — assumes the package exists on disk in this shape.

Output: the extended `efxPaintPersistence` funnel staging manifest + layer sub-files + media and committing them through plan 05's transaction, machine-relative cache references at every producer, `saveProject`/`saveProjectAs` orchestration, and per-file telemetry.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime state → package files | Money-equivalent user content is written here; a partial write loses work |
| Package files → future readers | Whatever is written must be readable by the read-back leg and acceptable to the parser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-21 | Tampering | partial multi-file save | critical | mitigate | Every authoritative file is written into the staging generation and reaches its canonical path only through plan 05's publish step; the staged set is bound with the aggregate digest and committed as one, and any refusal settles with rollback. Nothing canonical is written before the transaction, so the pre-save package survives — asserted by the refusal case against a pre-save byte snapshot. |
| T-52.2-22 | Information Disclosure | raster payloads or machine-local paths in emitted JSON | high | mitigate | The save's own cases scan the staged strings for base64-shaped payloads and for absolute/backslash/drive-letter paths, and the read-back leg's on-disk round-trip case (plan 09) repeats the scan against every emitted file; the parser (plan 02) refuses payload-carrying records on the way back in, so a leak fails both directions. |
