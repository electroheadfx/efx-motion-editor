<objective>
Replace the single-document save with the package save: write only the files whose content changed (per-file change tokens extending `savedFrameTokens`, D-11), commit the whole set through the extended transaction (D-10), and never serialize the project as one string again (spec §6). Layer granularity holds structurally because a layer sub-file contains exactly that layer's document (D-09).

Purpose: this is the plan that kills the measured ~4.6 s `persist.serialize` term. Everything after it — refusal gate, read-back, bridge — assumes the package exists on disk in this shape.

Output: the extended `efxPaintPersistence` funnel, `saveProject`/`saveProjectAs` writing manifest + layer sub-files + media, and the round-trip contract test.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime state → package files | Money-equivalent user content is written here; a partial write loses work |
| Package files → future readers | Whatever is written must be readable by the read-back leg and acceptable to the parser |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-52.2-21 | Tampering | partial multi-file save | critical | mitigate | Every emitted file joins one bound transaction (plan 05) with the aggregate digest; nothing is renamed into place until the whole set is staged, and a refusal leaves the pre-save tree intact — asserted by the rollback case. |
| T-52.2-22 | Information Disclosure | raster payloads or machine-local paths in emitted JSON | high | mitigate | The round-trip test scans every emitted file for base64-shaped strings and for absolute/backslash/drive-letter paths; the parser (plan 02) refuses payload-carrying records on the way back in, so a leak fails both directions. |
| T-52.2-23 | Repudiation | a save silently rewriting unchanged files | medium | mitigate | The change set is asserted as an exact token set and the unchanged-save case asserts an empty write list, so "only changed files" is a test-observable contract rather than an intent. |
| T-52.2-24 | Denial of Service | whole-project serialization creeping back | medium | mitigate | Telemetry is split into per-file stages (`persist.manifest`, `persist.layers`, `persist.media`, `persist.commit`) so a regression to one big serialize shows up as a single dominant stage in the Gate 4 comparison instead of hiding inside `persist.total`. |
</threat_model>
