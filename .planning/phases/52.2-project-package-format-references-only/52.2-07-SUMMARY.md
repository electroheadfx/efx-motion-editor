# Phase 52.2 Plan 07: The package save Summary

**`savePackage` stages the manifest, one `layers/<layerId>.json` per changed layer and one `frames/<layerId>/<keyId>.webp` per changed key of both roto collections, then commits the whole set through one package transaction — and a no-op save writes nothing at all**

## Accomplishments

- **The single-document save is gone.** `saveEfxPaintDocumentsWithProjectWrite` is deleted; `savePackage(packageDir, input)` is the one funnel, and no step serializes the whole project into one string.
- **Change sets are per file.** `computeChangedFiles` over the token space `frame:<layerId>:<keyId>` / `layer:<layerId>` / `manifest` means a second identical save writes nothing — no staging root, no bind, no publish, no manifest — while a repaint still refreshes the derived frames through the best-effort cache leg.
- **One transaction owns the authoritative set.** Media lands first (the sub-file carries the digest the native write returned), then the layer sub-files, then the manifest; bind → publish → settle('commit'), with rollback-and-rethrow on any refusal leaving the canonical package byte-identical.
- **The derived-frame cache reference speaks one shape end-to-end** — `efx-paint/<layerSegment>/<trackId>/frame-NNNN.webp` — produced by every producer, accepted by the guard, and the legacy package-relative value refused at intake.
- **Both call sites settled the dead parameter plan 05 left behind:** neither `saveProject` nor `saveProjectAs` passes a cache transaction id any more, and the source-shape assertions moved with them rather than being deleted.
- **The eight known-red tests this plan owned are green** (7 roto round-trips + the persistence round-trip), and the collateral suites that drive the real save were retargeted onto the package surface.

## Decisions Made

- **The bound set is the publish set.** Every staged media path is pushed onto the staged set before the bind, so a reference can never reach a sub-file while its bytes stay behind in the staging generation.
- **A no-op save still runs the cache leg, and only the cache leg.** A repaint moves derived frames without moving any document token; skipping the leg on an empty change set would publish stale derived frames (D-14 best-effort preserved).
- **The Save As script-library step keeps its own transaction.** The package funnel commits the destination package, then `projectSaveAsWithScriptLibrary` re-publishes the same manifest for the library migration — two transactions, not one.
- **The duplicate-keyId refusal is asserted at the save's intake**, because a document re-read from disk is data: the save never trusts its caller.
