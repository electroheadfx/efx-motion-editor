## Decisions Made

- **The port is a forced capture-queue drain, not `flushLivePixels`.** The pipeline forces the gate and settles the gesture's queued captures itself; parent deliveries (and their retries) stay inside the caller's step 2. This keeps the plan's "changes who schedules the steps, not what they do" literally true — no delivery behavior moved into the port.
- **Join returns the same promise object.** The in-flight drain *is* the answer for every concurrent caller, so the outcome object is shared and the close block cannot observe a different result than the requested flush it joined.
- **Outcome-not-rejection settlement, caller owns the throw.** The pipeline resolves on failure/interruption; the Studio runner (`if (outcome.status === 'flushed') return; throw …`) rethrows so the facade still emits 'unavailable' and the close hook still logs its error path. Both call sites share this one translation, so the two paths cannot diverge.
- **Interruption races the port drain.** `interrupt()` bumps a generation, calls `port.interrupt()` and resolves an interrupt wake; the drain races the forced drain against that wake and re-checks the generation before every step — a port whose work never settles cannot hold a Save/Export hostage (T-52.2-48), and an interrupt that lands mid-step is observed at the next step boundary.
- **The retry turn is `beginFlush`-wrapped.** A retry can run mid-gesture; without the forced flush its turn would park on the machine gate and deadlock the very flush that awaits it. The wrapped turn settles through the queue's never-rejecting contract, and the loop's own error check still throws the delivery error for the fail-closed paths.
- **The retry queue is created lazily, not via `useRef(createFinalizationQueue())`.** The codebase's eager-ref idiom would build an Effect queue (and its `Queue.bounded` `runSync`) on every Studio render and discard all but the first; the null-check init makes the first call the only one.
