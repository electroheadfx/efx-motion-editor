### Group Copy/Paste Status Capsule Copy (this phase)

Reject copy names the operation and reason concisely; full detail goes to LOG:

| Situation | Copy |
|-----------|------|
| Group copy accepted (2+ keys) | `Copied {N} keys` |
| Single copy (exactly 1 key) | existing single-key copy feedback — unchanged |
| Group paste accepted | `Pasted {N} keys` |
| Group paste rejected (destination collision) | `Paste rejected — key in the way` |
| Group paste rejected (range/capacity) | `Paste rejected — not enough room` |
| Group paste busy (acknowledged transaction pending) | `Pasting keys…` |
| Paste unavailable (empty clipboard) | Guarded tooltip carries the verbatim controller reason per the 36.15 guarded-state grammar; no capsule entry until activation is attempted |

### Status Capsule Idle Context (this phase, D-08..D-10)

The static `Missing frames play transparent/background` baseline is **deleted**. When idle (no pending operation, saving indicator, or guard/action feedback), the capsule shows a current-cell context line that follows navigation/selection:

| Current cell state | Idle context line |
|--------------------|-------------------|
| Real Roto key (with or without cached paint) | `Real Roto key · Frame {n}` |
| Generated interpolation cell | `Generated frame · Frame {n}` |
| Empty cell | `Empty frame · Frame {n}` |

Rules: the idle context line never shows missing-frame information as filler (D-08); missing-frame information is event-driven only — it may appear when an active playback/export makes it factually relevant (existing playback status lines in `useRotoCachedPlayback` remain the event-driven surface, D-10); the detailed explanation stays in LOG. The capsule stays one line with ellipsis truncation; fixed controls never move.

### Tooltip Copy (unchanged grammar, new rendering)

All existing tooltip strings (guarded-action grammar `Name — unavailable: {verbatim controller reason}`, per-cell semantic state copy, Select All, key utilities, script utilities) are unchanged. The only change is rendering: text wraps to multiple lines instead of truncating with `...`. Tooltip content remains Preact text children only — controller strings are never injected as HTML (T-36.15-01).

## Interaction Contract

### Group Copy (D-01..D-03)

- **Exactly 1 key selected**: Copy is today's single-key copy, unchanged (guard, tooltip, feedback, clipboard shape).
- **2+ keys selected**: Copy captures the whole group. This supersedes Phase 37 D-16 for the multi-selection case only; Duplicate, Insert, and Paste targeting rules from 37 D-16 are otherwise untouched.
- **One shared clipboard slot**: group Copy overwrites a single-key clipboard and vice versa — one "copied paint" concept, immutable and reusable until the next Copy or disposal (the approved 260715-kgf clipboard mental model).
- Each copied group entry captures an **immutable payload snapshot + source physical appFrame + stable source keyId provenance**. Relative offsets are derived from the source appFrames at paste time; no separate offset table.
- Copy is not a mutation: no transaction, no history entry, no dirty state. Feedback is the `Copied {N} keys` capsule line only.

### Group Paste (D-04..D-07)

- Paste targets the **current editing cell** (destination-based, unchanged), including while a multi-selection is active.
- The **earliest copied key anchors the group** at the destination; every other copied key lands at destination + its relative physical offset.
- **All-empty-or-reject collision policy (D-05)**: if ANY computed destination cell is occupied by an existing real key, the whole paste is rejected atomically with `Paste rejected — key in the way` (detail in LOG). Group paste never overwrites — deliberately unlike single paste's replace-style behavior. Out-of-range or over-capacity computed destinations reject atomically with `Paste rejected — not enough room`.
- **Exact frames, zero ripple (D-06)**: group paste places keys at exact computed frames and never shifts existing keys. Landing on a generated cell is valid — it becomes a real key and neighbors re-derive per the 36.12 render-only contract.
- Every pasted key gets a **fresh keyId**. The whole paste is **one accepted transaction and exactly one Undo/Redo action** through the existing accepted-only history — preview-free explicit apply through the generic coordinator, like existing paste.
- **Post-paste selection (discretion adopted)**: the pasted group becomes the selection with the earliest pasted key as the current editing key, mirroring 37 D-06/D-17 aftermath patterns; focus and minimal scroll follow the earliest pasted key's cell per the existing focus-follow rule.
- On reject: zero partial mutation; selection, map, and clipboard are fully preserved; clipboard remains reusable for another destination.

### Tooltip Placement (D-11, D-12)

- **Opposite-of-element-position** for all styled tooltips, computed from the source element's UI region:
  - Elements at the bottom of the UI (bottom action row, tube/log) → tooltip **above**.
  - Elements at the top (header controls, status capsule) → tooltip **below**.
  - Elements at the right edge (right sidebar controls) → tooltip to the **left**.
  - Elements at the left edge → tooltip to the **right**.
- Tooltips are **viewport-positioned** (fixed/portal-style coordinates), not absolutely positioned inside the strip. This replaces the 36.15 Gap B in-strip `placement='below'` workaround while preserving its visual outcome for header controls (top-of-UI elements still show below). The exact mechanism (portal vs fixed positioning) is planner discretion provided behavior here and the T-36.15-01 text-children rule hold.
- **Viewport clamp**: every tooltip is clamped inside the viewport with an `8px` margin on all sides; when the preferred side lacks room, the tooltip flips to the opposite side before clamping.
- One shared direction-aware placement computation is consumed by every `PhysicsPaintStyledTooltip` mount — header, capsule, cells, action rows, sidebar. No per-mount hand placement.

### Tooltip Notch (D-13)

- A small triangular notch (`10px` base × `6px` height) sits on the control side of the pill, centered on the source control, pointing at it.
- The notch flips direction with placement (up/down/left/right) and uses the same `#20262D` fill so pill + notch read as one shape.
- Viewport clamping shifts the pill within bounds; the notch stays centered on the source control (notch offset tracks the control, not the pill center).

### Tooltip Multiline (D-14)

- Tooltip text **wraps to multiple lines**: `max-width: 280px`, `max-height: 96px` (8 lines at 10px/1.2), **no internal scroll** — overflow is a copy defect to fix by shortening the string, never by scrolling.
- The `...` ellipsis truncation inside tooltips is removed entirely.
- Interaction contract preserved verbatim from 36.15: exactly `1000ms` hover delay, instant show on keyboard focus, Escape hides (listener registered only while visible with idempotent cleanup), Preact text children only, compact timeline geometry intact.

### Delivery and Validation Sequence (D-15, D-16)

- Production implementation first; **native user-owned UAT is blocking** before any regression test creation, modification, deletion, renaming, or execution. After explicit UAT approval: deterministic regression coverage with `vitest run` (never watch mode), then typecheck, then build. The agent does not launch the server, browser, or native app — the user runs the server.
- No sourceFrame/displayFrame compatibility, migration code, forwarding wrappers, aliases, dual-write paths, or second timing authority. Stable keyId + direct appFrame remains the only durable physical ownership model.

## Status and LOG Routing (inherited, restated with new arbitration)

- Capsule priority model: pending operation > saving indicator > guard/action feedback > **idle current-cell context** (new lowest rung, replacing the deleted static baseline).
- Group-paste rejects show only the concise copy from the Copywriting Contract; full resolver/validation diagnostics (which destinations collided, computed offsets, capacity numbers) go only to the LOG tab (36.14 D-26).
- Copy (single or group) is not a mutation: its feedback line appears under guard/action feedback and never touches dirty state or history.
- The capsule never grows the strip, never pushes control groups off-screen, truncates with ellipsis; LOG remains the running diagnostic surface with no automatic tab switching.

## Preact and State Ownership Contract

Presentation receives (additions to the 37 list): clipboard availability/reason ports for Paste, group-copy feedback strings, the current-cell descriptor for the idle context line (cell state + physical appFrame supplied by the strip from its existing cell/selection ports — the selector stays pure), and the resolved tooltip placement per mount.

Presentation emits user intent only: copy (single or group — the controller resolves which from the selection set), paste at current cell, and all existing actions. The view never branches on selection size to decide copy semantics; it forwards one Copy intent.

Presentation must not own: clipboard entry shape or immutability, relative-offset computation, collision/capacity validation, transaction construction, acknowledgement matching, rollback, history, persistence, cache publication, generated-cell derivation, or the tooltip placement policy table (the direction computation is a shared presentational utility; the *content* and *availability* come from controllers).

Group clipboard state lives at the Roto controller/hook boundary alongside the Phase 37 selection state — never in the view. Use Signals/computed for view state; no `useEffect` chains copying controller clipboard/selection state into local view state.

## Responsive Contract (inherited, unchanged)

- One header row at every host-supported width; the status capsule alone absorbs width changes.
- The bottom action row stays fit-content and non-wrapping in its 34px band; below minimum host width the strip scrolls horizontally.
- Viewport-positioned tooltips must respect the clamp at every window size, including minimum host width.
- No cell scaling, density breakpoints, overflow menus, or hidden groups.
