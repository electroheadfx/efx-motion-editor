--- USER-OWNED NATIVE UAT SCRIPT (Phase 38) ---

Setup: open a project with a Physics Paint layer that has at least 4 real Roto keys (some adjacent, some spaced) plus generated interpolation cells between them. If you need keys, paint or duplicate a few first.

A. Group Copy (plans 38-01)
1. Select exactly ONE real key and Copy: the capsule shows the usual single-key line `Copied key {n}.` — unchanged from before this phase.
2. Multi-select 2+ real keys (Ctrl/Cmd-click) and Copy: the capsule shows `Copied {N} keys` with N = your selection size. No timeline change, no dirty state.
3. Copy a group, then copy a single key, then re-copy the group: each Copy silently replaces the clipboard; Paste availability never flickers or disappears.
4. Select keys, delete one of the source keys, then Copy again with a fresh selection: nothing stale happens (if you ever see `The selected Roto keys are no longer available.`, that is the correct guard, not a bug).

B. Group Paste — accept path (plans 38-02/38-04)
5. Copy 2+ keys, click an EMPTY destination cell with enough empty room after it, Paste: the capsule shows `Pasted {N} keys`; the earliest copied key lands on the destination cell and the others land at the same relative spacings as the source; every pasted key is a NEW key (editing one does not affect the source keys).
6. Immediately Undo once: the WHOLE pasted group disappears in one step. Redo once: the whole group returns in one step. (One paste = exactly one Undo/Redo action.)
7. Paste onto a destination whose landing cells include GENERATED interpolation cells: the pasted keys become real keys there and the surrounding generated cells re-derive — nothing breaks visually.
8. After a successful paste: the pasted group is the selection, the earliest pasted key is the current editing key (accent highlight), and the timeline scroll/focus follows it. The clipboard stays reusable — Paste again at another empty destination without re-copying.
9. During the paste you may briefly see `Pasting keys…` in the capsule; it is always replaced by the success or reject line.

C. Group Paste — reject paths (plans 38-02/38-04)
10. Copy 2+ keys, choose a destination where ANY computed landing cell is already occupied by a real key, Paste: the whole paste is rejected — capsule shows `Paste rejected — key in the way`, NOTHING on the timeline changes, your selection and clipboard are preserved, and the LOG tab carries the detailed reason.
11. Copy a wide group and aim it near the end of the timeline so it would overflow (or fill the timeline near capacity): capsule shows `Paste rejected — not enough room`, nothing changes.
12. After each reject, Paste again at a valid empty destination: the same clipboard still works (no re-copy needed).

D. Single-key paths unchanged (plans 38-01/38-04)
13. Copy exactly 1 key and Paste onto an occupied cell: today's replace-style single paste behavior is unchanged.
14. Single-key Copy/Paste/Undo/Redo feel and feedback lines are identical to before this phase.

E. Status capsule (plan 38-03)
15. With nothing running, click a REAL key cell: capsule shows `Real Roto key · Frame {n}` with that cell's frame number.
16. Click a GENERATED interpolation cell: capsule shows `Generated frame · Frame {n}`.
17. Click an EMPTY cell: capsule shows `Empty frame · Frame {n}`. Navigate around: the line follows the current cell.
18. The old permanent `Missing frames play transparent/background` line NEVER appears as idle filler — not on real keys, not anywhere while idle.
19. Start cached playback with missing frames present: missing-frame information may appear DURING playback (event-driven) and disappears back to the idle context line when playback stops.
20. Trigger any action feedback (Copy, a rejected Paste, etc.): the feedback line wins over the idle context line, then the idle context returns.

F. Tooltips (plan 38-05) — includes the two UI-SPEC backstop items
21. Hover (1 second) a HEADER control (status capsule area, interpolation control, close button): tooltip appears BELOW the control.
22. Hover a CELL tooltip and each BOTTOM ACTION ROW icon (add, duplicate, insert, copy, paste, delete, select-all, apply): tooltips appear ABOVE.
23. Hover the SCRIPTS panel buttons (right sidebar): tooltips appear to the LEFT of the buttons.
24. Every tooltip has a small dark triangular NOTCH pointing at its source control, same dark fill as the pill — pill + notch read as one shape, in all directions seen above.
25. Hover a guarded action with a long reason (e.g. Paste with an empty clipboard): the text WRAPS to multiple lines inside a bounded pill — no `...` truncation, no scrollbar.
26. BACKSTOP 1 — viewport clamp/flip: move/resize the window so a control sits near a window edge (including minimum window width): the tooltip stays fully inside the window (about 8px margin) and flips to the other side when the preferred side has no room.
27. BACKSTOP 2 — notch tracking when clamped: in the clamped situations above, the notch still points at its source control even when the pill body has been shifted sideways by the clamp.
28. Scroll the timeline horizontally with a tooltip source visible, then re-hover: the tooltip tracks the control's new position correctly.
29. Keyboard: tab-focus a guarded control — its tooltip shows instantly; Escape hides it; Escape again (no tooltip visible) keeps the Phase 37 collapse-selection behavior.

G. Downstream parity spot-checks (plan 38-04, requirement 38-DOWNSTREAM-PARITY)
30. After a group paste, SAVE the project, close, and REOPEN: all pasted keys are present at the same frames.
31. Playback across a region containing pasted keys: correct frames play; preview/export reflect the pasted keys.
32. If the pasted anchor landed on your launch start frame, its cached reference/onion shows the pasted paint exactly like a single paste would.
33. The timeline extent (ruler/scrollbar) reflects the accepted keys only — no phantom frames from rejected pastes.
