<objective>
Build the phase's data spine: fit a painted stroke's recorded samples into interpolating anchors, then convert the stroke on its first committed edit through the ONE existing path write.

Purpose: this is the tracer that proves the whole architecture before any surface is wired — a Brush/Water/Pen stroke carrying no `anchors` gains a fitted path, commits through the shipped `beginAquarellePathEdit -> updateAquarellePathInScript -> storeAquarelleEdit` seam, re-bakes from the recovered pre-script base, and undoes to its exact pre-edit samples. Nothing here forks the Phase 61 editor; the fit is held in a session module and only enters the document at commit (D-01, D-03, D-12).

Output: `vectorPathFit.ts`, `vectorPathCurveBracket.ts`, the conversion extension of `updateAquarellePathInScript` / `beginAquarellePathEdit`, and the D-07/D-08 re-sampling law with the affected Phase 61 pins retired with stated reasons.

Project law for this plan:
- Preact signals only, compare-then-write setters, `.peek()` in handlers (`efx-preact-reactivity`). No render-body writes.
- `efx-async-orchestration` §1: no async library or state machine is adopted here; the existing single-flight latch and synchronous snapshot seam are the whole orchestration.
- The conversion's persisted mode is `resolveAquarelleCurveMode(stroke.curveMode)` — the SAME expression the 62-03 overlay previews with. The in-app gesture passes no explicit mode, so the first conversion writes no `curveMode` key and preview/persisted mode cannot diverge.
- This plan's end-to-end pin drives `beginAquarellePathEdit` directly, below the Studio handler; 62-02 T2 widens `handleAquarelleVectorPathEdit` so the same route is live in-app.
- REL-01: no new runtime dependency. `fit-curve` stays a reference only.
- Vitest only, never watch; `.test.ts` only.
</objective>
