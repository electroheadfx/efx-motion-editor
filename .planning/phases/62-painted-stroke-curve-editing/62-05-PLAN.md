<objective>
Make one source-scoped cache identity the single authority for every loop occurrence, and pin the three loop edge cases that decide whether a curve conversion can safely re-bake once for all occurrences.

Purpose: CRV-03's proof. A converted painted stroke re-bakes the SOURCE key; loop occurrences are never materialized and never own a cache entry, so one source edit must invalidate every occurrence in the same transition. Today the same identity string is hand-built in five production files — any divergence silently splits the cache and leaves one occurrence stale. This plan extracts the ONE builder, proves byte-identical behaviour across every shipped pin, then pins adjacency, ordering and empty-frame resolution against the re-bake path and proves that occurrence frames carry no editable stroke row at all (D-11).

Output: `buildRotoRealCacheRevision` in the physical model, every real-identity site routed through it, and the CRV-03/D-11 proof suite.

Project law for this plan:
- Pure model work plus test pins; no surface, no engine and no persisted-document change.
- The extraction is identity-preserving: every shipped cache-revision pin must stay byte-for-byte green. This is the whole risk of the plan.
- `efx-preact-reactivity` / `efx-async-orchestration`: not applicable — no signal writes, no async ownership; this plan touches no component and no hook state.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| source key -> loop occurrence | An occurrence is a projection of one source payload; an identity built per occurrence would split the cache and serve stale pixels. |
| resolved frame -> curve edit target | A frame that resolves to a placeholder or no source must never become an edit target or a re-bake input. |
| edit buffer -> persistence cache | The persistence projection must use the same identity family as the render path, or a converted frame is served from a stale buffer key. |
