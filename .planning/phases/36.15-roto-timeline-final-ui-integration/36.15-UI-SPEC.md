## Spacing Scale

Declared values (must be multiples of 4) — inherited from the 36.14 base contract:

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight icon-to-icon gaps inside pills, action-row button gaps |
| sm | 8px | Gap between control-group pills; compact control spacing and header group gaps |
| md | 16px | Workflow-strip horizontal padding |
| lg | 24px | Icon-only focus/touch box and compact control width |
| xl | 32px | Header control-island (pill) outer height and transport grouping |
| 2xl | 48px | Reserved major separation only; not used inside the compact timeline bands |
| 3xl | 64px | Reserved application-level spacing only; not used inside the timeline |

C-03 resolution: the complement's "minimum 5px before and after the divider bar" is satisfied by pill islands separated by the **8px (sm) gap** — the reference's ~10px island gap normalized to the 4-point scale. No literal `|` divider glyphs are rendered (D-04: reference uses pill islands, not divider glyphs).

Exceptions are locked geometry rather than reusable spacing tokens (inherited, unchanged):

- Timeline frame cell: `18px` wide by `24px` high; adjacent cells abut with no layout margin, padding, or gap; compact separation stays via the existing `1px` cell border/inset inside each locked cell.
- Header: `46px` high. Ruler: `28px`. Frame lane: `38px`. Context action row: `28px`. Synchronized scrollbar band: `14px`. Complete strip: `155px` including divider/border treatment.
- Primary header controls: `30px` high; pill islands may use a `32px` outer height.
- Context action buttons: `22px` high (icon glyphs `14–16px` inside, matching reference proportions).
- Interpolation-mode select and numeric inputs keep existing compact heights (`22px` inputs).
- Occupied-target insertion caret: `2px` wide, aligned to the selected left or right cell edge.
- EFX Motion layer key marker diamond: `~9px`, reusing existing `drawKeyframeDiamonds` geometry.

Do not turn these geometry exceptions into new general spacing tokens. Do not scale cell width, ruler cadence, or band heights at responsive breakpoints.

## Typography

Use exactly these four sizes and two weights within the final timeline UI (inherited from the 36.14 base contract):

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 12px | 600 | 1.5 |
| Label | 10px | 600 | 1.2 |
| Heading | 13px | 700 | 1.2 |
| Display/status | 11px | 700 | 1.2 |

Rules:

- Weight `600`: ruler labels, secondary metadata, tooltip text, supporting copy. **Styled tooltip text uses the Label role (10px / 600 / 1.2).**
- Weight `700`: button labels, key identity, compact numeric fields, the `Key {n}` chip, and the status capsule.
- Do not introduce weight `800` or `900` even where the static reference uses `font-extrabold`/`font-black`; normalize to the declared two-weight contract.
- Use tabular numerals for frame numbers, cadence, Force Spacing values, and ruler marks.
- Truncate the status capsule to one line with an ellipsis; never reduce its text below `11px` to make controls fit.

### Cell-State Tooltips (D-16)

With the bottom legend removed (C-06), each timeline cell exposes its semantic state through the styled per-cell tooltip: `Real key`, `Generated — render-only`, `Cached`, `Background only`, `Empty`.

### Guarded-State Tooltip Grammar (D-12)

Unavailable actions stay visible, in order, and focusable. The styled tooltip carries BOTH the action name and the verbatim controller-supplied reason: `{Action name} — unavailable: {controller reason}`, e.g. `Paste key — unavailable: no copied key`. Controller availability/reason ports (`scriptAvailability`, `can*RotoKey` flags, `forceSpacingDisabledReason`) are the only source; presentation must not shorten, reinterpret, or reconstruct reasons.

### Status Capsule Priority Model (D-15)

A single prioritized line: pending operation > saving indicator > guard/action feedback > ambient info (baseline status), with the amber Info glyph from the reference.

- Successful operations use concise verb-first results: `Frame inserted`, `Frame deleted`, `Spacing applied`, `Key moved`, `Undo complete`, `Redo complete`; Force Spacing may append `— {N} empty frames`.
- Occupied drag boundary: `Insert before Key {N}` / `Insert after Key {N}` (or `frame {F}` consistently if keys are identified by frame).
- Busy copy uses an ellipsis only while an acknowledged operation is pending: `Applying spacing…`, `Moving key…`, `Deleting frame…`.
- Do not add a permanent legend, generated-frame explanation, cached-reference explanation, interpolation diagnostic, or developer status paragraph anywhere under or beside the timeline.

## Fixed Layout Contract

### Overall Geometry (inherited, unchanged)

The bottom workflow strip is a fixed `155px` high and consists of these bands in order: `46px` single-row header, `1px` divider, `28px` ruler, `38px` physical-frame lane, `28px` fit-content context action row, `14px` synchronized horizontal scrollbar band. The retired developer status stack and the removed cell-states legend (C-06) must not be replaced with another band, legend, toast rail, expandable diagnostics region, or multiline status block.

### Header Order (D-01 — complement wins over the 36.14 base header order)

One non-wrapping row, left to right:

1. **Mode label** (e.g. `Roto #1`) — keeps current structural appearance; no pill treatment (D-03).
2. **Navigation pill** — first / previous / play-stop / frame number / next / last.
3. **Elastic status capsule** — the only `flex: 1` region, `min-width: 0`, single-line truncation with ellipsis.
4. **Interpolation pill** — lucide `blend` icon toggle (**no border**, D-05/C-01) + interpolation mode select. **No count input anywhere** — count authority is retired by the physical contract.
5. **Playback pill** — loop toggle + fps input.
6. **Apply-spacing pill** ("key space" group — D-02: same group) — lucide `align-horizontal-space-around` icon **before the number** (C-02) + nonnegative `N` input + `Apply` button.
7. **Close button** (inherited from base contract).

Groups 2, 4, 5, 6 render as gray pill islands (rounded-full, tonal-variant backgrounds per the Color contract) separated by the 8px sm gap — no `|` divider glyphs. The reference's `+Key` and `Duplicate` header buttons are **not adopted** (locked in discussion); quick key actions live only in the bottom action row.

### Timeline and Ruler (inherited, unchanged)

Frame cells remain `18px × 24px` at every supported width; ruler ticks stay aligned to physical cell pitch and synchronized with the frame lane; longer ranges use the existing shared horizontal scroll and visible scrollbar; no cell scaling, cadence changes, or density breakpoints; auto-scroll only enough to reveal the newly selected/moved physical cell.

## Interaction Contract

### Force Spacing (inherited, restated for the new pill)

- Pill order: `align-horizontal-space-around` icon, nonnegative `N` input (`min="0"`, `step="1"`, accessible name `Empty frames between real keys`, compact width for at least three digits), `Apply` button.
- Only whole integers `N >= 0` publish a transaction on `Apply`; empty, fractional, negative, nonnumeric, and over-capacity values publish nothing.
- The value is session-local only — never written to project state, interpolation state, persistence, history, cache metadata, or script state.
- `Apply` acts immediately after validation; no confirmation dialog; one acknowledged undoable operation on success; rejection/timeout/transport/capacity failure leaves state and history unchanged or fully restored.

### Interpolation Toggle

- The `blend` icon button toggles interpolation enabled state only — it never moves real keys, selection, navigation, or Script Motion.
- The toggle button has no border (D-05); its pressed/active state is conveyed by the existing active-state treatment (glyph/surface emphasis), not by adding an outline.
- The mode select remains the only other control in the pill.

### Bottom Action Row (C-05 / D-10..D-14)

- Render a single fit-content pill in this exact order: `Key {n}` label chip, then icon-only buttons: Insert, Dup, Copy, Paste, Delete, Copy Script, Apply Script.
- The `Key {n}` chip stays at row start (D-13) and keeps its Label/Heading-weight chip styling.
- Do not add `Discard Script` to this row. `Discard Script` (`clipboard-x`) moves to the existing right-panel Scripts toolbar (D-11) without changing durable script-library behavior.
- Key-action icons use the neutral action surface; Delete uses the destructive surface; Copy/Apply Script use the script action surface (Color contract).
- The row stays anchored in its `28px` band, non-wrapping, horizontally synchronized with timeline scrolling where the current implementation requires it.

### Styled Tooltip Behavior (D-14, D-17)

- One shared styled tooltip component serves the icon row, timeline cells, and the status capsule's full-text reveal.
- **Pointer-hover delay: exactly 1 second — never instant.** This is a global contract for the new tooltip component.
- Keyboard focus reveals the tooltip without the pointer-hover delay so guarded reasons are reachable without a pointer (prescriptive default; aria-labels remain the accessible name at all times regardless of tooltip visibility).
- Tooltips never intercept pointer events, never change layout, and dismiss on pointer leave, Escape, or activation.

### Guarded Script Controls (inherited, restated)

`Copy Script` and `Apply Script` (and toolbar `Discard Script`) remain keyboard-focusable when unavailable: real `button` without native `disabled`; `aria-disabled="true"` when the controller reports unavailability; guard pointer/Enter/Space activation before invoking the controller; expose the exact controller-supplied reason via the styled tooltip and `aria-describedby`; an attempted guarded activation may place the concise supplied reason in the status capsule. Presentation must not infer availability from frame type, mode, paint count, clipboard presence, or busy state.

### Insert, Delete, Undo, Redo, Drag (inherited, unchanged)

The 36.14 base interaction contract for ripple Insert/Delete, D-29 occupied before/after caret drag, complete-mapping drag preview, acknowledgement focus follow, and Escape cancellation applies verbatim. This phase changes presentation only; it must not alter threshold, pointer-capture, caret, or preview semantics.

### Application Selection Guard (inherited, target `app/index.html`)

```css
html,
body,
#app {
  -webkit-user-select: none;
  user-select: none;
}

input,
textarea,
[contenteditable="true"],
.physics-paint-log-messages {
  -webkit-user-select: text;
  user-select: text;
}
```

Equivalent selectors are acceptable only if they preserve the same contract. The guard must not interfere with canvas painting, sliders, timeline dragging, pointer capture, keyboard focus, native input editing, contenteditable fields, or LOG message selection/copying.

### EFX Motion Layer Key Markers (C-04 / D-06..D-09)

- One small diamond per **real** Roto key, canvas-drawn on the physic-paint layer row in the main EFX Motion timeline (`TimelineRenderer.ts`) at the key's physical `appFrame`.
- Reuse the existing `drawKeyframeDiamonds` ~9px geometry and the `drawPhysicPaintPlayScriptMarkers` physic-paint layer seam; marker data flows through the existing FxTrackLayout path.
- Always visible on physic-paint layers — **not** selection-gated.
- Real keys only; generated in-betweens get no marker.
- Diamond color: physics-paint orange `#F5A623`.
- Visual-only: no click target, no hit-test path, no new interaction surface.

## Visual State Contract

Every cell exposes its physical frame and semantic state through both visuals and an accessible label (inherited table applies verbatim): Empty (neutral, full drag destination), Real/cached key (green, only editable durable authority), Generated (blue, render-only, full drag destination), Background only (striped), Current physical frame (orange layered over semantic base), Selected real key (outline distinguishable from current-frame orange), Drag source, Empty/generated target (whole-cell overlay preserving semantic fill), Occupied before/after target (2px caret + capsule boundary copy), Pending acknowledgement (stable committing treatment), Invalid/capacity failure (no commit; concise status + LOG detail).

Additions for this phase:

| State | Required presentation |
|-------|-----------------------|
| Control-group pills | Distinct gray tonal-variant backgrounds per group; 8px gaps; rounded-full; fixed width (non-shrinking) |
| Interpolation toggle off/on | Borderless button; active state via surface/glyph emphasis only — never an added border |
| Unavailable icon action | Reduced-emphasis icon treatment; remains visible, in order, focusable; tooltip carries name + verbatim reason |
| Tooltip visible | Dark `#20262D` pill after the 1s hover delay (or immediately on keyboard focus); never instant on hover |
| Capsule overflow | Ellipsis truncation; full text available in the styled tooltip; capsule never grows the strip or pushes groups off-screen |
| EFX Motion layer with real Roto keys | Orange 9px diamond per real key at its physical frame on the physic-paint layer row |

Do not restore `saving`, `pending save`, or `unsaved changes` timeline overlays. Do not reintroduce the status stack or the cell-states legend in any form.

## Status and LOG Routing (inherited, restated)

- The header capsule shows the latest successful relevant timeline/script operation until navigation, playback, or a later operation replaces it; otherwise the baseline status.
- Priority: pending operation > saving indicator > guard/action feedback > ambient info (D-15).
- The capsule is always one line, never increases panel height, never pushes control groups off-screen, and truncates with ellipsis.
- Failures show only a concise actionable summary; full error objects, transport details, validation diagnostics, and stack information go only to the existing right-panel LOG tab.
- The capsule is the single current status line; LOG remains the running history/diagnostic surface, unchanged — the capsule stops duplicating it (D-19). Do not add a Log button to the timeline header and do not automatically change the user's right-panel tab.

## Accessibility and Input Contract (inherited, extended)

- Visual focus order follows header order, then physical cells, then the context action order.
- Every icon-only control has an explicit accessible name (`aria-label`); the styled tooltip supplements, never replaces, the accessible name.
- Focus rings at least 2px, `#F2F5F7`, never reliant on current-frame orange alone.
- A successful acknowledged move/insert/delete/undo/redo places focus on the controller-selected real key cell.
- Escape cancels an active drag without publishing; Delete/Backspace use the existing paint-mode shortcut guard and the same Delete action as the visible control.
- Native number-input editing, mode-select activation, tab traversal, and text selection remain intact.
- Guarded controls: no native `disabled`; `aria-disabled="true"`; guarded activation paths; verbatim reason via tooltip + `aria-describedby`.

## Preact and State Ownership Contract (inherited, condensed)

Presentation receives: physical cell view models keyed by stable `keyId`, current physical frame and selected identity, resolver-supplied drag target/boundary/mapping/validity, interpolation enabled state and mode, session-local Force Spacing value and action state, concise status presentation state, script controller callbacks/availability/reasons/busy/status, and all existing action/transport/cadence/close handlers. Marker data for the EFX Motion layer arrives through the existing FxTrackLayout path.

Presentation emits user intent only: select, drag lifecycle, toggle interpolation, change mode, apply Force Spacing, activate an existing action, navigate, play/pause, change cadence, close.

Presentation must not own: mapping legality or ripple resolution, transaction construction, capacity validation beyond native field affordances, acknowledgement matching, rollback, durable history, persistence, cache publication, preview/export invalidation, generated interpolation derivation, script clipboard data/eligibility, engine inspection, error formatting, or LOG storage.

Use direct values or computed Signals for view state; keep gesture-local mutable values in focused refs/signals; submit intent through event handlers. No `useEffect` chains copying controller props into local state or orchestrating transaction flow; effects only for genuine external lifecycle synchronization per existing project patterns.

## Responsive Contract (inherited + D-18)

- One header row at every host-supported Physics Paint window width; no breakpoint, density mode, abbreviated labels, overflow menu, hidden group, wrapped row, or independent header scrollbar.
- All fixed control groups remain visible at declared heights with readable content; the status capsule alone absorbs width changes (`flex: 1`, `min-width: 0`, truncation).
- Extra width goes only to the capsule; control islands stay tightly grouped.
- Below the minimum host width the strip scrolls horizontally rather than crushing controls (D-18).
- Timeline overflow stays horizontal and synchronized between ruler, cells, playhead, action anchoring, and scrollbar.
