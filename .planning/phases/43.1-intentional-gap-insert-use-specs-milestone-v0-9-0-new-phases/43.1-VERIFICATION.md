## Blocking Gaps

### GAP-03-A: Cache replacement is not failure-atomic

**Classification:** BLOCKER  
**File:** `app/src/lib/physicPaintPersistence.ts:214-224`

The save path removes the previous valid cache directory before the replacement directory and every PNG sidecar are durable. A directory creation or sidecar write failure can destroy the previous accepted raster state while persisted metadata still references it.

**Required closure:**

- Build the complete replacement in a sibling temporary directory.
- Swap only after every sidecar write succeeds.
- Restore the previous directory if replacement fails.
- Add a failure-path test proving the previous valid cache survives.

### GAP-03-B: Parent authority does not semantically prove every lifecycle edit

**Classification:** BLOCKER  
**File:** `app/src/lib/physicPaintBridge.ts:728-923`

The parent semantically validates the new empty-segment, duplicate/paste, Play Script, and interpolation operations. Existing map operations including slot insertion, delete, move, group move/delete, and Force Spacing can still install a structurally valid complete document without proving that it is the canonical result of the declared operation.

This violates the phase prohibition against trusting child semantic claims without parent recomputation.

**Required closure:**

- Carry a typed intent for every existing physical mapping operation.
- Re-run the canonical resolver on the parent.
- Compare complete records, break ownership, Loop Clips, selection, and resulting document before mutation.
- Add adversarial tests proving unrelated structurally valid proposals are rejected without publication.

This closure must not add deferred group UI or an `Insert Gap` action.

### GAP-03-C: Undo/Redo authorization is not scoped to its authority context

**Classification:** BLOCKER  
**Files:** `app/src/lib/physicPaintBridge.ts:123-135,884-955`, `app/src/components/physic-paint/hooks/useRotoPhysicalEditHistory.ts`

Accepted history commands are retrieved globally by original operation ID without binding the ledger entry to project context, layer, launch operation, or capacity. Equal document revisions can allow a command accepted under one authority scope to authorize replay in another.

**Required closure:**

- Bind ledger entries to `projectContextId`, `layerId`, `launchOperationId`, and capacity.
- Verify the complete authority tuple before replay.
- Compare complete before/after snapshots.
- Partition or clear the ledger when authority changes.
- Add a cross-project/layer/launch rejection test proving no mutation.
