# Phase 43.1 Code Review

## Assessment

The Phase 43.1 implementation and automated gates pass, but the targeted review confirmed four blocking correctness or security risks and one warning. The prior pre-gap review body was replaced because Plans 07–11 closed its parent-authority and replay findings. Group operation expansion remains explicitly deferred and is not reopened here.

## Critical Findings

### CR-01: Cache publication is not transactional with project persistence

**Files:**
- `app/src/lib/physicPaintPersistence.ts:163-168`
- `app/src/lib/physicPaintPersistence.ts:246-273`
- `app/src/stores/projectStore.ts:684-692`
- `app/src/stores/projectStore.ts:725-752`

`savePhysicPaintData()` publishes the staged cache as canonical before `saveProject()` or `saveProjectAs()` persists the corresponding `.mce` document. If project-file persistence then fails, the old `.mce` remains authoritative while its fixed `cache/physic-paint/...` paths may contain new bytes or may have been deleted. The empty-output branch removes the canonical cache before the project file records that outputs are empty.

**Impact:** Reopening the last successfully saved project can load unsaved pixels, lose referenced sidecars, or fail hydration after a project-file save failure.

**Remediation:** Use immutable generation-qualified cache paths. Write a new generation without replacing the old one, atomically save the `.mce` document referencing that generation, then remove unreferenced generations. On project-save failure, delete only the unpublished generation.

### CR-02: Provenance-only Loop Clip changes are silently discarded

**Files:**
- `app/src/stores/physicPaintStore.ts:1495-1511`
- `app/src/components/physic-paint/roto/physicsPaintRotoPhysicalModel.ts:878-897`

`replaceRotoPhysicalLoopClips()` compares `loopId`, placement, repeat, mode, and source keys, but omits persisted provenance: `scriptId`, motion deformation/position, and `overrideColor`. The canonical Loop Clip fingerprint includes those fields.

When only provenance changes, the store reports success without installing the new collection, changing the physical revision, marking the project dirty, or notifying rendering.

**Impact:** Valid Play Script motion or color metadata changes can appear accepted but be silently lost and never persisted.

**Remediation:** Replace the partial comparator with one shared canonical Loop Clip equality helper covering every persisted field, including absent provenance versus explicit null color. Add provenance-only replacement tests.

### CR-03: Native publication acknowledges a non-durable directory rename

**Files:**
- `app/src-tauri/src/services/physic_paint_cache.rs:45-69`
- `app/src-tauri/src/services/physic_paint_cache.rs:88-120`
- `app/src-tauri/src/commands/physic_paint_cache.rs:23-52`

The service synchronizes staged content before publication but does not synchronize `cache_parent` after the first `fs::rename()` or replacement `RENAME_SWAP`. Synchronizing the staging directory does not make the containing directory's renamed or swapped namespace entry durable.

**Impact:** Publication can return `accepted: true` even though a crash or power loss may lose or revert the canonical directory entry.

**Remediation:** Open and `sync_all()` the cache parent directory after every successful rename or exchange and before returning success. Define post-mutation sync-failure semantics explicitly and add a test seam that proves parent-directory synchronization is requested.

### CR-04: Browser frame-sync accepts unauthenticated postMessage senders

**Files:**
- `app/src/lib/physicPaintBridge.ts:1448-1467`
- `app/src/lib/physicPaintBridge.ts:1786-1797`
- `app/src/main.tsx:37-41`
- `app/src/lib/physicPaintBridge.test.ts:1994-2011`

The browser fallback listener forwards every message payload to frame-sync handling without checking `event.origin`, `event.source`, the active Physics Paint child window, or a launch identity. A correctly shaped message can immediately seek and reveal a frame.

**Impact:** Any window with a reference to the editor, including a foreign-origin sender, can forge frame-sync messages and mutate editor timeline state.

**Remediation:** Retain the active child-window reference and require both the expected origin and exact source window. Include and validate the active launch operation ID so stale sessions cannot control the timeline.

## Warnings

### WR-01: Unscoped live-pixel flush loses settled delivery failures

**File:** `app/src/components/physic-paint/hooks/useRotoFramePersistenceCoordinator.ts:99-129,275-299`

Failed deliveries remain in `parentDeliveryErrorRef` and `failedParentPayloadRef`, but their settled promises are removed from `parentDeliveryRef`. An unscoped `flushLivePixels()` enumerates only `parentDeliveryRef`, so it can return without retrying or surfacing a settled failure while `hasPendingLivePixels()` remains true.

Current production call sites pass an explicit frame, so the defective all-deliveries branch is not currently reached.

**Remediation:** Enumerate the union of keys from pending, error, and failed-payload maps, or retain failed deliveries in one explicit state machine until retry, invalidation, or terminal surfacing. Add a regression test where delivery rejects and settles before an unscoped flush.
