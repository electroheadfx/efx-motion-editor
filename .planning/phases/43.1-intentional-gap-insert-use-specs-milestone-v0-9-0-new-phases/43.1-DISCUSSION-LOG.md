## Break marker

### Physical-strip representation

| Option | Description | Selected |
|--------|-------------|----------|
| Left-edge cut | Compact marker immediately before the real key inside existing cell geometry; no new row or badge. | ✓ |
| Broken-link glyph | Small unlink/broken-chain icon on the key cell; more explicit but visually heavier. | |
| Implicit only | Persist the break without a visible marker. | |

**User's choice:** Left-edge cut.
**Notes:** The boundary must remain legible without creating another timeline surface.

### Interpolation Off presentation

| Option | Description | Selected |
|--------|-------------|----------|
| Stay visible | Keep the same marker because the durable break will become effective again when Interpolation is On. | ✓ |
| Show muted | Reduce marker contrast while Interpolation is Off. | |
| Hide while Off | Show the marker only while interpolation is active. | |

**User's choice:** Stay visible.
**Notes:** The visual state reflects durable structure, not only current interpolation activation.

### Marker explanation

| Option | Description | Selected |
|--------|-------------|----------|
| Extend cell tooltip | Append `Starts a new interpolation segment` to existing real-key tooltip/accessibility copy. | ✓ |
| Marker-only tooltip | Give the cut its own tooltip target. | |
| No tooltip copy | Use only the visual cut. | |

**User's choice:** Extend cell tooltip.
**Notes:** No separate hit target or competing tooltip lifecycle.

### First-key behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Keep dormant | Retain the break on stable key identity but suppress it while no predecessor exists. | ✓ |
| Remove break | Delete the break automatically when the key becomes first. | |
| Draw leading cut | Display a cut even on the first real key. | |

**User's choice:** Keep dormant.
**Notes:** The break reappears and becomes effective if an earlier key later exists.

## Copy/delete semantics

### Duplicate and Copy/Paste

| Option | Description | Selected |
|--------|-------------|----------|
| Copy key only | Copy Paint payload/content but never clone the break to a fresh identity. | ✓ |
| Copy break too | Fresh duplicate/pasted identities inherit the source break. | |
| Ask on paste | Prompt whether to carry the break. | |

**User's choice:** Copy key only.
**Notes:** Starting a new segment remains an explicit empty-frame Insert action.

### Deleting the owning key

| Option | Description | Selected |
|--------|-------------|----------|
| Delete break too | Delete key and attached break atomically; do not transfer it. | ✓ |
| Transfer forward | Move the break to the next real key. | |
| Keep orphan break | Persist a frame-position boundary without a key. | |

**User's choice:** Delete break too.
**Notes:** No orphan or implicit mutation of another key.

### Pasting onto an existing break key

| Option | Description | Selected |
|--------|-------------|----------|
| Preserve destination break | Replace Paint payload while retaining destination identity and break. | ✓ |
| Clear destination break | Pasting converts the key to a normal interpolating key. | |
| Use source state | Destination break state follows the copied source. | |

**User's choice:** Preserve destination break.
**Notes:** Clipboard content cannot silently change structural timeline intent.

### Identity-preserving timing edits

| Option | Description | Selected |
|--------|-------------|----------|
| All identity-preserving edits | Direct drag, group drag, Push Left/Right, and partial Key Spacing carry the break with the key. | ✓ |
| Only prompt-listed moves | Carry the break only through explicitly named group drag and push operations. | |
| Frame-position boundary | Leave the break at its original frame instead of following identity. | |

**User's choice:** All identity-preserving edits.
**Notes:** Reordering recomputes which predecessor the stable-key-owned break separates from.

## Rejection feedback

### Known-invalid target behavior

| Option | Description | Selected |
|--------|-------------|----------|
| Disable with reason | Disable Insert and expose the exact reason in the existing guarded tooltip; resolver still rejects races. | ✓ |
| Allow then reject | Keep Insert clickable and publish an error after activation. | |
| Hide Insert | Remove the action while invalid. | |

**User's choice:** Disable with reason.
**Notes:** Preserve discoverability without inviting avoidable failed commands.

### Failure-reason granularity

| Option | Description | Selected |
|--------|-------------|----------|
| Target-specific reasons | Distinguish generated, linked, unresolved, occupied-as-empty, invalid, capacity, and in-flight states. | ✓ |
| One empty-only reason | Use one generic `Select a genuinely empty Roto frame` reason. | |
| Technical resolver text | Expose raw codes and implementation details. | |

**User's choice:** Target-specific reasons.
**Notes:** Reasons should explain what state must change and remain product-facing.

### Race rejection copy

| Option | Description | Selected |
|--------|-------------|----------|
| Same verbatim reason | One reason mapper feeds guarded tooltip and status capsule. | ✓ |
| Short status, detailed tooltip | Maintain separate short and long copies. | |
| Generic status | Publish only `Insert failed`. | |

**User's choice:** Same verbatim reason.
**Notes:** Preflight and resolver rejection must never disagree.

### Two valid Insert contexts

| Option | Description | Selected |
|--------|-------------|----------|
| Context tooltip only | Existing real-key Insert copy stays unchanged; segment-starting copy appears only on genuinely empty frames. | ✓ |
| Combined tooltip | Always explain both valid behaviors. | |
| Persistent helper | Add toolbar text describing the active mode. | |

**User's choice:** Context tooltip only.
**Notes:** The visible label remains `Insert` in both valid contexts.
