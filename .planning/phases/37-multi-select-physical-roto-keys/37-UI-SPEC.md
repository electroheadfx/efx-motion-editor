## Interaction Contract

### Multi-Selection Gestures (D-01, D-02, D-05)

- **Cmd/Ctrl-click** a real key: toggle that keyId in/out of the selection set. The current editing key never leaves the selection by this gesture — toggling the current key off collapses selection to the clicked key instead (selection is never empty, D-02).
- **Shift-click** a real key: select the contiguous physical range from the anchor keyId to the clicked keyId, real keys only, skipping generated/empty cells. Anchor is the current editing key unless a previous Shift-click established a different anchor within the same selection session.
- **Plain click** (no modifiers): collapse selection to exactly that key; it becomes the current editing key (existing behavior preserved).
- **Escape**: collapses a multi-selection to the current single key. Drag cancellation wins while a drag gesture is active (36.14 D-24 unchanged).
- Selection tracks **stable keyId values only** — never frames, never projected ownership. Selection survives physical retiming (Force Spacing keeps the multi-selection on the retimed keyIds, D-17). Generated and empty physical cells can never become selected identities and must ignore selection gestures entirely (no hover affordance change, no tooltip change, no selection class).

### Select All (D-03)

- New icon in the bottom icon-only action row, placed **after Delete and before Copy Script** (key utilities group | script utilities group separation preserved). Tooltip `Select all keys`.
- Keyboard route: **Cmd/Ctrl+A while the timeline strip has focus** performs the same action. The shortcut must respect the app selection guard and the `isPaintEditMode` shortcut guards; it must not fire while focus is inside an input, textarea, contenteditable, or the LOG.
- Select All selects every real keyId; the current editing key is unchanged if already part of the map, otherwise the first ordered real key becomes current.
- Guarded presentation: Select All stays visible, in order, and focusable; when the controller reports no selectable real keys it renders with `aria-disabled="true"` and the guarded tooltip grammar — never native `disabled` (36.15 D-28 pattern).

### Group Drag & Drop (D-06..D-09)

- Pointer mechanics inherited verbatim from the approved single-key drag (260718-m2f / 36.14): same threshold, Pointer Events capture, edge-scroll, Escape cancellation. Grabbing any selected real key starts a group drag; grabbing an unselected real key first collapses selection to that key and starts a single-key drag.
- The grabbed key anchors the drop: it maps to the drop target; every other selected key shifts by the same physical delta, preserving relative physical distances (D-06).
- **Valid group drag preview**: the existing D-22 complete-mapping preview generalizes — every shifted selected key renders with the existing `roto-drag-moved` treatment, unselected rippled keys with `roto-drag-shifted`, vacated cells with `roto-drag-vacated`, re-derived generated cells with `roto-drag-generated`, and the target with the existing D-23 whole-cell highlight or before/after 2px carets. No new preview color is introduced for valid moves.
- **Invalid group drag preview (D-08)**: conflicting destination cells (occupied by an unselected real key) render the blocked-target treatment (destructive dotted outline + fade, per Color contract) while the pointer is over the invalid target; the grabbed key shows `cursor: not-allowed`. Out-of-range/over-capacity proposals reuse the existing `roto-drag-target-invalid` fade. Preview is Studio/resolver-authoritative; the view renders only resolver output.
- **Release on invalid target**: atomic reject, zero partial mutation (D-07). Concise reason to the status capsule; detail to LOG.
- **Commit**: one acknowledged physical-map transaction; after acceptance the full moved group stays selected, the grabbed key becomes the current editing key, and focus/scroll follow it per D-24.
- **Source-gap policy (D-09)**: empty/generated whole-cell target closes the group's source gaps; occupied before/after caret leaves the group's source gaps open and ripples only at the destination boundary. Locked mappings GD-1..GD-3 are the UAT anchors.

### Group Force Spacing (D-10..D-12)

- The existing apply-spacing pill (icon + N input + `Apply`) is shared by both scopes — **no new control, no mode switch, no label change**.
- Exactly one key selected → existing 36.14 full-timeline behavior (GFS-3 regression anchor).
- Two or more keys selected → selected-only scope: earliest selected key anchors, exactly N empty physical slots open between each adjacent selected pair; unselected keys are hard walls and never move (D-11, D-12).
- Rejection is atomic with a status-capsule reason (`Spacing rejected — not enough room`); input validation (nonnegative whole integer, capacity) and session-local non-persistent N are unchanged from 36.14 D-19/D-20.
- On success the multi-selection is preserved on the retimed keyIds (D-17); one accepted history action.

### Group Delete (D-13..D-15)

- Backspace/Delete (existing paint-mode shortcut guard), the toolbar Delete icon, and any future keyboard route share the same transaction (D-13).
- With a multi-selection active, Delete removes all selected real keys in one atomic operation: unselected identities and payloads preserved, later physical keys ripple left, exactly one Undo/Redo action.
- Survivor selection (D-14): the next key after the group's last position becomes selected/current; if the group was at the end, the previous key. Selection collapses to this single survivor. Focus follows the survivor cell.
- Select All + Delete is allowed (D-15): empty timeline, editing context returns to the launch frame as a plain empty cell, empty-state copy shown, one Undo restores the full map.
- No confirmation dialog at any selection size (Copywriting Contract).

### Single-Key Actions Under Multi-Selection (D-16)

- Copy, Duplicate, Insert, and Paste keep their exact current single-key behavior, always targeting the current editing key (strongest orange highlight). Their tooltips, guards, and availability reasons are unchanged.
- Only Delete, drag, and Force Spacing are group-aware.
- The `Key {n}` chip at action-row start continues to identify the current editing key — it never switches to a count display (no `3 keys selected` chip replacement; selection count is conveyed by the cell visuals and the `All keys selected` status entry only).

## Visual State Contract

The inherited 36.15/36.14 cell-state table applies verbatim (empty, real/cached, generated, background-only, current frame, drag source/target/committing/invalid, occupied carets, pending). Additions for this phase:

| State | Required presentation |
|-------|-----------------------|
| Current editing key (multi-selection active) | Existing `.current` orange ring — unchanged, always the strongest highlight (D-04). |

Must read as subordinate to the orange current ring. |

| Group drag — blocked targets | New blocked-target class on conflicting destination cells: destructive-family dotted outline + existing invalid fade; `cursor: not-allowed` on the grabbed key (D-08). |

## Accessibility and Input Contract

Inherited 36.15 contract applies verbatim (focus order, 2px `#F2F5F7` focus rings, aria-labels on every icon-only control, guarded-control pattern, Escape semantics, native input editing, selection guard). Extensions:

- Secondary selected cells expose their selected state through the styled per-cell tooltip (`Selected key`) and through `aria-selected="true"` on the cell button where the existing cell button semantics permit; the current key remains the focus target for roving focus — selection does not add tab stops.
- Cmd/Ctrl+A is scoped to timeline-strip focus only; it must never hijack text-field select-all (inputs, textareas, contenteditable, LOG keep native behavior).
- Cmd/Ctrl-click and Shift-click must not break the app selection guard, pointer capture, or the existing paint-mode shortcut guards.
- Acknowledged group operations place focus on the controller-selected cell (grabbed key after move; survivor after delete; earliest anchored key unchanged after Force Spacing) per the existing focus-follow rule.
- Guarded Select All: no native `disabled`; `aria-disabled="true"`; guarded activation blocked before the controller call; verbatim reason via tooltip + `aria-describedby`.

## Preact and State Ownership Contract

Presentation receives (additions to the 36.15 list): ordered selected keyId set, anchor keyId, current editing keyId, resolver-supplied group drag mapping/validity including the conflicting-cell list for blocked previews, and Select All availability/reason ports.

Presentation emits user intent only: toggle-select, range-select, collapse-select, select-all, group drag lifecycle, group delete, scoped Force Spacing apply, and all existing single-key actions.

Presentation must not own: selection-set persistence across retiming (controller owns keyId tracking), mapping legality or collision detection, transaction construction, capacity validation, acknowledgement matching, rollback, history, persistence, cache publication, or generated-cell derivation.

Multi-selection state (ordered stable keyId set + anchor keyId + current editing keyId) lives at the Roto controller/hook boundary — never in the view (CONTEXT.md code context). Use Signals/computed for view state; gesture-local mutable values in focused refs; no `useEffect` chains copying controller selection state into local view state.
