REVISION DISCIPLINE — audio context revision is a monotonically increasing integer owned by the main-side publisher module (bumped once per publish, embedded in both the launch-context audioPreview section and every update event); child applies only when incoming.revision greater-than current.revision; equal or lower is dropped silently (D-02). Same-revision re-application is a defined no-op (AUDIO-04 idempotency).
    5. DRIFT POLICY — after a seek-aligned start, audio free-runs on the Web Audio clock; per throttled check (about every 10 playback ticks, never per frame) expected = anchor.audioTime + (cursorAppFrame - anchor.appFrame)/projectFps vs actual = anchor.audioTime + (ctx.currentTime - anchor.ctxTime); correct via full seek-restart only when absolute drift exceeds 40ms (D-10).

    7. ASSET TRANSPORT — payloads carry only efxasset://localhost URLs built main-side via assetUrl() (app/src/lib/ipc.ts:25-30); AudioTrack.filePath and relativePath never appear in the payload (D-04); decode is local via fetch + decodeAudioData through the existing audioEngine.
    8. SCRUB POLICY — scrubbing produces no audio; each scrub repositions the engine anchor at the cursor, ready for Play (D-09).
    9. DECISIONS PENDING — placeholder section listing A4, A6, revision-counter confirmation, and the D-04 proof-mode selection, filled by Task 3's checkpoint outcome.
