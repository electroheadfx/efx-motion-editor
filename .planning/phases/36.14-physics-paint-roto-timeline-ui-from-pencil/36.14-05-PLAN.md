## Phase Goal

**As a** stop-motion animator, **I want to** have every real Roto key, generated in-between, timeline edit, persisted frame, and rendered output use one deterministic physical-frame authority, followed by a polished timeline UI that exposes the approved behavior without duplicating business logic, **so that** editing, reopening, previewing, and exporting the same Roto work cannot disagree about frame identity.

<objective>
Route accepted-only physical history, Undo, and Redo through the shared coordinator per D-01, D-03, D-05, D-06, D-07, D-08, D-09, D-10, D-11, and D-12. Replace the move-only command ledger with immutable complete physical commands, make one exact parent acceptance the only cursor-transition authority, preserve the established interleaved paint barriers, and ensure history replay uses the same complete-map stage/publication/settlement/rollback lifecycle as ordinary edits.

Purpose: Make every current and later physical operation uniformly undoable without adding a second reliability protocol. Users must be able to Undo and Redo accepted work while rejected or cancelled work leaves both the physical state and visible history position intact.

Output: One generic Preact-native physical history hook, replay provenance in the closed physical transaction, one coordinator replay route, one stable coordinator port bundle, one final bridge-result listener, Studio composition cutover, preserved paint-history behavior, and deletion of move/apply lifecycle wrappers.
</objective>

## Edge-Case Coverage

| Edge | Required behavior |
|---|---|
| Empty applied or redo stack | Return false; no coordinator call, status change, stack mutation, availability publication, or source-revision notification. |
| Top entry is a paint barrier | Call the matching engine action; move the barrier only on engine success; restore exact stack order if declined. |
| Accepted new physical edit with empty redo | Append one complete command and publish once. |
| Accepted new physical edit after Undo | Append one complete command and clear the entire redo stack once. |
| Rejected new edit while redo exists | Preserve redo and applied stacks exactly. |
| Duplicate/stale accepted edit callback | Ignore by operation ID plus launch/layer tuple; do not append or clear redo twice. |
| Undo/Redo while any physical edit is pending | Reject before snapshot, stage, publication, or cursor mutation. |
| Ordinary edit while Undo/Redo is pending | Coordinator pending guard rejects it through the same authority. |
| Rapid repeated Undo or Redo | First request owns pending settlement; later requests are inert and cannot pre-move the cursor. |
| Current state does not equal command's expected side | Reject replay before local stage and parent publication; keep stacks unchanged. |
| Complete source and target are equal | Return `no-change`; no parent request and no history transition. |
| Undo matching acceptance | Move the exact top physical command from applied to redo once; selection follows stored `before` identity/frame. |
| Redo matching acceptance | Move the exact top physical command from redo to applied once; selection follows stored `after` identity/frame. |
| Parent rejection | Coordinator restores pre-replay snapshot; history stacks, redo, availability, and selection remain at the pre-request state. |
| Timeout or transport failure | Same complete rollback and cursor-neutral outcome as rejection. |
| Settlement matches operation ID but not command/direction/revision/launch | Treat as mismatch; do not transition history; coordinator fails closed according to 36.14-04. |
| Accepted result arrives after command is no longer top | Ignore as a cursor transition; exact serialization should make this unreachable, but the guard remains. |
| Undo Delete | Parent proves target equals original accepted `before`, restores removed stable identity and payload, then accepts one cursor transition. |
| Redo Delete | Parent proves target equals original accepted `after`, removes the same identity, then accepts one cursor transition. |
| Launch replacement during replay | Cancel and restore old launch first, resolve replay false, then clear old history scope; late result cannot touch new launch. |
| Disposal during replay | Idempotently cancel/restore and clear refs; emit no history transition or notification. |
| New completed paint mutation after Undo | Add its paint barrier, clear redo once, preserve ten-level paint trimming. |
| Engine paint availability shrinks | Trim only the oldest excess paint barriers; preserve physical command ordering and publish resulting availability once. |
