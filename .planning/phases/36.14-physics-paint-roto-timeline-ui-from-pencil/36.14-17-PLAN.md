## Trust Boundaries

| Boundary | Description |
|---|---|
| Controller signals → Preact views | Controller-owned availability and reason strings cross into untrusted presentation code that must not reinterpret them. |
| Pointer/keyboard input → Script actions | User input reaches state-changing Copy, Apply, or Play operations and must be blocked consistently while guarded. |
| Native/bridge result → status and LOG | External diagnostic content enters the UI and must be routed without exposing verbose details in the compact status surface. |
| Global shell CSS → editable content | A broad selection policy crosses into user-editable and diagnostic-copying surfaces and requires explicit exceptions. |

## STRIDE Threat Register — OWASP ASVS Level 1

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|---|---|---|---|---|---|
| T-36.14-17-01 | Tampering | Guarded Script buttons | high | mitigate | Gate the real button's single native click path with the same controller-supplied reason used for aria-disabled; prove guarded operations are not invoked. |
| T-36.14-17-02 | Spoofing | Disabled-reason presentation | medium | mitigate | Render controller reason strings verbatim in title and aria-describedby and prohibit view-side eligibility or reason reconstruction. |
| T-36.14-17-03 | Denial of Service | Keyboard/pointer activation | medium | mitigate | Use native button activation with one click guard and no parallel key synthesis, preventing duplicate Apply or Play launches. |
| T-36.14-17-04 | Information Disclosure | Compact status capsule | medium | mitigate | Route concise transition text to status and diagnostic-bearing detail only to existing LOG state; do not auto-open LOG. |
| T-36.14-17-05 | Tampering | Shell selection CSS | low | mitigate | Scope non-selection to the shell and enumerate only approved input, textarea, editable-content, and LOG exceptions in regression tests. |
| T-36.14-17-06 | Repudiation | Guarded action feedback | low | mitigate | Forward the exact guard reason to concise status so users receive deterministic feedback without recording a false operation or error. |
| T-36.14-SC | Tampering | Package supply chain | high | mitigate | This plan contains no package-manager install task; use only dependencies already pinned by the repository and run existing pnpm scripts. |
</threat_model>

<edge_cases>
- Availability changes between render and activation: the click path reads the current controller-backed value supplied to the render and the underlying controller retains its own fail-closed guard.
- A reason contains punctuation or native diagnostic text: transport it verbatim; do not split, parse, normalize, or concatenate it in the view.
- A user tabs to a guarded button and presses Enter or Space repeatedly: each native click publishes concise guard feedback but never invokes the operation or opens a dialog.
- A user activates an available button by keyboard: the operation fires once because no custom keydown click is synthesized.
- Play confirmation closes by cancel, Escape, or completion: focus returns to the real Play button, including after transitions between available and guarded states.
- A user drags across timeline cells, resize handles, or buttons: shell text selection remains suppressed and Plan 16 pointer behavior is unchanged.
- A user selects text inside an input, textarea, true editable node, or LOG output: the explicit exception permits native text selection and copying.
- An apply failure has no diagnostic: status and LOG may share the same concise message; no empty or duplicated diagnostic suffix is created.
- An apply failure has a diagnostic: status receives only the concise message and LOG receives the detailed composition.
- No current operation status exists on a missing frame: the accepted missing-frame baseline remains visible per D-25.
</edge_cases>
