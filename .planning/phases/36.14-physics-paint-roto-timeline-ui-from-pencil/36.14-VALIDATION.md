# Phase 36.14 — Validation Strategy

> Per-phase validation contract for feedback sampling during execution.

---

## Test Infrastructure

| Property | Value |
|----------|-------|
| **Framework** | Vitest 2.1.9 |
| **Config file** | Existing Vite/Vitest project configuration; no one-off config |
| **Pre-UAT quick command** | `pnpm --dir app typecheck` |
| **Pre-UAT full gate** | `pnpm --dir app build` |
| **Post-UAT focused command** | `pnpm --dir app exec vitest run <approved-focused-files>` |
| **Post-UAT full suite** | `pnpm --dir app exec vitest run` |
| **Estimated runtime** | Determine during execution from existing commands |

---

## Mandatory Sequence

1. Implement the production physical schema/model and remove legacy timing fields and readers.
2. Implement the shared acknowledged transaction, physical edit operations, and downstream parity.
3. Run `pnpm --dir app typecheck` and `pnpm --dir app build`.
4. Stop for user-owned native physical-model UAT and explicit approval.
5. Do not create, modify, or run regression tests before that approval.
6. After approval, add deterministic regression coverage and run focused then full `vitest run` commands.
7. Integrate the final UI and complete user-owned native visual and interaction validation.

---

## Sampling Rate

- **After each pre-UAT production task:** Run `pnpm --dir app typecheck` when the bounded change can compile independently; do not run Vitest.
- **After each pre-UAT production wave:** Run `pnpm --dir app typecheck`.
- **At the physical-model gate:** Run `pnpm --dir app typecheck` and `pnpm --dir app build`, then stop for native UAT.
- **After each approved post-UAT regression task:** Run the focused `pnpm --dir app exec vitest run <files>` command.
- **Before final native UI validation:** Run full `pnpm --dir app exec vitest run`, typecheck, and build.
- **Max feedback latency:** Keep focused checks bounded to the files changed by the active plan.

## Post-UAT Wave 0 Requirements

Wave 0 is intentionally deferred until explicit physical-model UAT approval.

- [ ] Pure physical resolver invariants: unique IDs/frames, sorted complete maps, exact interiors, capacity, invalid intent no-op.
- [ ] Locked Insert examples `1,2,3 -> 2,3,4 -> 2,4,5`.
- [ ] Delete ripple, deterministic survivor selection, payload preservation, and toolbar/shortcut equivalence.
- [ ] Empty/generated whole-cell drag and occupied before/after drag, including `A@1, B@3, C@5, D@8` with B after D resolving to `A@1, C@4, D@7, B@8`.
- [ ] Preview and commit return the same complete proposal.
- [ ] Force Spacing `0`, `2`, invalid input, and over-capacity rejection.
- [ ] Acceptance, rejection, timeout, transport failure, launch replacement, disposal, and one-pending-operation serialization.
- [ ] Complete rollback of every snapshot category and accepted-only history/Undo/Redo cursor movement.
- [ ] Save/reopen, bridge revision, cache publication, playback, onion/reference, preview/export, missing/background rendering, and timeline length.
- [ ] Final UI geometry/order, guarded script controls and reasons, Discard relocation, status/LOG split, focus follow, minimal auto-scroll, and selection exceptions.

## Security Verification

- Runtime-validate every bridge field and reconstruct allowlisted plain records.
- Require a complete final identity-to-frame mapping; reject partial mappings.
- Reject duplicate IDs, duplicate frames, invalid ranges, unknown operation kinds, stale revisions, and incomplete maps before mutation.
- Match settlement by operation ID, kind, layer, launch context, and expected revision.
- Validate capacity against the complete proposal before optimistic publication.
- Serialize physical edits while one acknowledged operation is pending.
- Restore all snapshot categories and history cursor state on rejection, timeout, transport failure, launch replacement, or disposal.
- Route concise failure copy to the status capsule and diagnostic detail to LOG.
