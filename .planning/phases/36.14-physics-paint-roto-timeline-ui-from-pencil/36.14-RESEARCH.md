## User Constraints (from CONTEXT.md)

### Locked Decisions

### Physical Key Identity and Interpolation
- **D-01:** Every durable real Roto key has one stable `keyId` and one physical `appFrame`. Source, stored, displayed, selected, cached, reopened, previewed, and exported position are the same coordinate; every key-owned payload moves with the identity.
- **D-02:** Automatic interpolation persists only enabled/disabled state and derives exactly `max(0, rightFrame - leftFrame - 1)` interior frames from adjacent physical real keys. Adjacent keys are valid, no leading/trailing paint interpolation exists, and toggling interpolation cannot move real keys.
- **D-03:** Remove global `inBetweenCount`, source/display projection, minimum-spacing rules, segment and moved-key spacing overrides, stale-spacing restoration, durable generated timing truth, and every production reader/writer of those concepts. Do not retain compatibility aliases, adapters, hydration fallbacks, or old-project migration.
- **D-04:** Script Motion `deform` and `position` remain supported but move into a separate script-motion settings contract rather than surviving inside interpolation timing state.

### Atomic Physical Timeline Edits
- **D-05:** Insert Frame shifts the selected identity and every later real key right by one physical slot, creates no key, preserves selected identity, validates full capacity, and records one acknowledged Undo/Redo action.
- **D-06:** Delete Frame removes the selected identity and its physical slot, shifts every later survivor left by one, shares toolbar and Delete/Backspace routing, preserves survivor payload/identity, selects deterministically, and records one acknowledged Undo/Redo action.
- **D-07:** Drag is ripple cut-and-insert. Empty/generated physical cells are direct destinations; occupied real keys expose before/after boundaries and are never overwritten. Preview and commit use the same pure resolver and track source/target by identity.
- **D-08:** Force Spacing is an explicit action where integer `N >= 0` creates exactly `N` empty physical slots between adjacent ordered real keys, anchors the first key, accepts `N = 0`, validates full capacity, and records one acknowledged Undo/Redo action.
- **D-09:** Insert, Delete, Drag, Force Spacing, Undo, and Redo use one complete `keyId -> appFrame` mapping transaction: validate the final map, stop/finalize pending paint, capture one immutable complete snapshot, stage locally once, publish once, await one matching parent acknowledgement, finalize history only on acceptance, and restore complete state on rejection/timeout/transport failure.
- **D-10:** Reopen, live cache publication, playback, onion/reference, preview, timeline length, missing-frame rendering, and export consume direct physical positions and runtime-derived interior gaps. No downstream consumer may revive source/display ownership.

### Delivery and Validation Sequence
- **D-11:** Plan this as bounded sequential plans, not as the rejected monolithic quick. Separate physical model/schema, shared transaction, ripple Insert/Delete, ripple Drag, Force Spacing, downstream parity, native UAT, post-UAT regressions, and final UI integration into reviewable boundaries.
- **D-12:** Production implementation and binary legacy-field cleanup run first, followed by typecheck/build. Stop ready for user-owned native UAT. Do not add or run regression tests until the user explicitly approves the physical model; afterward use `vitest run`, including the deferred deterministic drag coverage, before final UI validation.

### Responsive Timeline Layout
- **D-13:** The final header remains one compact row at the minimum supported width. Every control group stays visible; the central status capsule shrinks and truncates before controls compress, wrap, hide, or create a separate header scrollbar.
- **D-14:** On wider windows, extra horizontal space goes to the status capsule only. Transport, quick actions, interpolation/Force Spacing, cadence, and close remain tightly grouped rather than spreading across the width.
- **D-15:** Keep the corrected reference's compact fixed timeline height. Long status text truncates instead of growing the bottom panel or recreating the removed developer-status block.
- **D-16:** Frame cells and ruler proportions remain fixed across window sizes. Longer ranges use the existing synchronized horizontal timeline scroll/scrollbar; do not scale cells continuously or add density breakpoints.

### Force Spacing Control
- **D-17:** Replace the old live in-between count with an explicit compact nonnegative `N` input plus an **Apply** button inside the interpolation group, after the interpolation icon and enabled checkbox. The UI must read as a one-shot action, not a persisted live timing setting.
- **D-18:** The action button label is **Apply**.
- **D-19:** Keep the last entered `N` value only for the current window/session to support repeated timing work. It is not project timing truth and must not be persisted.
- **D-20:** Apply immediately after validation with no confirmation dialog. Capacity/validation failure leaves all state and history untouched; successful application is one undoable acknowledged action.

### Ripple Drag Feedback
- **D-21:** Occupied real-key targets use a clear left/right edge insertion caret plus concise boundary text. Do not split the locked 18px cell into tiny half-cell hit areas or add permanent gap elements.
- **D-22:** Before release, render the complete resolver-proposed mapping: moved identity, every shifted real key, and visually re-derived generated cells. The preview must expose the actual ripple result, not only the destination.
- **D-23:** Empty and generated physical destinations use a whole-cell target highlight. Generated styling remains visible underneath the target treatment; occupied cells continue to use before/after edge carets.
- **D-24:** After matching acknowledgement, selection and focus follow the moved `keyId` to its final physical cell. Auto-scroll only enough to keep that cell visible.

### Status and Script Routing
- **D-25:** The compact header capsule shows the latest successful relevant operation until navigation, playback, or another operation replaces it. When there is no newer event, show the concise missing-frame baseline.
- **D-26:** Failures show a concise actionable capsule summary such as `Apply failed — see LOG`; full errors and diagnostic detail go only to the existing right-panel LOG tab.
- **D-27:** The final timeline action row ends with `Copy Script | Apply Script`. Move the approved manual volatile-clipboard `Discard Script` action to the right-panel Scripts toolbar so the lifecycle remains available without violating the corrected timeline order.
- **D-28:** Unavailable `Copy Script` and `Apply Script` controls remain focusable through guarded `aria-disabled` presentation. Hover/focus exposes the controller-supplied reason through tooltip/accessibility text, and attempted activation may place the concise reason in the status capsule. Do not reconstruct availability in the UI.

### Claude's Discretion
- Exact CSS values, icons, tooltip implementation, status wording, caret animation, and component extraction are flexible when they preserve the corrected reference, fixed geometry, accessible behavior, and all decisions above.
- Exact TypeScript names and plan boundaries are flexible, but the single physical model, shared acknowledged transaction, UAT-first sequencing, and presentation/business-logic separation are not.

### Deferred Ideas (OUT OF SCOPE)
- Multi-selection UI and group movement — future capability; the complete identity-mapping transaction should not block it, but Phase 36.14 adds no UI or behavior for it.
- Legacy Roto timing migration or compatibility support — explicitly excluded; the phase performs a clean schema replacement.

## Summary

Phase 36.14 is a clean authority cutover, not an incremental extension of the existing source/display timing model. The current code stores interpolation count, mode, motion values, source/display metadata, and spacing overrides across shared types, the store, persistence, launch hydration, selectors, timeline presentation, and tests. The phase must replace that graph with one durable real-key identity (`keyId`), one physical location (`appFrame`), and runtime-only strict interior interpolation. No adapter may keep the old model alive. [VERIFIED: codebase]

The safest plan is a sequence of narrow production slices around two deep modules: a pure physical-timeline resolver and an acknowledged physical-edit coordinator. The resolver accepts real keys plus a typed intent and returns a validated complete `keyId -> appFrame` proposal, derived cells, selected identity, and concise status. The coordinator owns paint finalization, immutable snapshot capture, one local stage, one parent publication, matching settlement, accepted-only history, and complete rollback. Presentation receives resolver/controller state and emits intent; it does not calculate timing, capacity, script eligibility, or transaction state. [VERIFIED: codebase]

The delivery gate is unusual and must appear explicitly in the plans: production code and legacy-field deletion first, then `pnpm` typecheck/build, then a hard stop for user-owned native UAT. Regression files must not be added, modified, deleted, or run before canonical approval bytes pass. After approval, Plan 13 transfers valid behavior to final owners, deletes six obsolete wrapper tests, rewrites the surviving interpolation-controller test, and runs focused `vitest run`; Plan 14 then updates downstream parity and runs the full suite before final compact timeline UI integration and native validation. [VERIFIED: codebase]

**Primary recommendation:** Plan nine bounded sequential slices—physical schema/model, shared transaction, ripple Insert/Delete, ripple Drag, Force Spacing, downstream parity, native UAT gate, post-UAT regressions, and final UI—with no parallel legacy compatibility path. [VERIFIED: codebase]

### Pattern 1: Deep Pure Physical Resolver

**What:** Expose one small discriminated-intent interface that hides sorting, cut-and-insert ordering, complete-map construction, capacity checks, gap derivation, target classification, and deterministic selection. Production preview and post-UAT tests must call the same interface. [VERIFIED: codebase]

**When to use:** For Insert, Delete, Drag preview/commit, Force Spacing, and history replay validation. [VERIFIED: codebase]

**Recommended target interface:**

```ts
// Planner blueprint based on D-01 through D-10 and existing controller seams.
type PhysicalRotoKey = Readonly<{
  keyId: string;
  appFrame: number;
}>;

type PhysicalEditIntent =
  | { kind: 'insert-slot'; selectedKeyId: string }
  | { kind: 'delete-key'; selectedKeyId: string }
  | {
      kind: 'move-key';
      movedKeyId: string;
      target:
        | { kind: 'physical-cell'; appFrame: number }
        | { kind: 'before-key' | 'after-key'; targetKeyId: string };
    }
  | { kind: 'force-spacing'; emptyFrames: number };

type PhysicalEditResolution =
  | { ok: false; reason: string }
  | {
      ok: true;
      mapping: ReadonlyMap<string, number>;
      orderedKeys: readonly PhysicalRotoKey[];
      cells: readonly PhysicalTimelineCell[];
      selectedKeyId: string | null;
      status: string;
    };

function resolvePhysicalEdit(input: Readonly<{
  keys: readonly PhysicalRotoKey[];
  intent: PhysicalEditIntent;
  capacity: number;
  interpolationEnabled: boolean;
}>): PhysicalEditResolution;
```

The resolver must reject duplicate IDs, duplicate physical frames, missing identities, non-integer/out-of-range frames, invalid spacing values, and over-capacity maps before mutation. [VERIFIED: codebase]

### Pattern 2: Complete Snapshot Rebuild

**What:** Capture every frame-owned collection once, then reconstruct each collection from the complete identity mapping. Do not loop through pairwise `fromFrame -> toFrame` moves against mutable maps because ripple chains can overwrite values and can lose payload fields. [VERIFIED: codebase]

**When to use:** Local staging, accepted snapshot capture, rollback, Undo, and Redo. [VERIFIED: codebase]

**Required snapshot ownership:** real-key records, cached frames, editable frame states, preview/captured payloads, dirty frames, live-overlay counts, editable-frame list, selected identity, engine state, cached reference URL, cached repaint base, interpolation enabled state, and separated script-motion settings where operation scope requires them. [VERIFIED: codebase]

### Pattern 3: One Acknowledged Physical-Edit Coordinator

**What:** Generalize the accepted single-key move lifecycle instead of adding operation-specific asynchronous helpers. One coordinator should serialize timeline edits, finalize paint, snapshot, stage, publish, match acknowledgement, finalize history, and roll back. [VERIFIED: codebase]

**When to use:** Every Insert, Delete, Drag, Force Spacing, Undo, and Redo. [VERIFIED: codebase]

**Required order:**

1. Reject while another physical edit is pending. [VERIFIED: codebase]
2. Stop playback and finalize pending paint/cooperative work. [VERIFIED: codebase]
3. Revalidate launch identity, lock state, selected identity, and current authority revision. [VERIFIED: codebase]
4. Resolve and validate the complete final map. [VERIFIED: codebase]
5. Capture one immutable complete snapshot. [VERIFIED: codebase]
6. Stage all local state from that snapshot exactly once. [VERIFIED: codebase]
7. Publish one closed bridge payload with one operation ID. [VERIFIED: codebase]
8. Await one matching result. [VERIFIED: codebase]
9. On acceptance, record one history command and finalize selection/focus/status/cache invalidation. [VERIFIED: codebase]
10. On rejection, timeout, transport failure, launch replacement, or disposal, restore the complete snapshot and do not advance history. [VERIFIED: codebase]

### Pattern 4: Direct/Computed Preact View State

**What:** Derive ordered physical cells, generated interiors, control availability, drag preview cells, and status presentation directly from Signals/controller outputs. Use effects only for genuine external synchronization such as timers, event listeners, pointer lifecycle cleanup, or bridge subscriptions. [VERIFIED: codebase] [CITED: https://preactjs.com/guide/v10/signals/]

**When to use:** Timeline selectors, playback lists, status selection, and the workflow-strip presentation adapter. [VERIFIED: codebase]

**Example:**

```ts
// Source pattern: official Preact Signals guidance.
import { computed, signal } from '@preact/signals';

const realKeys = signal<readonly PhysicalRotoKey[]>([]);
const interpolationEnabled = signal(true);

const physicalCells = computed(() =>
  derivePhysicalCells(realKeys.value, interpolationEnabled.value),
);
```

Do not create an effect that writes `physicalCells` into a second signal or component state. Computed values are lazy, cached derived state; effects are intended for synchronization outside the reactive graph. [CITED: https://preactjs.com/guide/v10/signals/]

### Pattern 5: Guarded Focusable `aria-disabled` Buttons

**What:** Keep script controls as focusable real buttons without native `disabled`, set `aria-disabled`, expose the exact controller-supplied reason, and guard every activation path before invoking the controller callback. `aria-disabled` communicates state but does not suppress behavior. [CITED: https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-disabled]

**When to use:** Unavailable `Copy Script` and `Apply Script` only, according to the locked contract. [VERIFIED: codebase]

```tsx
<button
  type="button"
  aria-disabled={!availability.available}
  aria-describedby={!availability.available ? reasonId : undefined}
  onClick={(event) => {
    if (!availability.available) {
      event.preventDefault();
      showGuardReason(availability.reason);
      return;
    }
    onActivate();
  }}
>
  Copy Script
</button>
<span id={reasonId} class="sr-only">{availability.reason}</span>
```

Keyboard-focus order must remain predictable, and focus must remain visibly distinct from current-frame/selection styling. [CITED: https://www.w3.org/WAI/ARIA/apg/practices/keyboard-interface/]

### Anti-Patterns to Avoid

- **Compatibility projection layer:** Keeping `sourceFrame`, `displayFrame`, count, or overrides behind adapters lets old authority survive and makes downstream parity unprovable. Delete the concepts from production readers/writers. [VERIFIED: codebase]
- **One transaction helper per operation:** Separate Insert/Delete/Drag/Spacing settlement paths will drift in rollback, history, paint barriers, and error handling. Use one coordinator. [VERIFIED: codebase]
- **Pairwise mutable remapping:** Moving map entries in operation order can overwrite ripple payloads. Rebuild from the immutable pre-operation snapshot. [VERIFIED: codebase]
- **Presentation-side timing logic:** The workflow strip must not compute capacity, target legality, generated cells, or script availability. [VERIFIED: codebase]
- **Effect orchestration:** Do not coordinate transaction phases or copy resolver output with component effects. Use explicit async controller actions and computed/direct values. [VERIFIED: codebase] [CITED: https://preactjs.com/guide/v10/signals/]
- **Native `disabled` for guarded script actions:** It removes the controls from ordinary focus order and prevents the locked reason-discovery interaction. Use guarded `aria-disabled`. ## Common Pitfalls

### Pitfall 1: Stable Identity Added Only to the Timeline View
**What goes wrong:** `keyId` exists in cells but not in cache metadata, snapshots, bridge payloads, persisted records, revisions, or reopen hydration. A move appears correct until save/reopen, rollback, or export. [VERIFIED: codebase]

**Why it happens:** Current production identity is largely represented by source/display frame numbers. [VERIFIED: codebase]

**How to avoid:** Cut shared, persisted, bridge, store, and controller types together before operation work. Make every durable real-key record carry `keyId + appFrame`. [VERIFIED: codebase]

**Warning signs:** Any production function still identifies a real key solely by `sourceFrame`, `displayFrame`, or current frame number. [VERIFIED: codebase]

### Pitfall 2: Half-Migrated Source/Display Readers
**What goes wrong:** One downstream consumer silently reprojects or restores old spacing, producing mismatched timeline, playback, preview, export, or reopen positions. [VERIFIED: codebase]

**Why it happens:** The old concepts are distributed across selectors, store generation, hydration, persistence, onion traversal, and tests. [VERIFIED: codebase]

**How to avoid:** Maintain a deletion checklist for every production reader/writer of `inBetweenCount`, source/display metadata, minimum spacing, segment overrides, moved-key overrides, and generated timing persistence. Run a final binary grep gate before UAT. [VERIFIED: codebase]

**Warning signs:** Compatibility aliases, `?? appFrame` fallbacks, or adapters translating old and new coordinates. [VERIFIED: codebase]

### Pitfall 3: In-Place Ripple Remapping
**What goes wrong:** A destination is overwritten before its original payload is copied; dirty/editable/preview/onion/reference state follows a frame number instead of the key identity. [VERIFIED: codebase]

**Why it happens:** Current helpers apply frame mappings to mutable maps and operation-specific cleanup. [VERIFIED: codebase]

**How to avoid:** Capture one immutable snapshot and rebuild every frame-owned map/set/list from the complete mapping. Add payload-preservation assertions after UAT. [VERIFIED: codebase]

**Warning signs:** Loops that delete and set against the live map, or normalization functions that delete fields such as `backgroundOnly` inconsistently. [VERIFIED: codebase]

### Pitfall 4: Generic Insert/Delete Bypass Acknowledged Settlement
**What goes wrong:** The child updates optimistically, parent persistence fails, and only an error is posted; selection, cache, and history remain in a state the parent never accepted. [VERIFIED: codebase]

**Why it happens:** Current move has settlement/rollback, while generic key utilities use asynchronous persistence without complete restoration. [VERIFIED: codebase]

**How to avoid:** Retire the split paths before implementing new semantics. All physical edits, including history replay, must use one coordinator. [VERIFIED: codebase]

**Warning signs:** Calls to generic `applyKeyFrames()`/`persistKeyFrameTransaction()` from physical timing actions, or history recorded before acknowledgement. [VERIFIED: codebase]

### Pitfall 5: Preview and Commit Use Different Drag Logic
**What goes wrong:** The visible ripple proposal differs from the committed ordering, especially around occupied targets because cutting the moved key changes target indices. [VERIFIED: codebase]

**Why it happens:** UI hit testing, preview, and controller commit each recalculate destination semantics independently. [VERIFIED: codebase]

**How to avoid:** Resolve target identity/boundary once through the same pure resolver interface for preview and commit. Track moved and occupied target by `keyId`, not stale frame/index. [VERIFIED: codebase]

**Warning signs:** Commit receives only `fromFrame`/`toFrame`, or the UI hides shifted peers during preview. [VERIFIED: codebase]

### Pitfall 6: Capacity Checked Incrementally
**What goes wrong:** Insert or Force Spacing partially stages before discovering the final key exceeds sequence capacity. [VERIFIED: codebase]

**Why it happens:** Capacity is checked per moved frame instead of against the complete final map. [VERIFIED: codebase]

**How to avoid:** Resolver and parent authority both validate the complete map before mutation/acceptance; invalid operations leave state and history untouched. [VERIFIED: codebase]

**Warning signs:** Any local collection changes before a complete map is available and valid. [VERIFIED: codebase]

### Pitfall 7: Motion Settings Remain Hidden in Interpolation State
**What goes wrong:** Removing old interpolation fields accidentally removes Script Motion `deform`/`position`, or keeping them preserves a mixed timing contract. [VERIFIED: codebase]

**Why it happens:** Current script-motion reads come from `PhysicPaintRotoInterpolationSettings`. [VERIFIED: codebase]

**How to avoid:** Extract the script-motion settings contract in the physical schema slice and update script readers/writers before deleting the old interpolation type. [VERIFIED: codebase]

**Warning signs:** Production interpolation settings contain any field besides enabled state after cutover. [VERIFIED: codebase]

### Pitfall 8: Effects Recreate Domain Authority in the UI
**What goes wrong:** Props/signals are mirrored into local state, causing stale drag previews, selection corrections after render, dependency loops, or status races. [VERIFIED: codebase]

**Why it happens:** React-style effect orchestration is used for internal state transitions. [VERIFIED: codebase]

**How to avoid:** Derive cells/status with computed/direct values and perform edits in explicit event/controller actions. Reserve effects for external subscriptions, timers, and cleanup. [VERIFIED: codebase] [CITED: https://preactjs.com/guide/v10/signals/]

**Warning signs:** Effects whose only purpose is to copy one internal reactive value into another. [VERIFIED: codebase]

### Pitfall 9: `aria-disabled` Without Behavioral Guarding
**What goes wrong:** Assistive technology announces the action as unavailable, but click/Enter/Space still invokes it. [CITED: https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-disabled]

**Why it happens:** ARIA changes semantics, not native behavior. [CITED: https://developer.mozilla.org/en-US/docs/Web/Accessibility/ARIA/Reference/Attributes/aria-disabled]

**How to avoid:** Guard the shared activation handler, preserve focusability, expose the exact controller reason, and test pointer plus keyboard activation after UAT. [VERIFIED: codebase]

**Warning signs:** `aria-disabled` is present but the callback is passed directly to `onClick`, or UI recomputes the disabled reason. [VERIFIED: codebase]

### Force Spacing Complete Mapping

```ts
// Source: D-08 locked phase contract.
function mapForceSpacing(
  orderedKeys: readonly PhysicalRotoKey[],
  emptyFrames: number,
): ReadonlyMap<string, number> {
  if (!Number.isInteger(emptyFrames) || emptyFrames < 0) {
    throw new Error('Spacing must be a nonnegative integer.');
  }

  const firstFrame = orderedKeys[0]?.appFrame ?? 0;
  return new Map(
    orderedKeys.map((key, index) => [
      key.keyId,
      firstFrame + index * (emptyFrames + 1),
    ]),
  );
}
```

### Cut-Then-Insert Occupied Target

```ts
// Source: D-07 and the authoritative A@1, B@3, C@5, D@8 example.
function reorderAfterTarget(
  orderedIds: readonly string[],
  movedKeyId: string,
  targetKeyId: string,
): string[] {
  const withoutMoved = orderedIds.filter((id) => id !== movedKeyId);
  const targetIndex = withoutMoved.indexOf(targetKeyId);
  if (targetIndex < 0) throw new Error('Target identity is missing.');

  return [
    ...withoutMoved.slice(0, targetIndex + 1),
    movedKeyId,
    ...withoutMoved.slice(targetIndex + 1),
  ];
}
```

The resolver then assigns physical frames according to the selected physical destination/ripple rule and returns the complete map; the UI must not implement this ordering itself. [VERIFIED: codebase]

// Source: W3C Pointer Events lifecycle and existing workflow-strip mechanics.
function finishDrag(pointerId: number, reason: 'commit' | 'cancel') {
  if (activePointerId.value !== pointerId) return;
  stopEdgeScroll();
  activePointerId.value = null;
  dragPreview.value = null;

### Known Threat Patterns for the Desktop Webview Bridge

| Pattern | STRIDE | Standard Mitigation |
|---------|--------|---------------------|
| Forged or malformed replacement payload | Spoofing / Tampering | Parse as an exact closed structure; reject unknown operation kinds, invalid IDs, invalid frames, duplicate IDs/frames, and incomplete mappings. Revalidate in parent authority. [VERIFIED: codebase] |
| Reused operation ID with a different payload | Tampering / Repudiation | Preserve accepted-operation deduplication and reject mismatched reuse; include operation identity in settlement matching. [VERIFIED: codebase] |
| Stale acknowledgement settles a newer launch/edit | Tampering | Match operation ID, kind, layer, launch/start context, and expected revision before acceptance; cancel on launch replacement/disposal. [VERIFIED: codebase] |
| Over-capacity map causes partial state changes | Denial of Service / Tampering | Validate the complete final map in resolver and parent before mutation; rollback all local state on any failed settlement. [VERIFIED: codebase] |
| Prototype/extra-field injection through message data | Tampering | Construct validated plain records/maps from allowlisted fields rather than spreading untrusted bridge objects into durable state. [CITED: https://github.com/OWASP/ASVS/blob/v5.0.0/5.0/en/0x24-V15-Secure-Coding-and-Architecture.md] |
| Internal error detail exposed in compact UI | Information Disclosure | Send concise operation failure to the status capsule and diagnostic detail only to existing LOG. [VERIFIED: codebase] |
| Double activation while pending | Tampering / Denial of Service | Serialize physical edits and guard pointer/keyboard controls while one acknowledged operation is pending. [VERIFIED: codebase] |
