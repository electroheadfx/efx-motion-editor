## Scope Rules for the Planner

- This is a clean authority cutover. Do not preserve `sourceFrame`/`displayFrame` projection, `inBetweenCount`, minimum spacing, segment/moved-key overrides, or durable generated timing through adapters or fallback fields.
- The two required deep modules are one pure physical resolver and one acknowledged physical-edit coordinator. Do not create one resolver or coordinator per operation.
- D-29 is the occupied-boundary Drag oracle: `A@1,B@3,C@5,D@8` dragged after D becomes `A@1,C@5,D@8,B@9`; empty/generated whole-cell Drag retains its source-closing direct-destination semantics.
- D-30 governs the current rejected-UAT recovery track: Plans 21-27 production gap fixes use bounded static checks only, Plan 28 is an integrated bounded static read-only review, and Plan 29 is user-owned native UAT. Only exact native approval may make separate later regression/typecheck/build planning eligible; no approval TXT is created and Plans 13-18 remain locked.
- Preact presentation receives derived/controller state and emits intent. It does not resolve mappings, capacity, acknowledgement, rollback, history, generated cells, or script availability.
- `app/index.html` is listed because CONTEXT names it as the application-shell integration point. The existing styling seam is `app/src/index.css`; use one shell-level CSS owner rather than duplicating the rule.

## Shared Patterns

### Stable Identity Ownership

**Source:** current move snapshot/controller seams, replaced by the physical model.

**Apply to:** schemas, store, cache metadata, bridge payloads, snapshots, history, selection, launch hydration, scripts, preview/export, onion/reference, playback, and timeline cells.

Every durable real key carries one stable `keyId` and one physical `appFrame`. Payload follows identity. New Duplicate/Paste-created durable keys should receive new IDs while cloning content; timing edits preserve existing IDs.

### Complete Validation Before Side Effects

**Sources:** `physicsPaintRotoKeyController.ts` builder pattern; `physicPaint.ts` fail-closed validator; `physicPaintBridge.ts` authority checks.

Validate unique IDs, unique frames, integer/range/capacity, target identities, survivor set, and complete mapping before local mutation. Revalidate the same invariants in parent authority.

### One Pending Physical Edit

**Sources:** `useRotoApplyLifecycle.ts`, Studio move guard, script controller busy computed values.

Insert/Delete/Drag/Force Spacing/Undo/Redo serialize behind one pending operation. Presentation disables or guards mutation activation from controller state; it does not invent a second lock.

### Immutable Complete Snapshot and Rollback

**Source:** `PhysicsPaintStudio.tsx` lines 560-706.

Capture and restore all frame-owned state, selection identity, engine state, reference/repaint state, interpolation enabled state, and required motion state. Rollback is complete on rejection, timeout, transport failure, launch replacement, disposal, or unexpected exception.

### Accepted-Only History

**Source:** `useRotoKeyMoveHistory.ts` lines 97-159.

No history entry is recorded before matching parent acceptance. Undo/Redo replay uses the same coordinator and moves its cursor only after acceptance.

### Signals and Direct Derivation

**Sources:** project `CLAUDE.md`; `frameMap.ts` computed subscription; script controller computed availability.

Use Signals/computed/direct values for shared/derived state. Use event handlers for intent. Effects are reserved for timers, bridge/event subscriptions, pointer cleanup, focus restoration tied to an external dialog lifecycle, and disposal.

### Concise Status, Detailed LOG

**Sources:** `usePhysicsPaintApplyResultController.ts`; script controller `status`/`error` split.

The header capsule receives one-line relevant operation copy and truncates. Full error detail goes to the existing LOG state only. Do not add a timeline Log button or auto-switch tabs.

### Runtime-Only Generated Cells

**Sources:** store regeneration and `rotoFrameDraw.ts` strict interior policy.

Real keys are the sole editable/durable authority. Generated cells are derived from physical gaps for timeline/render consumers and excluded from bridge mapping authority, history identity sets, persisted metadata, and cache ownership.

### Version Invalidation

**Source:** `physicPaintStore.ts` `_notifyVisualChange()` and `frameMap.ts` `void physicPaintVersion.value`.

Accepted mutations affecting render output bump `physicPaintVersion` once after complete replacement. Preview/export/timeline consumers remain subscribed.

### No Authentication Pattern

This phase adds no authentication or authorization. The relevant guard is parent bridge authority, runtime payload validation, operation/revision matching, and local controller availability.
