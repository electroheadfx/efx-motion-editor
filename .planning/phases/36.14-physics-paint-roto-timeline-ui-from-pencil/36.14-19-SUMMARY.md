## Decisions Made

- Duplicate does not accept or calculate a destination in any Plan 19 owner. Only the source `keyId` crosses the utility boundary; Plan 20 owns fresh identity allocation and `source.appFrame + 1` ripple semantics.
- Paste uses the current direct physical frame. A real destination contributes its current `keyId`; an empty or generated destination contributes `null`, allowing Plan 20 to choose the correct create-versus-replace semantic delta.
- The copied session frame is converted into a frozen `PhysicPaintRotoRealKeyPayload` for each Paste request. The stored copied snapshot is never consumed, retargeted, or mutated by Paste.
- The existing coordinator pending signal remains the sole physical concurrency authority. The local `keyActionInFlight` state remains presentation-local and brackets only the delegated user action; no settlement or pending-operation mirror was added.
- The legacy session `replaceKeys` effect is retained only as an exhaustive fail-closed union branch because its type is owned outside Plan 19's five-file boundary; it has no mutation or persistence implementation in this route.
