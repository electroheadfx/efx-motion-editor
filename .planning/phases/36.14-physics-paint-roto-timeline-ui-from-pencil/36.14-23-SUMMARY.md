- Verified and preserved prerequisite commits `e404be61`, `12f2170f`, and `395c680c` before Task 2; Task 1 was not repeated.
- Added a shared PNG data-URL guard that verifies both the PNG media type and decoded eight-byte PNG signature before canonical payload decode or generated reference consumption.

## Decisions Made

- Decode remains asynchronous only at the launch/publication barrier. The established synchronous generated render-source and reference lookup seams remain unchanged and no effect-driven render race was introduced.
- Exact canonical payload URLs remain registry keys. Fresh paint and reopened payloads therefore converge on one lookup contract without aliases, wrappers, compatibility fields, or dual writes.
- Generated output has no fallback image. If either adjacent canonical source is absent, invalid, or stale, the store returns no generated source and the existing empty/background behavior remains authoritative.
- Reference validation checks the generated source's exact appFrame and deterministic cacheRevision string before accepting its PNG, preserving the current physical content revision as the only generated-read authority.
- Registry pruning is reference-aware across physical records and established legacy frame collections, preventing replacement/reopen residue without deleting a canvas still used by another layer or frame.
