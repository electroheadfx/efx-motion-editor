## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Tight icon-to-label gaps, action-row button gaps |
| sm | 8px | Compact control spacing and header group gaps |
| md | 16px | Workflow-strip horizontal padding |
| lg | 24px | Icon-only focus/touch box and compact control width |
| xl | 32px | Header control-island height and transport grouping |
| 2xl | 48px | Reserved major separation only; not used inside the compact timeline bands |
| 3xl | 64px | Reserved application-level spacing only; not used inside the timeline |

Exceptions are locked geometry rather than reusable spacing tokens:

- Timeline frame cell: `18px` wide by `24px` high.
- Gap between adjacent timeline cells: `2px`.
- Header: `46px` high.
- Ruler: `28px` high.
- Frame lane: `38px` high.
- Context action row: `28px` high.
- Synchronized scrollbar band: `14px` high.
- Complete workflow strip: `155px` high including its divider/border treatment.
- Primary header controls: `30px` high; grouped control islands may use a `32px` outer height.
- Context action buttons: `22px` high.
- Checkbox: `14px` square.
- Occupied-target insertion caret: `2px` wide, aligned to the selected left or right cell edge.

Do not turn these geometry exceptions into new general spacing tokens. Do not scale cell width, ruler cadence, or band heights at responsive breakpoints.

## Typography

Use exactly these four sizes and two weights within the final timeline UI:

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 12px | 600 | 1.5 |
| Label | 10px | 600 | 1.2 |
| Heading | 13px | 700 | 1.2 |
| Display/status | 11px | 700 | 1.2 |

Rules:

- Use weight `600` for ruler labels, secondary metadata, checkbox labels, and supporting copy.
- Use weight `700` for button labels, key identity, compact numeric fields, and the status capsule.
- Do not introduce weight `800` or `900` in the implemented timeline even when the static reference uses `font-extrabold` or `font-black`; normalize those examples to the declared two-weight contract.
- Use tabular numerals for frame numbers, cadence, Force Spacing values, and ruler marks.
- Truncate the status capsule to one line with an ellipsis; never reduce its text below `11px` to make controls fit.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Primary CTA | `Apply` — exact visible label for Force Spacing |
| Empty state heading | `No real Roto keys` |
| Empty state body | `Paint on a real frame or duplicate a key to begin timing.` |
| Baseline status | `Missing frames play transparent/background` |
| Error state | `Apply failed — see LOG` |
| Destructive confirmation | `Delete Frame`: no confirmation dialog; execute through the acknowledged, undoable transaction. Existing durable script deletion keeps `Delete “{name}”?` and `This removes the project script file and cannot be undone.` in the Scripts panel. |

### Operation Status Grammar

- Use a concise verb-first result: `Frame inserted`, `Frame deleted`, `Spacing applied`, `Key moved`, `Undo complete`, `Redo complete`.
- A successful Force Spacing result may append the value: `Spacing applied — {N} empty frames`.
- An occupied drag boundary uses concise live copy: `Insert before Key {N}` or `Insert after Key {N}`. If the UI identifies keys by frame rather than ordinal, use `Insert before frame {F}` or `Insert after frame {F}` consistently.
- Busy copy uses an ellipsis only while an acknowledged operation is pending: `Applying spacing…`, `Moving key…`, `Deleting frame…`.
- Failure copy names the attempted operation and sends detail to LOG: `{Operation} failed — see LOG`.
- Controller-supplied Copy Script and Apply Script disabled reasons are authoritative and must be shown verbatim. Do not shorten, reinterpret, or reconstruct them in presentation.
- Do not add a permanent legend, generated-frame explanation, cached-reference explanation, interpolation diagnostic, or developer status paragraph under the timeline.

## Fixed Layout Contract

### Overall Geometry

The bottom workflow strip remains a fixed `155px` high and consists of these bands in order:

1. `46px` single-row header.
2. `1px` divider.
3. `28px` ruler.
4. `38px` physical-frame lane.
5. `28px` fit-content context action row.
6. `14px` synchronized horizontal scrollbar band.

The removed developer status stack must not be replaced with another band, legend, toast rail, expandable diagnostics region, or multiline status block.

### Header Order

The header is one non-wrapping row in this exact order:

1. Roto identity, for example `Roto #1`.
2. Transport controls.
3. Elastic status capsule.
4. Quick key actions: `Key` and `Duplicate`.
5. Interpolation and Force Spacing group.
6. Playback cadence group.
7. Close button.

All groups except the status capsule are `flex: none`/non-shrinking control islands. The status capsule is the only `flex: 1` region and must use `min-width: 0`, single-line truncation, and ellipsis. Extra width belongs only to the status capsule. Reduced width is absorbed by the capsule before any control wraps, hides, compresses, changes label, or creates a header scrollbar.

### Timeline and Ruler

- Frame cells remain `18px × 24px` at every supported window width.
- Ruler ticks remain aligned to the physical cell pitch and synchronized with the frame lane.
- Longer physical ranges use the existing shared horizontal timeline scroll position and visible scrollbar.
- Do not fit all frames by scaling cells, changing ruler cadence based on width, or introducing density breakpoints.
- Auto-scroll only enough to reveal the newly selected/moved physical cell; do not recenter the timeline unnecessarily.

## Interaction Contract

### Force Spacing

- Render the group in this order: interpolation icon, enabled checkbox, nonnegative `N` input, `Apply` button.
- The checkbox changes only interpolation enabled/disabled state. Toggling it must not move real keys.
- The `N` input represents the exact number of empty physical slots required between each adjacent ordered real key.
- Use a numeric input with `min="0"`, `step="1"`, an accessible name of `Empty frames between real keys`, and a compact width sufficient for at least three digits.
- Accept only a whole integer `N >= 0` when `Apply` is activated. Empty, fractional, negative, nonnumeric, and over-capacity values do not publish a transaction.
- Keep the last entered value only for the lifetime of the open Physics Paint window/session. Do not write it to project state, interpolation state, persistence, history snapshots, cache metadata, or script state.
- `Apply` acts immediately after validation. There is no confirmation dialog.
- A successful action is one acknowledged undoable operation. Rejection, timeout, transport failure, or capacity failure leaves key positions, selection, generated output, cache, and history unchanged or fully restored.
- Presentation submits the integer intent and renders controller state. It does not calculate the final key mapping or capacity.

### Ripple Drag

- Preserve the existing pointer threshold, pointer capture, Escape cancellation, pointer-cancel/lost-capture cleanup, and edge-scroll behavior.
- Before the drag threshold is crossed, a pointer interaction retains normal click-to-select behavior.
- Empty and generated physical destinations use one whole-cell target highlight.
- Occupied real-key destinations remain whole-cell targets but expose one resolver-selected insertion boundary using a clear left-edge or right-edge `2px` caret and concise boundary status text.
- Do not split an `18px` occupied cell into permanent half-cell controls, tiny sub-buttons, or extra gap elements.
- During drag, render the resolver-proposed complete mapping: the moved identity, every shifted real key, and all newly derived generated cells. A destination-only ghost is insufficient.
- Keep the moved identity visually distinguishable from shifted peers without replacing its semantic real-key color.
- During acknowledgement, retain a stable committing treatment and prevent a second timeline mutation from being issued.
- On matching acknowledgement, selection and keyboard focus follow the moved `keyId` to its final physical cell. Scroll only enough to keep it visible.
- On rejection or timeout, restore the complete pre-operation mapping and focus a valid restored cell; show concise failure copy and send details to LOG.

### Insert, Delete, Undo, and Redo

- `Insert` shifts the selected identity and all later real keys right by one physical slot; it creates no key and preserves selected identity.
- `Delete` and Delete/Backspace shortcut routing invoke the same controller action. Delete removes the selected identity and slot, shifts later survivors left, and applies controller-defined deterministic survivor selection.
- `Undo` and `Redo` present one pending action at a time and finalize visible history only after matching acknowledgement.
- Timeline controls submit operation intent only. They must not mutate keys, caches, persistence, selection, or history directly.

### Context Action Row

Render a single fit-content pill in this exact order:

`Key N | Insert | Dup | Copy | Paste | Delete | Copy Script | Apply Script`

- Keep the row anchored inside its `28px` band and horizontally synchronized with timeline scrolling where the current implementation requires it.
- Do not add `Discard Script` to this row.
- Move the manual volatile-clipboard `Discard Script` action into the existing right-panel Scripts toolbar without changing durable script-library behavior.

## Visual State Contract

Every cell must expose its physical frame and semantic state through both visuals and an accessible label.

| State | Required presentation |
|-------|-----------------------|
| Empty | Neutral `#505860` cell; remains a full drag destination. |
| Real/cached key | Existing cached-key green treatment; represents the only editable durable authority. |
| Generated | Existing generated blue treatment; render-only, not selectable as a durable key; remains a full physical drag destination. |
| Background only | Existing striped neutral treatment; label it as background-only rather than empty paint. |
| Current physical frame | Orange playhead/current-cell treatment layered over the semantic base state. |
| Selected real key | Clear selected outline/focus treatment that remains distinguishable from the current-frame orange marker. |
| Drag source | Stable source identity marker after threshold; do not remove it from the complete preview model. |
| Empty/generated target | Whole-cell overlay or inset ring; preserve the underlying semantic fill. |
| Occupied before/after target | Left or right insertion caret plus status-capsule boundary copy. |
| Pending acknowledgement | Stable committing treatment; no animated geometry or speculative second movement. |
| Invalid/capacity failure | No proposed mapping commit; retain prior state and route concise failure to status plus detail to LOG. |

Do not restore `saving`, `pending save`, or `unsaved changes` timeline overlays. Save-barrier and transaction progress are controller concerns surfaced only as the concise relevant operation status.

## Status and LOG Routing

- The header capsule shows the latest successful relevant timeline/script operation until navigation, playback, or a later operation replaces it.
- When there is no newer relevant event, show the baseline status from the Copywriting Contract.
- The capsule is always one line, never increases panel height, and never pushes control groups off-screen.
- Failures show only a concise actionable summary. Full error objects, transport details, validation diagnostics, and stack information go only to the existing right-panel LOG tab.
- Do not add a Log button to the timeline header and do not automatically change the user's right-panel tab.
- Script progress, status, errors, availability, and reasons come from the existing script clipboard controller. The timeline may choose which supplied concise status is most recent, but it must not derive script eligibility or inspect engine state.

## Accessibility and Input Contract

### Guarded Script Controls

`Copy Script` and `Apply Script` remain keyboard-focusable when unavailable:

- Use a real `button` without the native `disabled` attribute.
- Set `aria-disabled="true"` when the controller reports the action unavailable.
- Guard pointer, Enter, and Space activation before invoking the controller action.
- Expose the exact controller-supplied reason on hover and keyboard focus through the project's tooltip/accessibility-text pattern.
- Associate persistent hidden reason text with `aria-describedby` when necessary so the reason is available without hover.
- An attempted guarded activation may place the concise supplied reason in the status capsule.
- Do not infer availability from selected frame type, current mode, paint count, clipboard presence, or busy state in the presentation component.

### Focus and Keyboard

- Visual focus order follows header order, then physical cells, then context action order.
- Every icon-only control has an explicit accessible name.
- Focus rings are at least 2px and must not rely on orange current-frame color alone.
- A successful acknowledged move, insert, delete, undo, or redo places focus on the controller-selected real key cell.
- Escape cancels an active drag without publishing.
- Delete and Backspace use the existing paint-mode shortcut guard and the same Delete Frame action as the visible control.
- Native number-input editing, checkbox activation, tab traversal, and text selection remain intact.

### Application Selection Guard

Apply the selection policy at the application shell level:

```css
html,
body,
#app {
  -webkit-user-select: none;
  user-select: none;
}

input,
textarea,
[contenteditable="true"],
.physics-paint-log-messages {
  -webkit-user-select: text;
  user-select: text;
}
```

Equivalent selectors are acceptable only if they preserve the same contract. The guard must not interfere with canvas painting, sliders, timeline dragging, pointer capture, keyboard focus, native input editing, contenteditable fields, or LOG message selection/copying.

## Preact and State Ownership Contract

This phase uses Preact-native direct derivation and the existing Signals/controller architecture.

### Presentation Receives

- Physical cell view models keyed by stable `keyId` where applicable.
- The current physical frame and selected identity.
- Resolver-supplied drag target kind, before/after boundary, complete proposed mapping, and validity.
- Interpolation enabled state.
- Session-local Force Spacing input value and controller action state.
- Concise status presentation state.
- Script controller callbacks, availability, disabled reasons, busy/progress state, status, and error summary.
- Existing Insert, Duplicate, Copy, Paste, Delete, Undo, Redo, transport, cadence, and close handlers.

### Presentation Emits

- User intent: select physical frame/key, begin/update/cancel/commit drag, toggle interpolation, apply Force Spacing, activate an existing action, navigate, play/pause, change cadence, or close.

### Presentation Must Not Own

- Physical mapping legality or ripple resolution.
- `keyId -> appFrame` transaction construction.
- Capacity validation beyond native field affordances.
- Parent acknowledgement matching, rollback, durable history, persistence, cache publication, preview/export invalidation, or timeline-length calculation.
- Generated interpolation derivation.
- Script clipboard data, script eligibility, paint-engine inspection, target promotion, script replay, or script history.
- Detailed error formatting or LOG storage.

Use direct values or computed Signals for view state. Keep gesture-local mutable values in focused refs/signals where needed. Use event handlers to submit intent. Do not add `useEffect` chains that copy controller props into local state, reconstruct derived mappings, synchronize selection after ordinary renders, or orchestrate transaction control flow. Effects are permitted only for genuine external lifecycle synchronization with focused cleanup, following existing project patterns.

## Responsive Contract

- Preserve one header row at every host-supported Physics Paint window width.
- Do not add a timeline-specific breakpoint, density mode, abbreviated label mode, overflow menu, hidden group, wrapped row, or independent header scrollbar.
- All fixed control groups remain visible and maintain their declared heights and readable labels.
- The status capsule alone absorbs width changes through `flex: 1`, `min-width: 0`, and truncation.
- On wider windows, additional space goes only to the status capsule; control islands remain tightly grouped rather than spreading across the width.
- Timeline overflow is horizontal and synchronized between ruler, cells, playhead, action anchoring, and scrollbar.
- Long operation text truncates in the capsule and remains available through accessible text/title or the LOG detail path; it never increases workflow-strip height.

## Validation Sequence

1. Implement the physical model, shared acknowledged transaction path, downstream parity, and binary legacy-field cleanup first.

3. Stop ready for user-owned native UAT. Do not claim final completion before that visible UAT passes.
