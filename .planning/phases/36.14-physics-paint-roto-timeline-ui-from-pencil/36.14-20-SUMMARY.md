## Decisions Made

- Duplicate callers provide only the source stable identity. The exported factory allocates one fresh ID once, while the resolver alone derives the destination as `source.appFrame + 1`.
- Paste intent data is closed: an empty/generated target carries one fresh ID, while an existing target carries its current keyId and no fresh ID. The clipboard payload remains immutable and reusable; only its direct physical payload frame is retargeted in the proposed record.
- Complete `nextRecords` plus `semanticDelta` are reserved for Duplicate/Paste. Mapping-only ordinary operations and complete-snapshot Undo/Redo retain their existing proposal and staging behavior.
- The active runtime result validator discriminates `replace-roto-physical-map` into the exact parent acknowledgement. The generic TypeScript result base remains broad enough for unchanged read-only store constructors, while every received physical result is runtime-validated and exact-matched before coordinator settlement.
