## Phase Goal

**As a** stop-motion animator, **I want to** have every real Roto key, generated in-between, timeline edit, persisted frame, and rendered output use one deterministic physical-frame authority, followed by a polished timeline UI that exposes the approved behavior without duplicating business logic, **so that** editing, reopening, previewing, and exporting the same Roto work cannot disagree about frame identity.

<objective>
Establish the production-only pre-UAT boundary and replace the durable Roto timing schema with stable `keyId` plus direct physical `appFrame` identity, persisted interpolation enabled state, and a separate Script Motion contract; remove compatibility and migration paths rather than layering an adapter. Regression files and Vitest remain untouched through approval of 36.14-12.

Purpose: Give plans 36.14-02 onward one closed, runtime-validated physical contract so resolver, store, transaction, persistence, rendering, and UI work cannot reintroduce source/display projection or durable generated timing truth.

Output: Physical Roto identity/settings types, strict project/bridge/Script schemas, a native key-ID creation seam, and direct Script Motion ownership in production code only.
</objective>
