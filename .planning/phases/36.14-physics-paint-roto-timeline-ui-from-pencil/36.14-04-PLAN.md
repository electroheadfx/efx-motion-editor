## Phase Goal

**As a** stop-motion animator, **I want to** have every real Roto key, generated in-between, timeline edit, persisted frame, and rendered output use one deterministic physical-frame authority, followed by a polished timeline UI that exposes the approved behavior without duplicating business logic, **so that** editing, reopening, previewing, and exporting the same Roto work cannot disagree about frame identity.

<objective>
Build the single acknowledged physical-edit coordinator per D-01, D-03, D-09, D-10, D-11, D-12, D-25, and D-26. Introduce generic request/result, settlement, and coordinator interfaces additively; implement the coordinator behind those inactive interfaces; then rewire every Studio, persistence, launch, result, and bridge consumer in one coherent final task before removing move-specific exports. The final path serializes pending work, revalidates launch/layer/revision before staging and settlement, captures immutable complete snapshots, stages once, publishes once, matches one exact acknowledgement, and restores fail-closed state for every unsuccessful or cancelled outcome.

Purpose: Replace the accepted move-only lifecycle with one operation-agnostic physical transaction seam without ever requiring a deleted-export/live-consumer intermediate build or leaving a compatibility transaction path. Plan 05 owns generic accepted-only history, and Plans 06-08 own operation delivery semantics.

Output: Additive generic contracts, a deterministic physical revision/envelope, parent complete-map authority, one Preact-native coordinator, one atomic consumer cutover, complete snapshot/rebuild ports, exact settlement, and concise status-versus-LOG routing.
</objective>
