**CRITICAL — Pitfall 1 (the one place this branch must NOT be copied verbatim):** the filter at L3200-3202 only *removes* deleted break owners. Delete Key Rail (D-15) must additionally ADD the vacated-interval successor break per 43.3 rule (a) — the next surviving real key at/after the vacated end owns/reuses the break (never when no successor exists, never duplicated). Reuse the complete-collection-replacement idiom:

```typescript

// ... (a) vacated-gap ownership is a pre-move fact; select the next external real key, then:
if (successor !== null) owners.add(successor);
// ... output is a complete collection replacement, never a delta; deterministic ascending order (L2181-2185):
return [...owners].sort((left, right) => {
  const frameLeft = mapping.get(left) ?? Number.POSITIVE_INFINITY;
  const frameRight = mapping.get(right) ?? Number.POSITIVE_INFINITY;
  return frameLeft - frameRight || left.localeCompare(right);
});
```

**Clamp sibling (KDRAG-01):** fork `clampPhysicPaintGroupDragDestination` (L2010-2106) into a key-rail clamp. Its collision algebra to preserve: boundary key-frame Set built while skipping the dragged segment's own keys (pass-through — L2036-2046), `intervalFree`/`keysLandFree`/`valid` composition, directional nearest-free search that never crosses the current position (L2092-2106):

```typescript
if (proposed > current) {

  // never moving left of the current placement.
```

Simplifications for Key Rails: no `attached`/duplicated branch (always source-attached), no Infinity/zero-width cases (span always ≥ 1). Do NOT copy `move-key-group`'s rejection-on-collision semantic (43.3 Pitfall 3) — clamp, reject only on zero valid movement.

**Post-move break derivation (KDRAG-02):** mirror `deriveMoveGroupIncomingInterpolationBreakKeyIds` (L2110-2186, docstring quoted verbatim):
