## Debug Round 5 — Key Rail keyboard shortcuts + focus parity

Fixes applied on top of the frozen commit (RED tests first, then shared-path implementation; no Key-Rail-only fork when a shared path exists):

- **Defect 7** — Cmd+Z / Cmd+Shift+Z inert after Delete Key Rail (focus escaped to body; the Defect 6 restoration called `container.focus()` on a non-focusable div). Fix commit `04591cad`: the timeline scroll container is `tabIndex={-1}`, so post-commit focus restoration lands on a Studio element and the shortcuts route through the same physical undo/redo the visible buttons use — one path for every rail family.
- **Defect 8** — Key Rail focus graphic diverged (band-only ring, 1px offset, clipped). Fix commit `44e0b3be`: one shared `physics-paint-rail-target` class and one full-row ring drawn on the focused target's `::after` (2px `#F2F5F7`, 2px offset, wrapping the 38px lane = 3px band + full 24px cell row, unclipped, `pointer-events: none`). Selected-orange rail paint unchanged.
- **Defect 9** — focus cycling semantics. Fix commits `5888d161` + `55f030c4`: a shared `physicsPaintRailKeyboardNavigation` module gives the lane's rail targets a single roving tab stop ordered by canonical first-key frame; Tab/ArrowLeft/ArrowRight cycle rail-to-rail across all three types, the boundary stays put (no wrap) and Tab exits to the stable timeline scroller. Frame-level cycling is selection-gated: with a real key in the primary selection, plain arrows jump to the adjacent REAL KEY frame (never generated/interpolated/empty), the landing key becomes the selection so presses chain, and plain cursor movement / Shift+Arrow saved-frame jump are preserved.
