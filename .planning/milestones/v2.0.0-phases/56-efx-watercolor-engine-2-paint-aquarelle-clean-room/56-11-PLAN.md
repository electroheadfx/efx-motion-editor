As an animator in the Physics Paint Studio,
I want the Water color module to paint with the aquarelle engine (wet-in-wet bloom, tide line) on the same Studio canvas,
so that what I paint is what records, plays, and bakes.

Surface pin (hard): PHYSIC PAINT STUDIO modal window. Canvas = `PhysicsPaintCanvasMount` / `EfxPaintCanvas`
(`packages/efx-physic-paint/src/preact.tsx`) inside the Studio. NOT the inline EFX Paint editor.

engine owns the Studio canvas. If a step touches anything outside the Studio window, STOP and ask.
</user_story>

  - per sample: stampTool / depositStrokeOnSheet on the FluidSheet; per tick: step(sheet, dt); display via a sheet raster, throttled
  - stroke end → snapshotAquarelleRecord() + AquarellePoint[] + ticks → the script payload (the record seam)
  - Dry = forceDrySheet at the recorded tick + the recorded payload event (D-15/D-16). No forced Dry at frame boundaries
  - activeModule === 'brush' → unchanged physics path (EfxPaintEngine owns input)
  - shared block D-05 renders Color, Size, Opacity widgets for BOTH modules; Size maps to aquarelleParams.size in Water color

<implementation>
ENGINE CONSTRAINT (one engine PER SCRIPT, not one global engine): inside Water color, live and bake
must both be the clean-room engine (`packages/efx-watercolor`). Physics and watercolour stay separate
paint systems (EngineId union, module switcher, separate adapters). A1/A2 constrain live look and
baked look OF THE SAME SCRIPT to come from the same engine.

SURFACE: one shared Studio (MOD-03 / D-24). Both engines paint on that same canvas region.
`activeModule` decides which engine owns it. Today it only drains `PhysicsPaintRightPanel` — that is
the bug.

BUILD SHAPE — one engine, one stepping law (live == bake):
1. Pointer down/move/up on the Studio canvas when `activeModule === 'watercolor'`, routed to a live
   aquarelle surface, NOT to `EfxPaintEngine`. Interception seams that do not modify efx-physic-paint:
   `engine.setInputLocked(true)` plus a pointer-capturing aquarelle canvas in the same
   `demo-canvas-shell` (`PhysicsPaintCanvasMount.tsx`), or the existing `pointerEvents` gate in
   `PhysicsPaintStudioView.tsx`. Do not add a new Studio window.
2. Resample the pointer path onto the recorded tick grid (~1/60 s) — the SAME grid record uses, so
   live stepping == play stepping. `toStudioStroke` law: `pts[].tick ← sample index i`,
   `ticks = max(1, pts.length - 1)`. Host helpers: `HOST_TICK_HZ`, `snapSampleToTick`
   (`packages/efx-paint-host/src/time/ticks.ts`).
3. `stampTool` / `depositStrokeOnSheet` on the FluidSheet per sample, `step(sheet, dt)` per tick,
   sheet raster → display (throttled). `sheetToBytes` is the determinism byte view — this plan adds a
   display rasterizer (`sheetToRgba` / `drawSheetToCanvas`) that composites mobile+fixed pigment with
   alpha 0 where unpainted.
4. Stroke end → `snapshotAquarelleRecord()` + points/ticks → the script payload. THIS is where the
   record seam belongs. Supersede the params-only store (`recordAquarellePayload` at physics mutation
   completion, commit 34edfbf1) with a full-stroke store (points + params + tool + brushId + color).
5. Dry = `forceDrySheet` at the recorded tick + the recorded payload event (D-15/D-16). No forced Dry
   at frame boundaries.
6. Same closure, shared block D-05: Color/Size/Opacity live in the shared block for BOTH modules.
   Size maps to the shared slider (`aquarelleParams.size` in Water color).

PLAY/BAKE PARITY: `createAquarelleEngineAdapter` today deposits via the 2D tracer `depositStroke` and
`stepTick` is a no-op — bake cannot show bloom/tide line (A3). This plan moves the adapter onto the
FluidSheet path: `applyStroke` → `depositStrokeOnSheet`, `stepTick` → `step(sheet, 1)`,
`captureFrame` → the sheet raster. Live and bake then share one stepping law.

RISK to carry, not paper over: CPU FluidSheet at canvas resolution may miss interactive framerates.
Allowed mitigation: decouple sim resolution from display resolution (upsample for display) and/or a
live step budget — but RECORDED ticks/params stay complete and exact, and play steps them as recorded.
Decimate preview only, never the record.

P1 CLEAN-ROOM LOCK: no code copied or transliterated from
`SPECS/v1.1.0-water-color/watercolor-playground`. The playground stays a read-only look oracle.
</implementation>
