<interfaces>
Use the existing public seam `savePhysicPaintData(projectDir, outputs): Promise<McePhysicPaintOutput[]>` and preserve canonical returned paths under `cache/physic-paint`. Add `publishPhysicPaintCacheGeneration(projectDir, stagingBasename)` in `app/src/lib/ipc.ts`, invoking the narrow Tauri command `publish_physic_paint_cache_generation`. The command accepts only the project directory and a basename matching the direct-sibling staging contract (for example `.physic-paint-staging-&lt;token&gt;`), constructs both `cache/physic-paint` and its sibling internally, and delegates to `publish_cache_generation`. The service recursively syncs staged files and directories before publication. On first publication it performs one same-filesystem rename; when canonical exists it calls the contained `atomic_exchange_directories` macOS wrapper around `libc::renameatx_np(libc::AT_FDCWD, ..., libc::AT_FDCWD, ..., libc::RENAME_SWAP)`. The non-macOS implementation returns unsupported before mutation. After a successful exchange the old generation occupies the staging path; deletion is best-effort and the serialized accepted result reports cleanup complete or deferred without changing publication success. No general rename command, filesystem capability change, alternate cache root, or test feature is introduced.
</interfaces>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Runtime physical outputs → sibling staging generation | Validated in-memory raster authority becomes a complete but not-yet-accepted filesystem generation. |
| TypeScript invoke → narrow native command | The frontend supplies project authority plus one basename; Rust must prevent path selection or traversal from becoming general filesystem authority. |
| Safe Rust service → macOS FFI | Validated, synchronized directory paths cross one contained `unsafe` boundary to `renameatx_np`. |
| Successful exchange → best-effort cleanup | Canonical publication is already accepted before cleanup status is known, so error semantics must not make accepted authority ambiguous. |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-43.1-07-01 | Tampering | `publish_physic_paint_cache_generation` path authority | high | mitigate | Accept only project directory plus a strict direct-sibling staging basename, construct `cache/physic-paint` internally, canonicalize/contain the parent, and reject traversal, separators, absolute paths, and wrong prefixes before mutation. |
| T-43.1-07-02 | Tampering | `atomic_exchange_directories` unsafe FFI | high | mitigate | Contain `unsafe` in one target-macOS wrapper after `CString` validation; call only `renameatx_np(AT_FDCWD, ..., RENAME_SWAP)` and convert errno immediately. |
| T-43.1-07-03 | Denial of Service | Unsynced or failed publication | high | mitigate | Recursively `sync_all` staged files/directories before first rename or exchange; any sync/exchange error leaves the old canonical directory untouched. |
| T-43.1-07-04 | Repudiation | Cleanup after accepted exchange | medium | mitigate | Return accepted publication with explicit complete/deferred cleanup status; never convert post-exchange deletion failure into publication rejection. |
| T-43.1-07-05 | Information Disclosure | General filesystem mutation surface | high | mitigate | Expose no arbitrary rename API and no additional plugin-fs permission; fixed paths are derived only inside Rust. |
| T-43.1-07-06 | Elevation of Privilege | Unsupported platform execution | medium | mitigate | Compile a fail-closed non-macOS implementation that returns unsupported before touching canonical authority. |
