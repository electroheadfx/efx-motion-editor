# Phase 43.6 — UI Design Contract

> Visual and interaction contract for the multi-rail selection set (Key Rail + Motion Rail + Static Rail in one shared session-only set), the four batch operations (Delete Rails, Move Rails, Key Spacing, Solo playback), and the set copy family in the EFX Paint/Roto bottom workflow strip. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

**Primary authority:** `43.6-CONTEXT.md` D-01..D-27, gathered 2026-08-18, and the activated product prompt `SPECS/milestone-v0.9.0-new-phases/phase-43.6-multi-rail-selection-batch-operations-prompt.md`. Supporting authority: `.planning/phases/43.5-timeline-toolbox-and-directional-push-tools/43.5-UI-SPEC.md` (accepted armed-tool orange language, ToolCase popover, Push ghosts/status contract), `.planning/phases/43.4-derived-key-groups-and-scissor-breaks/43.4-UI-SPEC.md` (accepted Rail family presentation, dynamic Delete scope, single-rail drag contract, one deterministic mapper), `.planning/phases/43.3-motion-and-static-group-drag-within-free-space/43.3-UI-SPEC.md` (accepted ghost/clamp/gap-preview contract carried verbatim), `.planning/phases/43-hold-loop-clips-filmstrip-capsule/43-UI-SPEC.md` (accepted integrated rail contract).

**Extension rule:** this contract adds one selection scope (the multi-rail set), one strip toggle (Solo), one batch drag application, and one Delete-scope form on top of the accepted Phase 43/43.3/43.4/43.5 rail contract. It changes no strip geometry (161px height, 38px physical row, 3px rail, 12px rail target, 18px pitch), no rail mode colors, no selection orange, no physical-cell semantics, no ToolCase layout beyond one scope line inside the Key Spacing section, and no Motion Editor timeline paint. The set, solo state, and all drag previews are session-only presentation — never accepted truth, never persisted, never crossing the bridge (43.6 process boundaries; D-05, D-14, D-17).

**Terminology (43.4 D-01 carried, binding):** user-facing copy uses the Rail family — **Motion Rail**, **Static Rail**, **Key Rail** — and the set noun **Rails**. The straddle rejection sentence (D-10) is a Group-domain sentence about source-cycle sharing, not a rail type label — it keeps Group vocabulary verbatim, following the 43.4-07/43.5 Group-domain precedent.

## Geometry and Layering Contract

### Existing geometry is immutable

The workflow strip remains exactly **161px**; the physical-frame row remains **38px**; the visible rail remains exactly **3px** high at `y: 0`; each rail target remains **12px** high at `top: 0`; frame pitch remains **18px/frame**. The multi-set paint, anchor tick, Solo button, ghosts, gap preview, blocked edge, and popover scope line add zero row, track, lane, or height. Nothing covers the rails/cells lane except the established 12px transparent rail targets (43.4 D-11 carried).

### M1 set selection geometry

- Every set member paints its existing 3px rail line in selection orange on its existing geometry. Member geometry, endpoint cuts, lifecycle dots, linked indicators, and mode base paints underneath are unchanged; selection paint is confined to the 3px rail line exactly as for single-rail selection (43.4 carried).
- **Anchor tick (Claude's discretion within D-02/D-03 — locked here):** the range anchor rail carries a **2px wide × 8px high `#F2F5F7` tick at 70% opacity** at its leading (left) edge, vertically centered on the 3px line (`top: 4px` in the 12px target band) — the established 43.5 pivot-tick idiom reused as a range-reference marker. The tick is `aria-hidden="true"`, `pointer-events: none`, paint-only; it never changes geometry, never shows on non-anchor members, and moves only when the anchor moves (a plain click or a Shift+click range replacement).
- The set is visually distinguishable from single selection by construction: multiple orange rail lines simultaneously plus the D-27 set copy in the status capsule. No new color, badge, or rail-height change is introduced.
- An **empty set** (D-05) paints nothing: no orange line, no anchor tick, no rail selection capsule. The strip returns to its no-rail-selection presentation.

### M2 Solo button geometry

- `Solo` is ONE `physics-paint-roto-key-icon-button` instance (26px high, 18px `Focus` icon, 10px compact label `Solo` under the icon per the existing icon-label layout) in the strip action row, in its own group **immediately after the Push tool group** (rightmost control in the action row). Spacing follows the existing toolbar flow gap; no new row, no strip-height change, nothing covers cells or rails.
- Placement rationale (Claude's discretion within D-15): solo is a playback-scope arm, not a key mutation, so it sits outside the key-utilities group; grouping it beside the Push tool keeps all mode-toggle tools adjacent at the row's end, mirroring the locked 43.5 grouped-tool idiom.
- The armed (active) state is paint-only on the same button geometry (see Color); armed state never changes size, never moves neighboring controls.
- Guarded tooltip and screen-reader reason span follow the exact Cut/Copy/Delete/Scissor/Push idiom (`buildGuardedActionTooltipCopy`, `aria-describedby`, `PhysicsPaintStyledTooltip`).

### M3 batch drag preview geometry (43.3/43.4/43.5 contract extended to the explicit set)

- **Per-rail ghosts:** every selected rail renders a paint-only 3px ghost at the clamped destination with that rail's exact geometry, in the rail's kind base color at **55% opacity** (Motion `#8B5CF6`, Static `#06B6D4`, Key Rail `#8A939C`). Ghosts never show selection orange, white endpoint cuts, lifecycle dots, hover brightening, or the anchor tick. Originals stay fully visible at 100% opacity until commit, and every member's orange selection line stays visible at its original interval for the whole drag (the 43.5 anchor-capsule rule generalized to every set member).
- **Gap preview:** intervals the move would open (at the vacated set edges) preview as ordinary empty cells — existing class `roto-fill-empty` (border `#3D454D`, background `#4D535A`), byte-identical to the 43.2/43.3/43.4/43.5 gap treatment. No distinct set-gap visual (D-09).
- **Blocked edge on clamp:** when the set is clamped, a **2px wide × 12px high `#FF6B6B` vertical bar** paints on the colliding member's ghost blocked edge — left edge of the leftmost blocked ghost for leftward movement, right edge of the rightmost blocked ghost for rightward movement (43.3 blocked-edge-direction rule carried). The bar is the sole blocked signal; ghosts remain kind-colored at 55% opacity.
- All preview paint is `aria-hidden="true"`, `pointer-events: none`, and removed on commit, cancel, or rejection.

### M5 popover scope line geometry

- The ToolCase popover keeps its exact 43.5 geometry (232–280px width, above-strip placement, liquid-glass surface per the 43.5 smoke revision). When a rail set is active, the Key Spacing section renders one scope line directly under the `Key Spacing` heading and above the relocated controls, in the existing section flow (Body role, `#9CA3AF`). The line adds no new panel, no divider, and no layout change to the relocated controls; when no set is active the line is absent and the popover is byte-identical to 43.5.

### Layer order

Unchanged from 43/43.3/43.4/43.5-UI-SPEC: physical cells 0; existing cell overlays 1–5; transparent rail targets 6; visible 3px rail paint 7 (`pointer-events: none`); anchor tick paints on layer 7 beside the selection line; ghosts and blocked edge between 7 and 8; rail focus ring 8; member selection capsules above the ghost layer (43.5 anchor-capsule z-order carried); styled tooltip and toolbox popover 60.

### State precedence

Highest visible state wins (accepted rail layer), then preview layers:

1. Keyboard focus ring `#F2F5F7` (focused member only)
2. Selected `#F59E0B` rail line (every set member)
3. Anchor tick `#F2F5F7` at 70% opacity (anchor member only, paint-only marker)
4. Hover brightened base (unselected rail hover only — a set member keeps its orange line on hover)
5. Normal base color (Motion purple / Static cyan / Key Rail gray)
6. Ghost kind paint at 55% opacity + blocked-edge bar on the ghost layer (batch drag only)
7. Gap preview empty-cell fill (cell layer, beneath all rail paint)

The accepted rail never inherits hover, ghost, clamp, or gap state. State changes alter paint only, never geometry.

### Responsive contract at 1280×720 minimum

Unchanged from 43-UI-SPEC: existing three-column Studio layout, 161px strip, shared horizontal scroller. The action row keeps every control readable and unclipped at 1280×720 with the Solo button added at the row end; ghosts, blocked edge, anchor tick, and gap preview clip at the shared timeline viewport exactly like accepted rails.

## Interaction Contract

### M1 set gestures and lifecycle (D-01..D-06)

- **Plain click** on a rail collapses any multi-set to that single rail (existing single-rail selection takes over) and moves the anchor to it. Plain click on empty strip/frame clears the set entirely.
- **Shift+click** replaces the set with the canonical anchor→clicked range, ordered by canonical first-key frame across all three rail kinds in one shared ordering; the anchor stays put.
- **Cmd/Ctrl+click** toggles one rail in/out of the set without moving the anchor; toggling off the last member leaves the valid empty set (D-05).
- **Cmd+Shift+click** adds the anchor→clicked range to the current set (union; already-selected members stay selected); the anchor stays put (D-03).
- **Escape** collapses layers one at a time: solo exit first, then selection collapse (D-04; 43.5 one-Escape-one-layer carried).
- Selecting a physical frame or key clears the rail set (43.4 mutual exclusion extended to the set).
- Stale authority (membership, breaks, or document revision changed under a set) clears the invalid set instead of inventing a fallback scope (43.4 stale-selection rule carried).
- After an accepted batch Move, the whole set stays selected at the new positions and the anchor follows its rail's identity; Undo restores the set at the original positions; Redo re-applies at the destination. After an accepted Delete Rails the selection is empty and the cursor stays on its current valid frame; one Undo restores the exact pre-delete set; Redo clears it again (D-06).

### M2 solo lifecycle (D-14..D-20)

- Clicking `Solo` arms the filter: button shows the armed orange tint with `aria-pressed="true"`, and the status capsule persistently carries `Solo — {N} Rails, frames {A}–{B}.`. Solo is an arm, not a transport command — the user presses Play (or playback continues if already playing).
- While armed and playing, only the selected rails' content renders and the play range restricts to the selection's effective coverage (first selected placement start to last selected effective end — generated/linked occurrences included), looping within it by default.
- Scrubbing while armed but stopped is unrestricted: the stopped canvas always renders everything at any cursor position (D-18).
- Solo exits on: re-click of the Solo button, Escape (first Escape layer), or any rail-selection change/clear (including collapse to a different rail). Exit clears the button tint and the capsule copy immediately.
- Solo persists across stop/start while the selection is unchanged; it never persists across save/reopen, never enters the document, history, or session restore, and never touches preview stills, export, or the canonical render source (D-14, D-17).
- While playback/busy locks mutations, the Solo button follows the existing availability gating; solo itself never gates mutations.
- No keyboard shortcut arms solo this phase (43.4 D-05 / 43.5 D-10 precedent).

### M3 batch Move drag session (D-07..D-13; 43.3/43.4 carried verbatim)

| Input | Result |
|-------|--------|
| Pointer down on a selected rail | begin tracking; no paint change, no navigation, no drag session yet |
| Pointer moves ≤ 4px and releases | plain click behavior (collapse set to that rail; anchor moves to it) |
| Pointer moves > 4px horizontally | batch drag session starts; pointer capture; cursor `grabbing`; every set member ghosts at the clamped proposed destination; would-open gaps preview as `roto-fill-empty` cells; status capsule begins the live readout |
| Pointer moves during session | ghosts and gap preview recompute the clamped destination; blocked-edge bar appears/disappears with clamp state; live readout updates |
| Escape during session | cancel: originals byte-untouched, zero history, all preview paint removed; the set stays selected (D-13) |
| Release (drop) | commit request at the currently shown (possibly clamped) position — the preview is the commit |
| Release with zero delta | nothing publishes; no status, no history entry; the set stays selected (D-13) |
| Release with zero valid movement | rejection: preview removed, nothing mutates, status publishes `No empty space in that direction.` |
| Pointer down on an unselected rail | the set collapses to that rail first (normal single-rail selection), then its own 43.3/43.4 drag applies — never a batch drag (D-08) |

- Clamp contract (D-07): the set clamps or rejects as one unit at the first collision with any unselected key, Group occupancy (including linked occurrences), frame 0, or capacity. Dropping while clamped commits at the clamp. Rejection only when zero valid movement exists.
- The whole set translates rigidly by one delta: relative offsets, internal gaps, and internal breaks preserved exactly; unselected objects never move; movement-created gaps persist with 43.3 D-12 / 43.4 break authority (D-11).
- Shared-source Groups inside the set follow 43.3 algebra (source-attached move source keys with identity; duplicated placements move placement-only). A straddling unselected Group rejects the move with the locked straddle sentence — the family is never silently pulled in (D-10).
- The batch drag never pushes, pulls, reorders, stretches, splits, or retimes anything outside the set; the 43.5 Push tools remain the only directional multi-object push and never consume the set (43.5 D-20, binding).
- Ghosts, gap preview, blocked edge, and the live readout are presentation-only; nothing presents as moved before exact correlated parent acknowledgement. The complete movement — records, Loop Clips, breaks, selection, cursor — is one atomic parent-acknowledged history command with one Undo/Redo.

### M4 Delete routing (D-21..D-23)

- Delete, Backspace, and the visible Delete control share one activation-time scope classifier: physical-frame selection routes to Delete Frame; single-rail selection routes to existing single-rail deletion; an active rail set routes to Delete Rails. No choice modal exists at any set size (43.4 D-12/D-13 carried).
- Delete Rails removes each selected rail with its own type semantics — Key Rail deletion removes its real keys and derived projection; Motion/Static Rail deletion follows the 43.2 Delete Group semantics and never deletes the referenced Action — as one atomic history command with selection clearing, cursor on the same valid frame, and canvas reconciliation.

### M5 Key Spacing on a set (D-24..D-26)

- With an active set, the ToolCase popover's Key Spacing section shows the scope line and Apply dispatches spacing-on-set: the spacing factor applies per selected rail, each rail keeping its own first key as anchor, validated all-or-nothing before commit. Without a set, behavior is exactly the 43.5 single-selection behavior.
- The popover never creates or modifies the selection set itself; opening/closing it changes nothing about the set.
- If any selected rail fails preflight (membership, anchor, capacity, collision), the entire command rejects with the mapped reason — no partial application (D-25).

### Keyboard and focus

- Every set member exposes its existing single tab stop (`role="button"`, `tabIndex=0`); tab order follows canonical first-key frame order across all members, then existing strip controls. Roving arrow-key cycling moves the focus ring member-to-member within the set in canonical order, then falls through to ordinary rail cycling outside the set (43.4 focus machinery extended, no per-type fork).
- **Space** plain-selects the focused rail (collapses the set to it; prevents page scroll). **Enter** performs no action (43.4 carried).
- **Delete/Backspace** with an active set invokes Delete Rails through the shared scope classifier (D-22).
- **Cmd+Z / Cmd+Shift+Z** undo/redo the atomic batch command including the exact selection set (D-06).
- **Escape** layering: solo exit, then selection collapse — one Escape handles at most one layer (D-04).
- Solo and the batch operations introduce no new keyboard shortcuts this phase.
- Focus ring: 2px `#F2F5F7` with 1px offset around the focused member's 12px target, visible at viewport edges, never clipped.

### Busy and rejected-operation behavior

- During controller preparation/commit, accepted rails remain visible in place with the existing `aria-busy`/busy-opacity idioms; Solo and Delete expose `aria-disabled="true"` with the current controller reason. A second batch drag session cannot start while a physical mutation is in flight.
- No optimistic movement, gap, break, deletion, or status change. Update only from accepted canonical authority state.
- On rejection, preserve prior geometry, selection set, anchor, focus, cursor, and solo arm; announce the reason through the existing status channel.

### Accessibility

- Rail band group: `role="group"`, `aria-label="Rails"` (43.4 carried); set membership and anchor are announced through each member's accessible name (the M1 set sentences) and the status-capsule set copy.
- Solo button: `aria-pressed` reflects armed state; guarded tooltip plus screen-reader reason span follow the Cut/Copy/Delete/Scissor/Push idiom.
- Status updates publish through the existing `aria-live="polite"` status capsule; rejections additionally use `role="alert"`. The live drag readout updates at pointer-move cadence on the same polite channel — it never creates live-region churn on rails or cells.
- All preview paint (anchor tick, ghosts, blocked edge, gap preview) is `aria-hidden="true"` with `pointer-events: none`.
- The 12px rail target and 26px toolbar buttons are the established compact-editor exceptions; tooltips, keyboard access, and the toolbar provide equivalent larger action access.
- Reduced motion: set paint, anchor tick, solo arming, ghosts, clamp, and gap-preview changes are immediate paint changes with no slide, tween, spring, shimmer, or pulse. Under `prefers-reduced-motion: reduce`, no transition is added to any touched element.
- No state relies on color alone (see Non-color cues).
