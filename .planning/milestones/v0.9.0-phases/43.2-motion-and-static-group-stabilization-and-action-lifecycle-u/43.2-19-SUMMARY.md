## Decisions Made

- Retained history remains physically and semantically separate from active journals, committed markers, working tombstones, and acknowledgement receipts.
- Stable command IDs are SHA-256 hashed before use in hidden filenames, avoiding untrusted command text in filesystem paths while preserving command/generation identity through metadata.
- Release writes a `cleanup-pending` receipt before deletion and replaces it with `released` afterward; startup completes pending cleanup before an ordinary scan.
- A released command ID/generation cannot be reused to create new retained authority.
- Corrupt retained authority is never silently collected; ordinary scans remain blocked until recovery or explicit owned release resolves it.
