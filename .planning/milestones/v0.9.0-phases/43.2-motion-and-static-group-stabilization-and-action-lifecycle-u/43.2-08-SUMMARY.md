## Decisions Made

- The visible workflow control remains presentation-only; it invokes the same callback as keyboard Delete and never reads `loopId`, `visibleRanges`, or classifier internals.
- Canonical Group ownership is classified at activation for the dialog, but mutation authority is recomputed from `records.getDocument()` after lease acquisition so stale presentation state cannot authorize deletion.
- Dialog state remains Studio-local because it is transient presentation state; canonical records, Group selection, cursor, and coordinator state remain Signal/store-owned.
- Native button activation owns Enter. The dialog keyboard handler only traps Tab and handles Escape, avoiding duplicate activation behavior.
- Accepted lifecycle operations reuse the existing immutable coordinator before/after output, so the established history layer records one command and restores complete Loop Clip state for Undo/Redo.
