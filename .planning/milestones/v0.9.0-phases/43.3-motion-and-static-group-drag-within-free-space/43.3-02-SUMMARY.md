## Accomplishments
- `clampPhysicPaintGroupDragDestination` — one exported pure clamp authority consumed by the resolver branch and (plan 03) the ghost preview so preview-is-the-commit holds (D-05, RESEARCH Open Question 2). Clamps against frame 0, physical capacity/parent end, every unowned real key outside the dragged Group's own interval, and every other Group interval including linked occurrences; the dragged Group's own current interval is pass-through (D-08)
- Clamp-and-commit replaces the plan-01 fail-closed-on-collision tracer behavior: a proposed destination beyond a boundary resolves ok at the clamped position; rejection happens only when zero valid movement exists in the dragged direction, surfaced through one new closed-union failure code `'no-free-space-in-direction'` with no partial proposal (D-05, D-06 substrate, T-43.3-02-04)
- Duplicated shared-source placement-only branch (D-11, D-19): attachment is resolver-derived from canonical facts only (`placementStart === framesByKeyId.get(sourceKeyIds[0])`, Pitfall 4); duplicated placements emit identity key mapping (zero key movement), placement-only `nextLoopClips`, and byte-identical shared source keys and owned breaks; no materialization, no repeat/mode change (T-43.3-02-02)
- Stable-key-owned break derivation (D-09..D-13): `deriveMoveGroupIncomingInterpolationBreakKeyIds` computes the complete next collection — vacated-interval successor owns/reuses the incoming break, landing gap before the first source key creates a new break, breaks on moved keys travel unchanged (43.1 D-14), D-12 no-break cases (end-of-content vacated, no-predecessor landing), D-13 Group-local fragments never convert — threaded through the unchanged `finalizeProposal` path so the collection flows proposal → apply payload → canonical revision → history exactly like 43.1 (T-43.3-02-03)
- All automated gates green: resolver suite 83 tests pass (clamp matrix 9 + duplicated placement 5 + break lifecycle 6 + pre-existing), full physic-paint suite 1321 tests pass, typecheck exits 0, `move-key-group` and `buildMoveGroupCandidate` byte-unchanged vs the plan-01 baseline, failure-code union gained exactly one new member
