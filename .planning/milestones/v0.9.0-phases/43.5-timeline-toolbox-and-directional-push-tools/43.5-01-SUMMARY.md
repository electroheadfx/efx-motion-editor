## Decisions Made
- `derivePhysicPaintPushSet` and `clampPhysicPaintPushDestination` are exported pure authorities so plan 05's hover preflight consumes the SAME logic the resolver commits with (D-17 — preflight and rejection can never disagree; Pitfall 4)
- The clamp is the single push delta authority: the branch commits its clamped delta and never re-derives clamp math (D-14, preview-is-the-commit)
- Push translates ALL moved Group rails' clips (attached AND duplicated) so `changed` reflects placement deltas — fixing Task 1's attached-only movedClips filter per CONTEXT/Pitfall 5
- Reverse-close normalization is frame-0 provable: a reverse Push Left that returns the moved set's first key to frame 0 removes the (provably meaningless) head-gap break; adjacent-landing cases preserve an existing break rather than risk destroying an intentional one
- Straddle checks only source-attached MOVED groups against ANY fixed-side group sharing `sourceCycleId`; duplicated placements never straddle (43.3 algebra, D-16)

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 2 - Missing functionality] Task 1's movedClips filter translated only `attached === true` group clips**
- **Found during:** Task 2 (directional set/clamp authority) — CONTEXT states duplicated (shared-source) placements inside the moved set move placement-only per 43.3 algebra, and Pitfall 5 requires `changed` to reflect placement deltas
- **Issue:** A push whose moved set contained duplicated placements would never report the placement delta; the fix was deferred into Task 2 per the plan's own Task 3 instruction ("fix the computation if the Task 1/2 implementation misses it")
- **Fix:** The dispatch branch now translates every moved Group rail's clip (attached AND duplicated) through `buildMoveGroupNextLoopClips`, so `clipPlacementChanged` reflects placement deltas for duplicated placements
- **Files modified:** app/src/components/physic-paint/roto/physicsPaintRotoPhysicalResolver.ts
- **Verification:** "duplicated-placement straddle impossible" test asserts `changed:true`, `code:'ok'`, translated placement, untouched shared keys
- **Committed in:** 8a9b7448 (Task 2 GREEN)

**2. [Rule 1 - Bug] Zero-delta push published an unchanged clips array instead of null**
- **Found during:** Task 3 (zero-delta no-change edge test — RED exposed it)
- **Issue:** The moved-clips block set `nextLoopClips = current` unconditionally; with signedDelta 0 every `buildMoveGroupNextLoopClips` call returns null so `current` stayed `loopClips` and the proposal published the unchanged collection — breaking the valid-no-change "publish nothing" channel
- **Fix:** `nextLoopClips` is now assigned only when `clipPlacementChanged` is true (a real placement delta committed one)
- **Files modified:** app/src/components/physic-paint/roto/physicsPaintRotoPhysicalResolver.ts
- **Verification:** zero-delta placement-only test asserts `nextLoopClips` is null and status `ok-no-change`
