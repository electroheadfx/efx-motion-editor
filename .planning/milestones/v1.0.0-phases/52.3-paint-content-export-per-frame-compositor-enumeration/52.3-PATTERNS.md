Note the doc comment at :44-45: "A gap deliberately carries no clipId" — the same move is mandated for `GapFrameEntry` (RESEARCH Open Question 2 recommends `sequenceId: ''` to keep the field required across the union; either is Discretion, but the gap arm must not claim ownership).

**Current FrameEntry to convert** (`app/src/types/timeline.ts:26-35`, verbatim):
```typescript
export interface FrameEntry {
  globalFrame: number;
  sequenceId: string;
  keyPhotoId: string;
  imageId: string;
  localFrame: number; // frame index within this key photo's hold duration
  solidColor?: string;       // hex color for solid frames
  isTransparent?: boolean;   // true for transparent frames
  gradient?: GradientData;   // Gradient fill data for rendering
}
```

**Exhaustiveness idiom** (same file, :193-196 — copy for any future FrameEntry switch):
```typescript
default: {
```

**Target shape** (RESEARCH.md Code Example 1, Discretion within D-01/D-02): `ContentFrameEntry` (gains `kind: 'content'`, keeps every current field) | `PaintFrameEntry` (`kind: 'paint'`, `globalFrame`, `sequenceId` = owning fx id, layer identity — **no `keyPhotoId`/`imageId`**) | `GapFrameEntry` (`kind: 'gap'`, `globalFrame`, `sequenceId: ''`). ### `app/src/lib/frameMap.ts` (service — paint enumeration branch, D-04/D-05)

**Analog:** itself — the existing `frameMap` computed.

**Computed subscription discipline** (lines 16-21, verbatim — the new branch lands inside this same computed; note Pitfall 2's optional one-line `void efxPaintVersion.value;` beside :17, to be flagged as a conscious inclusion if taken):
```typescript
export const frameMap = computed<FrameEntry[]>(() => {
  void physicPaintVersion.value;
  const entries: FrameEntry[] = [];
  let globalFrame = 0;
  const sequences = sequenceStore.sequences.value;
  const contentSeqs = sequences.filter(s => s.kind === 'content');
```

**Content construction loop with conditional-spread materialization** (lines 23-39, verbatim — the paint branch's entry construction copies this spread idiom; the tail pad at :41-45 automatically preserves the discriminant via `{ ...tailEntry, globalFrame: entries.length }`):
```typescript
  for (const seq of contentSeqs) {
    for (const kp of seq.keyPhotos) {
      for (let f = 0; f < kp.holdFrames; f++) {
        entries.push({
          globalFrame,
          sequenceId: seq.id,
          keyPhotoId: kp.id,
          imageId: kp.imageId,
          localFrame: f,
          ...(kp.solidColor ? { solidColor: kp.solidColor } : {}),
          ...(kp.isTransparent ? { isTransparent: true } : {}),
          ...(kp.gradient ? { gradient: kp.gradient } : {}),
        });
        globalFrame++;
      }
    }
  }
```

**Insertion point** (lines 41-47, verbatim — the new branch goes AFTER the tail pad, gated on `entries.length === 0` per Finding F1):
```typescript
  const targetLength = getTimelineRequiredFrameCount(sequences, entries.length);
  const tailEntry = entries[entries.length - 1];
  while (tailEntry && entries.length < targetLength) {
    entries.push({ ...tailEntry, globalFrame: entries.length });
  }
  return entries;
});
```

**N law — reuse unchanged** (D-04; lines 244-259): `getTimelineRequiredFrameCount` already iterates fx sequences, skips `visible === false` (:247), and extends by `seqStart + rotoEnd` via `getPhysicPaintRotoDisplayEndFrame` (:227-242, loop-aware). Do NOT write a second total-frame computation.

**Coverage predicate — the enumeration/render anti-drift lock** (lines 261-270, verbatim — the paint branch's per-frame coverage test MUST call this same function the overlay leg gates on):
```typescript
export function getTimelineOverlaySequenceOutFrame(seq: Sequence, fallbackOutFrame: number): number {
  let outFrame = seq.outFrame ?? fallbackOutFrame;
  const startFrame = seq.inFrame ?? 0;
  for (const layer of seq.layers) {
    if (layer.type !== 'physic-paint') continue;
    const rotoEnd = getPhysicPaintRotoDisplayEndFrame(layer, seq);
    if (rotoEnd !== null) outFrame = Math.max(outFrame, startFrame + rotoEnd);
  }
  return outFrame;
}
```

**Fail-closed integer validation style** (`resolveSequenceTimelineRange` :163-172 — house validation idiom the branch inherits for free): `Number.isInteger(...)`, `globalStart < 0`, `globalEndExclusive <= globalStart` → `return null`.
