## Decisions Made

1. **Failures are data, not fiber death** — Effect v4's `Effect.tryPromise({catch})` maps into the typed error channel, so a throwing producer killed the turn (observed: a throwing turn settled `cancelled`, not `failed`). Produce and commit are now never-rejecting `Effect.promise` thunks whose internal `try/catch` returns a discriminated result.
2. **The machine's wait IS the yield** — `waitForGate` unconditionally awaits `waitUntilDrainable()` (a macrotask when already drainable) and re-checks `flushDepth`/drainability after. Without it, a gate that completed synchronously in the same task let a turn start producing ahead of a second capture submitted later in that same task, and the supersede never landed.
3. **Settle-through interruption** — `interrupt()` fires `Fiber.interrupt` fire-and-forget; the turn reports its own settlement through the promise `submit` returned, so `drain()` cannot hang on a cancelled turn.
4. **Ledger registration precedes the fiber** — `workQueued()` + the live-turn record are registered before `Effect.runFork`, so a turn that settles immediately cannot race `drain()` into an early exit.

### Auto-fixed Issues

**1. [Rule 1 - Bug] `Effect.tryPromise`'s failure channel killed the turn instead of reporting a failure**
- **Found during:** Task 2 (GREEN run 1)
- **Issue:** the queue's probe test "reports a failed turn" settled `'cancelled'` instead of `'failed'`. Root cause: `Effect.tryPromise({try, catch})`'s catch maps the error into the typed ERROR channel — the effect still FAILS, so the fiber died and no settlement outcome was ever produced. Verified empirically against the installed `effect@4.0.0-rc.115` with a throwaway probe script (deleted after).

- **Files modified:** `app/src/components/physic-paint/pilot/finalizationQueue.ts`
