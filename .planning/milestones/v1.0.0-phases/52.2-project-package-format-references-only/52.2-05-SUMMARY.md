# Phase 52.2 Plan 05: Package Transaction + Machine-Local Cache Summary

**One authoritative transaction now covers the whole package file set (manifest, `layers/*.json`, changed `frames/*.webp`) with an order-independent aggregate digest and a rollback/recovery path that leaves the pre-save package intact, while the derived-frame cache moved out of the package to `<app_data_dir>/frame-cache/<projectId>` as a best-effort leg that can no longer fail a save.**

## Accomplishments

- The shipped single-directory cache swap was EXTENDED, not replaced (D-10): `services/physic_paint_cache.rs` now owns two transactions — the authoritative package one (staged intake, per-file atomic publish, digest-bound commit, rollback, open-time recovery) and the disposable machine-local cache generation.
- The cache leg's project binding is gone: `bind_cache_transaction_to_project_write` and the marker's expected-project-digest are deleted, a cache marker found at open is always rolled back, and no project write carries a cache transaction id (`grep -c physic_paint_cache_transaction_id` over `project_io.rs` = 0).
- The authoritative set is bound through plan 01's allowlist and an order-independent SHA-256 aggregate (`path\0sha256\n` over the path-sorted list), so the same file set yields the same digest whatever the discovery order.
- Derived frames moved to `<app_data_dir>/frame-cache/<projectId>` (D-05); every cache command takes that root explicitly and answers with a typed soft failure (`accepted: false` + `diagnostic`) so no cache error can fail or roll back an authoritative save (D-14, T-52.2-16).
- `project_create` now makes `layers/` and `frames/` (and no package-local `cache/`), and `save_project` writes the manifest at the path it is handed with no cache transaction id.
- Save As runs ONE transaction open across the active-path migration (publish → migrate → commit | rollback), so a migration failure restores the previous destination through the transaction's own rollback (T-52.2-18).
- The renderer transport exists for plan 07: `bind/publish/settle/recover` package wrappers, `resolvePhysicPaintCacheRoot`, and `stageEfxPaintPackageSave` (Rust-shaped basename, staged manifest write through `projectSave`, one-entry-set bind).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] The marker's on-disk entry shape was silently rewritten to camelCase**
- **Found during:** Task 2, first GREEN run (`package_rollback_reentry_converges_after_an_interrupted_rollback`)
- **Issue:** `#[serde(rename_all = "camelCase")]` on the shared `BoundFile`/`PackageBinding` structs governed the transaction MARKER's on-disk JSON as well as the wire shape, so a forged snake_case marker failed to parse (`missing field 'hadOriginal'`) — the marker is untrusted input that tests (and older builds) legitimately write.
- **Fix:** removed the attribute from the service structs and added command-layer camelCase DTOs (`BoundPackageFile`, `BoundPackageFileSet`) with an explicit mapping in `bind_efx_paint_package_transaction`.
- **Files modified:** `app/src-tauri/src/services/physic_paint_cache.rs`, `app/src-tauri/src/commands/project.rs`
- **Verification:** the forged-marker cases and the full 39-case integration run pass.
- **Committed in:** `4ed07644`

**2. [Rule 1 - Bug] Three cache cases still asserted the old raised-error contract and the removed package-local layout**

- **Fix:** the two cases now assert `!accepted` plus a present diagnostic (and that the canonical generation is untouched, and that a legitimate second settle is accepted); the fixture takes the machine cache root itself.
- **Files modified:** `app/src-tauri/tests/physic_paint_cache_publication.rs`
