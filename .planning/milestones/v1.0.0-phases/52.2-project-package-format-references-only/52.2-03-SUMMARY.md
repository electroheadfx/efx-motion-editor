- `NumericStepper.tsx` owns the `− [field] +` layout, the field's own `step`, its `min`/`max` clamp, keyboard editing, and hold-to-repeat (400 ms delay → 60 ms interval), with every emission route funnelling through one `clampToStep` path (T-52.2-08) and both timers cleared on `pointerup`/`pointercancel`/`pointerleave` + unmount (T-52.2-09).

## Decisions Made

- `type="text"` + `inputMode="decimal"` over PATTERNS.md's spinner-suppression class string: the markup genuinely carries no native spinner affordance, and the sweep contract has a stable textual target (`type="number"` retired).
- The stepper's state is refs + timers only — never `useState`, never a signal written from the render body (CLAUDE.md / `efx-preact-reactivity`).
- `pointerdown` steps immediately and `click` only steps for keyboard/AT activation (`detail === 0`), so a press produces exactly one step.
- One formatter: `NumericInput.formatDisplay`'s 3-decimal rule moved into the stepper as `formatStepperValue` (`step >= 1` → integer, else up to 3 decimals, trailing zeros stripped).
- The commit gesture is normalized to blur/Enter + the buttons across all swept sites (see deviation 6).
- `onFocus`/`onBlur` run *in addition* to the stepper's own focus/blur handling so the Studio guarded-pattern tooltip survives the conversion.

**3. [Rule 2 - Missing Critical] ColorPickerModal channel commits take a single-channel override**
- **Found during:** Task 2 (ColorPickerModal conversion)
- **Issue:** `commitRgba`/`commitHsl` read the R/G/B/H/S/L string states. The old inputs kept those states in sync per keystroke; the stepper emits only a committed number, so `set(String(v))` followed by `commit()` would commit the stale state and drop the user's edit.
- **Fix:** `commitRgba(override?: {r?, g?, b?})` / `commitHsl(override?: {h?, s?, l?})` — the stepped channel wins, the others fall back to the text state.
- **Files modified:** `app/src/components/shared/ColorPickerModal.tsx`
- **Verification:** `tsc --noEmit` clean; suite unchanged.
- **Committed in:** `677e60f1`

**4. [Rule 2 - Missing Critical] Hold Frames popover keeps its commit-on-close**
- **Found during:** Task 2 (KeyPhotoStrip conversion)
- **Issue:** the popover unmounts on outside-`mousedown`, so the field's blur-commit never runs; a value typed but not committed would be silently lost, where the pre-stepper code committed the live-typed value on close.
- **Fix:** the close path reads the field's text back through the same clamp (min 1 / max 999) before committing.
- **Files modified:** `app/src/components/sequence/KeyPhotoStrip.tsx`
- **Verification:** `tsc --noEmit` clean; suite unchanged.
- **Committed in:** `677e60f1`

**5. [Rule 1 - Bug] Three source-scan assertions in `PhysicsPaintWorkflowStrip.test.ts` tracked the raw `<input>` markup**
