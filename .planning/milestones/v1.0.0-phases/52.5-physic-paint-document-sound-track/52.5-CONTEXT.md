# Phase 52.5: Physic Paint document sound track - Context

**Gathered:** 2026-10-06
**Status:** Ready for planning

<domain>
## Phase Boundary

Give the Physic Paint document its own sound clip (dialogue or foley for the animation being drawn). One clip per document. In the Studio it is imported/replaced/removed through the existing shared media gallery, shown as a dark-blue waveform stain behind the Studio timeline's frame numbers, repositioned by drag, and trimmed via a 2 px top bar (in/out), with volume + fades in the same audio modal. Studio playback plays this clip mixed with the main app's global audio (preview-mix toggle lets you isolate the studio sound). In the main editor, playing a Physic Paint layer plays that clip together with the existing main-timeline audio; the clip follows layer hide/solo and is gated by the modal's "sound in output" switch. Studio edits reach the main editor through the existing two-window sync and survive save/reopen — `.mce` keeps the sound as a reference, per 52.2.

**In scope:** one document-owned sound clip; Studio timeline stain + drag + 2 px in/out bar; audio modal (import/replace/remove via shared gallery, volume, fades, "sound in output", preview-mix); Studio playback mix; main-editor mixed playback with hide/solo follow; cross-window sync of reposition/in-out/volume/fades/toggles; save/reopen as a `.mce` reference; export inclusion when "sound in output" is on.

**Out of scope:** multiple clips / multi-track audio; a separate audio rail or audio row in the Studio timeline; a separate file picker or second gallery; Add-Audio button, Tools-popover import, or a drag-and-drop-only path; new audio engine, new IPC channel, or a new bridge; main-editor audio editing (music/ambience stays read-only in the Studio, exactly as today); showing main-editor audio waveforms inside the Studio (separate backlog FUT item); full independent EFX Paint audio editing (FUT-07).

</domain>

<decisions>
## Implementation Decisions

### Clip model & import
- **D-01:** **One clip per document.** The document carries a single sound clip (dialogue or foley). No multi-clip sound track, no gaps/overlaps model. — **Reversibility:** costly — the document model, modal, stain renderer, mix paths, and sync payload are all shaped around a singleton clip; lifting to N clips means new identity/range/overlap semantics everywhere.
- **D-02:** **Import entry point = an audio icon on the Studio timeline strip** (the frame-number band). Clicking it opens the audio modal. Explicitly rejected: Add-Audio button, Tools-popover entry, drag-and-drop-only path, or any new panel beyond that modal. — **Reversibility:** reversible — the icon is a launcher; other entry points could be added later without moving the model.
- **D-03:** **Import/replace/remove goes through the SAME shared media gallery** used for reference-image and Background import (`BackgroundAssetPickerView`), opened for audio. **No separate file picker, no second gallery, no new import path.** The modal is the only new surface; the gallery underneath is reused. — **Reversibility:** costly — the gallery is the asset-authority seam for the document; a second picker would fork import/persistence/copy semantics (52.2 reference packaging).
- **D-04:** **Formats = same as the main app** (WAV, MP3, AAC, FLAC). Reuse the existing decoder + peaks pipeline unchanged. — **Reversibility:** reversible.
- **D-05:** **The audio modal is the single control surface for the clip.** It carries: import / replace / remove (via D-03 gallery), volume, fade-in/out, **"sound in output"** (export/master gate, D-12), and **preview-mix** (include main-app audio in the Studio preview, D-11). No second properties panel. — **Reversibility:** costly — modal field set becomes the clip's edit contract consumed by sync + persistence.

### Studio waveform surface
- **D-06:** **Not an audio rail.** The waveform is a **dark-blue filled stain** (same blue as the main app) drawn **behind the frame numbers** across the **full height of the timeline strip**. The stain shape carries the sound variations (loudness). — **Reversibility:** costly — the strip renderer, layout metrics, and hit-testing key on this presentation; converting to a rail later re-lays out the Studio timeline.
- **D-07:** **Frame numbers stay on top (filled, no outline).** Tick marks and cuts stay at the bottom, unchanged. The strip becomes **slightly taller** so the numbers sit lower and the wave has room to express. — **Reversibility:** reversible — height is a layout constant.

### Trim + reposition
- **D-08:** **Drag the stain to reposition** the clip on the time axis. Drag law from Phase 51 stands: drag updates playhead + a short audio peek only; full settle on release. — **Reversibility:** reversible.
- **D-09:** **In/out edited from a short bar at the top of the timeline, 2 px tall.** Left end sets start, right end sets end. No handles on the stain edges. — **Reversibility:** reversible.
- **D-10:** **Volume + fades are in scope** and live **inside the audio modal** (not on the timeline). Timeline stays lean: stain + 2 px bar only, no extra handles. This is justified by the roadmap's "the way the main app shows audio" (Phase 15 ships volume + fades); it is still one clip, not FUT-07 NLE editing. — **Reversibility:** costly — volume/fades enter the clip model, the mix math, and the sync payload.

### Playback mix & export
- **D-11:** **Studio playback hears both** the document clip **and** the main app's global audio by default. The modal's **preview-mix toggle** can exclude the main app audio from the Studio preview so the user can **isolate the studio sound** while working. **Preview-only** — this toggle never affects export or main-editor playback. — **Reversibility:** reversible.
- **D-12:** **"Sound in output" is the master gate.** ON: the clip is exported mixed with the main audio **and** audible on main-editor playback. OFF: removed from export **and** not audible from main-app play. Studio preview still lets you hear the clip while editing regardless. Two distinct modal toggles: *sound in output* (export + main playback) vs *preview main app too* (monitoring isolation). — **Reversibility:** costly — export mixer and main playback both branch on this flag; it is part of the persisted clip state.
- **D-13:** **The clip follows layer hide/solo in the main editor.** Audible whenever the Physic Paint layer is in the composite (not hidden, or soloed when solo is on) — sound follows the layer like its pixels. Combined with D-12: D-12 is the clip's master on/off; hide/solo is the layer's compositing state. — **Reversibility:** reversible.
- **D-14:** **Clip volume + fades ARE the level everywhere** (Studio preview, main-editor playback, export). No second main-side fader. — **Reversibility:** reversible.

### Claude's Discretion
- Document-model field names/shape for the singleton clip (identity, source ref, position, in/out, volume, fades, the two toggles) within D-01/D-05.
- Where the audio icon sits on the frame-number band and its visual treatment (must stay inside the "lean timeline" law).
- Stain rendering mechanics (peaks → filled path) and the exact dark-blue token lookup; reuse `audioWaveform`/`audioPeaksCache` math where possible.
- 2 px bar hit-slop / affordance details (the drawn bar is 2 px; the hit target may be larger for usability).
- Preview-mix and sound-in-output control types inside the modal (checkboxes vs toggles).
- Sync payload shape for clip edits over the existing two-window bridge (no new channel — D-03 guardrail).
- How volume/fades are expressed in the modal (sliders, steppers) consistent with existing Studio modal controls.

</decisions>

### Reusable Assets
- `audioWaveform.ts` / `audioPeaksCache.ts` — 3-tier peaks + cache; the stain can be drawn from these peaks (no new decode path)
- `TimelineRenderer.drawAudioTrackRow` — waveform/center-line/fade/selection drawing math (adapt to full-height stain, not a row)

- `efxPaintAudioMonitor` + `useRotoCachedPlayback` — Studio playback drive path the document clip joins (D-11)
- `audioEngine.ts` — one AudioContext per child webview; the clip plays through it
- `audioExportMixer.ts` — export mix the clip joins when "sound in output" is on
- `physicsPaintLaunchContext` / `physicPaintBridge` — existing revisioned two-window sync for clip edits

### Established Patterns
- **Read-only main-audio authority boundary** (AUDIO-01): the child never owns copied main-audio state. The document clip is a NEW owner (the document itself) — keep the two domains separate: main audio stays payload-reflected and read-only; the clip is document-owned and editable.
- **First-player-wins ownership guard** (Phase 41 D-05/D-06) — applies to doubled *main* audio; the document clip is a second source in the same context and must not trip this guard into suppressing the clip (or vice versa). Mix, don't contend.
- **`pickerOpen` step-aside** (260923-fhn) — while a gallery picker is open, every parent modal (including the new audio modal) stays hidden and returns with prior state.
- **Drag law** — drag: playhead + audio peek only; full settle on release.
- **`.mce` references-only** (52.2) — the sound clip is a media reference; no byte inlining.
- **Fail-closed / clean-break** house style — missing reference, missing bytes, or invalid clip state is explicit and recoverable (CMP-05 style), never a silent blank.

### Integration Points
- Studio timeline strip renderer (frame-number band) — stain layer behind numbers, taller strip, 2 px top trim bar, audio icon launcher
- Audio modal (new) — hosts gallery launch, volume, fades, both toggles; obeys `pickerOpen`
- Studio playback loop (`useRotoCachedPlayback`) — mix clip + optional main monitoring
- Main-editor playback (`playbackEngine.ts` / `audioEngine.ts`) — mix clip with main audio, gated by D-12 and D-13
- Export mixer (`audioExportMixer.ts`) — clip joins when "sound in output" is on
- Two-window bridge — push clip-edit revisions (position, in/out, volume, fades, toggles)

<specifics>
## Specific Ideas

- "It shows the way the main app shows audio" is the north star for *capability* (waveform, reposition, in/out, volume, fades) — but the **presentation is deliberately different**: a full-height dark-blue stain behind the frame numbers, **not** an audio rail. Do not "fix" this toward Phase 15's row layout.
- Frame numbers stay **filled, no outline** on top of the stain. Ticks and cuts stay at the bottom, unchanged. The strip gets **slightly taller** so numbers sit lower and the wave has room to express.
- The 2 px top bar is short and precise — that is intentional. The drawn bar is 2 px; usability hit-slop is Claude's discretion (D-09).
- "Sound in output" is the user's phrase for the master gate (D-12). Keep that user-facing label.
- Preview-mix exists "to isolate the studio sound" — a working aid, never an export behavior.
- Dialogue/foley framing: the clip is diegetic to the animation being drawn (lip sync, footsteps), while main-timeline audio stays music/ambience. That is why it follows layer hide/solo (D-13).
- Live/native evidence is the verdict (Plan 1/2 guardrails). ONE fix at a time; user retests.

</specifics>
