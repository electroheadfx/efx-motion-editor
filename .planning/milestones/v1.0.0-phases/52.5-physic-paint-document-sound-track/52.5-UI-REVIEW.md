## Top 3 Priority Fixes

1. **Missing CSS for the modal's error/confirm/armed states** — `.physics-paint-audio-error`, `.physics-paint-audio-confirm-copy`, `.physics-paint-audio-remove-armed`, `.physics-paint-audio-empty-body`, `.physics-paint-audio-filename` appear only in `PhysicsPaintAudioModalView.tsx` and in NO stylesheet, so decode/missing-file errors render as plain inherited-color body text (the UI-SPEC declares `--color-error-text #FF6666` for error copy and the confirm state), and the armed `Confirm remove?` state is visually identical to disarmed — a user can miss that the next click deletes the clip. — Fix: add rules in `physicsPaintStudio.css`: `.physics-paint-audio-error { color: var(--color-error-text, #ff6666); }`, `.physics-paint-audio-confirm-copy { color: var(--color-error-text, ...); font-size: 11px; }`, and `.physics-paint-audio-remove-armed { border-color: ...; background: ...; }` intensifying the destructive look while armed.

2. **Waveform stain fill ignores the declared token** — the stain path renders with `fill={SOUND_WAVEFORM_FILL}` = hardcoded `#166ECB` (`soundBandGeometry.ts:46`, `PhysicsPaintWorkflowStrip.tsx:4685`) while the UI-SPEC's new token `--color-audio-stain: #2D5BE3` (`physicsPaintStudio.css:10`) is only consumed by the vertical trim edge (`::before`). The spec's headline stain color, its launcher tint (spec: accent; impl: `#2da8e3` at css:4059), and its selected-state color (impl: undeclared `#DEBD34`) all diverge — three undeclared blues/yellows on one surface, and the declared token unused where it matters. — Fix: either switch the path fill to `var(--color-audio-stain)` (and the `has-sound` tint + selection state to declared tokens), or amend 52.5-UI-SPEC Color section to ratify `#166ECB` / `#2da8e3` / `#DEBD34` / `#7DD3F5` from the UAT rounds — one source of truth, not both.

3. **Fade/In/Out steppers stay fully interactive during `Reading audio…`** — `controlsDisabled` (busy) is passed to Import/Replace/Remove, the range slider, the curve selects, and the On/Off toggle, but NOT to the four `NumericStepper`s at `PhysicsPaintAudioModalView.tsx:362, 383, 410, 422` (`NumericStepper` supports `disabled` + `ariaDisabled`, `NumericStepper.tsx:90-91`). — Fix: pass `disabled={controlsDisabled}` and `ariaDisabled={controlsDisabled}` to each of the four steppers so the E9 loading row ("NumericInputs and curve selects render aria-disabled") holds.

## Detailed Findings

### Pillar 1: Copywriting (3/4)

**Holds (verbatim, evidence-based):**
- All modal constants defined verbatim at `PhysicsPaintAudioModalView.tsx:51-68`: `Document sound`, `No sound yet`, empty body, `Import sound`, `Replace…`, `Reading audio…`, `Remove`, `Confirm remove?`, both error strings.
- `AUDIO_REMOVE_CONFIRM_COPY` (:59) is a one-word deviation only (`gain` vs spec `volume` — consistent with the gain model drift).
- Close button `aria-label="Close"` (:236); launcher `aria-label="Document sound"` + `title` (`PhysicsPaintTrackRow.tsx:1112-1113`); stain double-click tooltip and trim `title`s are specific, not generic.
- Gallery audio empty state reuses `AUDIO_EMPTY_BODY` (`BackgroundAssetPickerView.tsx:298`) — no generic "No data" copy.
- No generic `Submit`/`OK`/`Click Here` labels on any phase surface (the one `Cancel` hit is a pre-existing sole-occurrence dialog in `PhysicsPaintStudio.tsx:5118`).

**Contract misses (WARNING):**
- `Sound in output` — **0 occurrences** in `app/src/components/physic-paint`. CONTEXT D-12 says "'Sound in output' is the user's phrase… Keep that user-facing label." The shipped UI has a single `On/Off` button with `aria-label="Document sound on/off"` (`PhysicsPaintAudioModalView.tsx:313`).
- `Preview main app too` — **0 occurrences**; replaced by a header Volume2/VolumeX icon toggle with long tooltip copy (`:70-73`), and the UI-SPEC's two-toggle row (field order item 7) does not exist.
- `Volume` label / `NN%` readout — replaced by `Gain` with signed `±NN` readout (`:62, :334`); `NN%` = 0 occurrences.
- Mitigation of record: `52.5-02-SUMMARY.md` "Model drift" table documents these as UAT-round-2 shipped-contract changes (`soundInOutput` → single `enabled`, `volume` → `gain`). The implementation is self-consistent with the shipped model, but **52.5-UI-SPEC's Copywriting Contract was never amended**, so the approved baseline and the shipped UI now disagree on three declared strings. Amend the spec or restore the labels — do not leave both standing.

### Pillar 2: Visuals (2/4)

- **BLOCKING-quality WARNING — modal width contradicts itself:** the component doc says "Width 300px (UI-SPEC spacing exception)" (`PhysicsPaintAudioModalView.tsx:11`) while the surface renders `style={{ width: '340px' }}` (:203). The spec's only declared dialog width is 300px; E1 overflow resolutions reason from "the 300px dialog". Nothing pins it in tests.
- **Five styled class names with no styles:** `physics-paint-audio-error`, `-confirm-copy`, `-remove-armed`, `-empty-body`, `-filename` have zero CSS rules (verified across all `app/src/**.css`). The empty heading survives only because it reuses `.physics-paint-photo-reference-label`; error copy, confirm copy, and the empty body get no color, size, or spacing of their own.
- **Filename backstop unmet:** `.physics-paint-photo-reference-chip` (css:4485) sets `white-space: nowrap` but no `max-width`/`overflow: hidden`/`text-overflow: ellipsis`; the inner `.physics-paint-audio-filename` is unstyled. Title tooltip IS present (`PhysicsPaintAudioModalView.tsx:273`), but a long filename will overflow the row rather than truncate (E6 long-text backstop).
- **Trim bar law replaced:** UI-SPEC E4/gesture table specify a 2px top bar with 6px end zones and 8px hit depth; the constants exist (`soundBandGeometry.ts:41-43`) but are **dead — zero non-test consumers**. The shipped trim UI is two full-height (36px) vertical end bars (`.physics-paint-sound-edge`, css:3219; strip :4720-4741, "UAT round 3"). Behaviorally equivalent for the user, contract-wise the spec's interaction table no longer describes the shipped surface. The stain overlay also draws fade curves + a gain line (`strip :4685-4711`) which the spec explicitly forbids ("NO center line, NO fade gradients… Fades are modal values only").
- **Holds:** band layering law is correct — stain `z-index: 0` rendered first behind `.physics-paint-ruler-tick` spans (`pointer-events: none`, css:3179), playhead `z 30` untouched; launcher is a 24×26 nav button with icon + label + title in the non-scrolling ruler-spacer (`PhysicsPaintTrackRow.tsx:1108-1116`); no backdrop, Escape close, focus capture/restore, header drag all implemented (`PhysicsPaintAudioModalView.tsx:120-198`).

### Pillar 3: Color (2/4)

Counts on phase-owned code:
- Declared token `--color-audio-stain` (`#2D5BE3`): 1 declaration (css:10) + 1 consumer (trim edge `::before`, css:3235). **Not used on the stain it was created for.**
- Hardcoded/undeclared colors introduced by this phase: `#166ECB` (stain fill, `soundBandGeometry.ts:46`), `#7DD3F5` (fade/gain overlay stroke, :48), `#2DB3E3` (superseded, referenced in comment), `#DEBD34` (selected stain outline + selected edge, css:3240/3244), `#2da8e3` (`has-sound` launcher tint, css:4059), `#2d5be3` re-hardcoded inline for the preview toggle + slider `accentColor` fallback (`PhysicsPaintAudioModalView.tsx:225-231, 348`).
- Spec's accent reserved-list item 3 says the launcher tints with `--color-audio-stain`; impl uses a brighter cyan-blue with a UAT comment ("the stain blue reads as near-black on the chrome rail") — a legitimate design reason, but the contract wasn't updated.
- Spec reserved-list item 4 says the modal toggles use the photo-ref on-style (`bg #1d2e4e / border #3d5fb0 / text #cfe0ff`): the clip `enabled` toggle does reuse `.physics-paint-photo-reference-toggle` (compliant), but the new header preview toggle uses a solid `#2d5be3` fill (off-style).
- Error copy: declared `--color-error-text #FF6666` for "Remove-sound confirm state and error copy only" — neither gets it (no CSS rule, see Pillar 2).
- 60/30/10 distribution: dominant `#0F0F0F`/`#1A1A1A` chrome unchanged, band `#47494b` unchanged, accent-family appears only on sound surfaces + existing selection — no accent overuse. The pillar fails on **token fidelity**, not distribution.

### Pillar 4: Typography (3/4)

- New phase rule `.physics-paint-audio-field-label` = `font-size: 10px; font-weight: 600;` (css:4588-4594) — spec Label role is 11px/400 and "all NEW text uses 400 or 700". 600 appears 33× file-wide (pre-existing), but this is a **new** rule using a non-contract weight and a size below the declared 11/12/13 cluster.
- The Gain readout rides `.physics-paint-photo-reference-opacity output` = 10.5px/600 with `tabular-nums` (css:4349-4355) — spec Data role is 12px/700. Reused pre-existing chrome, but the readout is a new phase element.
- Holds: frame numbers `12px / 700 / font-variant-numeric: tabular-nums` exactly per contract (css:3174-3177); dialog base 13px with `<strong>` heading (13/700 equivalent); curve selects at 10px inherit the Studio cluster; no display sizes introduced; hierarchy carried by weight/uppercase labels as designed.

### Pillar 5: Spacing (3/4)

- Modal width **340px** vs declared exception **300px** (see Pillar 2) — the single declared dialog width in the spec's spacing table.
- `.physics-paint-audio-grid { gap: 10px }` (css:4575) — 10 is not on the 4/8/16/24/32 scale and not in the spec's exception list. (The photo-ref content `gap: 10px` at css:4564 is pre-existing and reused wholesale.)
- Holds: `flex: 0 0 36px` on BOTH `.physics-paint-ruler` (css:3153) and `.physics-paint-track-column-strip` (css:3928) — the plan's grep-count ≥ 2 law; band geometry constants match the spec exactly (`SOUND_BAND_HEIGHT_PX=36`, `SOUND_STAIN_INSET_PX=8`, half-extent 14, arms 4/2 — `soundBandGeometry.ts:30-43`); field gap 4px (css:4584), enable-row gap 8px (css:4615), icon 15px, launcher 24px wide all on-scale; no arbitrary `[Npx]` bracket values in phase TSX beyond the declared inline width.

### Pillar 6: Experience Design (3/4)

**Coverage present (evidence):**
- Empty state: `AUDIO_EMPTY_BODY` block with error slot above it (`PhysicsPaintAudioModalView.tsx:245-266`).
- Loading: `busy → AUDIO_LOADING` on Import/Replace CTAs + `disabled` (:261, :281); volume slider, curve selects, enabled toggle, Remove all disabled/aria-disabled during busy (:301, :315, :347, :373, :394).
- Error: decode + missing-file variants with `role="alert"` (:251, :286); fail-closed band behavior (no peaks → no stain) coded in the strip.
- Destructive: two-step Remove with `withDisarm` reverting on any other action (:182-185, :302-305).
- Dialog law: no backdrop, no Tab trap, Escape closes, focus captured/restored to launcher, header drag (photo-ref precedent).
- `pickerOpen` step-aside: audio modal gated behind the shared guard (`PhysicsPaintStudioView.tsx:327, 367`).
- Gesture truth table: identity fixed at pointer-down, 4px/2px arms, trim never seeks, settle-on-release — implemented in the strip session (`:2817-2966`) and pinned by 12 geometry tests (`soundBandGeometry.test.ts`).
- Launcher always visible in empty/error/loading/populated states (E2 rows) — unconditional render in the header column.

**Gaps (WARNING):**
- **E9 loading row unmet:** the four `NumericStepper`s (Fade in, Fade out, In, Out) receive no `disabled`/`ariaDisabled` prop while busy — a user can edit fade/trim frame values during `Reading audio…`, exactly the optimistic-edit case E9 forbids (fix in Priority 3).
- **Armed Remove has no visual distinction** beyond the label swap — `physics-paint-audio-remove-armed` has no rule, so the spec's "destructive styling" in the armed state is not rendered.
- **Verification caveat (not a code defect):** the 01b/02 summaries both record that the live/native UAT rows for this slice have NOT been run — this audit is static, and no interaction captures were taken (`interaction_capture: false`), so all interaction findings above are code-derived.
