## LRU memory budget

| Option | Description | Selected |
|--------|-------------|----------|
| Fixed ~512 MB | ~60 HD frames hot; smooth scrub with margin under WKWebView OOM history | ✓ |
| Fixed ~256 MB | ~30 HD frames hot; most memory-safe, more cold-miss decodes | |
| Fixed ~1 GB | ~120 HD frames hot; smoothest scrubs, highest OOM risk | |
| Auto-derive from RAM | Fraction of available memory; needs a Rust memory-query command | |

**User's choice:** Fixed ~512 MB.

**Follow-up — prewarm budget:**

| Option | Description | Selected |
|--------|-------------|----------|
| Share the 512 MB | One budget, one eviction policy | ✓ |
| Separate allowance | Prewarm gets ~64-128 MB headroom | |

**User's choice:** Share the 512 MB. Notes: the "lookahead evicts the current frame" scenario is impossible under proper LRU ordering (just-drawn frame is most-recently-used). Correctness rule: frames referenced by an in-flight composite/draw are PINNED (unevictable) until released; pinning is a correctness rule (cannot `close()` a bitmap mid-`drawImage`), not a second budget. Eviction of an unpinned handle owns the explicit `bitmap.close()` call.

## Base64 elimination scope

| Option | Description | Selected |
|--------|-------------|----------|
| Paint frames only | Eliminate base64 only for the paint frame runtime | |
| All three registries | Paint frames + background + photo-reference source images | ✓ |

**User's choice:** All three registries (`_rotoAlphaCanvasRegistry`, `_backgroundSourceImages`, `_referenceSourceImages`). Notes: imported background/reference photos are the same multi-MB-string-as-Map-key pattern (a 12 MP photo reference outweighs most paint frames); excluding them keeps two known-hot instances of the exact pattern this phase exists to eliminate, and v1.2.0's 2K assets would compound it. Keys become the existing stable `sourceRef`/library asset IDs; values become decoded handles in the same byte-budgeted LRU. Accepted cost: Phase 49/50 import+composite paths join the retarget, re-validated inside the phase's full native roto UAT.

---

## Decoded frame handle

| Option | Description | Selected |
|--------|-------------|----------|
| ImageBitmap (GPU) | Rust decodes WebP → raw RGBA → ImageData → createImageBitmap → GPU bitmap | ✓ |
| ImageData (CPU) | Rust decodes → raw RGBA held as ImageData in the LRU | |
| Keep canvas | Keep HTMLCanvasElement, re-keyed off dataUrl | |

**User's choice:** ImageBitmap as the canonical decoded handle. Notes: LRU eviction owns `bitmap.close()` explicitly; frames referenced by an in-flight draw are pinned (unevictable) until released. ImageData exists only as the transient IPC→bitmap bridge, never stored. Watch items: premultiplyAlpha convention (straight alpha per Phase 48 D-02) and a Safari `createImageBitmap(ImageData)` contract test.

---

## Final integration note (user)

The decode-once content-keyed caches shipped by the G-52-7/G-52-8 fixes (roto PNG decode off-main-thread, reveal-rail decode/encode storms) are absorbed into the new byte-budgeted LRU. There must be ONE decoded-frame cache authority after this phase — no parallel registry keyed by the dying dataUrl string survives. Their off-main-thread decode behavior is preserved by construction (Rust decode + `createImageBitmap`).
