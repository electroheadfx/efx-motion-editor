# Phase 52.1 Plan 02: Frame Codec Tracer Summary

**Codec-agnostic Rust `FrameCodec` trait with a `WebPLosslessCodec` (libwebp `config_exact` alpha) exposed as `encode_webp_frame`/`decode_webp_frame` Tauri commands, plus JS `invoke` helpers that move raw `Uint8Array` across the boundary with no base64.**

## Performance

- **Duration:** 35 min
- **Completed:** 2026-09-06
- **Tasks:** 2
- **Files modified:** 6

## Accomplishments

- Proved the hardest constraint of the new frame runtime: a WebP-lossless round-trip through Rust preserves straight-alpha RGB under fully-transparent pixels (`config_exact=1`), verified by a passing cargo test.
- Established the codec-agnostic seam — commands call `WebPLosslessCodec` through the `FrameCodec` trait, never a direct `webp::` call (D-02).
- Registered `encode_webp_frame` / `decode_webp_frame` in the Tauri `generate_handler` list.
- Added JS `encodeWebpFrame` / `decodeWebpFrame` helpers that use `invoke` with raw `Uint8Array` bodies (D-07), not `emitTo` JSON (which base64-encodes).

## Decisions Made

- Used `encode_advanced` with `exact = 1` (config_exact) rather than `encode_lossless()`, which does not set `exact` and would drop RGB under transparent pixels (D-01).
- Used direct `invoke` (not the `safeInvoke` wrapper) so the raw `Uint8Array` return is explicit and the acceptance grep `invoke(` matches; `safeInvoke` returns a `Result<T>` wrapper that would obscure the raw byte return.
- Kept `bytesToBase64` / `base64ToBytes` — their deletion is Plan 03's apply-path retarget, not this tracer's scope.

## Deviations from Plan

None - plan executed as written. The only clarification was resolving the plan's "via the existing safeInvoke wrapper" hint against the acceptance criterion grep `invoke(` — direct `invoke` satisfies the hard gate and the D-07 raw-byte contract.
