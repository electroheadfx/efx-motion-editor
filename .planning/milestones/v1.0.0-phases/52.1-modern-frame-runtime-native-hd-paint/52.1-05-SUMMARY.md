# Phase 52.1 Plan 05: Preview/Export + Compositor LRU Retarget Summary

**Retarget the main-editor preview/export readers and the shared compositor draw path from the string identity to the LRU ImageBitmap handle (D-05/D-13), with the export preload gated on decode completion so a cold LRU miss never renders a missing layer.**

## Performance

- **Tasks:** 2
- **Files modified:** 7 (3 production + 4 test)
- **Commits:** 3 (1 RED test + 1 feat + 1 blast-radius test)

## Accomplishments

- `previewRenderer.ts` fallback path (`getPhysicPaintImageSource`) retargeted from `new Image()` + Blob URL to `physicPaintStore.getDecodedImage(bytes)` — the LRU ImageBitmap handle (D-05). `isPhysicPaintFrameResolved` checks the LRU instead of the renderer's `imageCache`/`failedImages`.
- `exportRenderer.ts` `preloadExportImages` now triggers the per-frame decodes, awaits them (`renderer.awaitPhysicPaintDecodes()`), then re-collects the warm flattened rasters — the cold-miss correctness gate (D-13).
- `physicPaintStore.ts` gained `_compositorDecodePromises` (token → in-flight decode promise) + `awaitPendingDecodes()` so the export preload can await decode completion.
- The compositor (`efxPaintCompositor.ts`) and composite cache (`efxPaintCompositeCache.ts`) were **already retargeted in 52.1-03/04** — the store ports return ImageBitmap, the compositor draws `CanvasImageSource` via `drawImage`, and the cache key uses `buildFrameBytesToken`. No production change was needed there (deviation from the plan's `files_modified`).
