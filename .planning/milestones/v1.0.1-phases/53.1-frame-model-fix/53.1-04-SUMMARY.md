## Decisions Made

- **D-10 store boundary only:** the ceiling change lives in `timelineStore.seek`/`stepForward` and `frameFromX`'s default — `resolveTimelinePointerFrame` itself is untouched so the 260918-s52 drag-mapping law holds byte-for-byte.
- **D-10 END-STATE one policy site:** `mapPreviewEndStateFrame` is the single mapping. It is applied in `renderGlobalFrame` (the shared preview boundary every preview consumer rides) before `fm[frameIndex]` lookup, so preview at N shows `fm[N-1]` instead of a black hole. Export never passes N (`frame < fm.length`) so the mapping is a no-op there — export length law 0..N-1 unchanged. N=0 maps to -1 and `renderGlobalFrame`'s existing `frameIndex < 0` early return keeps today's empty render.
- **D-11 no number at N:** the `isEndLimit` branch draws only stroke+cap and `continue`s — a styled number at N would still assert "frame N exists" (the I-3 bug). The branch is entered even when `f % interval !== 0` so the end limit is always visible; the interval skip stays for ticks 0..N-1 exactly as today.
- **Store clamp harness seeds real N:** `timelineStore.test.ts` drives `totalFrames` through `sequenceStore.createSequence` + `addKeySolid(..., holdFrames)` + `updateHoldFrames` — no frameMap mock, so the clamp tests exercise the real N law.
- **Preact discipline:** the N-shrink clamp is a plain `effect` on `totalFramesSignal`, matching the existing `maxScrollY` scroll clamp effect in the same file (efx-preact-reactivity).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 3 - Blocking] END-STATE must apply before the fm lookup in renderGlobalFrame**
- **Found during:** Task 1 (GREEN — preview at N would still be black if the mapping lived only inside `PreviewRenderer.renderFrame`)
- **Issue:** `renderGlobalFrame` looks up `fm[frameIndex]` before any `PreviewRenderer.renderFrame` call. Mapping N→N-1 only inside `renderFrame` is too late: `fm[N]` is undefined, `hasContentEntry` is false, and the canvas is cleared to empty — the END STATE never shows. The plan named `previewRenderer.ts` as the policy home but the preview render boundary that owns the fm lookup is `renderGlobalFrame` in `exportRenderer.ts` (shared by Preview and export).
- **Fix:** the one-liner policy lives in `previewRenderer.ts` as `mapPreviewEndStateFrame` (plan + grep leg satisfied); `renderGlobalFrame` calls it once at the top before the fm lookup. Export is a no-op (never passes N). No per-consumer fork added.
- **Files modified:** `app/src/lib/previewRenderer.ts`, `app/src/lib/exportRenderer.ts`
- **Verification:** clamp 6/6 + frameList 10/10 + frameMap 36/36 + main 2/2 = 54 passed
