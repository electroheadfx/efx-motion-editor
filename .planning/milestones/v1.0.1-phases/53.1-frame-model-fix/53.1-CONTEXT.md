Make timeline, preview, and export agree on one frame model so the native signed 1.0.1 repro stops producing a black hole and an unreachable tick 17.

## Decided target laws (CLOSED — do not re-open)

From `.planning/debug/resolved/FRAME-MODEL.md` §7 (user checkpoint 2026-10-12).

### Law 1 — Content-overlay tail policy (I-1 / I-2 / I-5)

> "Untrimmed content-overlay follows N (it is a base layer — covers the
> composition). Once the user resizes it, out is AUTHORITATIVE: past out =
> nothing (standard clip end). Past the SOURCE: HOLD the last frame by default
> (fix I-5); keep LOOP as an explicit per-clip extrapolation choice (the user's
> workaround relied on the looped nebula and liked it). Never a silent black
> frame: a visible layer that does not cover N gets a visible gap marker on the
> timeline + an export diagnostic."

### Law 2 — Playhead / tick N (I-3)

> "Playhead can sit on tick N (the end boundary), NLE-style end-of-sequence
> position. At position N the preview shows the END STATE (the last frame's
> result), the export still writes 0..N-1. Ruler presents tick N as the end
> limit, not as a frame number."

### Law 3 — fps timebase (I-4)

Sequence `fps` follows project fps; video seek uses project fps. Kills the dual timebase (`seq.fps` born at 24 vs `projectStore.fps`).

### Law 4 — Fix shape / measurement

- FULL phase (not split into quick+phase).
- Measurement: automated export frame-LIST checks **assert the TARGET laws** (not just pin actual), plus live signed-build UAT as release evidence.
- Exclusive `outFrame` law `[in, out)` is **UNCHANGED**.
- Drag mapping (`resolveTimelinePointerFrame` floor) and the 260918-o0n span-drag law are **UNCHANGED**.

## Implementation Decisions

Nine placement decisions from the 2026-10-12 discuss (implementation approach only — the laws above stay closed). Cited against `.planning/debug/resolved/FRAME-MODEL.md` §7.

### I-4 — fps timebase (Law 3)

- **D-01:** Derived — project fps only. Every time-math call site reads `projectStore.fps`; no exceptions, no local caching of `seq.fps`. Delete `sequenceStore.setSequenceFps` (0 callers). Drop `seq.fps` from the model entirely (Sequence type, the three factories `sequenceStore.ts:148,280,312`, and the .mce serializer/parser) — clean break, no shim, no ignored leftover field. Video seek and export MUST go through the same reader (same project fps) so frame N always means N / projectFps seconds of source in both paths. Call sites: `exportRenderer.ts:315,329,367`; `previewRenderer.ts:832` (`targetTime = frame / fps`), `:977`; `SequenceList.tsx:96` (duration display). — **Reversibility:** one-way — [rationale: removing `seq.fps` from the .mce shape is a schema drop under the no-backward-compat law; undoing means re-adding a field plus a write path]
- **D-02 (U-01 fps law):** the 15fps project + 24fps-era .mov repro must show frame 15 = 1.0s in BOTH preview seek and export time mapping (not 0.625s).

**Why derived, not sync-on-change (user's rebuttal, recorded as data):** `sequence.fps` is born at 24 and `setSequenceFps` has 0 callers — the bug is a single stale field, not a real dual timebase. Keeping the field keeps the seed of the bug (any missed write path re-introduces it). A per-sequence fps field contradicts the one-document-timebase model law. No-backward-compat: dropping a dead field is the debt fix itself.

### I-1 / I-2 — tail policy owner + untrimmed representation (Law 1)

- **D-03:** One resolver in `frameMap.ts` (the frame-model module — already owns the N law and `getTimelineOverlaySequenceOutFrame`). Signature: `resolveOverlaySample(clip, globalFrame, N) → {kind:'sample', localFrame} | {kind:'skip'} | {kind:'hold-last'} | {kind:'loop', localFrame}`. Both paths call it — `exportRenderer.ts:339-340` past-out gate and `previewRenderer.ts:831-836` modulo-loop — **no local tail policy left anywhere**. I-5 HOLD/LOOP is an INPUT to this resolver (per-clip extrapolation property), never a second policy site — that is what kills the I-1 vs I-5 divergence class. Unit-testable: one describe in `frameMap.test.ts` covering the truth table (inside range / past out / past source HOLD / past source LOOP). — **Reversibility:** costly — [rationale: both render paths and their tests rewire to the resolver; undo means restoring per-path policy]
- **D-04:** Absent `outFrame` = untrimmed = follows N (base layer). Present `outFrame` = AUTHORITATIVE — past out = nothing. One field, two states, no flag, no sentinel. `createContentOverlaySequence` STOPS freezing `outFrame` at import (`sequenceStore.ts:317`) — that freeze is the I-1 root (overlay skipped the moment the sequence grows past the import-time out). `outFrame` is written ONLY when the user resizes. Timeline bar width and SequenceList duration treat absent `outFrame` as N. `getTimelineOverlaySequenceOutFrame` already does `seq.outFrame ?? fallback` — the fallback becomes the live N (base span), not a frozen import value. Untrimmed never gaps. Clean break: no migration, no shim. — **Reversibility:** one-way — [rationale: the meaning of `outFrame` in the .mce model changes (absent = follow-N); undoing rewrites every reader and any saved project written under the new meaning]
- **D-05:** Timeline gap marker = hatched tail on the clip bar. Per-clip range `(out .. N)` on the clip's OWN timeline row — the same surface as the range bar the user just resized. Derived from the resolver's skip region (one source, no second gap computation). Drawn alongside the clip bar in `TimelineRenderer` / `fxTrackLayouts` AFTER the bar's right edge; `barW` stays `(out-in)*frameWidth` (exclusive) and the fade stays flush against the bar — the hatched tail sits outside both. Fires only for VISIBLE layers with an authoritative out. Multiple clips can each carry their own tail. No new timeline lane (avoids noisy extra UI).
- **D-06:** Export diagnostic = non-blocking named warning. Deliberately NOT the SND-02 fail-closed shape: a gap is a valid compositional state the user may intentionally want (clip ends, paper / other layers continue) — blocking would withhold a deliverable by design. The law says "export diagnostic", not "export abort". Export still runs and writes 0..N-1 (export length law unchanged). The export progress / completed report carries a named warning per uncovered visible clip, e.g. `video "nebula.mov" does not cover frames 16..17` — clip name and exact range always in the message. Channel: `warnings: string[]` on the export progress/result object (see D-10), NOT the `exportStore` error status (that one aborts). Surfaced in the existing export UI — no new notification system. Same coverage source as the timeline marker: the resolver's skip region — timeline and export can never disagree about what a gap is.

### I-5 — per-clip extrapolation property (Law 1)

- **D-07:** `extrapolation: 'hold' | 'loop'` lives on the Sequence (the clip), beside `inFrame`/`outFrame` — the clip is what the user resizes and what Law 1 names ("per-clip extrapolation choice"). `resolveOverlaySample(clip, globalFrame, N)` reads `clip.extrapolation` as its I-5 input; `exportRenderer` and `previewRenderer` never branch on HOLD/LOOP themselves (D-03 single-resolver law). Content-overlay sequences carry one primary layer today — clip grain is the correct grain: no per-layer policy, no per-layer gap ranges. Factories default `'hold'`. Loader maps an absent field to `'hold'`. One store setter writes the user's explicit choice (undo action + `markDirty`, same shape as `setInOut`). — **Reversibility:** costly — [rationale: a persisted per-clip field plus its setter/inspector/serializer surface; undo means removing the field and the user-visible choice]
- **D-08:** Surfaces as a two-state control in the content-overlay inspector (`SidebarProperties`), next to the clip range (in/out). Labels follow the physics-paint left-sidebar naming style: **"Hold last frame" / "Loop"**, default Hold. No new panel, no timeline context menu (a Law-1 property must not hide behind right-click), no dual surface to keep in sync. Gap-tail interaction pinned: a LOOP clip never shows the hatched tail inside its own source repeat — the tail exists only past an authoritative out (D-05), independent of extrapolation. Untrimmed clips (absent `outFrame`) never gap, HOLD or LOOP.
- **D-09:** Default = HOLD everywhere, explicit LOOP write. Every clip — newly created, newly imported, and loaded from an existing .mce — is HOLD unless the user explicitly sets LOOP on that clip. In-memory the field is required and the factories default `'hold'`; the loader fills `'hold'` when an old .mce has no field (no legacy branch, no implicit-LOOP shim — clean break per no-backward-compat). Accepted consequence: a pre-53.1 project that relied on the silent modulo-loop (the nebula workaround) opens as HOLD; the user re-chooses LOOP once, and that choice must persist across save → close → reopen. **Rejected:** "legacy files keep looping" — that is exactly the silent default Law 1 was written to kill, and it needs a version branch.

### I-3 — playhead clamp + tick N + inspector (Law 2)

- **D-10:** Clamp ceiling becomes N inclusive at the STORE BOUNDARY ONLY: `timelineStore.seek`/`stepForward` `upper = max` (not `max-1`, `timelineStore.ts:86-103`); `frameFromX`'s `maxFrame` default becomes `totalFrames` (not `totalFrames-1`, `TimelineRenderer.ts:1552-1560`) so scrub can land on tick N. `resolveTimelinePointerFrame` floor math stays byte-untouched (260918-s52 / drag-mapping law). END STATE mapping is exactly one line at the preview render boundary (`previewRenderer`): `renderFrame = playhead >= N ? N-1 : playhead`. Export still writes 0..N-1 and never sees N. Audio needs no N branch — playhead N is simply the end of the timeline (offsetSeconds at N = sequence end, nothing starts). No `atEnd` flag; no per-consumer N fork (that is the I-1 divergence class again). Edge pinned: if N shrinks below the current playhead, clamp down to the new N; if N grows while the playhead sits on N, the playhead stays on the end limit. Empty timeline (N=0) keeps today's empty render. — **Reversibility:** costly — [rationale: store clamp + scrub default + preview boundary move together; undo touches every seek consumer]
- **D-11:** Ruler tick N = end marker, no number. Ticks 0..N-1 keep their frame numbers exactly as today. Tick N draws a distinct END LIMIT: a taller tick stroke with a small horizontal cap (end-of-timeline shape), NO numeric label and NO time glyph. `drawRuler` gets a single `isEndLimit` branch on the last tick (`f === N`) — the only behavioral change in the ruler loop; every other tick is byte-unchanged. Tick N still exists as a legal playhead position (D-10) — the marker is display-only. "End limit, not a frame number" literally: a styled number at N would still assert "frame N exists" (the bug being fixed); a time label at N mixes units on a frame ruler. UAT: no numeric N label survives anywhere on the ruler.
- **D-12:** Inspector shows the law = per-clip coverage law text in the content-overlay inspector (`SidebarProperties`), same panel as the Hold/Loop control (D-08). One compact per-clip readout, derived from the I-1 resolver state (never a second computation):
  - range line: `0 → 16 (exclusive)` — restates the unchanged `[in, out)` law
  - tail state line: `Follows sequence end` when `outFrame` is absent (untrimmed), OR `Ends at 16 · sequence runs to 17` when trimmed — and when N > out, the gap is NAMED in that same line, matching the hatched tail range and the export warning text (same coverage source as the resolver skip region, so the three surfaces cannot diverge).

  No separate playhead/end readout: the playhead is transient state, not clip law. No "no inspector change": the stated goal is that the inspector shows the law, and this is where the user edits the clip.
