## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Builder placement API: plan's literal `PhysicalPosition`/`PhysicalSize` builder calls do not exist in Tauri 2.11**
- **Found during:** Task 2 (cargo check: `E0061` — `.position` takes 2 `f64`s, `.inner_size` takes 2 `f64`s; both documented "in logical pixels"; no physical builder variant exists on `WebviewWindowBuilder` or `WindowBuilder`)
- **Issue:** The plan instructed `.position(tauri::PhysicalPosition::new(bounds.x, bounds.y))` + `.inner_size(tauri::PhysicalSize::new(bounds.width, bounds.height))` on the builder — that signature doesn't compile; and feeding physical pixels into logical-pixel builder APIs would double-place on scaled displays
- **Fix:** Fresh-create builder gets `bounds.x / mirror_scale` etc. (logical), where `mirror_scale` = the main window's own `scale_factor()` (fallback 1.0); the exact physical bounds are then re-applied post-show via `set_position(PhysicalPosition)` + `set_size(PhysicalSize)` — those APIs accept physical structs and compile clean, and they run on BOTH arms (covering reuse). Net behaviour matches the plan's intent: fresh arm placed correctly at create, reuse arm mirrored after show, no centring anywhere
