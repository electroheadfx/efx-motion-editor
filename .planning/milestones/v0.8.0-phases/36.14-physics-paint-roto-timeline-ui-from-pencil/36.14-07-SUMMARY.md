# Phase 36.14 Plan 07: Single-key Ripple Drag Summary

Single-key ripple Drag delivered as one versioned cut-and-insert proposal flowing from identity-based pointer targeting through a pure resolver-driven preview to an exact coordinator commit, with complete lifecycle-safe focus/rollback behavior and no active legacy move authority.

## Accomplishments

### Task 1: Whole-cell identity Drag with one versioned preview/commit proposal

- Extended `useRotoTimelineActions` with `RotoDragPublication`/`RotoDragPreparationResult`/`RotoDragTargetSignature` types and the `prepareRotoKeyDrag`/`commitRotoKeyDrag`/`canDragKey`/`dragDisabledReason` members on the stable physical action bundle.
- `prepareRotoKeyDrag` reads one coherent physical snapshot, invokes the pure resolver with a `move-key` intent plus the supplied target, rejects failure/self-target/no-change/stale/malformed results, and returns one immutable publication carrying the exact proposal object plus `proposalVersion` (revision:operationId:layerId), expected launch tuple, moved keyId, and target signature.
- `commitRotoKeyDrag` verifies wrapper coherence (`operationKind === 'move-key'`, `drag.movedKeyId === publication.movedKeyId`, non-empty launch tuple) and submits the unchanged proposal to `executePhysicalEdit` without resolver or mapping recomputation.
- Added pure `getRotoDragPreviewViewModel`/`collectRotoDragVacatedAppFrames` projection helpers to `physicsPaintWorkflowPresentation`.
- Rewrote `PhysicsPaintWorkflowStrip` Drag with identity-based DOM (`data-roto-key-id`/`data-roto-app-frame`), whole-cell target for empty/generated, before/after boundary for occupied (midpoint hit test), target signature equality at pointer-up (D-09), focus restoration on the moved identity at its accepted appFrame (D-24), and complete proposal preview (moved/shifted/target/generated/vacated).
- Removed legacy `resolveRotoKeyMoveTiming`/`buildRotoKeyMoveTransaction`/`RotoKeyMove*` types from `physicsPaintRotoKeyController` and `onResolveRotoKeyMoveCandidate`/`onMoveRotoKey`/`resolveStudioRotoKeyMoveTiming`/`resolveRotoKeyMoveCandidate`/`moveRotoKey` from `PhysicsPaintStudio`.
- Added CSS states for `roto-drag-target` (with before/after caret), `roto-drag-moved`, `roto-drag-shifted`, `roto-drag-vacated`, `roto-drag-generated`.
- Preserved the approved pointer lifecycle: 6px threshold, click suppression, pointer capture, Escape/pointercancel/lostpointercapture, edge scrolling.

### Task 2: Occupied before/after boundaries and complete ripple preview

- Fixed role precedence: occupied target identity takes precedence over shifted (D-07/D-21) so the target cell renders the caret rather than a plain shifted accent even when the target shifts because of the ripple.
- Added `targetPreDragAppFrame` to `RotoDragPreviewViewModel`, derived from the target identity's `beforeAppFrame` in `proposal.changes` (or post-proposal appFrame when unchanged).
- `buildDragConciseStatus` now references the target identity's current (pre-drag) frame for before/after copy so the text matches the cell the user is pointing at (D-21).
- Locked example `A@1/B@3/C@5/D@8` + B after D previews exactly `A@1/C@4/D@7/B@8` with D preserved as the occupied target, C and D shifted, B at 8, and selection metadata for B.

### Task 3: Seal release parity, cancellation restoration, focus, and legacy cutover

- `cleanup()` now always clears the transient preview; valid-release pointer-up sets its pending preview AFTER cleanup so the committing state survives (D-09/D-22).
- Every cancellation path (invalid release, Escape, pointercancel, lostpointercapture, validity-key change, unmount) clears the preview safely and idempotently.
- Added `restoreSourceFocus()` helper: on cancellation or failed settlement, restore focus to the source keyId when still mounted; otherwise leave focus on the stable timeline container rather than guessing a nearest frame (D-24).
- On accepted commit, focus the moved identity's cell via `data-roto-key-id` selector with appFrame fallback; the proposal IS the accepted state so `proposal.mapping` is authoritative.
- Failed settlement (`accepted === false`) and commit rejection both restore source focus after complete rollback.
- Legacy cutover audit complete: no active legacy move seam remains in the declared files (`onResolveRotoKeyMoveCandidate`, `onMoveRotoKey`, `resolveRotoKeyMoveTiming`, `buildRotoKeyMoveTransaction`, `RotoKeyMove*` types, `resolveStudioRotoKeyMoveTiming`, `moveRotoKey`, `rotoMoveInFlightRef`, `rotoMoveGuardRef` all removed).

- **Found during:** Task 2
- **Issue:** In `getRotoDragPreviewViewModel`, the `changesByKeyId.has(cell.keyId)` check came before the `targetKeyId` check, so an occupied target that shifted because of the ripple was labeled `shifted` instead of `target`, losing the caret.
- **Fix:** Reordered so the occupied target identity check takes precedence over the shifted check (D-07/D-21).
- **Files modified:** `physicsPaintWorkflowPresentation.ts`

**3. [Rule 1 - Bug] Cancellation did not clear the preview when a publication existed**
- **Found during:** Task 3
- **Issue:** `cleanup()` only cleared the preview when `!session.publication`, so Escape/pointercancel/lostpointercapture during a valid drag left the preview visible.
- **Fix:** `cleanup()` now always clears the preview; valid-release pointer-up sets its pending preview AFTER cleanup so the committing state survives.
- **Files modified:** `PhysicsPaintWorkflowStrip.tsx`
- **Commit:** 35c5f952

**4. [Rule 2 - Missing critical functionality] Focus restoration on cancellation/failure**
- **Found during:** Task 3
- **Issue:** Cancellation and failed settlement paths did not restore focus to the source identity (D-24).
- **Fix:** Added `restoreSourceFocus()` helper called on invalid release, Escape, pointercancel, lostpointercapture, failed commit, and commit rejection; falls back to the timeline container when the source identity is no longer mounted.
- **Files modified:** `PhysicsPaintWorkflowStrip.tsx`
- **Commit:** 35c5f952
