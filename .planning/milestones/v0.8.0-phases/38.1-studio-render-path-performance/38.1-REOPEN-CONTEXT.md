## Reopening Authority

The user explicitly rejected the historical completion claim for Phase 38.1 because localized-render acceptance remains unmet. This reopen adds a bounded instrumentation → localization → native acceptance sequence without revisiting the already-approved timing architecture.

## Locked Decisions

### R-D-01 — Preserve history; reopen only the unmet acceptance surface

Plans and summaries 38.1-01 through 38.1-07 are immutable historical artifacts. Their canvas-first navigation, save-before-leave, rAF propagation, latest-wins scheduling, playback freeze, and O(1) cache work remain the working baseline. Plans 38.1-08 through 38.1-12 address localized renders only.

### R-D-02 — Extend the existing profiler seam

Extend `physicsPaintPerformanceTrace` rather than creating a second profiler. Add development-gated named render/event counters, immutable snapshots, snapshot deltas, reset semantics, and a native `window.__EFX_PHYSICS_PAINT_PROFILE__` snapshot API. Profiling remains disabled unless the existing development/localStorage gate is enabled.

### R-D-03 — Instrument first and capture a red baseline without localization changes

Plan 38.1-08 instruments every required render, observer, and Efx lifecycle surface and captures the failing warm-up/delta baseline. It MUST NOT add memo wrappers, stabilize props, split render boundaries, change observer dependencies, or otherwise improve the measured path.

### R-D-04 — Exact sanctioned and unsanctioned render surfaces

After warm-up, adjacent committed frame navigation may update only:

- `PhysicsPaintStudio` / `PhysicsPaintStudioView` orchestration;
- frame-sensitive Workflow subregions;
- `PhysicsPaintCanvasStack` only when overlay or input-lock semantics actually change.

The following require a zero render delta for ordinary adjacent committed frame navigation:

- `PhysicsPaintTopBar` implementation;
- `PhysicsPaintToolRail` implementation;
- the entire right-panel region shell/toggle and `PhysicsPaintRightPanel` implementation;
- closed `PhysicsPaintPlayScriptDialog`;
- `PhysicsPaintCanvasMount`;
- the app-owned Efx child request boundary;
- static Workflow chrome.

`RotoTimelineCellButton` execution is capped at three cells per adjacent committed navigation. Timeline/canvas observer restart deltas are zero.

### R-D-05 — Preact-native memoization must preserve Signal reactivity and plain implementations

Use Preact Signals and `preact/compat` memo boundaries with identity-stable props. Parent memo skips MUST NOT freeze internal Signal subscriptions. Keep plain component implementations directly callable where current tests depend on that contract; place compat wrappers in dedicated modules when required. Do not introduce React-style effect/hook sprawl.

### R-D-06 — Workflow localization is one bounded behavior-preserving cut

`PhysicsPaintWorkflowStrip` installs its observers once, splits static chrome from frame-sensitive live regions, receives stable workflow/action callbacks, and memoizes private cell bodies. Preserve every existing tooltip, pointer drag, group selection, keyboard, wheel, custom scrollbar, focus, capsule-arbitration, and accessibility contract exactly.

### R-D-07 — Persistent CanvasMount/Efx isolation has a separate gate

Keep `PhysicsPaintCanvasStack` live for overlays and input locking while placing the persistent `PhysicsPaintCanvasMount` / Efx child behind a dedicated stable boundary. Stable callbacks read current values through existing refs. Adjacent navigation causes zero mount render, Efx request/execution, engine lifecycle, or mount-observer churn. A changed `canvasKey`, width, or height still performs the existing controlled replacement/reconfiguration.

### R-D-08 — Existing behavior and performance invariants are non-negotiable

Preserve canvas-first paint, save-before-leave error handling, rAF latest-wins propagation, playback freeze plus one catch-up render, O(1) projection/content/decode caches, exact pixels, scripts, save/reopen, preview/export, cached reference/onion behavior, and all existing user interaction semantics. Timing/localization changes may alter only when render work executes, never the resulting behavior.

### R-D-09 — No environment, dependency, or launch changes

No package changes, no speculative dependencies, no jsdom or happy-dom, no Vitest/test-config changes, and no watch mode. The agent MUST NOT launch the server, browser, or native app. Automated commands use `pnpm -C app exec vitest run ...`, `pnpm -C app exec tsc --noEmit`, and `pnpm -C app build`; engine/package tests use app-owned Vitest with `--root ../packages/efx-physic-paint`.

### R-D-10 — Two-stage user-owned acceptance, then final reverification

Plan 38.1-12 first runs automated preconditions, then blocks for user-owned native render-count UAT, then runs the complete Phase 38 `38-06` 33-step native UAT. Any rejection routes to the smallest owning boundary (09 static Studio regions, 10 Workflow, or 11 CanvasMount/Efx). Final automated reverification runs only after explicit user approval of both native stages.

## Warm-up and Native Snapshot Protocol

1. Enable the existing development profiler gate and clear it through `window.__EFX_PHYSICS_PAINT_PROFILE__.clear()`.
2. Open the target Physics Paint project and perform one adjacent committed navigation in each direction to warm component subscriptions and caches.
3. Capture `before = window.__EFX_PHYSICS_PAINT_PROFILE__.snapshot()`.
4. Perform one ordinary adjacent committed frame navigation and wait for the existing committed rAF propagation to settle.
5. Capture `after = window.__EFX_PHYSICS_PAINT_PROFILE__.snapshot()` and compute the native profiler delta.
6. Compare named counters against R-D-04. Repeat in the reverse direction.
7. Separately change overlay/input-lock semantics to prove `CanvasStack` remains live, and separately change `canvasKey`/dimensions to prove controlled CanvasMount/Efx replacement remains functional.

No wall-clock timing is an acceptance criterion.
