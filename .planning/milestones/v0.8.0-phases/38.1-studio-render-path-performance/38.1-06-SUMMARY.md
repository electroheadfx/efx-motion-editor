## Root Causes (fixed by gap plan 38.1-07)

Diagnosis of the run-1 A/C failure found four stacked per-navigation costs the UI-layer restructure (38.1-01..05) had not touched:

1. **Store O(N) projection/revision per read** — `getRotoPhysicalProjection` / `getRotoPhysicalContentRevision` recomputed the full physical projection (and a dataUrl-inclusive revision rehash) on every read, so every navigation paid O(total key count) in the store layer. Fixed by the per-layer identity-triple structural memo (recordMap / frozen interpolation / capacity) — per-navigation reads are now O(1), spy-proven zero recomputes on navigation/selection, exactly one byte-identical recompute per structural mutation class.
2. **Engine decode-less reload** — every frame revisit constructed and decoded a fresh `Image` from the dataUrl. Fixed by the decoded-Image cache (Map keyed by dataUrl, FIFO cap 32, destroy-cleared) — revisits apply synchronously with zero new decodes under the identical requestId/destroyed/animationMode/drawing guards.
3. **Redundant resetBackground work** — unchanged-background resets re-ran drawBg/redraw. Fixed by the input/identity-guarded skip with the requestId bump unconditional.
4. **Flush-serialized paint** — `navigateToSyncedPhysicalFrame` awaited the save-before-leave flush BEFORE painting the destination. Fixed by the paint-before-flush reorder — flush initiated without await, destination paints in the navigation intent tick, flush awaited afterward with the verbatim error path, `isLatest` gating propagation and the post-flush generated-cell repaint.

Evidence: 38.1-07-SUMMARY.md — full app suite 871 passed / exactly 3 known-red D-15 failures; engine suite 98/98; both typechecks clean.
