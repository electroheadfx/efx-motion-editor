# Phase 38.1: Studio render-path performance - Research

**Researched:** 2026-07-27
**Domain:** Preact + @preact/signals render-path restructure (timing-only refactor, canvas-first ordering, rAF batching, playback UI freeze)
**Confidence:** HIGH (root cause verified against source; mechanisms verified against official docs)

## Summary

The many-key slowdown is a per-frame O(N) render cascade with four verified links, all in the Studio hot path:

1. **Timeline-model rebuild** (`useRotoTimelineModel.ts:77`): the `useMemo` dependency array includes `input.currentFrame`, so every navigation recreates the entire model. That re-runs BOTH the legacy `selectRotoTimelineView` (O(N) normalize/sort/projection over cached frames) and `selectRotoPhysicalTimelineView` → `projectPhysicPaintRotoPhysicalTimeline` (O(capacity) cell array + O(N) identity mapping), and recreates all 14 computeds — producing new array identities downstream on every frame.
2. **Strip re-render per frame** (`PhysicsPaintWorkflowStrip.tsx`): new `physicalCells` identity per frame defeats the `physicalCellByAppFrame` memo (O(N) Map rebuild per render); `rotoDragValidityKey` (line 433) builds an O(N) string over all cells + records per render; all 120 `RotoTimelineCellButton` children re-diff with per-cell `getRotoCellViewModel` scans (O(120 × cachedFrames)).
3. **Studio per-render O(N) derivations** (`PhysicsPaintStudio.tsx`): `getRotoCachedPlaybackFrames()` builds the full frame array with per-frame cache lookups just to compute `selectRotoPlaybackAvailable` (lines 698/912–916); `projectRotoOnionPreviewFrames` re-projects per render (line 903); the ~200-property view-model literal (lines 943–1148) is rebuilt per render (the hook is a passthrough), defeating any downstream memoization.
4. **Playback tick drives a full Studio render** (`useRotoCachedPlayback.ts` + `PhysicsPaintStudio.tsx:563–565`): per tick, `setFrame` + `onFrame → setAnimFrame` re-render the whole Studio tree — cells, capsule, right panel included — at up to 60 fps.

The fix architecture, fully constrained by the locked decisions: **split structural signals from frame/selection signals** (currentFrame and selectedKeyId become in-place signal writes, never model-rebuild triggers), **canvas-first same-tick paint with a scheduled-flag rAF flush for Preact UI** (D-03/D-04/D-05), **fine-grained signal subscription for per-frame cell variation** (only old/new current cells re-render), and a **playback freeze gate** that leaves only the canvas image, a minimal frame indicator, and transport state live, queuing capsule events for one flush on stop (D-01/D-02).

**Primary recommendation:** Restructure in one pass per D-08 — (a) model split in `useRotoTimelineModel`, (b) signals-native rAF batching around the Studio UI flush with latest-wins canvas tokens, (c) fine-grained current-cell subscription in the strip, (d) subscription-gated playback freeze in `useRotoCachedPlayback`/Studio wiring — preserving every source-grep-asserted string and the Phase 38 tooltip/capsule mechanisms verbatim.

## User Constraints (from CONTEXT.md)

### Locked Decisions

**Playback UI Suspension**
- **D-01:** During cached playback, the ONLY live UI updates are the **canvas**, a **minimal current-frame indicator**, and **play/stop control state**. Cells, capsule, and tube/log are **frozen** for the duration. On playback stop, exactly **one catch-up render** restores full UI currency. — reversible (subscription-gating change, not a data-model contract).
- **D-02:** Missing-frame events that would have appeared in the capsule during playback (Phase 38 D-10) are **queued and shown once on stop**, then the idle context line resumes. The 38 D-10 event-driven behavior is preserved, deferred — not dropped.

**Scrub / Navigation Policy**
- **D-03:** **Canvas-first ordering:** on key-click or any navigation, the canvas paint is issued in the same tick, BEFORE any Preact UI work. — costly to reverse; becomes the render-ordering invariant of the Studio hot path.
- **D-04:** **UI updates are rAF-batched:** at most ONE UI render per animation frame regardless of click/nav rate.
- **D-05:** **Latest-wins canvas under saturation:** when navigation outruns the canvas (fast drag-scrub), stale queued paints are skipped — the canvas always shows where the playhead IS. Discrete key-clicks still each paint.

- **D-07:** Regression protection = **native UAT (blocking) + one deterministic render-count instrumentation test** (vitest run, never watch) asserting a frame change does NOT rebuild the timeline model and triggers bounded renders. No timing-budget assertions.

**Surgery Scope and Behavioral Boundary**

### Pattern 1: Structural/frame signal split (the core fix)

**What:** Create the model once per structural-input identity; write `currentFrame` and `selectedKeyId` into signals in place; expose frame-dependent values as cheap computeds.
**When to use:** `useRotoTimelineModel` — the line-77 defect.
**Why it is correct here:** `selectRotoPhysicalTimelineView` uses `currentAppFrame` ONLY for a `projection.cells.find(...)` (rotoTimelineSelectors.ts:262) and `selectedKeyId` only for a `records.find(...)` (line 265–266). The expensive part (projection) has zero frame dependency — the split is mechanical and safe. The legacy `selectRotoTimelineView` likewise uses `currentFrame` only for three `.find()` lookups (lines 127–140).
**Example:**

```typescript
// Pattern shape (project conventions; mechanism is Claude's discretion per CONTEXT):
export function createRotoTimelineModel(input: RotoTimelineModelInput) {
  // Structural inputs: recreated only when records/interpolation/capacity identity changes.
  const structural = signal({ records: input.rotoKeyRecords, interpolation: input.rotoInterpolationState, capacity: input.capacity, cached: input.cachedRotoFrames, settings: input.interpolationSettings });
  // Frame/selection: written in place on every navigation — never a rebuild trigger.
  const currentFrame = signal(input.currentFrame);
  const selectedKeyId = signal(input.selectedKeyId ?? null);

  const physicalProjection = computed(() => /* projectPhysicPaintRotoPhysicalTimeline over structural.value only */);
  const currentCell = computed(() => physicalProjection.value.cells.find(c => c.appFrame === currentFrame.value) ?? EMPTY_CELL(currentFrame.value));
  // ... identical return shape so ALL callers stay untouched
}
```

**Constraint:** keep the exported `RotoTimelineModel` interface and `useRotoTimelineModel(input)` signature byte-compatible — callers include `useRotoTimelineActions` (`getModel: () => rotoTimelineModel.view.value.model`), the Studio body, and `useRotoFrameEditingController`.

### Pattern 2: Scheduled-flag rAF batch (D-04) with latest-wins canvas token (D-05)

**What:** Canvas paint synchronously in the event tick; schedule the Preact UI flush behind a single pending-rAF flag; each flush reads latest signal state.
**Source:** dominant idiom across production editors (mx.js architecture docs, Excalidraw optimization guidance, CopilotKit #3499, Obsidian StoryLine notes). [CITED: see Sources]
**Example:**

```typescript
// Signals-native scheduler sketch (discretion; must not add a hook layer per CLAUDE.md):
let pending = 0;
function scheduleUiFlush(flush: () => void) {
  if (pending) return;                       // scheduled-flag guard: max 1 flush/frame
  pending = requestAnimationFrame(() => { pending = 0; flush(); });
}
// Latest-wins canvas (D-05): monotonic nav generation; stale generations skip painting.
let navGeneration = 0;
function navigate(frame: number) {
  const gen = ++navGeneration;
  // ...async prep (flush of previous frame — unchanged behavior)...
  if (gen !== navGeneration) return;         // a newer nav superseded this paint
  paintCanvas(frame);                        // same tick as the newest intent
  frameSignal.value = frame;
  scheduleUiFlush(() => { /* one Preact state propagation */ });
}
```

**Discrete-click rule (D-05):** discrete key-clicks each paint — latest-wins skipping applies only to saturation (drag-scrub), never to distinct clicks. A per-click generation that is not superseded always paints.

### Pattern 3: Fine-grained current-cell subscription (strip)

**What:** Move per-frame visual variation (the `.current` ring, `Key {n}` context, capsule ambient line) behind signal reads at the narrowest component, instead of re-rendering all 120 cells from the parent.
**Source:** official Preact signals docs — reading `.value` in a component subscribes only that component; signals passed as props are references that skip VDOM diffing. [CITED: preactjs.com/guide/v10/signals]
**When to use:** `RotoTimelineCellButton` — each cell reads `currentFrameSignal.value` (or a boolean `isCurrent` computed) so a frame change re-renders exactly the old-current and new-current cells.
**Hard constraint:** every `data-roto-app-frame`, `data-roto-kind`, `data-roto-key-id`, class hook, aria string, and tooltip child must remain byte-identical in the DOM (D-09) — and in many cases byte-identical in the SOURCE (55 source-grep assertions in `PhysicsPaintWorkflowStrip.test.ts`; see Pitfall 1).

### Pattern 4: Playback freeze gate + event queue (D-01/D-02)

**What:** During `rotoCachedPlayback.isActive`, only three surfaces consume per-tick signals: the playback canvas image (`cachedRotoPlaybackUrl`), the minimal current-frame indicator, and play/stop control state. Cells/capsule/right-panel subscriptions are gated; capsule events are queued and flushed once on stop, followed by exactly one catch-up render.
**Where:** `useRotoCachedPlayback` currently drives two `useState` updates per tick (`setFrame`, `setAnimFrame` at `PhysicsPaintStudio.tsx:563–565`), each re-rendering the whole Studio. Convert the per-tick surface to signals read by the minimal live components (mechanism — subscription gating vs render short-circuit — is Claude's discretion).
**Preserve:** `start()`/`stop()`/`toggle()`/`updateFps` semantics, status strings verbatim, `resetForLaunch`, the `workflowMode !== 'roto'` stop effect, and the existing `useRotoCachedPlayback.test.ts` contract.

### Anti-Patterns to Avoid
- **Recreating signal graphs in `useMemo` with frame deps:** the exact line-77 defect in new clothes. Frame/selection flow through in-place `.value` writes only.
- **`untracked()`/`peek()` on `physicPaintVersion`-subscribed memos:** breaks the bump-AND-subscribe contract (project memory) — store changes would stop invalidating the Studio.
- **A new state-management layer or React-style `useSyncExternalStore` shim:** violates project CLAUDE.md (signals-native, no new abstractions).
- **Debounce/cancel-and-reschedule for the UI flush:** defers UI until updates settle — violates D-04's "max 1 render per frame" (a settled delay can starve under continuous scrub and makes the UI feel unresponsive). Use the scheduled-flag guard; the flush always renders the latest state.
- **Freezing the playback canvas image or transport button:** D-01 names exactly three live surfaces; freezing more is a behavior change.
- **"Fixing" the 3 known-red D-15 tests while editing these files:** 2 presentation baseline assertions + 1 strip `placement="below"` source-grep stay red until 38-08 by explicit decision.
- **Changing `getRotoCellViewModel`/capsule/tooltip derivation semantics to "optimize":** D-09 — derivations stay pure and identical; only WHEN they run changes.

## Don't Hand-Roll

| Problem | Don't Build | Use Instead | Why |
|---------|-------------|-------------|-----|
| Coalescing multiple signal writes in one tick | custom dirty-flag diffing | `batch()` from `@preact/signals` | Official API: one commit at outermost batch end [CITED: preactjs.com/guide/v10/signals] |
| Memoized derivations | hand-rolled memo caches with invalidation bugs | `computed()` (lazy, cached, glitch-free) | Recomputes only on read after dependency change [CITED: preactjs.com/guide/v10/signals + preactjs/signals repo README] |
| Per-frame render throttle | `setTimeout`/`setInterval` throttle | scheduled-flag `requestAnimationFrame` guard | rAF aligns with paint; timer throttles fire off-vs-cycle and starve under load [CITED: debugbear.com/blog/requestanimationframe] |
| Render-count assertion | DOM renderer (jsdom/happy-dom) + new test env | spy counters inside `computed` functions + synchronous `effect()` from signals in node | Project rule: no test config hacks; signals-core runs standalone in node; official signals repo test suite uses exactly this vitest+spy pattern [CITED: github.com/preactjs/signals packages/core] |

**Key insight:** every mechanism this phase needs (fine-grained subscription, batching, lazy computed caching) is already in the installed `@preact/signals` — the defect is placement (what subscribes to what, and what recreates what), not missing tooling.

## Common Pitfalls

### Pitfall 1: Source-grep regression tests pin the surgery surface
**What goes wrong:** `PhysicsPaintWorkflowStrip.test.ts` (55 assertions), `PhysicsPaintStudio.test.ts` (7), `PhysicsPaintRightSidebar.test.ts`, `PhysicsPaintScriptsPanel.test.ts` assert literal source strings — aria-labels, class hooks, handler snippets (`props.onAddRotoKey?.()`), prop names, guard expressions.
**Why it happens:** the project locks UI contracts via source greps, not DOM tests.
**How to avoid:** before restructuring a block, grep the test file for every literal it asserts in that block; preserve them verbatim (moves are fine, mutations are not), or update the test deliberately in the same commit with justification. Do not fix the 3 known-red D-15 assertions.
**Warning signs:** `vitest run` fails on files you "only reformatted."

### Pitfall 2: Rebuild-by-dep-array returns in a new place
**What goes wrong:** the new memoization (strip `physicalCellByAppFrame`, view-model slices) reintroduces `currentFrame`/frame-derived arrays in a dependency array — identity churn defeats the split.
**Why it happens:** `rotoTimelineModel.physicalCells.value` etc. flow into memos; if the model still returns new identities per frame, every downstream memo breaks.
**How to avoid:** verify at each integration point that structural outputs keep reference identity across a pure frame change. The D-07 instrumentation test exists precisely to assert this for the model.
**Warning signs:** strip memos (`useMemo` on `currentPhysicalCells`) recompute on navigation.

### Pitfall 3: Signal writes during render creating write→render→write loops
**What goes wrong:** syncing props into model signals during the Studio render can retrigger subscribers mid-render.
**Why it happens:** writing `.value` is synchronous in signals; a component that writes a signal it also reads can loop.
**How to avoid:** write frame/selection signals from event handlers/navigation pipeline (same tick as canvas paint), not from render bodies; or guard writes by equality (`if (sig.peek() !== next) sig.value = next`). Effects remain reserved for external sync per CLAUDE.md — rAF scheduling qualifies.
**Warning signs:** nested render warnings, double paints per click.

### Pitfall 4: Freezing the wrong surfaces during playback
**What goes wrong:** the freeze gate also freezes the playback canvas image, the frame indicator, or the transport state — or forgets the D-02 queue so capsule events are dropped.
**Why it happens:** D-01's live set is small and explicit; over-gating is as much a behavior change as under-gating (D-09).
**How to avoid:** enumerate the three live surfaces in the plan and test them in UAT: canvas advances, indicator advances, Play/Stop state toggles; queued missing-frame events appear exactly once on stop, then the idle context line resumes (38 D-10 wording verbatim).
**Warning signs:** playback looks frozen; capsule loses events; two catch-up renders flicker on stop.

### Pitfall 5: Canvas-first ordering broken by the save flush
**What goes wrong:** `navigateToSyncedPhysicalFrame` awaits `rotoPersistence.flushLivePixels(currentFrame)` BEFORE the canvas paint (Studio:720–735) — under fast clicking, serialized awaits delay the same-tick paint D-03 demands.
**Why it happens:** the save-before-leave behavior is correct and must stay (36.6 contract + D-09), but its await currently gates the paint of the DESTINATION frame.
**How to avoid:** keep the flush (source-frame save semantics unchanged) but structure the pipeline so the destination canvas paint is not queued behind stale work: latest-wins generation tokens (Pattern 2) ensure only the newest intent paints; do NOT skip or weaken the flush itself.
**Warning signs:** canvas lags one click behind during fast key-clicking.

### Pitfall 6: Legacy view consumers silently stale
**What goes wrong:** `useRotoTimelineActions` reads `rotoTimelineModel.view.value.model` (legacy source/display model) and the Studio reads `occupiedRotoFrames`/`savedRotoFrames`/`cachedRotoFrames` — if the split makes these stale or per-frame-churned, keyboard nav, strip markers, and playback availability break subtly.
**How to avoid:** the split keeps BOTH views' structural parts structural; frame-dependent legacy fields (`currentFrameSelectionKind`, `currentFrameOwnerSourceFrame`, `currentFrameIsGenerated`) become cheap computeds exactly like `currentCell`.
**Warning signs:** arrow-key navigation targets stale frames; markers vanish after edits.

### Pitfall 7: Per-render O(N) availability check left in the Studio body
**What goes wrong:** `selectRotoPlaybackAvailable({ frames: getRotoCachedPlaybackFrames() })` (Studio:912–916) builds the full frame array (with per-frame cache lookups via `findCachedRotoDisplayFrame`) on every render just to answer "is anything playable" (`physicsPaintStudioSelectors.ts:24–29` — `.some(Boolean)`).
**How to avoid:** derive availability from a cheap structural computed (e.g. projection length / any cached frame) with identical boolean semantics; verify the equivalence — including the no-launch and all-missing cases — before swapping.
**Warning signs:** Play button enabled/disabled state flips vs. current build (a D-09 violation).

// Mutate signals immediately (canvas + cheap computeds see them same-tick);
// the Preact state flush happens at most once per animation frame.
let rafId = 0;
function scheduleFlush() {
  if (rafId !== 0) return;
  rafId = requestAnimationFrame(() => {
    rafId = 0;
    batch(() => { uiFrameSignal.value = frameSignal.peek(); });
  });
