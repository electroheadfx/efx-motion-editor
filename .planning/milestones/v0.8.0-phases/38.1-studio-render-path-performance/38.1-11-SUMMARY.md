# Phase 38.1 Plan 11: Persistent Canvas and Efx Isolation Summary

**Memoized CanvasStack and keyed CanvasMount boundaries now keep the persistent Efx child out of frame-only Studio work while latest-ref callbacks preserve current engine and Roto behavior.**

- **Runtime ownership:** The agent did not launch the server, browser, or native application.

## Accomplishments

- Replaced the fresh CanvasStack children vnode path with a memoized private CanvasStack implementation that receives stable semantic props and creates the keyed memoized mount internally.
- Added a dedicated `MemoizedPhysicsPaintCanvasMount` compat wrapper while preserving `PhysicsPaintCanvasMount` as a plain directly callable implementation.
- Added per-Studio `canvasStackPropsMemo` and `canvasMountPropsMemo` caches whose dependency lists explicitly exclude current frame, start frame, and navigation generation values.
- Converted Studio engine-ready and completed-mutation props into stable named callbacks backed by render-updated implementation refs, preserving the full current-frame, launch, cache, history, and script behavior.
- Converted every CanvasMount-to-Efx callback into a stable forwarder reading the latest parent callback ref without adding synchronization effects.
- Preserved the existing CanvasStack ResizeObserver/MutationObserver markup and lifetime, CanvasMount dimension observer dependencies, mount rAF check, error copy, performance counters, and keyed replacement route.

## Boundary Ownership

| Surface | Plain implementation | Memo boundary | Key owner |
|---|---|---|---|
| CanvasStack | `PhysicsPaintCanvasStackImpl` in StudioView | private `memo(PhysicsPaintCanvasStackImpl)` | N/A |

CanvasStack no longer accepts `children`. Its stable props include `canvasKey` and `mount`, and it instantiates `<MemoizedPhysicsPaintCanvasMount key={props.canvasKey} {...props.mount} />` directly.

## Decisions Made

- Kept compat imports out of the plain CanvasMount module to preserve direct invocation and match the established RightPanel wrapper pattern.
- Memoized the CanvasStack itself rather than only the CanvasMount because R-D-04 also requires zero CanvasStack render when overlay/input-lock/playback/reference semantics are unchanged.
- Made CanvasStack instantiate the persistent child internally because a parent-created children vnode would defeat default shallow memo comparison on every Studio render.
- Used render-updated refs rather than synchronization effects so callbacks remain current without effect dependency churn or a copied-state lifecycle.
- Kept default shallow memo comparison and explicit identity-memo dependency lists; no custom comparator or additional state-management abstraction was introduced.
