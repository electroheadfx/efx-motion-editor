## Decisions Made
- Structural input changes recreate the graph via the surviving useMemo dependency entries (the plan's mechanism (c)); within a model instance structural inputs never mutate — the structural-invalidation test proves recreation rebuilds the projection exactly once with byte-equal values.
- `RotoLegacyTimelineStructuralView` carries `realKeyDisplayFrames` so the assembly's selection-kind `includes()` check is byte-identical to the pre-split derivation (no membership-equivalence re-derivation risk).
- Structural outputs (occupiedRotoFrames, savedRotoFrames, cachedRotoFrames, orderedRealKeyRecords, generatedCells, physicalCells) are computed directly from the structural computeds rather than from the assembled views, so frame writes do not even re-evaluate them.
