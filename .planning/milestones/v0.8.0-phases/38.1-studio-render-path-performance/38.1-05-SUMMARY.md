## Decisions Made

- **`playbackTick` shape is `{ frameIndex, appFrame, frame }`** (executor latitude per plan): keeping `frame` generic preserves the hook's `Frame` genericity (the coordinator instantiates it with `RenderedFramePayload`); the view narrows for `dataUrl`. The `frame` getter over the signal preserves the plain-value read contract — the hook test passes UNMODIFIED.
- **The D-02 deferred event IS the start/missing-frame line.** The plan names "the missing-frame status set in start()" as the queued event, but the hook test asserts that line visible DURING playback (and Task 2's scope guard forbids test edits). Resolution: the line publishes at the start transition (one sanctioned render — transport state is a live surface) AND is enqueued as the deferred event; the stop flush re-publishes it once (recency refresh in the 36.15/38 arbitration) before the idle context resumes. On `toggle()`-stop the verbatim `'Cached Roto playback stopped.'` line overrides within the same catch-up render — existing stop-time behavior preserved. No event is dropped: every stop path flushes the queue's latest event into the status channel exactly once.
- **`statusMessage` peeks, never subscribes:** the frozen `Previewing` line reads `rotoPlaybackFrameIndex.peek() + 1` / `rotoPlaybackFrameCount.peek()` — identical values at every render the Studio actually performs (start transition, stop catch-up), zero per-tick subscription. Per resolved Open Question 1, this line is NOT the live indicator and freezes with the capsule.
- **Null clears pass through the D-02 gate:** `setStatus(null)` is channel maintenance, not an event; only non-null status publishes queue during active playback.
