## Evidence Boundary

The Node runtime executes one plain `PhysicsPaintCanvasMount` hook-slot sequence. It proves:

- stable Efx callback identity with latest parent behavior;
- dependency-aware dimension effect retention/reconfiguration;
- ResizeObserver and requestAnimationFrame resource ownership;
- exactly-once active cleanup under repeated unmount calls.

It does not render the mocked Efx child, reconcile keyed VNodes, persist a child instance, replace a keyed child, or prove memo-boundary behavior. Existing source assertions locate the compat memo wrapper and keyed VNode as architecture checks only. Plan 38.1-18 remains the blocking native oracle for actual same-key persistence, changed-key replacement, dimension-only reconfiguration without Efx replacement, and exactly-once real child ownership.

## Decisions Made

- Kept the runtime interface narrow and test-only: callers reset a render, route mocked hooks through the runtime, flush effects after assigning refs, and unmount once testing is complete.
- Copied dependency arrays into slots to avoid test-owned mutation changing prior dependency history.
- Cleared cleanup slots before invoking cleanup so recursive or repeated lifecycle flushing cannot execute one resource cleanup twice.
- Used the existing Node Vitest environment and mocked browser resources instead of adding jsdom, happy-dom, a package, or test configuration.
